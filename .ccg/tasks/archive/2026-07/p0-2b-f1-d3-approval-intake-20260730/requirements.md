# P0-2B 需求收口

## 目标

在不连接生产、不写入受限审批系统、不代签、不猜测 managed 拓扑值的前提下，确认 F1 D3
真实审批资料的采集容器、责任边界和后续关闭条件已经就位。

## 范围

- 核验 B1–B9 技术 SSOT、审批治理包、D3 预检报告与 runbook 之间无漂移。
- 将 M1–M4、B1–B9 按“仓库事实 / 组织审批输入 / D3 窗口核验”分类。
- 形成一份只引用字段 ID 的时点性 readiness 审查快照。
- 同步正式进度入口。

## 禁止事项

- 不修改 `apps/`、`services/`、`packages/` 或生产配置。
- 不填写或推断 M1–M4、B1–B9 真实值，不改变其状态。
- 不连接 SSH、PM2、Nginx、数据库、Redis，不读取环境变量值或凭据。
- 不把本地 CI、D2 fixture、旧主机、HTTP 200 或本地摘要当作 D3 生产证据。
- 不代替机构、运维、安全负责人签批。

## 文件预算

最多新增/修改 3 个正式文档：一份 `docs/reviews/` 时点报告，以及两个 `docs/progress/`
正式进度入口。技术 SSOT、审批模板和 runbook 保持不变。

## 完成口径

本轮只能完成“受限采集准备已就绪”。production F1 继续 NO-GO；真实审批输入与 D3
只读核验仍由具名负责人和独立授权窗口完成。
