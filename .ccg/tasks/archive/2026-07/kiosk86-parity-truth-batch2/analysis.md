# 第二批只读分析结论

## 口径

- “86 张原型”是历史路由数口径，不是当前视觉文件数。
- 当前权威视觉目标为 77 个主视觉目标 + 5 个 Fusion 状态参考，共 82 个。
- 当前生产路由为 87 个 URL pattern：82 个组件落点 + 5 个兼容重定向。
- 原型 73 是 `/assistant` 页内通话子状态；34A 同时对应 `/scan/start` 和 `/scan/settings`；`/me/privacy-requests` 无独立原型，必须标记 `NO_INDEPENDENT_PROTOTYPE`。

## 功能真实性

- `/print/done` 缺状态时默认成功，属于假成功；真实真相源是既有打印任务查询。
- 打印完成页帮助/反馈是死按钮，本地评分无持久化来源。
- `/scan/start` 依赖不存在的 `/kiosk/device/status`；`/scan/settings` 直达会创建会话，失败状态仍可能显示已创建。
- `/resume/export` 目前是诚实守门页；真实导出已经在生成/优化流程完成，不应在该路由建立第二套状态。
- 场馆导览页面本身不是可打印产物；真实可打印来源是既有 `venue_map` 材料链路。
- 线下机构后端与前端服务均已支持真实 `keyword` 查询；页面按钮尚未接线。

## 视觉证据

- W0–W6 约 160 个 Playwright case 证明路由、行为、布局与契约态，不等于原型/生产逐屏配对证据。
- W6 的 current-only、fullPage 截图不能称为同视口视觉验收。
- 新证据必须固定 `1080×1920`，两条 mobile 路由固定 `390×844`，同一业务状态下生成 prototype/current 对照；fixture 必须标记 `contract-fixture`。
- 自动化负责完整性、尺寸、几何、运行错误与产物；最终视觉一致性仍需逐对人工判定和 27 寸/手机真机验收。

## 双模型结论

- Antigravity 与 Claude 均把 `/print/done` 假成功列为最高优先级。
- 两者均建议把证据基础与功能真实性修复分层，不以假数据恢复原型展示指标。
- Claude 进一步确认扫描实时硬件状态目前没有真实后端来源，不能继续声称“扫描仪已就绪”。
