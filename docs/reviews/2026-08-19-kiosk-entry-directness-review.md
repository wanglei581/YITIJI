# Kiosk 功能入口直达性评审（2026-08-19）

> 起因：产品负责人在真机上点「打印扫描 → 手机扫码上传」，落地页却又摆出一个含「扫码上传」的四选一，
> 标题还写着「文档打印」。要求：**入口不要重复，点完即达对应功能页，不要进去再选一遍。**
>
> 参与：Claude（主）+ DeepSeek v4 ultra / Antigravity Gemini 3.7 Flash High /
> Cursor GPT-5.6 Sol High / Grok 4.6 high，全部只读调查，结论经交叉核对与本地实跑复核。
>
> 本文只做评审与方案，**不含代码改动**。

---

## 一、问题定性：三类缺陷

| 类别 | 定义 | 用户感受 |
|---|---|---|
| **A 类｜二次选择** | 入口已声明具体意图，落地页仍要求在**含该意图同义项**的列表里再选一次 | 「我不是刚选过吗」 |
| **B 类｜同址异名** | 落地页标题 / 面包屑与用户点击的入口名不一致；或多张不同名的卡指向同一 URL | 「我是不是点错了」 |
| **C 类｜跨链同义** | 落地页内的快捷按钮与上级 Hub 的卡片指向同一终点 | 同一个东西出现两次 |

三类的共同根因是**两级页面在问重叠的问题**：Hub 层按「你要做什么事」组织，落地页按「文件从哪来」组织，
而这两套分类天然交叉——「手机扫码上传」既是一件事，也是一个通道。

## 二、全站盘点

### 2.1 同一 Hub 内两张卡指向同一 URL（全站仅 2 处，已实跑穷举）

| Hub | 卡片 A | 卡片 B | 共同目标 | 严重度 |

| 入口 | 落地页 | 又问了什么 |

| 手机扫码上传 | `PrintUploadPage:382` 无条件渲染 2×2 网格 | 选择文件 / **扫码上传** / U盘导入 / 扫描原件 |

`PrintUploadPage:419` 的「扫描原件」按钮直接 `navigate('/scan/start')`，

`PrintUploadPage:129`（文档打印 / 简历打印）、`ScanStartPage:124`、`ResumeSourcePage:179`、

**`PrintPickupClaimPage:244`（入口叫「到机码核销」，标题却是「扫码取件」）**、

## 三、判定规则（建议写入 CLAUDE.md 作长期口径）

一个入口带两个维度的信息：**任务**（要什么产物）与**通道**（输入从哪来）。

| 入口声明了 | 落地页应当 |
|---|---|
| 只有任务（如「文档打印」） | **保留**通道选择器 —— 用户确实还没决定文件从哪来 |
| 只有通道（如「手机扫码上传」） | **直达**该通道面板，标题用入口名；其余通道降级为一行次要链接，不做等权按钮 |
| 两者都有（如「照片打印 + 本机上传」） | 直达，且标题、步骤条、文件类型限制都按该组合定制 |

配套三条：

1. **标题跟随入口**。落地页标题不得写死为其中一个入口的名字。
2. **同一 Hub 内两张卡不得指向完全相同的 URL**。要么合并（但入口已定版，不能删），要么让 URL 带上区分参数并让落地页据此改变表现。
3. **落地页不得内嵌与上级 Hub 卡片同义的跳转按钮**，除非它携带了额外意图（如「扫描后直接打印」而非裸跳 `/scan/start`）。

## 四、实现方式：照抄仓库已有的三种先例，不另发明

| 先例 | 位置 | 适用 |
|---|---|---|
| **动态 `:key` 路由**：字典映射 key → 标题/副标题/内容，落地页零选择 | `SmartCampusServicePage.tsx:32-87`（`smart-campus/service/:key`）、`PrintScanFeatureInfoPage.tsx:28-102` | 每个意图内容差异大 |
| **显式 `intent` 参数**：切标题、副标题**和流程步骤条** | `ResumeSourcePage.tsx:78-107,178-180`（`INTENT_COPY` 字典 + `intent=diagnose\|optimize`） | 多意图共用同一条链路 ← **本次首选** |
| **白名单 `tab` 参数**：直达激活选项卡 | `renshi/shared.ts:14-20` + `RenshiPage.tsx:64-66` | 同一页面内的平级分区 |

**关键设计约束（Cursor Sol 指出，务必遵守）**：
不能只用 `tab` 参数判断是否收起选择器——**文档打印和照片打印也带 `tab=file`**，
按 `tab` 收就会把它们正常的通道选择一起干掉。必须引入独立的意图参数（如 `mode=transfer`）。

## 五、门禁约束：决定了改造只能是「增量」

Grok 实测的反向钉死清单：

| 门禁 / 用例 | 钉死了什么 |
|---|---|
| `fusion-w2-print.spec.ts:403-411` | 访问**不带 tab 的** `/print/upload?source=document`，要求四个按钮同时可见，并会点击「扫描原件」跳 `/scan/start` |
| `verify-fusion-w2-print-scan.mjs:354-363` | 源码必须含 `UploadTab='file'\|'qr'\|'usb'`、`navigate('/scan/start')`、`w2-print-upload-source-grid` |
| `verify-print-entry-source-split.mjs:48-60` | 源码必须含三个通道文案与「文档打印」字面量 |
| `fusion-w6-route-cases.ts:115` + `fusion-w6-routes.spec.ts:120` | 不带 query 的 `/print/upload` 上必须能看到「文档打印」 |

**推论（重要）**：**默认视图（不带意图参数）必须原样保留**——四个按钮、标题「文档打印」一个都不能动。
只有携带意图参数的深链走新行为。这反而是好事：改造变成纯增量，**回归面接近零**，
且条件隐藏时源码字符串仍在，静态门禁不会红。

`verify-kiosk-runtime-error-boundary.mjs:58-66` 只断言 `ACTIONBAR_ROUTES` 含 `/print/upload`，改 UI 不受影响。

## 六、改造方案（分批，按「用户困惑 × 出现频率 ÷ 风险」排序）

### 批次 1｜打印扫描直达（负责人当场发现的那条，风险最低）

- `PrintUploadPage` 引入 `mode=transfer` 意图参数（照抄 `ResumeSourcePage` 的 `INTENT_COPY` 字典写法）：
  - 标题改为「手机扫码上传」，副标题说明「只是把文件传到这台机器」；
  - 直接渲染扫码面板，2×2 网格收起为一行次要文字链「也可以：选择文件 / U盘导入」；
  - 步骤条不显示 6 步打印流程（搬运不等于打印）。
- `PrintScanHomePage` 的「手机扫码上传」卡改指 `/print/upload?source=document&mode=transfer`。
- 上传成功后**不自动跳走**：主按钮「继续文档打印」（带当前文件直接进材料检查，不再选通道），次按钮「返回打印扫描」。
  Cursor 特别提醒：不要默认回首页——当前重进上传页会 `file=null`，用户会被迫重传。
- 「照片打印」卡改指 `?source=document&tab=file&category=photo`，落地页标题随之显示「照片打印」。
- 「扫描原件」按钮**只在意图模式下隐藏**，默认视图保留（否则 `fusion-w2-print.spec.ts:409` 必红）。

### 批次 2｜政策服务 Hub 的错位卡（严重度最高，改动最小）

「政策收藏」不应落到 `/me/ai-records`。需要先确认产品意图：是要一个真的收藏页，还是这张卡本身就该合并。
**这条需要你拍板**，因为它可能意味着一个尚不存在的页面。

### 批次 3｜材料扫描 3 步压到 2 步

`/scan/start` 的扫描类型三选一（简历 / 证件 / 普通文档）可由入口预置。
但 `/print-scan` 首页只有一张「材料扫描」卡，不带类型——所以这条要么在首页卡上做类型细分（**会新增入口，与定版规则冲突**），
要么保留现状。**建议保留现状**，把 3 步视为可接受，理由是扫描类型确实是用户到场后才决定的。

### 批次 4｜标题跟随入口（逐页低风险修）

按 §三 判据筛出真正会让用户怀疑点错的几处，优先 `PrintPickupClaimPage`（「到机码核销」→「扫码取件」）。

### 批次 5｜长期防复发门禁

Cursor 第二轮未返回结论。我的判断：**能钉一部分，钉不住全部**。

- 可以静态钉：同一 Hub 文件内不得出现两个相同的 `to:` 字面量（本次实跑用的就是这个方法，能抓出 2 处）。
- 可以静态钉：声明了通道意图的入口，其目标 URL 必须带意图参数。
- **钉不住**：落地页第一屏「是不是又是一个选择器」——这需要渲染后判断，只能靠 Playwright 逐条写，
  成本高于收益。建议改为在 CLAUDE.md 写清判据 + code review 时人工把关。

## 七、不做什么

- **不删任何入口**（负责人已定版）。改的全部是「点进去之后」的行为。
- **不新建页面**。全部复用现有落地页 + 意图参数。
- **不动默认视图**。所有既有门禁与 Playwright 用例依赖它。
- 不在本轮做 V6 逐页迁移——那是另一条长尾。
