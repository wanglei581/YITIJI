# 小程序“求职 + 职业生活服务”扩展终审

> 日期：2026-08-06  
> 状态：产品与合规方案审查，通过后仍需 Gate 0，不代表批准开发或上线  
> 审查范围：视频自我介绍二维码、自我探索测评、生活服务扩展、商业与信息架构  
> 协作审查：Codex + 本地 Claude Code 2.1.222（两轮只读审查）

## 一、结论

总体判定：**CONDITIONAL GO**。

产品可以从“AI 求职打印服务”升级为“AI 求职与职业生活服务”，但不能变成泛生活平台。扩展边界必须围绕四件事：求职准备、入职决策、劳动权益、材料与线下公共服务。任何与招聘撮合、医疗诊断、金融销售、泛 O2O 或公共候选人库相关的能力继续禁止。

当前优先级不是马上增加视频或测试，而是先完成找回小程序的 Gate 0、唯一源码归位、真实支付与 Order-only 到机履约。新增能力的推荐顺序为：

1. 将主仓已经完成并验证的“自我探索 v1”适配到小程序，保持本人私密使用。
2. 试点“外部视频自我介绍链接二维码”，平台不托管视频、不提供候选人搜索。
3. 通过百宝箱逐项开放与求职相邻的生活服务，不增加首页长度。
4. 平台托管求职者视频暂不进入 0-6 个月开发计划，未来另做法务、微信类目、隐私影响、内容安全和成本 Gate。

## 二、Verdict

| 能力 | 结论 | 产品口径 |

| 小程序自我探索 v1 | CONDITIONAL GO | 复用既有服务端与共享类型，只做小程序适配 |
| 测评报告单独保存/打印 | GO（随迁移） | 本人资产，可撤回、删除，不对企业开放 |

| SCL/PHQ/GAD/MMPI 等心理量表 | NO-GO | 不提供临床、心理健康诊断或风险评价 |

## 三、视频自我介绍二维码

### 3.1 正确产品定义

建议名称：**视频自我介绍链接**，不使用“视频简历库”“候选人视频”“HR 看简历”等表述。

它是求职者本人制作和主动分享的求职材料，平台只帮助生成二维码和管理分享状态。它不是平台向企业提供候选人的渠道，不进入岗位投递、企业筛选、候选人推荐或 Partner 数据面。

### 3.2 首发采用 B+ 方案

用户先在受支持的外部平台保存本人视频，再将 HTTPS 链接填入小程序。服务端生成不可猜测的分享令牌，纸质简历二维码指向平台的中性过渡页，由过渡页显示离开提示并打开经审核的外部链接。

相比直接把外部 URL 印进二维码，B+ 方案多一层平台分享令牌，价值是用户可以撤回、暂停或更新链接；相比平台托管视频，又不承担视频文件、转码和 CDN 的第一阶段成本。

### 3.3 必须满足的安全契约

- 二维码只包含随机分享令牌，不含 userId、手机号、简历 ID、视频 URL 或其他个人字段。
- 令牌至少 128 bit 随机，服务端只存哈希；默认 30 天，可由本人续期，最长周期由法务与运营 Gate 冻结。
- 分享页不可搜索、不可索引，响应使用 `X-Robots-Tag: noindex, nofollow`、严格 CSP 和 `Referrer-Policy: no-referrer`。
- 外部链接仅允许 HTTPS；拒绝 IP 字面量、内网、localhost、非标准端口、用户信息段、`javascript:`、`data:` 和多级开放重定向。
- 采用经过审核的域名白名单；不由服务端主动抓取用户 URL，避免 SSRF 和隐私探活。
- 分享页只展示“即将打开用户提供的外部内容”和有效/已撤回/已过期状态，不展示候选人列表、搜索、联系方式或其他简历内容。
- 用户可随时撤回；撤回后二维码落到友好失效页，不返回裸 404，也不自动跳其他内容。
- 不记录查看者身份、企业名称、扫码后的招聘结果；如需运营指标，仅记录脱敏聚合的成功打开次数并设置最小样本阈值。
- 未成年人、普通人像视频与平台托管视频的具体适用义务必须由中国法务和微信类目专项确认，不能仅凭产品免责声明放行。

### 3.4 简历体验

- 二维码只能由用户在导出/打印前主动勾选，默认不加。
- 二维码区域写“视频自我介绍 · 有效期至 YYYY-MM-DD”，不写“扫码看候选人”或“HR 扫码”。
- 打印前明确提示：纸张可能长期流通，但链接会过期、撤回或因外部平台下线而失效。
- 二维码不遮挡姓名、联系方式、经历或分页；没有真实有效链接时不生成占位二维码。
- 简历导出后不因链接撤回重新修改 PDF；扫码页只显示已撤回/已过期状态。

### 3.5 平台托管视频的未来 Gate

当前不开发。未来至少同时满足以下条件才重新评审：

1. 中国法务对微信类目、备案/许可、用户内容托管和人像信息处理出具书面意见。
2. 完成个人信息保护影响评估、单独同意、保存期、删除和未成年人规则。
3. 完成内容审核、举报、下线、申诉和管理员访问审计。
4. 新增独立 `FilePurpose`，不能复用机构宣传用途 `partner_video`。
5. 完成视频 MIME 嗅探、大小/时长、转码、封面、恶意文件、存储、CDN 和成本配额。
6. 证明平台托管相较 B+ 外部链接能显著提高真实使用率，而不是增加一个昂贵的展示功能。

## 四、自我探索 v1 迁入小程序

### 4.1 当前代码事实

主仓不是只有方案文档。当前已经存在：

- `packages/shared/src/types/selfAssessment.ts`
- `packages/shared/src/data/selfAssessment/`
- `services/api/src/ai/resume/self-assessment.service.ts`
- `services/api/src/ai/self-assessment.controller.ts`
- `services/api/src/ai/resume/self-assessment-pdf.service.ts`
- `apps/kiosk/src/pages/resume/SelfAssessmentFlow.tsx`
- `verify:self-assessment`、`verify:assess-isolation` 和真实网络 Playwright

现有 v1 为 25 题、五个维度：兴趣偏好、工作风格、团队偏好、价值取向、求职动机。它明确是“非临床、非诊断、本人自助参考”，不复用 MBTI、大五、DISC、霍兰德或临床心理量表。

### 4.2 小程序复用边界

复用：

- 服务端 submit/get/withdraw/print API 与 `AiResumeResult(kind='self_assessment')`。
- 共享问题、维度、纯函数评分和合规词拦截。
- answersHash、结果 TTL、本人/匿名 token 隔离、撤回和物理清空。
- 本人 AI 记录、PDF 文件和打印链路。

小程序必须重做：

- 原生微信页面和授权体验，不能复制 Kiosk React 页面。
- Kiosk 的 `sessionStorage` 与 60 秒公共终端闲置逻辑；小程序答案只保存在当前页面内存，不写 Storage、URL、埋点或日志。
- 小程序退出、后台切换和异常恢复规则；退出作答默认清除未提交答案。
- 小程序隐私保护指引中的处理目的、数据类型、保存与删除说明。

### 4.3 报告与简历关系

推荐默认交付是“个人自我探索报告”，保存在本人 AI 记录/文档中。它不应默认成为求职简历的一部分。

如用户主动选择附加：

- 只附加一页“本人自述偏好摘要”，不输出心理结论、人格类型、岗位适配或综合排名。
- 开关默认关闭，每次生成新简历版本都需要重新确认。
- 简历页面明确提示：加入后会把个人偏好主动披露给扫码者或收件方。
- 不将测评结果单独发送、推送或开放给企业、学校、Partner、Admin 或来源平台。

明确禁止：

- 不做综合总分、人格优劣、职业成功率或“适合/不适合某岗位”。
- 不把结果加入岗位匹配、岗位推荐、候选人排序或职业规划的事实判断。
- 不支持朋友圈/微信群一键分享测评结果。
- 不以“解锁完整人格”“企业认可测评”“测评后更容易录用”收费。

## 五、求职 + 职业生活服务边界

### 5.1 产品定位

建议对外定位：**AI 求职与职业生活服务**。

“生活”必须是职业生活，而不是所有生活。准入判断为：该能力是否直接帮助用户完成求职准备、入职决策、劳动权益理解、办事材料准备或到线下服务点履约。无法回答这一问题的能力不进入产品。

### 5.2 推荐服务清单

首批最多选择 3 项试点，不同时上齐：

1. 证件照制作与打印。
2. 文档扫描、格式转换、材料整理与打印。
3. Offer 对比（本人手填、会话内使用，不形成企业 Offer 管理）。
4. 薪资沟通练习与公开行情参考。
5. HR 常识问答（求职者视角）。
6. 劳动合同条款风险提示（非法律意见）。
7. 社保、公积金、劳动权益官方政策入口。
8. 就业登记、失业登记与档案转接办事指引。
9. 就业补贴材料清单与官方申请入口，不代办、不承诺到账。
10. 公开就业服务机构与真实地址/电话/开放时间。
11. 招聘会行前清单、导航和材料包。
12. 压力管理与心理援助的官方科普/热线入口，不做测试、诊断或咨询替代。

### 5.3 明确拒绝

- 贷款、征信、理财、保险销售或金融导流。
- 医疗诊断、心理诊断、用药建议或风险评分。
- 法律代理、代写诉讼材料或承诺案件结果。
- 职业资格代考、论文/考试作弊、未授权题库。
- 外卖、购物、打车、旅游、泛租房、社交、婚恋等普通 O2O。
- 企业候选人池、简历库、代投、内推中介、企业查看测评/视频。
- 代用户办理政府事项、长期保存身份证/银行卡/社保卡等高敏材料。

### 5.4 信息架构

- 首页保持当前一屏，不新增生活服务卡片。
- “今天”只显示来自真实状态的任务，不推广低频生活工具。
- “材料”承载证件照、文档、报告、材料包和打印成果。
- “发现”新增“职业生活服务”分区，承载官方信息和已发布微应用。
- “我的”只显示本人订单、权益、消息、反馈、设置和隐私，不聚合生活服务入口。
- 低频能力全部通过百宝箱 manifest 的 `career/life/legal/hr` 分类发布，继承双人审核、域名白名单、权限、数据政策、熔断和审计。

### 5.5 商业模式

- 免费：公开政策、劳动权益、服务机构、官方入口与基础科普。
- 付费：AI 工具成果、文件处理、导出、打印和明确额度的会员权益。
- B2B2C：学校、人社大厅和公共就业服务机构的终端、SaaS、运维与聚合运营报表。
- 禁止按简历数、候选人数、投递、面试、Offer、入职或招聘效果收费。
- 外部服务合作方不能获得个人简历、视频、测评、浏览明细或扫码者身份。

## 六、0-6 个月路线图

### 0-2 个月：不增加新能力

- 完成上线前 P0、Windows/奔图真机、生产 PostgreSQL、密钥轮换和法务材料。
- 完成小程序 Gate 0：产品名、四 Tab、首发阶段、选定终端履约、微信主体与工程路线。
- 将找回源码选择性归位到唯一 `apps/miniapp/`，接入 CI 和合规门禁。
- 关闭手机支付、Order-only 待到机、到机 release 和真实打印状态缺口。

### 2-4 个月：自我探索小程序适配

- 只做小程序前端适配和隐私/会话差异，不复制服务端。
- 先上线私人报告、撤回、删除、PDF 与本人记录。
- “附加到简历”作为独立小实验，默认关闭；没有充分用户需求时不上。

### 3-5 个月：外部视频链接二维码试点

- 先做 20-50 名自愿用户的 B+ 方案测试。
- 只支持 1-2 个审核过的外部平台域名。
- 验证完成率、二维码实际扫码率、撤回率、投诉率和失效链接率。
- 不托管视频、不采集查看者身份、不做企业入口。

### 4-6 个月：相邻生活服务试点

- 从合同风险提示、社保/公积金官方指引、公共服务机构三个已有底座较强的方向中选择最多 3 项。
- 通过百宝箱发布，不改首页，不一次上齐 12 项。
- 每项必须有真实来源、负责人、更新周期、下线机制和商业成本口径。

## 七、负向测试与合规门禁

1. 小程序未同意非敏感作答说明时提交测评，服务端拒绝且不落库、不调 LLM。
2. 测评答案出现在 Storage、URL、日志、埋点或崩溃上报，CI/测试失败。
3. 他人 userId 或错误匿名 token 读取测评结果，统一同形 404。
4. 撤回后再次读取、打印或附加测评，统一拒绝；并发撤回保持幂等。
5. LLM 产生“适合岗位、人格类型、心理问题、录用概率”等词，丢弃或拒答。
6. 测评结果进入岗位匹配、岗位推荐、职业成功率、企业/Partner/Admin 页面，门禁失败。
7. “附加到简历”默认选中或未做独立确认，UI 门禁失败。
8. 分享令牌不足 128 bit、明文入库或二维码含 userId/视频 URL，安全门禁失败。
9. 外部链接为 HTTP、IP 字面量、内网地址、localhost、非标准端口或开放重定向，服务端拒绝。
10. 已撤回/过期分享令牌继续跳转外部视频，E2E 失败。
11. 分享页可被搜索引擎索引、泄露 Referrer 或展示候选人搜索入口，发布门禁失败。
12. 系统记录扫码者身份、企业、投递或招聘结果，数据契约测试失败。
13. 没有有效链接时仍在简历输出占位二维码，导出门禁失败。
14. 生活服务未经过 manifest 审批、域名白名单或人工复核即展示，百宝箱发布失败。
15. 生活服务页面出现代办、必得补贴、保录用、代投、企业查看简历等文案，合规扫描失败。
16. 手机已支付但未到机时创建可被 Agent claim 的 PrintTask，履约门禁失败。
17. 合作机构通过统计下钻到个人视频、测评或简历，权限测试失败。
18. 平台托管视频功能在法务、类目、内容审核、隐私影响和成本 Gate 任一未通过时可被开关启用，发布守卫失败。

## 八、Claude 审查记录与修正

Claude 第一轮认可：外部链接二维码、自我探索迁移和相邻生活服务为 CONDITIONAL GO；MBTI/临床心理量表、泛生活平台与当前阶段的平台视频托管为 NO-GO。

第一轮有两处需修正：

1. Claude 受旧设计文档“候选文件”表述影响，误判自我探索服务端可能尚未合入；第二轮按当前实际文件和 Git 提交复核后，确认 Kiosk v1 已实现，小程序应复用现有 API。
2. Claude 将平台视频托管资质与普通人像视频的敏感信息属性表述得过于绝对。本报告不把模型意见替代正式法律意见；当前 NO-GO 基于上线阶段、内容安全、隐私、微信类目与成本未完成，未来是否可做必须由中国法务专项确认。

最终联合结论：**先把真实求职闭环做好，再迁移已验证的私人自我探索能力；视频只从可撤销的外部链接二维码试点；生活服务只做职业相邻服务并通过百宝箱治理。**
