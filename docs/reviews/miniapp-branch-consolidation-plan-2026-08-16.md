## 二、待决策的三个问题

### Q1 视觉以哪条线为准？

**建议：以 C 为准，从 B 提取仍有价值的页面级设计。**

理由：C 的视觉改动伴随可验证的约束——对比度已按 WCAG 4.5:1 调整（`--muted` / `--faint` / `--teal` 原值仅 2.4–2.9:1，
不达标且触及 §9 可访问性要求），信息架构按「用户处境」而非技术属性重组，并清除了两个无后端支撑的模块。
B 的视觉未经门禁与对比度检查。

**推翻条件**：若 B 的视觉已有设计侧确认或用户反馈支持，则反过来以 B 为基底，把 C 的对比度修正与
信息架构调整重打上去——但**不得**因为采用 B 的视觉而一并接受其 PII 闸门缺失与岗位搜索回退。

### Q2 B 的 9 个空壳页：继续做还是砍掉？

**建议：全部砍掉，不进入合并。**

理由：3 个调用不存在的后端端点，4 个是 0 API 调用的静态原型。按 §9「不伪造能力」，
没有真实数据与接口支撑的页面不应出现在用户面前。C 已在 `pages/ai/` 移除了指向
`/community/feeds` 与 `/assistant/daily-report` 的入口与请求，同一口径应贯穿。

**注意**：`utils/api.js` 中 `getCommunityFeeds` / `getDailyReport` 两个方法目前**保留**，
因为 B 的两个页面仍在调用，删除会打断在制工作。若 Q2 决定砍掉这些页面，这两个方法应同批删除。

**推翻条件**：若这些页面对应的后端已在其它分支实现或已排期，则保留并按排期接真，
但在后端就位前不得注册进 `app.json`。

### Q3 tab 文案最终叫什么？

**建议：`AI百宝箱`。**

理由：`docs/product/market-validated-strategy-2026-08.md` §6 的结论是
「界面上不出现『职业生活圈』这五个字（内部概念名），对外名字是『怎么办』，**0 新 Tab、0 新一级入口**，
挂在求职 Tab 的分段控件下」。且该战略明确**不做 UGC 发帖社区**——叫「圈」会持续暗示一个不存在也不打算做的社区。

**当前不一致的三处**：主仓 `app.json` 写「职业生活圈」；`custom-tab-bar/index.js` 与本分支 `app.json` 写「AI百宝箱」；
`pages/ai/ai.wxml` 页面标题已由 C 统一为「AI百宝箱」。因用了自定义 tabBar，用户实际看到的是后者，
但原生兜底渲染时会突然变名字。

## 三、归并顺序（Q1–Q3 定案后执行）

1. **先修 B 的两处回退**，不带进合并：恢复 `_passPrintGate` 与 `amountCents` 透传；恢复岗位服务端分页与防竞态。
2. **处理 `package-orders`**：补齐或删除，不留半个模块。
3. 按 Q1 定的基底做视觉合并，逐页比对而非整目录覆盖。
   **`app.json` 只允许逐行增删，禁止整份覆盖**——本轮已因整份复制两次引入事故。
4. 合并 C 的鉴权与契约修复（`utils/{auth,request,storage}.js`、`pages/contract-review/`、
   `utils/{favorites,history}.js`）。这批与视觉无关，冲突面小。
5. 合并后在**主仓**跑 `verify-miniapp-static`（该门禁已于本轮修复，此前因嵌套 worktree 一直 EISDIR 崩溃，
   即开发者工具实际读的那份代码从未被检查过）。
6. **运行时验证**：三个 tab 渲染、合同审查完整流程、取件页续签。
