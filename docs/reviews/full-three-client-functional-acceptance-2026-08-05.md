# 三端全功能专业验收报告（2026-08-05）

## 1. 验收结论

本轮对一体机前台 Kiosk、管理员后台 Admin、合作机构后台 Partner，以及支撑三端的 API、Worker/Terminal Agent 静态与自动化门禁进行了完整回归。

结论分两层：

- **代码与本地真实 API 层：有条件通过。** 主 CI 口径最终归一化为 167/167 PASS；Kiosk 浏览器自动化 221/221 PASS；Admin 36 条导航路由和 Partner 12 条路由均可加载；岗位、招聘会、机构隔离、AI 文字咨询、本人资产登录边界等真实数据链路通过。原 F-01 设备状态真实性缺陷已于 2026-08-06 完成代码修复和本地浏览器回归。
- **整体商用上线：NO-GO。** Windows 真机出纸/扫描、生产 PostgreSQL、真实支付/短信/TRTC、密钥轮换和法务定稿仍未在本轮现场验收，不能用本地自动化替代。

上线前仍须在干净候选和 Windows 真机上复验 F-01，并完成第 7 节 P0 外部验收门槛。

## 5. 首跑异常与归一化

API Verify suites 首跑 167 项中 3 项失败，复核后均不属于业务实现失败：

1. `verify:partner-smart-campus`：脚本复制仓库内陈旧 `services/api/prisma/dev.db`，与 fresh schema 不一致。
2. `verify:terminal-device-config`：同一陈旧数据库夹具问题。
3. `verify:member-data-export-download`：执行环境 PATH 中找不到 `redis-server`，使用明确的 Redis 工具链后通过。

定向复验后三项全部通过，最终结果按 **167/167 PASS** 记录。仓库原 `dev.db` 已恢复，SHA-256 为 `a0be0abd87c5d9abd8ddca33feb99f8965bcda1089a83c250e4d223dca1659d0`。

## 6. 缺陷与风险分级

### P1：代码修复完成，待 Windows 真机复验

**F-01 首页设备状态自相矛盾，离线时仍宣称“打印就绪”（代码层已关闭）。**

- 原复现：真实 API 首页顶栏显示“打印机离线”，同屏“本机办结能力”仍用绿色状态展示“文档打印就绪”“材料扫描就绪”“自动双面可用”。
- 修复：`KioskRoot` 统一轮询 `useTerminalDeviceStatus(true)`，并通过 Outlet context 向首页复用同一份设备状态；首页移除三条固定就绪文案，打印机按 `checking`、`ready`、`unavailable`、`unknown` 展示，扫描和双面能力明确延后到办理阶段检测。
- 防回退：`verify:device-status-honest` 增加共享状态、禁止重复轮询、禁止假就绪文案和暖色主题语义色断言；新增 `verify:service-entry-readiness` 覆盖首页与各服务入口的 fail-closed 约束。
- 本地回归：两项专项 verifier、`fusion-shell`、`fusion-home`、`home-prototype-v1`、`home-narrow-visual-balance`、Kiosk typecheck、lint（0 error，7 条既有 warning）和 production build 通过；真实浏览器在 1280×720 与 1080×1920 下均显示“状态未知”，能力卡状态点为 `data-state=unknown`、计算色值 `rgb(107, 101, 96)`，无三条假就绪文案、无横向溢出、无控制台错误。
- 剩余边界：本地 `unknown` 状态回归不能替代 Windows Terminal Agent + 奔图真机的在线、离线、维护、缺纸、卡纸和恢复状态验收；支付前的最终设备预检仍按第 7 节现场清单验证。

### P2：建议上线前或首个补丁修复

**F-02 前端主包偏大。** Kiosk 主 JS 约 1.86 MB、TRTC chunk 约 1.03 MB，Admin JS 约 975 KB，构建持续出现 `>500 kB` warning。建议按服务中心、地图、TRTC、富文本/图表做路由级懒加载并复测弱网首屏。

**F-03 两个 API verifier 未完全隔离数据库。** `partner-smart-campus` 与 `terminal-device-config` 复制仓库 `prisma/dev.db`，本地陈旧库会造成假失败。建议每次创建临时数据库并执行 fresh schema/seed，不依赖开发库当前状态。

**F-04 招聘会 OSM 回退地图存在外部本地化占位符。** 无高德 key 时嵌入 OpenStreetMap，标记按钮可访问名称出现 `[missing "zh-CN.javascripts.map.marker.title" translation]`。主流程可用，但会影响触屏提示与无障碍体验；生产应优先配置受控静态地图/场馆图，或隔离外部 iframe 的内部控件。

### P3：工程改进

**F-05 Redis verifier 依赖 PATH。** `member-data-export-download` 未在 PATH 找到 `redis-server` 时直接失败。建议统一从 CI service、显式环境变量或仓库工具链解析二进制。

**F-06 当前脏工作区无法满足 W4 范围守卫。** 该项不是产品缺陷；在干净候选提交上发布前必须重新执行，避免把未审阅工作区内容带入候选。
