## 0. 一页结论

产品负责人的问题是：51 页原型、107 条路由都设计好了，但**每个功能跑完之后用户到底拿到什么**没有定清楚。五家的共同答案：

1. **后端定义的「结果」比前端画出来的多，但仍是半截。** 诊断报告在服务端有 6 维评分、建议、风险、优先级，**还有一份带原文证据的问题清单（`issues` + `contentBlocks`）**，一体机和小程序都没有渲染；报告本身不能打印、导出、存进「我的文档」或扫码带走。严重度、版本、收费、跨端一致这些「结果属性」也没定义。
2. **优化的结果是一份从零重排的新简历，不是在原件上改。** DOCX 原件只被抽成纯文本，版式、表格、图片全部丢弃；PDF / DOCX / TXT / Markdown 都是模板重排产物。这与 2026-06-29 写进 `feature-scope.md §2.2.1` 的「不承诺保留原件版式」一致，**与负责人今天的诉求相反**。五家一致：**「改了内容」和「版式绝对不变」不可兼得**，必须拆成两个能力分别定义（§2）。
3. **格式转换只有一条：多张图片合成 PDF。** Word → PDF 不存在，仓库里没有任何排版引擎，`services/worker` 是空壳。Word 上传后既不能页内预览也不能打印，UI 已诚实标注。
4. **其他 AI 功能里闭环最好的是岗位匹配、职业规划、自我探索**（结果 + PDF + 记录 + 打印 + 降级都有）。**最差的三处**：`/advisor` 后端 10 个端点写完前端一行没接；模拟面试在小程序做完就找不到报告；签约风险提示打印默认关闭。
5. 「能用 → 好用」的差距不在页面数量，而在每个结果页缺少同一套东西：**看得懂（结论 + 依据 + 置信）、带得走（PDF + 二维码倒计时 + 我的文档）、能出纸（打印副本）、不造假（事实核对、文件名防混、AIGC 标识）、丢不了（草稿版本）、离场干净（公共终端清场）**。§4 把它写成横切验收标准，§5 是合并四家意见后的 P0 清单。

## 2. Word → PDF「排版一致」的技术裁决（五家合议）

### 先说不可能三角

**内容实质优化 × 原件版式绝对不变 × 版面和谐（不孤行、不跑版）三者不可兼得。** 文字一变长，分页就变；表格简历（国内校招大量是表格版式）里改字必然挤格子。任何引擎都不能无条件保证与 Microsoft Word 像素一致。因此对用户只能承诺可验证的事：「关键元素无丢失、无重叠截断、最终 PDF 经你预览确认」，不能写「与原件完全一致」。

### 三条路线的合议结论

| 路线 | 能做什么 | 主要风险 | 部署现实 | 合议结论 |
|---|---|---|---|---|
| **A · 服务端格式转换**（LibreOffice headless，或其容器化封装 Gotenberg / Collabora） | **只转换不改字**：Word → PDF，解锁 Word 打印、Word 页内预览、我的文档「转 PDF」 | 文本框 / SmartArt / 艺术字 / 未嵌入字体偏差；`.doc` 更差；内存与并发要限；不可信文件要隔离 | **只放服务端容器**，固定版本 + 中文字体包（思源 / Noto CJK）+ 禁网络禁宏 + 超时并发上限；**一体机 Windows 不装 LibreOffice**，Agent 仍只打 PDF | 唯一能满足「格式变、内容与版式不变」的路线。**P1**；负责人若把「Word 打印 / 预览」写进本次上线承诺才升 P0。UI 必须写「由转换引擎生成，复杂版式请预览核对」 |
| **B · DOCX 段落原位回写**（保留原件样式，把优化文本回写进原段落） | 仅「无表格、无文本框、单栏」的简单 docx | DOCX 文本常被拆成多个 run、藏在文本框 / 域 / 修订 / 页眉里；回写会破坏编号与局部样式；1:1 段落映射锁死 LLM 的合并 / 精简能力；当前抽取是 `extractRawText` 已丢结构 | 要重写解析层 + 改优化契约（`paragraphId → text`）+ 复杂度检测 + 失败回退 | **不做默认，P2 受限实验开关**：复杂度检测不过即回退「修改清单」或模板重排 |
| **C · 换模板重排**（现状） | 任何原件 → 结构化 → 新 PDF/DOCX | 版式必变；pdfkit 中文排版能力弱；只有 1 个模板且双源断裂 | 已在 API 进程内；要补真 PDF 预览、字体包 | **默认路线**。名称必须叫「换模板出新稿」，**不得叫「保留原排版」** |
| 替代：OnlyOffice DocumentServer | 转换 + 在线编辑 | 重（Docker、4GB+ 内存底噪）、AGPL、一体机不适合开编辑器 | — | 排除 |
| 替代：Aspose.Words / docx4j | 商业保真最高 / OOXML 操作 | 授权费、Java/.NET 栈；docx4j 中文 PDF 仍弱 | — | 仅当「保版式转换」做成单独收费 SKU 时做 PoC 盲测 |
| 替代：Puppeteer + HTML（Paged.js） | 把**模板简历**排得更好（弹性布局、缩放到单页、所见即所得） | 需要无头 Chrome；**不能还原任意 Word** | 服务端 | **P1 评估替换 / 补强 pdfkit**，与 Word 原件保真无关 |

### 给用户的模式与话术

- 上传任何原件：默认「换模板出新稿」，导出前显示页数，提供「压到一页 / 放宽」微调，杜绝第 2 页只有两行的孤行。
- 上传 Word 原件（转换上线后）：多一个「只转 PDF、不改字」。
- 所有原件：多一份「修改清单」PDF（问题 + 原文 + 改法），用户回自己的 Word 改。这是对「保留原排版」诉求当前最诚实、最快落地的答复。
- PDF / 图片 / 扫描件原件：只有「换模板出新稿」和「修改清单」，页面不得暗示「改字但版式不动」。
- 导出后预览的是真实 PDF 本体，页面显示页数 / 大小 / 有效期 / 版本号，写「打印的就是这一份」。

### 需要改的口径

1. `feature-scope.md §2.2.1:112` 改为分模式表述：路线 C 维持「不承诺保留原件版式」并改名「换模板出新稿」；路线 A 承诺「只转换不改字、复杂版式可能有偏差、须预览确认」；路线 B 不进口径。
2. `§2.2.1:103,112` 的 **PNG 快照承诺废止**（全链路不存在，预览改为 PDF 本体后不再需要）。
3. 上述两条须产品负责人签字后才能改。

## 4. 「好用」层横切验收标准（每个结果页都要过）

1. **看得懂**：首屏是结论 + 3 条「先改这些」+ 每项一句人话；依据（原文引用）、置信 / 覆盖度（OCR 置信、截断、AI 还是规则）在同一屏；不出现百分比录用概率；严重度不只靠红绿色。
2. **带得走**：PDF + 二维码到手机（显示剩余有效时间，到期前可延长，过期可重生成）+ 登录后自动进「我的文档」；一体机不做「下载到本机」；游客不写「已存」。
3. **能出纸**：打印按钮只在打印副本真实就绪且打印机可用时可点；docx / txt / md 明确写「打印用的是同内容 PDF 副本」；打印失败给补打凭证，不静默吞单。
4. **一个文件**：预览 = 导出 = 打印同一份 PDF；页面显示页数 / 大小 / 有效期 / 版本号（哈希留给日志，不给用户）。
5. **不造假**：导出前事实核对墙；AI 新增内容标「待本人确认」；文件名与页眉区分原件 / 优化稿 / 诊断报告并标 AIGC；没有任何「已保存 / 已打印 / 已存我的文档」不是真的。
6. **丢不了**：登录用户改动自动存草稿，会话超时前提示；重新生成不覆盖已确认版本；可「回到原文」逐条撤销。
7. **诚实降级**：AI 挂 → 打印原件或通用清单；转换失败 → 原因 + 原件打印 / 手机保存；OCR 低置信 → 顶栏；失败不扣次，按钮写「这次免费重试 / 这次扣 1 次」。
8. **公共终端**：不留简历原文并在开始时告知；联系方式默认掩码；60 秒无触控倒计时清场；导出物有 TTL；触控 ≥48px，主按钮 ≥56px；关键操作有键盘 / 读屏可达路径。
9. **两端一致**：小程序与一体机对同一功能给同样的结果与动作；差的一端在页面写明「请到一体机 / 小程序完成」，不得静默少功能。
10. **结果分级**：高敏结果（签约风险、合同）可定义为「短时查看、默认不保存不打印」，三件套按分级执行，不一刀切。
