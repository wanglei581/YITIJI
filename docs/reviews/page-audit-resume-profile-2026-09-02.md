## 0. 先说环境（影响本次所有结论的可信度）

**API 后端没有在跑。** Vite dev server 在 5279 正常，但它反向代理的后端未监听：

```
/api/v1/health                 [500]
/api/v1/jobs                   [500]
/api/v1/job-fairs              [500]
/api/v1/job-materials/templates[500]
/api/v1/definitely-not-real    [500]   ← 不存在的路径也是 500
```

响应是 `Content-Type: text/plain` + 空 body，`lsof` 也查不到 API 端口的监听进程 —— 是代理到死目标的 ECONNREFUSED，不是业务 500。

**因此：本批 14 条路由没有一条在「有真实数据」形态下被验证过。** 下文凡涉及有数据形态的，一律标注「未验证」。

**但两件事不受此影响，可以放心下结论：**

1. `/me/*` 看到的是**未登录态**，不是 API 故障态。`MeListShell.tsx:76` 是 `!isLoggedIn ? <登录卡> : state==='error' ? ...`，登录闸在错误态之前，与 API 无关。
2. 本次对比的 5 份 `/me` 原型（35/38/39/40/41）**画的也是未登录态**。所以运行时 ↔ 原型是同态对比，结论成立。

## 1. `/resume/source` ↔ 21-resume-triage.html

**结论**：有 3 个问题
**运行时截图**：`/tmp/audit-rp/rt-21-source.png`　**原型截图**：`/tmp/audit-rp/proto-21-resume-triage.png`

1. **[高] 完全没有登录态表达，也没有登录入口。**
   用户会遇到：在公共一体机上传简历，看不出自己这份文件是「1 小时后被清掉」还是「存 90 天」，而且当场没有任何办法去登录改变它。这是本页最贵的信息，因为它决定了用户离开后简历还在不在。
   证据：`ResumeSourcePage.tsx` 全文 grep 无 `isLoggedIn`、无「去登录」、无「未登录」。页面只有一段静态隐私说明写了「未登录或高敏文件短期自动清理;登录后默认保存 90 天」—— 陈述了两种规则，却不告诉用户当前属于哪一种。原型对照：顶栏有「未登录 · 临时 1 小时」状态条，页中有整条橙色提示卡「当前未登录 · 这次按临时上传处理…服务端默认 1 小时清理，不进账号、不归档。登录后：U 盘 / 本机上传当场绑定账号存 90 天」+「去登录 →」。
   建议：在上传区上方加一条登录态条，未登录时给「去登录」，登录后显示实际留存期限。

2. **[中] 底部 351px 死区，同时三张来源卡被挤到 141px 宽。**
   用户会遇到：「U盘上传 / 云端上传 / 手机扫码上传」三张卡的说明文字被折成 6–7 行（如「从已插入一体机的 U 盘中选择简历文」），要凑近读；而屏幕下方 351px 完全空着。
   证据（DOM 实测，scale=1）：三张卡各 **141×183px**；主 CTA「请先上传简历文件」rect y=1513–1569；其下至 1920 无墨 = 351px；`scrollHeight == clientHeight == 1920`，页面不滚动，这 351px 无法被利用。原型对照：同样三张卡各约 318px 宽，正文 2–3 行，每张自带动作链接。
   补充线索：`ResumeSourcePage.tsx:509-518` 的注释记录了此前的反向事故 ——「内容 1903px 挤进 1844px 可视区」，靠折叠 291px 的维度清单解决。现在反而空出 351px，说明当时的折叠**过度收缩了**，这部分预算可以还给来源卡宽度或展开维度清单。
   建议：三张来源卡横跨整行（≥300px 宽），动作条贴底。

3. **[低] 缺「只想打印原件 → 去打印」出口。**
   用户会遇到：只想复印一份纸质简历的人进到这页后没有出路，得退回首页重选。
   证据：`ResumeSourcePage.tsx` 的 `navigate(` 只出现 `/resume/parse` 与 `/resume/generate`。原型底部有两条并列虚线入口：「没有电子简历 → 去生成」**和**「只想打印原件 · 不用 AI，直接去打印扫描 → 去打印」，运行时只实现了前者。
