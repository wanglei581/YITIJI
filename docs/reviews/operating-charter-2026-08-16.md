## 0. 商用级别的定义（唯一标准）

「商用」在本项目里不是视觉形容词，是四条可判定的门槛：

1. **不撒谎** —— 页面、接口、日志、健康检查，都不得让人以为系统做到了它没做到的事。假成功、假承诺、假健康、假统计，一律等同于故障。
2. **有内容** —— 信息类页面必须有真实数据。空库的岗位页做得再精致，对用户价值为零。
3. **能降级** —— AI 挂、设备挂、网络挂时，功能退化而不是消失或瘫痪；退化后用户仍能拿到东西（包括纸）。
4. **可运维** —— 出问题时，运维能在日志里看见原因。静默挂起、笼统报错、无审计的批量操作，都是不可运维。

**任何一条不满足，该模块就不算做完**，无论 CI 多绿。

## 一、六个职能

每个职能有：负责范围、验收标准、当前状态。批次派单必须声明自己属于哪个职能。

### F1 · 打印履约（收入主路径）

**范围**：上传 → 体检 → 参数 → 收银 → 出纸 → 取件 → 异常处理 → 退款。含小程序到机核销。

**验收标准**
- 八种订单状态每一种在前台都有明确落点，不出现"卡住且无提示"
- 用户付了钱必然拿到纸，或必然拿到退款，二者必居其一且用户看得见
- 「没出纸」的单**自动退**；主观争议进后台人工队列
- 一体机**不执行**退款，只提供「反馈问题」入口；`PrintCashierPage.tsx:494`「本机不提供自助退款」保持为真
- 0 元单显示「本单免费，无款可退」，不出现任何退款入口

**当前**：主链路已通（到机核销入口存在且可达，`33a8141e9`）。缺自动退档与反馈队列（`FEEDBACK-WIRE` 在做人工审档）。

---

### F2 · 内容供给

**范围**：岗位 / 招聘会 / 政策三个信息库的录入、审核、发布、展示。含 Partner 数据源与 Admin 审核。

**验收标准**
- 三个库在生产上**有真实数据可见**，不是 `total: 0`
- 外部数据必须审核后才展示（`approved` 且 `published`）；`pending`/`rejected` 绝不能被批量推上线
- 每条外部数据带完整来源标注（`source_org_id`/`external_id`/`source_name`/`source_url`/`sync_time`）
- 批量操作**先预览后执行**、可筛选、逐条审计、部分失败逐条可见

**当前**：管道端到端已验通（27 PASS/0 FAIL）。**约 217 条岗位卡在发布闸门**，全站无批量发布（`BULK-PUBLISH` 在做）。政策条件核对后端已建但**无 Partner 录入面**，故所有政策返回 `no_recorded_conditions`。

### F3 · AI 能力层

**范围**：所有 AI 功能位的接线、四态、证据分级、降级路径、用量与成本口径。

**验收标准**
- 每个 AI 功能位在 Admin 可见、可配、用量可查（**不得多个能力混算在一个 operation 下**）
- 四态齐全：空闲 / 进行中 / 有结果 / 不可用
- 降级三型正确落位：①有手动替代 → 退化成用户自己完成 ②唯一来源且有按钮 → 按钮置灰 + 写明原因 ③唯一来源且无按钮 → 结果区显示「AI 暂时无法使用」
- **降级路径本身不得依赖 AI**（兜底要调模型就不是兜底）
- 证据分级正确：E1 用户材料 / E2 来源信息 / E3 AI 判断。**确定性逻辑不得标 E3**
- 降级态下用户仍能**拿到纸**

**当前**：S1 原语已全站落位；P25/P22/P28 已接线。岗位要求计数端点已建（#636）。**降级态无打印路径**（`S3-DEGRADE-PRINT` 在做）。advisorWork 用量仍混在 `chatAssistant` 下（未派）。

### F4 · 平台可靠性

**范围**：启动语义、健康检查、门禁覆盖、部署可运维性、跨平台。

**验收标准**
- 依赖不可达时**明确失败或明确降级**，绝不静默挂起
- 健康检查如实反映降级状态，不返回笼统 `ok`
- 所有 `verify:*` 要么在 CI 跑，要么在脚本里写明为什么不跑
- 门禁覆盖面不得静默缩水（硬编码清单、只 glob 旧目录、断言宽到永真）
- Windows 上可独立运行，脚本不含 Unix 专用命令

**当前**：**Redis 不可达时 API 静默挂起** —— 进程活着、端口死了、日志无错误行，且 `redis.module.ts` 注释与行为相反（`FIX-BOOT` 在做）。门禁全量体检进行中（`GATE-AUDIT`）。

### F5 · 前端体验与 V6 迁移

**范围**：Kiosk 全部页面、V6 原型、触控可用性、信息密度、迁移排期。

**验收标准**
- 主按钮 ≥56px，可点击区 ≥48px，触屏上**不依赖 hover**（禁止用 `title` 承载关键信息）
- 能力门禁型 `disabled` 必须有**常显**的原因文字；瞬时态 `disabled` 保持原生即可
- 页面拥挤时**拆页**，页数不是越少越好
- V6 原型不得对用户开空头支票（承诺的入口必须存在）
- 迁移采用**纵切**：一次一个域，补原型 → 迁页 → 接线 → 验证，每刀切完可上线

**当前**：V6 原型 48 页 + 补的 4 页。`PROTO-FIX` 在修三处原型缺陷，`KIOSK-DEBT` 在修三处前端欠账。**纵切第一刀（打印域）未启动**，等运行时走查。

### F6 · 合规与隐私

**范围**：产品边界、按钮文案白名单、个人信息处理、同意管理、数据权利。

**验收标准**
- 不出现平台内投递 / 收简历 / 筛选 / 邀约 / Offer 闭环
- 投递预约文案走白名单，禁止「一键投递 / 立即投递 / 平台投递」
- 同意存**版本**不存布尔；条款改版后旧同意不得静默继承
- 敏感文件短留存、可清理、删除留日志；管理员访问文件记日志
- 政策口径必须可追溯到入库原文，**AI 不得编造政策结论**；判定支持 `unknown` 三态

**当前**：政策三态判定已实现（#631）。同意版本后端已建（#635），**前端尚未发送该字段**（`KIOSK-DEBT` 在做）。V6 原型 `11-jobfit-compare.html` 承诺可撤回授权但浮层无该入口（`PROTO-FIX` 在做）。

## 二、跨职能的三条硬纪律

来自 2026-08-16 的实际失败，详见 `parallel-batch-dispatch-guardrails-2026-08-16.md`。

1. **一律对 `origin/main` 取证。** 本仓 22 个 worktree，主仓 159 处未提交在制品。看工作区检出会得出错误结论。
2. **不引二手文档下结论。** 当日三份文档各自出错，根因都是引用了另一份文档的过期结论 —— 其中一份描述的页面**在同一天被重写了**。文档说「已完成」不等于它能用。
3. **未验证项必须如实登记。** 当日高质量交付全部带这个清单，且清单第一项往往正是后来 CI 报红的地方。**它是有效的风险预测，不是免责声明。**
