# 仓库体积与结构盘点（2026-09-06）

回答「项目现在多大、结构是不是脏乱差、怎么优化占用空间」。**本文只做盘点与方案，未执行任何删除。**

## 一、先纠正三个此前的错误认知

| 说法 | 实测 |
|---|---|
| 「仓库大概 6 GB」 | **26 GB**（早先的 `du` 把 node_modules 排除了，那恰恰是大头） |
| 「历史里图片太多，得 `git filter-repo` 重写」 | `origin/main` 的**全部历史只有 76 MB**。重写最多省 76 MB 的一部分，代价是 139 个 worktree 和全部在开 PR 重对。**负收益，不做。** |
| 「`.git` 2.3 GB 都是历史包袱」 | 2.3 GB 里 **1.24 GB 根本不被任何引用可达**——是纯垃圾，`git gc` 就能收，不需要删分支，更不需要重写历史 |

## 二、26 GB 都是什么

| 项 | 占用 | 说明 |
|---|---|---|
| node_modules（**168 份**） | ≈17 GB | 占 66%。每个 worktree 一套 |
| `.git` | 2.3 GB | 见下 |
| 源码 + 文档 + 设计稿 | 其余 | 正常 |

`.git` 拆开看：

| 口径 | 大小 |
|---|---|
| `origin/main` 可达 | **76 MB** |
| 全部本地引用（970 个分支）可达 | 860 MB |
| `.git/objects` 实际占盘 | 2.1 GB |

两个差值就是两块可回收空间：

- **860 − 76 = 784 MB**：只被本地分支钉住。删掉不再需要的分支后可回收。
- **2100 − 860 = 1240 MB**：**任何引用都够不着**，纯垃圾，`git gc --prune=now` 立刻可收，零风险。

## 三、结构是不是乱

结构本身不乱——`apps/` / `services/` / `packages/` 的 monorepo 划分清晰，职责有 `docs/project-structure.md` 记录。

乱的是**过程产物堆积**：

| 项 | 数量 |
|---|---|
| worktree | 139 个 |
| 本地分支 | 970 个 |
| 其中未并入 `origin/main` | 598 个 |
| node_modules 副本 | 168 份 |

139 个 worktree 里，**96 个工作区是干净的**（无未提交改动）：

| 位置 | 个数 | 占用 |
|---|---|---|
| 仓库目录内 `.claude/worktrees/` | 47 | **11.7 GB** |
| `~/.codex/worktrees/` | 21 | **13.1 GB** |
| `/tmp` 下 | 28 | 临时，重启即失 |

剩下 43 个有未提交改动。按 `CLAUDE.md` §8.1，**这些属于候选功能资产，未完成迁移或明确废弃前不得删除**。

## 四、清理方案（按风险分档）

### 第一档：零风险，立刻可做 —— 约 1.24 GB

```bash
git -C "/Users/wanglei/AI求职打印服务终端" gc --prune=now
```

只回收**任何引用都够不着**的对象。不动分支、不动 worktree、不改历史。唯一代价是跑的时候会占 CPU 几分钟，期间别在别的会话里提交。

### 第二档：低风险，需确认没人正在用 —— 约 24.8 GB

移除 **96 个干净 worktree**。「干净」= `git status --porcelain` 为空，即没有任何未提交改动，删了不丢代码；**分支引用本身保留**，随时可以重新 `git worktree add` 拉回来。

```bash
# 先看清单，确认里面没有你正在用的
git -C "/Users/wanglei/AI求职打印服务终端" worktree list --porcelain | awk '/^worktree /{print $2}' | while read -r w; do
  [ "$w" = "/Users/wanglei/AI求职打印服务终端" ] && continue
  [ -z "$(git -C "$w" status --porcelain 2>/dev/null)" ] && echo "CLEAN  $w"
done
```

确认后逐个 `git worktree remove <path>`（**不要加 `--force`**——加了就会连带删掉有未提交改动的那 43 个）。

建议保留正在跑任务的那几个（本轮的 `/private/tmp/team/*` 与当前会话的 worktree）。

### 第三档：需要产品负责人判断 —— 约 784 MB

删除 **598 个未并入 `origin/main` 的本地分支**。

**默认不做。** 按 `CLAUDE.md` §8.1，未并入的分支要先做只读盘点、确认内容已被 main 覆盖或已完成迁移，才能删。598 个逐个核不现实，建议的做法是分批：

1. 先删「已完全并入 main」的那 372 个（`git branch --merged origin/main`），这批是安全的；
2. 未并入的按最后提交时间排序，超过 3 个月且对应 worktree 已干净的，单独列表给产品负责人过目再删。

### 明确不做：`git filter-repo`

`origin/main` 的完整历史只有 76 MB。把里面所有图片剔光也省不到这个数的一半，而代价是：

- 139 个 worktree 全部要重对；
- 所有在开 PR 的 base 失效；
- 每个协作者都要重新 clone。

**投入产出比是负的。** 前面第一、二档加起来能省 26 GB，是它的三百倍，且零重写风险。

## 五、已经做掉的防复发（PR #809 已合入 main）

盘点发现磁盘上有 **722 MB 未跟踪证据文件没有任何 gitignore 拦着**，而全仓此前**没有任何体积门禁**——`docs/design/kiosk-redesign-2026-08` 的 549 MB 截图就是这么进历史的。

已合入：

- `.gitignore` 补上证据 / 对比 / 备份目录（保留 13 个被引用的测试夹具例外）；
- `verify-repository-integrity` 新增**资产体积门禁**：任何已跟踪文件 >1 MB 即失败，6 个既有运行时资源登记白名单。变异测试（塞 1.55 MB PNG）确认能拦。

这是唯一能防止 549 MB 事件重演的机械手段。清理是一次性的，门禁是长期的。

## 六、总账

| 档 | 动作 | 回收 | 风险 |
|---|---|---|---|
| 一 | `git gc --prune=now` | 1.24 GB | 无 |
| 二 | 移除 96 个干净 worktree | 24.8 GB | 低（分支引用保留，可随时拉回） |
| 三 | 删已并入 main 的 372 个分支 | 784 MB 的一部分 | 低 |
| 三 | 删 598 个未并入分支 | 其余 | **默认不做**，须逐批核 |
| — | `git filter-repo` | ≤76 MB | **不做**，负收益 |

一、二两档做完，26 GB 降到约 1 GB 量级的工作副本 + 1 GB 的 `.git`。
