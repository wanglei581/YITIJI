# 交给 Codex 开发：窗口划分与开工材料（2026-08-11）

> **这份文件是两条工作线共用的唯一答案。**
> 产品负责人在前端设计线与后端改造线**分别问了同一个问题**：
> 「怎么让 codex 按这些文档去做开发？是新建两个窗口，一个前端一个后端，还是一个窗口负责前端？」
> 为避免两边各答一套（那正是 2026-08-11 交叉对账要解决的毛病），结论只写在这里。
> 任何一边若不同意，**改这份文件并说明理由**，不要在别处另立一套。

---

## 一、先澄清：「前端」指的是哪一个

这决定了整个安排，先分清再谈窗口。

| | 是什么 | 状态 |
|---|---|---|
| `docs/design/kiosk-ai-os-v3-2026-08/` | V3 设计稿，46 个静态 HTML 原型 | **是规格，不是产品** |
| `apps/kiosk/` | 真实运行的一体机前端（React） | 已上线，页面结构与 V3 **不一样** |

所以「前端开发」有两种完全不同的含义：

- **A：把现有 `apps/kiosk` 接到新接口上** —— 工作量中等，与后端同步做
- **B：按 V3 设计稿重做 `apps/kiosk` 的界面** —— **另一个大项目**

**结论：先做 A，B 单独立项。**
今天拍板的口径（四道闸、计费页、不补差、双面不变价）必须先在**真实产品**里成立；
界面长什么样是下一步。把 B 混进计价链，会让一个本来可验收的改动变成无法收敛的重写。

---

## 二、不要按「前端 / 后端」切，按**闭环**切

计价这条链是**一条链**：

```
FileProvenance → OrderQuote → BenefitReservation
  → Order + RedemptionRecord → PrintTask attempt 1..N → Refund 或 RedemptionAdjustment
```

把它劈成前后端两个窗口，每改一次契约就要跨窗口对齐，
而**两个 Codex 窗口之间没法互相说话** —— 这就是 2026-08-11 上午
「你的问题在后端、后端的问题在前端」的成因。**不要重演。**

---

## 三、窗口安排

| 窗口 | 范围 | 依赖 | 何时开 |
|---|---|---|---|
| **① 计价权益主链** | 后端建模型与接口 + **同窗口顺手接 `apps/kiosk` 的核价 / 结算 / 权益** | 无 | **先开**，其余等它 |
| **② 两个后台配置面** | Admin 配四道闸规则、Partner 数据面 | 需要 ① 的 schema | ① 的 schema 落地后 |
| **③ 履约与硬件** | Agent 未确认出纸却报完成、取件页调不存在的端点 | 无 | **现在就能开**（已开两张任务卡） |

**① 之所以跨前后端放一个窗口**，正是因为它是一条链：契约在同一个上下文里定，不会漂。
**② ③ 与它没有数据依赖**，可以并行。


两份文件是配套的：**规格说「怎么建」，对接表说「哪一页的哪个按钮在等它」。**

## 五、必须写进每个窗口开工提示的护栏

1. **不许自创口径。** 遇到与规格不符的地方，**先说出来再改**，不要自己拍板 ——
   今天的矛盾全是这么来的。
2. **不许另建第二套订单或核销账本。**
   现有 `PriceConfig` / `Order` / `BenefitGrant` / `RedemptionRecord` 与审计表必须复用。
3. **每个窗口用独立 worktree**，否则多路互相踩文件。
4. **设计稿里没有后端的按钮和 AI 功能不是假的，是还没开发** ——
   `wiring-map.md` 里的 `❌缺` 是**施工清单**，不是删除建议。
5. **双 CI 必须保持绿**（SQLite 主 CI + `postgres-readiness`）。
6. 按 CLAUDE.md §8.1，每个任务开始前写清：范围、允许改哪些文件、禁改哪些、
   是否新增入口/数据模型/外部依赖、要跑哪些 typecheck/lint/build/verify。

## 六、① 号窗口的分期（取自实施规格）

| 优先级 | 内容 |
|---|---|
| **P0 上线阻塞** | 价格版本与报价锁价、可信场景溯源、四道闸判定、月度余额、权益预占、有效状态、履约结果与补偿 |
| **P0 立即止血** | 禁止现有 `/orders/:id/redeem` 按任意 Grant 整单免 |
| **条件性 P0** | 有政府资金才做独立资金预占/结算/冲正账本。**没有该账本，就不得把免单称为政府补贴** |
| **P1** | `AiUsageLedger` 先 shadow 计量，没闭环前 AI 继续免费 |
| **P2 建议不做** | 打印会员 / 订阅。「每月 N 次」不需要 Membership |

## 七、怎么算做完

- **①**：四道闸每一道都能用真实请求打出预期结果（整单免 / 整单正常价 + 结构化原因码）；
  报价锁价在改价场景下不串价；权益预占在并发下只有一台成功；
  券已核销而打印失败时走冲正而**不是删核销记录**。
- **②**：Admin 保存一条规则后，Kiosk 报价返回的可用权益随之改变（端到端可见）。
- **③**：未确认出纸不再上报 completed，且有 verify 脚本覆盖那三条路径。
