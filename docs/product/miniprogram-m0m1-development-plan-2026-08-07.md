# 小程序 M0/M1 开发与唯一工程底座迁移计划

> 状态：2026-08-07 制定。Gate 0 决策已确认（`miniprogram-gate0-decision-confirmation-2026-08-07.md`）；
> 岗位匹配真实结果页 API 级验收已通过；模拟器 UI 实点待环境解锁后执行。

## 0. 目标

- 建立唯一发布源码 `apps/miniapp/`（原生微信小程序，不迁 Taro 4）。
- 首发范围：M0 可登录壳 + M1 AI 百宝箱核心能力；M2 手机下单/到机履约/支付延后。
- 迁移原则：选择性迁入已核验页面与接口适配，不机械重写找回工程 57 页，不复制重复入口/占位页。

## 1. 唯一工程底座（apps/miniapp）

- 目录：`apps/miniapp/`（app.json / 页面 / 自定义 TabBar / project.config.json）。
- 迁移内容（页面级）：
  - 壳与 Tab：四 Tab（首页 / AI百宝箱 / 求职 / 我的）、登录、协议隐私、会话清场。
  - 求职：岗位 / 招聘会 / 企业 / 政策来源浏览（复用现有公开 API 契约；真实空态诚实展示）。
  - AI百宝箱：简历上传 / 解析 / 诊断 / 优化、岗位匹配、模拟面试、职业规划、自我探索适配。
  - 我的：订单 / 权益 / 消息 / 反馈本人只读。
- 不迁移：M2 相关的打印下单、支付、材料包页面与占位/重复入口。
- 工程接入：workspace 注册、CI 原生静态门禁（JSON / 路由 / TabBar / 合规文案 / verify 脚本）、
  微信 build 守卫；不接真实生产密钥，不使用微信云开发。

## 4. UI/UX 要求（用户重点）

- ~~视觉基线沿用找回工程的既有风格（暖奶油纸感、棕黑正文、陶土红、麦金、来源蓝）~~
  **已失效（2026-09-02 复核）**：实际视觉基线是**冷灰蓝**——`app.wxss` 的
  `--paper: #f5f7fa`、主色 `--teal: #2354E6`（名为 teal 实为蓝），自定义 TabBar
  同样用冷色，全部 52 页 wxss **零暖色残留**。暖色身份只在 `app.json` 里留了三个值
  （下拉回弹底 `#f4f1e8`、TabBar 底 `#fffdf8`、选中色 `#1f9e86` 青绿），
  真机上会在冷灰内容上方露出一条暖色带；已于 2026-09-02 改为对齐冷色。
  另于同日在 `app.wxss` 建立 7 级字阶（`--fs-xs`..`--fs-2xl`），
  并加 `verify-miniapp-visual-scale.mjs` 棘轮门禁防止偏离值增长。
  下方原文保留，作为历史决策记录：
  不另起新设计系统，不做“AI 味”通用界面。
- 每个页面先出设计再开发：手机一屏信息密度、触控目标友好、底部 Tab 短流程；
  页面交付前做真机/模拟器截图对比与设计走查，不直接堆功能。
- 与一体机保持差异化：手机端聚焦本人任务与轻量操作，不复制 27 寸竖屏布局。

## 5. 验证门禁（每次改动）

- 现有 `verify-job-fit` / `verify-interview` / `verify-resume-optimize` + JSON / 路由 / TabBar 审计。
- 每批开发者工具编译 0 Error、问题面板 0 新增。
- UI 实点按 `docs/acceptance/miniprogram-jobfit-ui-real-click-runsheet-2026-08-07.md` 执行。
- 发布前完成合法域名（`zyidai.cn` request/uploadFile/downloadFile）、主体/类目/隐私材料与真机预览。

## 6. 分批与文件预算

- 首批（M0.1–M0.2）：壳 + 登录，页面文件 ≤ 20。
- 二批（M0.3–M0.4）：公开浏览 + 我的只读。
- 三批（M1.1–M1.3）：今天引擎 + 简历链路。
- 四批（M1.4–M1.7）：岗位匹配 / 模拟面试 / 自评 / 资产。
- 每批独立 PR + 门禁，不一次大合并；单个页面文件超 300 行先拆分评估。

## 7. 待办（不阻塞开发启动）

- 微信 AppID / 主体 / 类目 / 隐私声明材料。
- 产品名最终确认（以微信后台注册名为准）。
- 真实岗位与政策来源及授权（求职 Tab 展示内容，空态保持诚实）。
- 模拟器 UI 实点：需在微信开发者工具「设置 → 安全设置」开启服务端口（或完成登录）后由 Codex 驱动执行。
