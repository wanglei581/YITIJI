## 1. 采购方最在意什么

采购方真正需要的是：**群众用得上，设备有人管，服务有凭据，费用讲得清，安全责任明确，项目到期能验收和接续。** AI 简历、面试与打印构成使用价值；后台负责证明这些价值并保证持续提供。

下面是基于公开采购样本和当前产品边界的优先级判断，**不是对所有政府买方的统一排名，也不是已完成客户访谈的结论**。

| 顺位 | 采购方的问题 | 必须交付的能力 | 主要关心的人 |
|---|---|---|---|
| 1 | 买回来群众会不会用，是否真正完成了服务？ | 五条真实使用路径、匿名会话与完成量、失败原因、易用性与无障碍检查 | 业务负责人、现场使用人 |
| 2 | 坏了谁知道、谁修、多久恢复？ | 分点位设备状态、报障、责任人、处理时限、恢复确认、维保范围 | 站点对接人、采购负责人 |
| 3 | 月底、年底拿什么报工作、验收和付款？ | 固定口径月报、合同条款对照、交付和维保记录、可复算证据包 | 业务负责人、验收组、财务 |
| 4 | 数据泄露、内容出错、越权操作，谁负责？ | 机构隔离、最小权限、清场、访问审计、内容责任、备份恢复 | 信息中心、安全与法务人员 |
| 5 | 除了设备，未来还要花多少钱？ | 设备/软件/维保/耗材/网络/AI/部署的费用边界、额度与到期提示 | 采购、财务、分管负责人 |
| 6 | 多站点能否统一管、换供应商能否交接？ | 采购项目与点位台账、权限内汇总、资产迁移记录、标准导出与交接清单 | 主管机构、资产管理人员 |

业务领导往往先问服务覆盖与效果，现场人员先问故障，财务先问验收依据，信息中心先问安全与接入。采购前必须同时覆盖这些问题。不能用一张大屏替代它们。

## 2. 先锁定采购对象和产品边界

优先争取「公共服务网点求职准备工具与打印终端＋随机软件＋年度技术维保」项目。避免把当前产品写成完整的就业驿站运营系统、公共就业业务经办系统或招聘平台。

| 场景 | 机构端主要任务 | 对应边界 |
|---|---|---|
| 人社就业服务中心、街道社区就业站、零工服务点 | 本点位/获授权点位的服务监督、故障、月报、政策与官方渠道 | 业务经办、实名帮扶台账、全国就业库报送等仍在采购人正式系统完成 |
| 高校、高职、技师学院就业中心 | 学生求职准备服务、设备保障、使用统计与公益指引 | 不采集学生就业去向、个人简历清单、院系就业率；分院系统计不能凭猜测或额外采集画像实现 |
| 持证机构购买终端 | 自有点位的工具与设备运营 | 对方有资质不等于我方获得招聘运营许可；我方云端边界照旧 |

现行托管 a：我方云上不托管岗位、招聘会和企业招聘资料；只允许本机构已核验官方域名的渠道二维码，政策由机构自行审核发布。现有码和菜单的保留不代表开放。客户私有化 b 单独做部署、安全、责任和费用评估，不能理解为一键切换即可交付。

机构机器按终端免费，按年提供技术服务，**用量报表不作为按印张结算账单**；不恢复向群众销售 AI 次数或按投递、入职收费。公共服务免费范围、合理使用限制和超额处理在合同里明确，不能临时弹出收费。面板复印不经过本系统，后台不能声称掌握它的任务数。

## 4. 双后台分工与页面设计

机构端回答「我买的设备和服务怎么样，今天我需要处理什么」；管理端回答「我们向哪些客户承诺了什么，现在谁负责交付和修复」。沿用现有页面和组件，以页内 Tab、抽屉、详情关联实现；新入口须在实施前证明现有页面无法承载。

### 4.1 机构端：六组任务

| 导航/优先复用页 | 用户看到什么 | 能做什么 | 完整状态 |
|---|---|---|---|
| 工作台 `/` | 选中项目/站点、服务完成量、设备异常、待确认事项、报表截止日 | 直接进入待办；切换获授权站点与时间 | 正常、无服务、未上报、样本不足、过期数据、加载失败分开显示 |
| 设备与维保 `/terminals` | 位置、编号、最后心跳、打印机和服务可用性、故障进度 | 报障、补充无个人信息的现场情况、确认恢复；查看质保与巡检 | 待安装、待验收、运营、故障、维修、暂停、退役；状态保留来源和时间 |
| 服务与报表 `/stats`、`/screen` | 求职准备/打印扫描服务聚合、完成/失败、合同指标、自然月报 | 筛选、预览、下载权限内报表、提交验收意见 | 草稿、数据待补、待复核、已封存、有修订；不把实时数当封存数 |
| 官方渠道与政策 `/profile`、`/policy` | 本机构渠道、政策版本与终端展示范围 | 维护白名单内渠道、确认发布责任、撤回政策、查看下架原因 | 草稿、待确认、发布、到期、撤回/紧急下架；未配置不能出现假内容 |

## 5. 功能需求清单与验收条件

本节 P0 表示**拟交付政府采购标准包前必须具备**，不表示立即插入当前开发队列；现有主线真实出纸、隐私与上线验收仍优先。P1用于复制到多点位，P2按合同单独立项。

| ID/级别 | 需求与双端动作 | 最小验收条件 |
|---|---|---|
| G01 P0 | 项目、合同范围、点位和终端一一关联；管理端登记，机构端核对 | 任抽一个项目可列明采购设备、实际安装位置、能力、维保起止和交付状态；数量差异有原因 |
| G02 P0 | 本机构设备健康与服务能力分开显示；沿用真实心跳、能力登记 | 模拟主机在线但打印故障、AI不可用、能力未开通、数据过期，均不显示「全部正常」；没有遥测的耗材值显示未接入 |
| G03 P0 | 告警/报障→认领/派单→处理→恢复→机构确认/复开 | 缺纸、卡纸、断网、断电各有责任人及时间记录；处理超时可升级；无出纸证据不得以「清队列成功」结单 |
| G04 P0 | 有效会话、服务完成量、失败量和覆盖率采用统一指标字典 | 同一测试集在两端、导出和报告结果一致；刷新/重试不重复计数；缺数据不补零；允许明确拒绝出数 |
| G05 P0 | 自然月报告与验收包，先人工复核后封存 | 指定月的周期、范围、口径、缺失项、版号可复核；相同快照重复导出一致；纠错保留旧版和理由 |
| G06 P0底线/P1扩展 | 本机构隔离、实名账号与服务端范围校验；只读权限按合同需要前置，细分岗位权限后续扩展 | 甲机构不能读取乙机构对象/导出/缓存；不向政府查看人员提供供应商全局后台。若交付只读账号，其直接调用写接口必须被拒 |
| G07 P0 | 用户隐私、终端清场、文件访问审计、退出失效与备份恢复 | 上一人离机、刷新、后退、断网/崩溃后不见上人材料；机构导出无个人字段；恢复演练有结果与责任人 |
| G08 P0 | 公益免费与合同额度透明、公共服务限额降级、维保与联系渠道 | 免费订单不出现收费/退款引导；AI用尽给模板/次日恢复说明，打印可独立继续；不能静默产生合同外费用 |
| G09 P0 | 官方渠道、政策责任与安全下架的真实链路 | 未核验域名被拒；机构自行确认政策责任，终端正确显示；托管关闭时招聘写接口被拒，不能只验菜单 |
| G10 P0 | 到货、安装、培训、真实用户试用与问题整改清单 | 设备清单对应实物；机构人员无需代操作能维护渠道、发政策、看报表、报障；原有五关验收逐项记录 |
| G11 P1 | 获授权的主管单位汇总和站点权限；共享项目的分工 | 上级只看明确授权项目/站点；地区相同不自动授权；下级不读其他站点；撤权立即生效 |
| G12 P1 | 调拨历史、巡检、耗材更换、备机与批量升级 | 终端改绑不迁移旧统计、不抹掉旧机构报告；升级有灰度、失败回滚和配置审计；不重复释放打印任务 |
| G13 P1 | 满意度、投诉响应与月报质量分析 | 评价自愿、去重，展示参与人数/覆盖率；未评价不算满意，零投诉不等于100%满意；个人投诉不透给机构 |
| G14 P1 | 政策作者/复核者分权、内容到期和撤回通知 | 同一人不能绕过约定双人确认；到期不继续展示；紧急下架保留事由和通知，机构不越权恢复 |
| G15 P2/合同前置 | 客户私有化、政务云、单点登录、正式报送接口、国产环境 | 先取采购方环境与接口规范，做权限/备份/升级/硬件适配验证再报价；有强制条款时升级为该项目准入阻塞 |
| G16 P2 | 汇报大屏、AI月报辅助解释、低使用站点建议 | 只解释已冻结的聚合事实，逐项可回指；人工确认后发送；不生成群众画像、就业率或招聘转化 |

P0 是能力与交付责任清单，**不是10个必须新建的软件模块**。已有能力优先核验和补缺，G06先保障机构隔离与实名账号，不建设通用权限平台；G11/G14需要业务分权时，再扩展同一权限来源。

### 5.1 首单最小集：只补四组能力

1. **资产点位台账**：先把机构、采购清单、终端、安装位置、维保和联系人对应好。现有页面加必要字段，合同文件和签收单可按现行制度人工保管，不先做完整合同流程引擎。
2. **真实服务与隐私**：现有五条任务、免费规则、机构隔离、离机清场必须先通过。真实AI/打印与报表的可观测覆盖不够时如实注明，不能用大屏掩盖。
3. **基本设备状态和报障处理**：群众/站点容易找到原有反馈或服务联系方式；我方接报、指定负责人、登记修复与通知。先做到有人接、有人修、可复开，派单自动化和复杂考核引擎后续再做。
4. **可复核自然月报和交付资料**：优先统一现有会话、出纸印面、心跳推导故障时长三类事实，标注范围、可信起点和证据等级；现有渠道/政策按真实使用补入。先CSV导出＋人工复核＋留存版号，再按合同需要生成PDF/整包和自动封存。

首单可先由一名具名机构对接人使用现有Partner账号，其他验收人员查看经授权导出的资料；不共用账号、不向其开放我方Admin。若采购文件明确要求机构只读账号、审批分权、自动月报或其他能力，就前移该项而非降低合同要求。G08/G09/G10等仍是免费、安全内容、培训与验收底线，复用已有实现和人工交付，不把它们另做成新系统。

## 6. 权限设计：不增加第三套后台

下列是**现有Partner/Admin账号内的拟议权限档与数据范围**，不是当前已实现的角色。政府主管单位、采购验收人员都走受限Partner视图；我方内部人员走Admin。现行角色边界不变。

| 权限档 | 可见范围 | 可操作内容 | 禁止 |
|---|---|---|---|
| 机构负责人 | 本机构获授权项目/站点的聚合与交付资料 | 确认交付、复核报告、确认恢复，维护授权内容 | 个人简历/轨迹、其他机构、全局模型密钥 |
| 机构只读/验收 | 指定项目、时间和站点的聚合与资料 | 查看/授权导出、提交验收意见 | 改配置、发布内容、改原始统计 |
| 站点对接人（P1） | 指定站点 | 无PII报障、恢复确认、巡检配合 | 调拨归属、修改其他站点、手工改服务数 |
| 内容维护/复核（P1） | 本机构渠道和政策 | 按职责创建、复核、撤回 | 代发岗位、把政策模块当招聘绕行入口 |
| 我方交付与运维 | 被分派客户/设备；按工作需要最小授权 | 交付、派单、诊断、核查、版本发布 | 默认查看简历、把遥测当结算、代采购人验收 |
| 我方商务/财务 | 合同、付款和发票必要信息 | 登记、对照、到期提醒 | 群众个人行为与模型提示词 |
| 我方安全管理员 | 账号、配置、安全与审计 | 授权/撤权、审计、安全处置 | 以安全权限默认开放全部用户文件 |

同机构也不意味着所有人可见全部合同或全部站点。用户身份从服务端当前账号取，客户端 `orgId/projectId/siteId` 只作筛选请求且必须校验；详情、列表、聚合、下载、异步导出和缓存应用同一范围。受限统计的小样本抑制对网页、CSV、PDF、接口和AI解释全部生效，防止总数减分组反推个人。

### 7.1 逻辑对象与最小字段（设计建议，不是迁移指令）

| 逻辑对象 | 必需字段/关联 | 复用和增量策略 |
|---|---|---|
| 机构与账号 | 机构、类型、域名核验、账号状态、授权范围及有效期 | 复用 `Organization/User`；不再建一套客户和用户库 |
| 采购项目/交付批次 | 项目编号、采购/使用机构、合同引用、设备与服务清单、日期、维保、验收条款 | 当前缺少完整对象；P0只做必要台账和附件引用，不做通用合同ERP；金额/实际合同留私有系统，不写公开仓库 |
| 点位/终端部署历史 | 项目、终端、位置、负责机构、安装/移出时间、能力验证记录、版本 | 复用 `Terminal` 和现有位置；单项目先复用现有字段，跨站点和调拨时才引入结构化点位与有效期历史 |
| 服务事实/完成证据 | 事件或任务ID、业务类型、状态、发生/完成时间、经过验证的终端身份、当时机构/项目归属、去重键、证据等级 | 复用 `KioskSession/PrintTask/ScanTask/AiUsageRecord` 等；先逐链核可靠性和归属，缺项补同一主链，不新建影子订单 |
| 运维工单 | 告警/设备关联、类型、等级、负责人、时限、操作记录、恢复证据、机构确认 | 复用已有告警、反馈关联；如现有对象不能容纳维保状态机，再增加最小运维对象。用户投诉正文与工单给机构的投影严格分离 |
| 指标与报告快照 | 指标版本、时区、区间、范围、截止时间、来源覆盖、缺失原因、聚合值、修订/确认、导出摘要 | 不复制个人原始材料；快照用于复核。摘要可验证文件变化，**不能单靠hash宣称数据真实或具有法律签章效力** |
| 额度与用量 | 合同覆盖、用途、额度规则、预占/履约/释放、到期、阈值、例外审批 | 复用现有权益和AI预算；非按量结算场景不为“完整”新建收费系统。若合同涉及按用量履约，先完成可靠账本 |

组织层级和项目授权是两件事：同一政府项目可涵盖多个点位，跨独立机构必须逐项授权；行政区名称、机构类型、同项目标签都不能自动产生读取权。历史事件按发生时归属，报告按当时合同范围，不能用当前归属反查重算旧账。

### 7.2 运维与验收状态机

运维目标：`新告警/报障 → 待认领 → 已派单 → 处理中 → 待恢复确认 → 已关闭`，支持挂起原因、超时升级、复开；首单允许人工完成派单与记录。恢复采用双轨：有可靠遥测/业务结果时记录为技术恢复，无法遥测时由我方现场验证；需要机构确认的再请其确认。机构未点按钮不能抹去真实恢复时间，也不能以沉默视为故障已解决或验收通过；机构随时可复开异议。用户材料泄露、未确认出纸等不能仅凭心跳自动结单。

挂起不自动停计时；客户停电/断网、停业、计划维护等，按合同分类并保留原始时长。现场无人值守，不能把售后承诺写成随时有工作人员驻场。机构只负责场地配合与监督，不承担我方维修调度和供应链审批。

交付：`待到货 → 待安装 → 待能力实测 → 试运行 → 待验收 → 待整改/通过 → 维保中 → 到期交接`。我方提交资料，采购方按其制度决定验收；后台按钮只记录意见与流程，不替代正式签章和付款审批。

## 8. 指标字典：什么能报，什么不能报

统一使用北京时间自然日/月、区间 `[起点,终点)`；实时看板另标当前截止时间。源数据质量与覆盖率一起展示，禁止“没上报=0”“小样本=0”“未知=成功”。

每类指标须登记**可信起算版本与时间**，机构/终端/项目归属、结果证据缺失的旧数据记为“历史未核验/不可统计”，不平滑补齐、不按当前归属反推。新旧口径并存时分别披露；新版月报不能悄悄混入旧遥测。设备遥测能力按现场实测标为“队列状态、故障状态、耗材读数”等支持项；未验证写“未验证”，确知不支持才写“本设备不支持，采用人工巡检”，不凭型号猜测。

| 指标 | 定义/展示要求 | 不得写成 |
|---|---|---|
| 服务会话数 | 当前已有按机构快照计数；同终端会话幂等。新增“有效使用”必须明确是否发生业务动作，并保留与原会话口径差异 | 独立服务人数、就业人数；不可为去重而强制群众交身份证 |
| 各类完成服务量 | 打印、扫描、简历结果、面试报告等各按业务最终状态与可用结果计，失败/重试/取消分列；同人多项可多次，不相加冒充人数 | 创建任务量、浏览量、AI请求量等于服务完成量 |
| 打印成功与未确认 | 统一现有终端运营和出纸模块判据；分别说明软件完成、管理员核查、真机确认的证据。分母含已结束失败，未确认另列，不因未知而美化 | 主机在线=出纸成功；队列清空=已出纸；模型状态=纸张实际质量 |
| 印面数/耗纸与耗材 | 系统印面数沿用订单/任务来源，双面与份数正确；面板复印和厂商计数器单列，读不到则未接入；人工盘点标人工来源 | 印面数等于纸张数；打印机总数全部等于本系统服务数；估算墨粉百分比 |
| 可用率/故障时长 | 区分主机心跳、打印可服务、扫描、AI；依据约定服务时段，披露离线、计划维护与不可观测时段及计算规则 | 一次心跳正常=整天服务正常；无故障记录=100%可用 |
| AI调用质量 | 现有遥测和`AiUsageRecord`需完成可信终端归属与共同口径；显示成功/失败/超时/降级、覆盖率。履约须有结果证据，不用best-effort日志填合同指标 | 模型返回200=成果可用；fallback/mock=真AI成功；估算成本=实收或履约金额 |
| 满意度 | 满意评价数/有效评价数，同时给评价参与量与覆盖；少样本抑制；允许说明偏差 | 未评价=满意；无投诉=100%满意 |
| 渠道/政策服务 | 聚合的展示/二维码入口使用，声明观测边界；无法观测用户在手机扫码后的办理结果 | 投递、报名、补贴到账、政策受益人数 |
| 故障处理履约 | 响应/恢复/确认时间分别记录；合同配置服务时间、级别、超时与排除项；投诉与设备故障分开 | 有人点“处理”=已修好；同一事件反复告警算多次故障 |

就业人数、就业率、录用、到岗、企业收到简历等结果不属于本产品可证明的指标。若采购人必须考核此类目标，由其正式业务系统给出并独立说明来源，不能回填成本终端的“转化”，也不据此扩大收简历/撮合能力。

现有多处机构统计阈值为5，并有补充抑制。封存报表沿用或加强保护；需要精确细项的验收应先确定合规的审计方式，不能简单给采购方开放个人明细。**失败样本少不应因抑制而被藏成100%成功**。

## 9. 一份月报与一份验收包应有什么

月报首屏：项目、机构、站点范围、统计月、数据截止/覆盖说明；随后是服务会话与各项完成量、设备可服务情况、故障和超时、公众反馈、资源使用、当月问题与下月计划。每项附定义、来源、未知/样本抑制。机构主管与财务可读的报告应使用任务名称，不暴露数据库术语。

验收包在月报基础上补齐以下材料，先复用现有导出与文件设施，不复制原始用户文件：

1. 合同条款清单与逐项结果：承诺、验收办法、实际值/状态、证据、未通过项、责任人。
2. 到货/安装/资产清单：编号、位置、能力与版本实测、质保范围、交付差异及说明。
3. 实际服务证据：统一聚合、业务同单链路抽验；群众个人材料不进入验收包。
4. 运维证据：告警、派单、响应与恢复、巡检、备机、超时原因和整改复验。
5. 安全证据：越权拒绝、文件访问留痕、会话清场、备份恢复及必要测评材料。
6. 培训/真实试用：机构人员培训记录、群众自主完成任务的结果、反馈和整改。
7. 商务交付与交接：合同覆盖与例外、维保联系方式、到期导出/迁移/销毁清单；发票和应收按权限提供。
8. 封存说明：报告ID、版号、口径、生成/复核人及时间、修订链、文件校验；纸质/外部签章文件引用。

报告状态：`草稿 → 数据检查 → 机构复核 → 封存`；有缺失可出“部分可用报告”，但不能自动判合同通过。导出失败说明原因并可重试，不给空文件冒充成功；导出权限与下载均记审计。
