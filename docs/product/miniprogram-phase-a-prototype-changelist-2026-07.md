# 小程序 Phase A 原型改动清单（2026-07）

> 依据 [双渠道差异化商业方案](miniprogram-vs-kiosk-differentiation-strategy-2026-07.md) 的 Phase A：
> **确立「手机准备 → 一体机履约 → 账户沉淀」分工，打通「材料包 → 到机码 → 出纸 → 状态回流」核心闭环。**
>
> 对象：当时针对 `docs/design/mini-proto-v2-2026-07/` 的 56 页原型。该目录已于 2026-08-22 按产品负责人确认删除；本文只作历史改动记录，不再指向可打开的原型文件。
> 原则：**不推翻重做**，只按分工重构信息架构与关键链路；不新增合规越界功能；改动后逐页视觉验证。
>
> 现状盘点结论：打印链路（`05-hub` 选门店取件流 / `10-store` 终端+设备状态 / `12-pickup` 到机码+诚实「尚未打印」状态）**已把到机履约做对大半**，Phase A 主要是补差距、统一口径、补「材料包」这个缺失的产品对象。

## 二、逐项改动明细

### A1 — 首页信息架构重构（`04-home.html`）P0

**现状**：Hero + AI今日建议 + 「快捷入口 2×3」（上传打印/AI诊断/浏览岗位/招聘会/扫码登录/我的记录，六个功能平铺）+ 附近终端 + 求职动态。问题：六个入口是「功能菜单」平铺，未体现「求职任务主线」，且「打印」与「求职」「AI」权重并列，无法引导用户先在手机准备、再到机履约。

**改法**（保留 Hero / AI建议 / 附近终端 / 求职动态，仅重构中段「快捷入口」区）：

- 把「快捷入口 2×3」改为**按求职任务分组的主线卡**，顺序体现「准备 → 发现 → 履约」：
  1. **准备简历**（AI 诊断/优化/生成 聚合入口）— 主推，`a-teal`
  2. **准备面试**（模拟面试 + 职业规划）— `a-plum`（AI 专属色）
  3. **发现机会**（岗位 / 招聘会 / 企业 / 政策，第三方来源）— `a-wheat`
  4. **到机打印**（上传/材料包 → 选终端 → 到机取件）— `a-clay`，副标题明确「手机下单，附近终端取件」
- 删除首页「扫码登录一体机」独立入口（并入「到机打印」流程 / 保留在打印 hub 内），避免与「到机打印」语义重复。
- 「到机打印」卡副标题文案改为：**「上传文件或材料包，选就近终端，到机扫码出纸」**（诚实：手机不出纸）。
- AI今日建议保留，`as-badge` 保持「仅供参考」。

**验收**：首页四张主线卡按「准备/面试/发现/履约」排列；打印入口文案不暗示手机直接出纸；触控目标 ≥48px；无平台内投递类文案。

### A2 — 新增「材料包 Bundle」对象 + 组装页（新增 `05b-bundle.html`，改 `05-print-hub.html`）P0

**目的**：把「单文件打印」升级为「材料包」这一更有求职服务价值、更易做成套餐的产品对象。材料包 = 多版本简历 + 求职信 + 作品材料 + 招聘会资料 + 面试/职业规划报告，手机准备、Kiosk 一次确认出纸。

**新增 `05b-bundle.html`（材料包组装）**：

- 页头：`navbar` 返回 + 标题「材料包」；说明条「把本次求职要打印的材料放进一个包，到机一次出纸」。
- **包内清单**（`.row-item` 列表）：每项含 文件名 / 类型标签（简历·求职信·作品·招聘会资料·AI报告）/ 页数 / 份数 / 单双面 / 彩黑 / 删除按钮。
- **来源聚合入口**：从「我的简历」「我的文档」「AI 报告」快速加入（跳选择器，原型内做静态示意）。
- 底部 `actionbar`：显示合计页数与预估价，主按钮「选择终端」→ 进 `10-print-store`。
- 合规：AI 生成类材料项加「AI 生成」小标；无真实文件不显示「已就绪」误导。

**改 `05-print-hub.html`**：

- 「上传文件打印」路径卡下新增「**组装材料包**」路径卡（`a-clay`，副标题「多份材料一次打印，适合招聘会/多版本投递」），指向 `05b-bundle.html`。
- 步骤条英雄区从「上传→选门店→结算取件」扩展表述为兼容「上传/材料包 → 选终端 → 到机取件」。

**验收**：材料包可增删项、显示合计、跳选终端；AI 材料标注；文案不出现平台投递；新增页画廊可打开。

### A3 — 打印终点语义诚实化（`13-print-done.html`）P0

**现状问题**：`12-pickup` 已正确显示「待到店取件·尚未打印」，但 `13-done` 直接显示「打印完成 / 已完成 / 已从终端出纸」。在小程序侧，出纸发生在 Kiosk，小程序不应凭空显示「已打印完成」——**必须由终端回流真实状态后才显示**，否则违反「无真实出纸不得显示已打印」红线。

**改法**——`13-print-done` 明确为**「终端已回流的完成态」**，并在页面顶部标注状态来源：

- 标题保留「打印完成」，但在 `done-sub` 增加来源标注：**「就业服务大厅 01 号 已回传出纸完成 · 14:36」**（强调是终端上报，非小程序自判）。
- 小票 `chip` 状态语义：仅当终端回流 `printed` 才显示「已完成」；否则页面应停留在 `12-pickup` 的「待取件」态。
- 增加一行诚实说明：「打印状态以终端上报为准，如与实际不符请在门店核对或联系客服」。
- 「再打一份」按钮改为从「我的文档 / 材料包」重新发起（不在完成页凭空复制文件）。

> 说明：这是原型文案与状态机口径修正，真实实现时「done」页只能在收到 Terminal Agent 的 `printed` 回调后进入。

**验收**：完成态明确标注「终端回传」；无终端回流不显示已打印；文案诚实。

### A4 — 新增「附近终端」独立页（新增 `04b-terminals.html`，改 `04-home.html` 入口）P1

**目的**：位置服务是小程序独占、把用户导向线下的关键钩子。现状首页仅有 2 行终端 + 「查看地图」死链。

**新增 `04b-terminals.html`**：

- 页头「附近的终端」；顶部地图占位区（静态示意 + 「开启定位获取精准推荐」）。
- 终端卡列表（复用 `10-store` 的 `.store-card` 风格）：名称 / 地址 / 距离·步行时间 / **设备状态（在线·空闲 / 在线·排队 N 人 / 离线维护）** / 「导航」「到这里打印」按钮。
- 招聘会现场场景提示卡：招聘会期间显示「现场哪台终端空闲」。
- 合规：设备状态需真实上报，无数据不显示「正常」；离线态如实标注。

**改 `04-home.html`**：「附近的终端」区的「查看地图」指向 `04b-terminals.html`。

**验收**：终端列表含真实语义的设备状态；离线/排队如实；导航与「到这里打印」入口可达。

### A5 — 打印全链路「到机履约」文案与步骤条对齐（`05`~`13`）P1

统一口径，逐页核对（多为文案/步骤条微调，非结构改动）：

- 步骤条统一为四步：**上传/材料包 → 选参数 → 选终端 → 到机取件**（`10-store` 已是此口径，其余页对齐）。
- 全链路禁用暗示「手机出纸」「已打印」的表述，改「下单 / 待取件 / 到机出纸」。
- 价格显示统一 `ab-price` 组件；「结算」语义为「支付后生成到机码」，不是「支付后即打印」。
- 保留 `12-pickup` 的诚实状态条为全链路状态基准。

**验收**：五页步骤条与文案一致；无「手机直接打印/已打印」误导。

## 三、合规红线复核（本清单全程遵守）

- 岗位/招聘会/企业：仅第三方信息入口；按钮白名单「查看岗位/去来源平台投递/扫码投递/查看招聘会/去来源平台预约/扫码预约」；禁用「一键投递/立即投递/平台投递/收简历/候选人管理/面试邀约/Offer」。
- AIGC：一律「AI 生成/仅供参考」。
- 状态诚实：无真实出纸/回流不显示「已打印/已完成」（A3 核心）；无真实设备数据不显示「正常」（A4 核心）。
- 记录：只记本人浏览/收藏/跳转/打印/AI 调用；不记投递/预约结果。
- 凭证：appSecret/支付凭证/apiSecret 只在服务端；前端只 `credentialConfigured`。
- 打印机：`printerName` 可配置，不硬编码型号；A4、无 A3。
- 「我的」页：只做入口概览，不做账户资产聚合。
- 触控：主按钮 ≥56px，可点击区 ≥48px。

## 四、执行顺序建议

1. **P0 先行**：A1（首页任务化）→ A2（材料包）→ A3（终点诚实化）——这三项构成 Phase A 的分工与核心闭环骨架。
2. **P1 跟进**：A4（附近终端页）→ A5（全链路文案对齐）。
3. **P2 收尾**：A6（AI 分工提示）→ A7（画廊维护）。
4. 每页改完立即 preview 验证（miniproto-v2 端口 5291），P0 三页改完做一次整体走查。

> 本清单为原型改动计划，不含真实业务代码改动。原型改定后，即作为对应功能的开发参考基准（承接商业方案 Phase A）。
