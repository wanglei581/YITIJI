## 零、定位与 AI 求职操作系统（2026-09-26）

### 0.1 一句话

AI 求职打印服务终端：放在高校就业中心、人社家门口就业服务站等公共网点的求职准备终端。AI 帮求职者把简历、面试和材料准备好，当场打印带走；手机上的小程序负责随身准备和到机取件。

公司是**设备与软件供应方**：卖终端、随机交付软件、按年收维保。公司**不运营招聘信息**，不是招聘平台，也不承接招聘会承办这类要持证的就业服务外包（next-tasks 3.11，compliance-boundary §1.1）。

### 0.2 谁用、谁买、怎么收费

| 角色 | 是谁 | 用什么 |
|---|---|---|

| 运营机构（客户） | 高校就业中心、公共就业服务机构、持证人力资源服务机构 | 机构后台；向我们买终端与维保 |

### 0.5 AI 设计原则

1. **AI 是加速器，不是前置条件。** AI 不可用时功能退化成手动，不消失、不整页瘫痪、不伪造结果（CLAUDE.md §9「不伪造能力」）。
2. **页面骨架是确定性的。** 表单、预览、打印控制不依赖模型；AI 以页内建议和按钮出现，状态分就绪、计算中、不可用（置灰并写明原因）三种。
3. **一体机上的小青做短任务。** 一句话带到功能、单次问答、填槽；长对话和长期资产回到小程序。公共终端人离即清。
4. **只处理本次提交的材料。** 不建兴趣标签，不主动推送岗位，不对岗位真伪、胜任等级、录用概率下结论（compliance-boundary §1.2 C、E）。
5. **AI 输出要标明。** 界面显式标注「AI 生成，仅供参考」，导出文件带隐式标识（compliance-boundary §1.2 A）。
6. **合规优先，其余 AI 不删弱。** 依赖云上岗位数据或带撮合属性的 AI（岗位推荐、岗位解读、按系统岗位匹配、招聘会参会准备）按托管 a 停放；个人准备类 AI（简历、面试、规划、材料）全部保留，不借整改之名删弱。
7. **不替求职者造假。** AI 只改表达、结构和措辞，不新增用户没提供的学校、公司、证书、时间段、薪资与获奖（§2.2.1）；生成与优化结果都要本人确认后才能导出或打印。

> **对外叫法（建议，待产品负责人确认）：** 投标、采购与小程序提审材料写「AI 求职准备与打印终端」，突出工具与设备属性；「AI 求职操作系统」作为产品架构名在内部和产品介绍里使用。依据：Agy 反方审查认为「操作系统」一词在政府采购语境里容易被理解成平台。

### 1.1 微信小程序定位

微信小程序是 **AI 求职操作系统的随身端**，不是一体机的缩小版，也不是招聘平台。渠道分工固定为：

```text
小程序：持续关系 + 私密准备 + AI 编排 + 下单支付 + 到机提醒
一体机：现场核验 + 硬件能力 + 队列释放 + 打印扫描 + 异常兜底
```

> 这条分工以 `phone_digital` 为默认。`hall_paper`（人社 / 街道 / 零工点、纸质、家属操作）的主表面是一体机；小程序只做家属准备与到机码。依据 [audience-growth-space.md](./audience-growth-space.md)（2026-09-05）。不因此新增底部 Tab 或同义入口。

小程序首要闭环是：微信登录 → AI 简历与求职材料准备 → 材料包 → 服务端报价并建单 → 生成到机码（二维码优先、10 位码兜底）→ 一体机现场付款与核验后释放打印 → Agent 回流真实完成状态 → 订单与本人资产沉淀。（2026-09-26 代码事实：单件与材料包都是小程序建未付订单、到一体机付款，金额为 0 的按免费直接记已付；小程序内没有 `wx.requestPayment`，小程序内付款按 next-tasks 4.1 验收后再开。）

AI 在小程序中作为全局交互层，通过“今天页 + 全局小青 + 页内建议”理解用户意图、编排已有能力并交付成品，不单独堆成功能入口墙。不提供平台内投递、预约结果回流或企业候选人能力。

**首发范围（2026-09-25 产品负责人「按推荐」拍板，next-tasks 2.6）：** 按工具类目提审。停放岗位、招聘会、企业、合同审查、政策、职业圈动态、收藏、足迹、会员权益等 20 页（源码保留，不注册、不打包，门禁 `verify-review-scope`）；底部 Tab 改为 首页 / AI 工具 / 打印 / 我的；「岗位匹配」改名「简历对照」，只接用户自填的岗位要求，只列已写到与未体现的要点和改法，不给档位结论；首发 AI 不收费；求职进度页首发不放。AI 类目材料赶不上时先提不含 AI 的版本。拿证并通过求职 / 招聘类目后再评估加回。以上已进入本地唯一候选（`9354c39f3`、`935755746`；另 `b6fec2a7c` 把非 Tab 页拆成分包，主包约 666KB），尚未合入 `main`、尚未提审；`main`（`eb0f20341`）上仍是旧四 Tab（首页 / 职业生活圈 / 求职 / 我的）。

### 2.2.1 AI 简历优化商用闭环口径（2026-06-29）

AI 简历优化属于求职材料工具服务，必须从既有「AI简历服务」入口真实化，不新增「AI改简历」等同义入口。目标闭环是：

```text
诊断报告 / 原始简历 / 后续语音生成文本
→ 选择目标岗位信息维度
→ AI 内容优化
→ 优化前后对比
→ 模板预览与在线编辑
→ 分阶段导出 PDF / DOCX / TXT / Markdown 或进入打印（PNG 快照承诺已于 2026-09-06 废止）
→ 结果沉淀到 AI服务记录、我的简历、我的文档、打印订单
```

商用级口径如下：

- 诊断后进入优化：`AI简历诊断` 的 `taskId`、结构化报告和本人简历归属可以作为优化输入；用户也可以直接上传/扫描简历进入优化。未登录用户只能使用短期预览或匿名任务，付费导出、长期保存、套餐/券核销必须绑定会员；后续运行时接线必须在登录/注册前后保留当前编辑草稿、`taskId` 和草稿版本，避免用户因登录丢失已编辑内容。
- 目标岗位维度：托管 a 下只允许用户手动粘贴岗位名称 / JD / 专业方向（3.14）；「选择系统内已审核已发布岗位」只在私有化部署（b）里可用。任意外部 URL 首期不自动抓取、不作为已审核岗位入库、不触发外部跳转记录；后续如做 URL 解析，必须先做来源白名单、抓取限流、内容安全、来源展示和合规审查。
- 优化原则：AI 只做表达压缩、经历量化建议、关键词覆盖、结构顺序、语气统一和版式适配，不得新增学校、公司、证书、时间段、薪资、获奖等未经用户确认的事实。
- 格式与排版（2026-09-06 产品负责人裁定，取代 2026-06-29 的单一表述；依据 [结果层评审 §2](../reviews/2026-09-06-result-layer-review.md)）：「内容实质优化」「原件版式绝对不变」「版面和谐单页」三者不可兼得，因此分两种模式对用户承诺，模式名称必须按下面写，**不得把模板重排叫「保留原排版」**：
  - **换模板出新稿（默认，任何原件）**：优化后的内容由服务端模板渲染链路从零排版；不承诺保留用户上传原件的字体、分栏、表格、图片、页边距或 Word 内部样式。PDF 是最终成果，预览、导出、打印必须是同一份 PDF 文件；DOCX / TXT / Markdown 是同一结构化内容的可编辑导出，不保证与 PDF 像素一致。导出前显示页数并提供「压到一页 / 放宽」微调。
  - **只转格式不改字（仅 Word 原件，依赖服务端转换引擎）**：把用户原件原样转为 PDF，承诺「关键元素无丢失、无重叠截断、经用户预览确认」，不承诺与 Microsoft Word 像素一致；界面固定写「由转换引擎生成，复杂版式可能有偏差，请预览核对」。
  - 所有原件另可导出**「修改清单」PDF**（问题 + 原文引用 + 改法），供用户回自己的 Word 修改。PDF / 图片 / 扫描件原件只有「换模板出新稿」与「修改清单」，页面不得暗示「改字但版式不动」。
  - 「在原件上原位回写优化内容」不进口径，仅作 P2 受限实验（复杂度检测不过即回退修改清单）。
- 前后对比与编辑：页面应支持优化前后对比、最终预览、字段级在线编辑、模板参数调整和 AI 一键调整；AI 一键调整只能在用户确认后覆盖当前编辑稿，并保留可撤回或重新生成路径。
- 无电子简历：语音生成简历是后续阶段能力，应先形成结构化文本，经用户确认后才可保存为 TXT / Markdown / DOCX，并可跳转到简历素材库选择模板、自动填充对应区域，再进入同一预览 / 编辑 / 导出 / 打印链路；不得把真实用户简历内容沉淀为公共模板素材。
- 收费显示（2026-09-06 补充：**收费与否由功能开关决定**，开关是 Admin「计费管理」价目表里的 `resume_export` 一行：单价为 0 且启用 = 免费，界面必须写「当前免费，不扣权益」；单价大于 0 且启用 = 收费，走下述规则；停用 = 导出不可用并写明原因，不是免费。界面沉默不等于免费）：优化页必须在导出、长期保存或打印前展示价格、会员权益、套餐抵扣、优惠券抵扣和预计打印费用。预览可免费或低门槛开放；最终成果导出、二次优化、长期保存、打印按订单 / 权益规则核销。已付费且未修改的同一成果，在有效保存期内不应重复扣同一导出权益；同一成果以后端成果版本 ID、内容哈希或 `FileObject` 标识判定，不能只靠前端状态；长期保存必须由用户主动确认保存条款。
