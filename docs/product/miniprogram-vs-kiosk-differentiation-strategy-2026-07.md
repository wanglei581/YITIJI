# 小程序 × 一体机 双渠道差异化商业方案（2026-07）

> 本方案回答一个战略问题：**微信小程序如何与线下一体机（Kiosk）差异化，同时保留两者各自不可替代的价值。**
> 结论由 Claude 独立分析 + Codex（analyzer 角色，商业战略视角）独立分析交叉得出，两方在核心判断上收敛一致。
> 合规口径以 [docs/compliance/compliance-boundary.md](../compliance/compliance-boundary.md) 与 [CLAUDE.md](../../CLAUDE.md) 为准，本方案不突破任何红线。
>
> 现状基线：Kiosk 原型 86 页全路由基准（docs/design/kiosk-proto-2026-07/），小程序原型 56 页（docs/design/mini-proto-v2-2026-07/）。

---

## 一、执行摘要（给决策者的一页话）

**最本质的差异不在屏幕尺寸，而在于「能否完成物理世界的最后一公里」。**

- 一体机 = **现场履约与实体服务节点**：把数字材料变成纸质成果，解决扫描、打印、ADF 批量、招聘会现场准备等「我现在就要」的即时需求。它有稀缺的物理能力、地点价值、政务/人才市场的信任背书。
- 小程序 = **随身求职工作台**：承接非现场、碎片化、长期反复的准备 / 管理 / 留存需求，是低边际成本的 AI 服务、会员、数字资产与复购经营渠道。

一句话定位：

> **小程序负责把用户「准备好」；一体机负责让用户在关键地点、关键时刻「交付成果」。**

**当前最大的战略误区**：把小程序当成一体机的「等比缩小版」——56 页几乎复刻了 86 页 Kiosk 的全部功能路径。若用户在手机上就能获得与到店相同的结果，一体机会退化为低频、低毛利的普通打印机，其高固定成本（硬件 + 点位 + 耗材 + Terminal Agent 运维）将无法被履约频次覆盖，ROI 崩塌。

**核心解法（三层模型 + 三个机制）**：

- 三层模型：**手机前置准备 → 一体机现场履约 → 统一账户资产沉淀**。
- 三个机制：**材料包（Bundle）**、**到机履约码（Pickup Code）**、**统一权益账本（数字权益 / 终端权益分账）**。

这样小程序成为 Kiosk 的**获客、准备、复购引擎**；Kiosk 成为小程序**无法替代的实体交付节点**。两端不争夺同一次用户行为，而是共同完成一次更高价值的求职材料服务闭环。

## 二、渠道本质差异（用户价值 × 商业价值）

| 维度 | Kiosk 一体机 | 微信小程序 |
|---|---|---|
| 用户价值 | 当场解决「我现在需要一份材料」 | 持续解决「我如何准备得更好」 |
| 不可替代能力 | 打印、扫描、ADF、纸质材料、现场设备、场地服务感、官方背书 | 随身可用、长期编辑、版本管理、提醒、留存、复访 |
| 商业价值 | 消化硬件固定成本，形成单次履约收入、场地合作价值、终端广告/赞助价值 | 低边际成本的 AI 服务、会员订阅、数字资产与复购经营 |
| 最适合场景 | 人才市场、招聘会、政务点、社区等「临门一脚」时刻 | 家中、通勤、课间、投递前、面试前的连续准备 |
| 成本结构 | 高固定成本（设备+点位+耗材+运维），需高履约频次回本 | 低边际成本，规模化后毛利高 |
| 获客逻辑 | 依赖点位人流，获客被动 | 微信生态裂变、社交分享，获客主动、成本低 |

**关键洞察**：两个渠道不是「同一产品的两个屏幕」，而是同一用户旅程中的**两种不同能力层**。硬件、点位、现场服务的成本不会因为小程序功能全而消失——所以小程序的目标应是**提高一体机的「有效到机率」和「到机后完成率」，而不是替代到机行为**。

## 三、「小程序复刻一体机」的三大商业风险

功能重叠本身不必然有问题；**真正危险的是小程序让用户「不去一体机也能获得相同结果」。**

### 风险一：一体机退化为低频、低毛利的普通打印机

若小程序完成 AI、简历、岗位、招聘会、材料管理，并允许用户脱离终端完成大部分闭环，用户到线下只剩「偶尔打印几页」的理由。后果：

- 高固定成本 / 维护 / 耗材 / 点位成本无法被足够的履约频次覆盖；
- 用户可能直接在家、公司、校园打印，Kiosk 建立不了必要性；
- 人才市场 / 政务点会质疑：为什么要占地、接电、维护一台终端？
- 终端从「求职服务入口」降级为「可替代的打印外设」。

### 风险二：内部蚕食（cannibalization），却没换来更优单位经济

小程序把用户留在线上并非坏事——但只有同时满足以下条件，线上替代才划算：

1. 小程序的单用户贡献毛利 **高于** 被替代的一体机履约毛利；
2. 一体机不再依赖高利用率回本；
3. 小程序能显著降低获客成本或提升付费转化。

当前仍有硬件、点位、Terminal Agent 投入，因此更现实的目标是：**小程序提高一体机的到机率与准备完成率**，而不是替代到机。

### 风险三：组织与用户认知都变模糊

若两端都主打「AI 求职 + 打印 + 岗位 + 招聘会 + 会员」，用户无法理解为何要两个入口，运营也无法定义各渠道 KPI。最终容易出现：

- 小程序追页面数 / DAU / 停留时长；
- Kiosk 追打印订单；
- 两者各自优化，却没有**共同的转化漏斗**。

## 四、渠道分工模型：手机准备 · 一体机履约 · 账户沉淀

```text
小程序：准备、管理、留存
    ↓ 材料包 / 到机码 / 权益
Kiosk：确认、打印、扫描、现场服务
    ↓ 订单、成果、异常状态
统一账户：简历版本、文档、权益、订单、记录
```

### 4.1 手机（小程序）应做什么——「随身求职工作台」

- AI 简历诊断、优化、生成、**版本管理**（手机独占的长周期能力）；
- 模拟面试、职业规划、岗位匹配参考（本人使用的深度工具）；
- 岗位 / 招聘会 / 政策的深度浏览、收藏、**提醒**；
- 上传文件、创建「待打印材料包」、**选择目标终端**；
- 查看打印订单、电子凭证、权益、异常反馈；
- 长周期消息、提醒、复访、会员经营。

> 手机上的「打印」应定位为**到机前预处理 / 下单**，而非独立的云打印替代品：选终端、预选参数、预估价、支付/权益校验都可以做，但**最终出纸、设备确认、异常处理仍在 Kiosk 完成**。

### 4.2 一体机（Kiosk）应做什么——「现场求职服务站」

- **扫码取回**已准备的简历、材料包、打印订单；
- 纸质简历扫描、ADF 批量扫描、U 盘导入（物理独占能力）；
- 打印参数最终确认、支付/核销、出纸与取件；
- 招聘会 / 人才市场的现场材料准备（简历多份打印、招聘会资料打印）；
- 现场紧急 AI 简历四步流：给「没准备、现在就要用」的用户；
- 依赖大屏、地点、设备优势的服务；**不承载长时间浏览或复杂资料管理**。

### 4.3 两者如何衔接——「材料包」是核心交接物

典型闭环：

1. 用户在小程序完成简历优化，选版本、份数、单双面、彩/黑白、目标终端；
2. 系统生成**短时有效的到机履约码 / QR Code**；
3. 用户到 Kiosk 扫码，终端**仅拉取本次材料包**；
4. 大屏完成最终预览、设备状态确认、支付/核销、出纸；
5. 打印订单、文件版本、取件码、异常状态**回流小程序**；
6. Kiosk 自动清除会话与临时文件，保护公共设备隐私。

**岗位 / 招聘会信息也应不对称分工**：

- 小程序：深度浏览、收藏、准备材料、查看来源平台；
- Kiosk：「我就在现场」的导览、材料打印、官方/来源平台 QR 引导；
- 两端始终用「去来源平台投递 / 扫码投递」「去来源平台预约 / 扫码预约」，**不形成平台内招聘闭环**。

## 五、商业模式与变现闭环

### 5.1 Kiosk 的收入逻辑：卖「现场履约能力」

- 按页打印、彩色、双面、扫描等服务费；
- 招聘会 / 人才市场的「现场求职材料服务包」；
- 场地 / 合作机构的终端服务费、运维费；
- 合规的品牌宣传屏、企业赞助打印券、政策服务宣传位。

> 赞助方只能获得**品牌曝光和权益发放效果**，不得获得简历、候选人资料或投递结果。

Kiosk 核心经营指标（**不是屏幕点击量**）：每台终端有效履约订单数 / 到机后完成打印率 / 单台终端贡献毛利 / **预处理包→到机出纸转化率** / 招聘会场景材料服务渗透率。

### 5.2 小程序的收入逻辑：卖「数字化求职工具与持续服务」

- AI 简历优化 / 生成 / 模板 / 成果导出 / 长期保存；
- 模拟面试、职业规划等本人使用的工具服务；
- 会员订阅 / 权益包；
- 与 Kiosk 绑定的打印额度、材料包折扣；
- 合规的信息服务赞助 / 品牌曝光（**不按简历投递结果收费**）。

> 红线：不得把收费包装成「保面试 / 保录用 / 内推 / 代投」等招聘结果承诺。

### 5.3 权益设计：统一身份，但两端不做成可替代品

一个账户、一个权益账本，权益分两类：

- **数字权益**：AI 服务次数、模板、导出、保存期限（小程序消费）；
- **终端权益**：打印页数、扫描次数、现场材料包折扣（Kiosk 消费）。

跨端激励（保留渠道分工，**不做成无限制通用余额**）：

- 小程序完成一次付费简历优化 → 赠「指定终端限时打印额度」；
- Kiosk 首次完成打印 → 赠一次小程序 AI 诊断 / 简历保存权益；
- 招聘会期间手机生成材料包 → 指定现场终端核销获限时优惠。

### 5.4 双向引流闭环

```text
线上引流线下履约：小程序 AI 准备 → 生成材料包 + 到机码 → 附近终端出纸
线下沉淀线上留存：Kiosk 游客用完 → 扫码把简历/订单存进小程序 → 转为长期会员
```

- **线上→线下**：手机把「思考/准备」做透，把「出纸/交付」导向就近终端（类似「线上点单、到店自提」）。
- **线下→线上**：Kiosk 游客态一次性用户，用完扫码沉淀为小程序账户，一次性履约转为长期私域经营与复购。

## 六、小程序定位调整：最高优先级产品建议

### 建议 1：从「复刻 Kiosk」改成「求职随身工作台」

首页与导航围绕**用户任务**组织，而非搬「打印机功能菜单」：准备简历 / 管理我的材料 / 准备面试 / 发现岗位·招聘会 / **到机打印**。

> 对应现有 56 页原型：`04-home` 首页信息架构应从「五大板块并列」调整为「以求职任务为主线」，把「打印」从门面降级为任务之一。

### 建议 2：移动端「打印」改造成「到机履约入口」

支持选终端、预选参数、预估价、支付/权益校验，但**明确最终步骤是「到指定终端扫码确认并出纸」**。既降低 Kiosk 现场操作时间，又不把手机做成一体机替代品。

> 对应原型：`05-print-hub`~`13-print-done` 这一串应引入「选择目标终端 + 附近终端地图/排队状态」步骤，并把「完成」语义从「已打印」改为「已下单，到机取件」（诚实文案，符合「无真实出纸不得显示已打印」红线）。

### 建议 3：建立「材料包 Bundle」而非「单文件打印」的产品对象

材料包可含：不同版本简历 / 求职信 / 作品材料 / 招聘会资料 / 面试·职业规划报告。手机准备、Kiosk 一次确认出纸。比「在线打印」更有求职服务价值，也更容易做成套餐收费。

### 建议 4：AI 能力「手机做深、Kiosk 做快」

- 小程序：多轮编辑、历史版本、长期任务、语音/文本输入、资料管理；
- Kiosk：四步快速生成、扫码继续编辑、现场紧急打印。

同一能力不必两端同等深度。Kiosk 的价值是降低现场摩擦，不是承接长时内容创作。

### 建议 5：用「跨端转化指标」替代「页面覆盖率」目标

给每个小程序功能加一条渠道归属判断：

1. 是否帮助用户完成准备？
2. 是否提高到机概率或到机后完成率？
3. 若不依赖物理设备，是否能带来独立数字服务收入或留存？

**三者都不满足的重复功能 → 降级 / 合并 / 取消优先级。**

### 建议 6（补充）：加一层「附近终端」位置服务

这是小程序独占、Kiosk 无法自我提供的能力，也是「线上→线下」的关键钩子：

- 附近一体机地图、距离、营业状态、当前排队/设备在线状态；
- 招聘会现场哪台终端空闲；
- 到机导航 + 到机码一键出示。

## 七、落地路线图（分三阶段，先协同后运营）

> 原则：不推翻已完成的 56 页原型，而是**按上述分工重构信息架构与关键链路**；不新增合规越界功能；每阶段先小范围验证转化，再放量。

### Phase A：确立分工与核心交接物（最高优先级）

- 小程序首页 / 导航按「求职任务」重构（建议 1）；
- 移动端打印链路改为「到机履约入口」+ 选终端 + 附近终端状态（建议 2、6）；
- 打通「材料包 → 到机码 → Kiosk 扫码拉取 → 出纸 → 状态回流」最小闭环（建议 3 + 四.3）；
- 「完成」等状态文案诚实化（无真实出纸不显示「已打印」）。

### Phase B：统一账户与跨端权益

- 一个账户、一个权益账本，数字权益 / 终端权益分账（五.3）；
- Kiosk 游客扫码沉淀到小程序（线下→线上）；
- 跨端激励券（线上付费送终端额度、线下打印送数字权益）。

### Phase C：私域运营与 B 端价值

- 消息/提醒、复访、会员经营；
- 合规的政策解读 / 求职干货内容提升日活；
- 招聘会现场材料服务包、场地/赞助商合规曝光位（不涉简历与投递结果）。

## 八、合规守护（本方案不突破任何红线）

- 岗位 / 招聘会 / 企业展示：两端**只做第三方 / 官方来源信息入口**；按钮仅用白名单「查看岗位 / 去来源平台投递 / 扫码投递 / 查看招聘会 / 去来源平台预约 / 扫码预约」；禁止「一键投递 / 立即投递 / 平台投递 / 企业收简历 / 候选人管理 / 面试邀约 / Offer 管理」。
- AIGC 内容：一律标注「AI 生成 / 仅供参考」；无真实数据不显示已完成 / 已保存 / 已打印 / 已投递 / 设备正常。
- 记录边界：只记录**本人**浏览、收藏、外部跳转、打印、AI 调用；**不记录任何投递 / 预约结果**，不同步候选人数据。
- 凭证安全：奔图 appKey/appSecret、支付凭证、数据源 apiSecret **只存服务端**，前端只读 `credentialConfigured`。
- 硬件：代码用可配置 `printerName`，禁止硬编码型号；A4、无 A3；云打印架构为「云端队列 → Windows Agent claim → 本地驱动」，非打印机自云打印。
- 变现：不得承诺招聘结果（保面试/保录用/内推/代投）；赞助方只得品牌曝光，不得获取简历或投递数据。
- 微信侧：小程序类目应归**生活服务 / 商业服务 / 打印**，避免落入需人力资源许可证的「招聘」类目；支付走微信支付，凭证后端处理。

## 九、两个必须记住的战略误区

**误区一：把功能覆盖率当作渠道竞争力。**「56 个页面」不等于商业能力。若小程序与 Kiosk 提供相同路径、相同结果，用户自然选更方便的手机端；但硬件、点位、现场服务成本不会消失。真正的竞争力不是「两个端都有」，而是「用户必须且愿意在合适的环节使用对应渠道」。

**误区二：把一体机理解为手机的弱版本。**一体机不是放大的手机，也不该是小程序功能不完整时的补丁。它是有稀缺物理能力、地点价值、即时履约价值的服务节点。若不能把 Kiosk 定义为「现场成果交付节点」，它的 ROI 只能依赖低频打印收入，长期难以成立。

## 十、一句话结论

> 优先确立「**手机准备、Kiosk 履约、账户沉淀**」的产品原则，把「**材料包 + 到机履约码 + 统一权益账本**」设为双渠道协同的核心机制。
>
> 小程序成为 Kiosk 的获客、准备与复购引擎；Kiosk 成为小程序无法替代的实体交付节点。两端不争夺同一次用户行为，而是共同完成一次更高价值的求职材料服务闭环。
