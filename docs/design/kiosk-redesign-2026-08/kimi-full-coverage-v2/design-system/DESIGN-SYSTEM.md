# 青序流光 · Kiosk v2 设计系统规范（第 0 批）

> 配套文件：`kiosk-tokens.css`（令牌）、`kiosk-components.css`（组件）、`templates/`（规划 10 型；当前只交付并可使用 T1-T4，T5-T10 尚未交付）。
> 本规范是所有 v2 页面的施工守则；与 `COVERAGE-MATRIX.md` §一 的口径一体生效。

---

## 1. 每屏 HTML 的固定结构

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8">
<title>职易达 · {屏名} ｜ 青序流光 v2</title>
<link rel="stylesheet" href="design-system/kiosk-tokens.css">
<link rel="stylesheet" href="design-system/kiosk-components.css">
<style>/* 仅允许本屏独有布局，禁止复制组件样式、禁止硬编码令牌值 */</style>
</head>
<body>
<!--
route: /print/cashier
state: 支付·待付（本文件 data-state 全量：pending/paying/paid/expired/checking/closed/unavailable）
api: POST /api/v1/orders/:id/pay → { attemptId, orderId, orderNo, channel, amountCents, status, qrCodeContent, expiresAt, orderPayStatus, orderExpiresAt }；GET /api/v1/orders/:id/pay-status → PayStatusView（以服务端 payStatus/attempt 为准）
fallback: 支付通道不可用 → 显示「请联系工作人员」+ 订单号，不显示二维码
-->
<div id="viewport"><main id="stage" data-screen="cashier" data-state="pending">
  <header class="k-topbar">…</header>
  <div class="k-scroll"><!-- 唯一中部滚动区；短内容页可省略 --></div>
  <div class="k-cta-bar"><!-- 主操作常驻 --></div>
  <nav class="k-navbar"><!-- 三 Tab 常驻 --></nav>
</main></div>
</body>
</html>
```

- 注释四行（`route` / `state` / `api` / `fallback`）是**机械翻译契约**，每屏必填；按钮文案变更加 `rename: 旧 → 新` 行。
- 多状态同文件：`<main data-screen="x" data-state="…">` 复制为多份或 JS 切态演示均可，状态容器带 `data-testid="x-state-<state>"`。

## 2. 布局铁律（覆盖旧「全屏无滚动」）

1. `#stage` 1080×1920 永不溢出：任何元素 top > 1920 或横向溢出 = 失败。
2. 长列表/长文/长报告：**仅允许一个 `.k-scroll` 中部滚动区**（或分页）；顶栏、主操作条、底部导航在滚动区外常驻。
3. 主操作**无需滚动即可触达**；底部三 Tab（首页/问小青/我的）固定，不加第四个。
4. 触控：主按钮 ≥56px 高且字号 ≥22px；任意可点 ≥48px；每屏可点元素 ≤20（不含底栏）。

## 3. 密度红线（沿用 DESIGN-PLAN，治文字墙）

- 每屏信息预算：**1 个小青问句 + ≤3 个区块 + 1 个主动作**。
- 屏内可见字符 ≤450（列表 550 / 长文 600）；文字覆盖面积 ≤12%（列表 14 / 长文 15）。
- 说明超过 2 行 → 拆编号步骤或收进次级；区块文字超 6 行 → 考虑拆屏。
- 下半屏不许大面积空白（弹性拉开内容）。

### 3.1 页面骨架先行（2026-08-25 产品化收束）

先判断页面的真实任务类型，再选择骨架；不能为了统一而让每个页面都套大号小青导语、三段说明卡和同一种等高卡片。

| 页面类型 | 适用 route / 场景 | 首屏骨架 | 禁止事项 |
|---|---|---|---|
| 服务首页 / Hub | 首页、服务域选择、首次进入复杂能力 | 顶栏 + 可选小青任务带 + 3--6 个任务入口 | 用于普通目录、详情或纯选择页 |
| 目录 / 列表 | 岗位、企业、机构、平台、招聘会列表 | 紧凑顶栏 + 筛选/搜索 + 列表或目录为主内容 + 常驻主操作 | 大任务带常驻；说明区占主视野；横向滑动目录 |
| 详情 / 工作台 | 岗位详情、企业详情、文件/简历/AI 工作区 | 紧凑顶栏 + 任务摘要 + 可操作内容 + 就地状态/下一步 | 把来源、隐私、失败说明重复放在标题、正文和页脚 |
| 引导流程 | 上传、扫码、支付、面试设置、打印设置 | 顶栏 + 当前一步 + 关键输入/预览 + 底部单一主操作 | 没有真实进度却画阶段进度；把同一任务拆成无必要的多页 |
| 异常 / 受限 | 空、失败、离线、无权限、来源不足、设备不可用 | 明确状态 + 原因 + 一个恢复/替代出口 | 用正常态的卡片墙或假数据填空 |

**小青任务带不是每页固定组件。** 仅用于服务首页、首次进入复杂流程、需要解释一个重要“下一步”的异常态。目录、详情、设置、选择页默认使用紧凑顶栏，把第一屏还给任务内容。

### 3.2 1080×1920 竖屏的视觉预算

- Ready 态的首要任务区（列表、工作区、选择项）应占中部可见高度约 **60%--70%**；解释、辅助和替代路径合计不超过约 **25%**。
- 同屏项目不多时，卡片按内容自然高度排列；**禁止用 `flex: 1` 或等高网格硬撑到整屏**，造成卡内无意义空洞。
- 列表/目录默认纵向浏览或分页：顶栏、主操作和底部三 Tab 固定；中部只有一个纵向滚动区。**不把关键项目放在横向滑动容器里。**
- 四项以内的同类选择：可用 2×2 紧凑卡或四行列表；当每项需要名称、来源、状态与唯一操作时，优先四行列表。每行必须在一眼内看清“是什么、下一步是什么”。
- 合规、真实性、隐私提示采用“**一次可见 + 就地出现**”：与按钮直接相关的原因放按钮旁；全局隐私只在页脚保留一条短提示；开发契约、硬编码实现、验收范围写入 HTML 注释和证据报告，不占用户正文。
- 无真实数据时，可以保留字段结构、加载和失败回退，但不得让“字段槽位 / 静态原型 / 服务端未返回”的解释成为 ready 态主视觉。真实结果回来后，列表、摘要、预览和主操作应自然占据空间。
- 大屏触控以可识别、可误触防护为优先：任意可点仍不低于 48px，主操作不低于 56px；主操作保持一屏可触达，但不因按钮大而把正文压缩成一角。

## 4. 语义化与可访问性（测试定位契约）

- `<button>` / `<a>` / `<h1><h2>` / `<ul><li>` / `<table>` 按语义使用；可点元素必须有可访问名。
- 禁用态：`aria-disabled="true"` + `.k-disabled-reason` 原因文字常驻，不只改颜色。
- 必备 testid（kebab-case，屏名前缀）：
  - 主操作 `data-testid="<screen>-primary"`
  - 状态容器 `data-testid="<screen>-state-<state>"`
  - 列表容器 `data-testid="<screen>-list"`
  - 降级/错误块 `data-testid="<screen>-fallback"`

## 5. 状态设计规范

| 状态 | 组件 | 要点 |
|---|---|---|
| 加载/处理中 | 状态文字；仅有真实 progress/stage 时使用 `.k-progress` / `.k-steps` | **禁止循环 spinner、假百分比和假阶段**；只有接口返回真实进度或阶段字段时才画进度条/步骤点，否则只显示整体处理中和已用时间，细则以 `MOTION-SPEC.md` 为准 |
| 空态 | `.k-state` | 诚实说明 + 一个去向动作；不画假数据 |
| 失败态 | `.k-state[data-kind="error"]` | 说清原因 + 重试/求助出口；失败块带 fallback testid |
| 过期态 | `.k-state[data-kind="warn"]` | 给刷新/重新获取路径（如付款码过期） |
| 离线态 | `.k-state` + `.k-status-pill[data-tone="down"]` | 标明哪些能力仍可用 |
| 锁定/未授权 | `.k-state[data-kind="lock"]` | 原因常驻 + 无假按钮；受控/冻结页此态为默认态 |
| 中断/恢复 | 中断/恢复模式（规划 T10，当前无模板文件） | 进度可恢复的要显示「已保留到哪一步」；T10 交付前不得声称已套用模板 |

- 公共终端个人信息默认遮挡（手机号 138****5678 式）；PII 预览默认脱敏。
- 无真实数据/接口/硬件状态时，禁止显示「已完成/已保存/已打印/已签到/设备正常」。

## 6. 合规内建（每屏自检）

- 岗位/招聘会卡片与详情必须渲染 `.k-source-meta`（来源名称 · 同步时间 · 外部链接/说明）。
- CTA 仅白名单：`查看岗位` `去来源平台投递` `扫码投递` `查看招聘会` `去来源平台预约` `扫码预约`。
- 匹配只给三档（较高/中等/偏低），禁百分比；条件核对写「确定性比对」不写「AI 判定」；材料检查写「隐私检查」不写「AI 体检」。
- 朱砂 `--cinnabar` 只用于不可逆确认（删除/清空/离场）。
- 诚实声明（「本机不代收简历」「不代办、不收费」等）不得为压字数删除。
- 支付成功仅由服务端 `pay-status` 驱动；设计稿中「已付」态注释必须写明该来源。

## 7. 资源与脚本

- 零外部资源：不引 CDN 字体/远程图片；图标用内联 lucide 线性 SVG（stroke 1.9–2.4，对应具体业务）。
- 无真实图源不留图位（防止灰块占位）。
- 原型 JS 可用于演示切态和本地表单交互（如必填校验/按钮启停）；不得发真实请求、驱动业务完成或伪造 API/硬件结果。
- 动效只用 transform/opacity，遵守 `prefers-reduced-motion` 与 `?flat=1` 降级。

## 7.1 AI 增强是任务能力，不是每页复制一个“小青卡片”

每条真实功能 route 都必须在 `COVERAGE-MATRIX.md` 登记 AI 处理方式，但页面是否显示 AI 控件取决于当前任务。底部“问小青”是全局求助入口，**不能代替当前页面的 AI 增强设计**；同样，也不能为了满足覆盖要求，在每页顶部重复大号小青任务带或通用“AI 帮你分析”按钮。

| 类型 | 适用任务 | 页面表现 | 例子 |
|---|---|---|---|
| `AI-DIRECT` 直接增强 | AI 本身就是当前任务的核心处理器 | 明确输入、授权、处理中、可核验结果、失败和重试 | 简历生成/诊断/优化、岗位匹配解释、模拟面试、职业规划、政策来源问答 |
| `AI-CONTEXT` 场景辅助 | 主任务不是 AI，但 AI 能减少查找、填写、准备或理解成本 | 在搜索、筛选、预览、结果或下一步附近提供一个就地辅助动作 | 从本人简历生成岗位搜索词、招聘会参会准备、企业/岗位对比、扫描件识别、打印参数建议 |
| `AI-EXPLAIN` 解释辅助 | 页面展示的是确定性事实或系统状态，AI 只能解释和提供人工操作建议 | 只解释已返回事实，不生成状态、不替用户确认 | 支付失败原因解释、打印异常排查、协议通俗说明、隐私请求说明 |
| `AI-NONE` 不在本页介入 | AI 会干扰安全、身份、硬件或单一确认任务，或该 route 只是重定向/手机辅助/冻结页 | 不放页内 AI 控件；保留全局“问小青”或帮助出口即可 | 登录、到机码校验、会话清场、支付结果、重定向、冻结能力 |

每个 `AI-DIRECT` / `AI-CONTEXT` / `AI-EXPLAIN` 设计必须同时写清六项契约：

1. **真实输入**：来自哪份本人简历、岗位、招聘会、文件、政策来源或服务端错误；无输入时显示缺少上下文，不生成演示结果。
2. **授权与告知**：使用个人文件、语音、历史记录或跨任务上下文前，说明用途并取得当前任务所需授权；默认不扩大授权范围。
3. **输出**：输出必须可编辑、可忽略、可追溯到输入；推荐、摘要和建议不得伪装成确定事实。
4. **失败状态**：模型未配置、超时、来源不足、内容不可解析、权限不足分别有诚实状态；禁止固定成功、假进度、假匹配分。
5. **非 AI 回退**：始终保留手动搜索、手动填写、查看原文、普通打印/扫描设置、文字作答或人工帮助路径。
6. **持久化**：明确是否生成 AI 记录、文件或报告；匿名临时结果和会员持久记录不得混写，删除与留存按真实服务端契约执行。

### 7.2 AI 不得判定的事实

以下结果只认对应真实系统、服务端、来源平台或设备回流，AI 最多解释，**不得决定、补写或推测**：

- 登录成功、用户身份、权限和本人关系；
- 报价、支付状态、优惠核销和退款结果；
- 打印/扫描完成、设备在线、耗材、卡纸和硬件能力；
- 到机码有效性、订单归属、会话超时和隐私清场完成；
- 岗位/招聘会/政策的来源真实性、有效期和外部投递/预约结果；
- 法律结论、补贴资格、招聘录用、面试通过和生产部署状态。

岗位与招聘会域的 AI 只帮助用户理解、比较和准备，不得形成平台内投递、候选人推荐给企业或招聘闭环。匹配结果使用“较高/中等/偏低 + 依据”，不使用伪精确百分比；政策回答必须展示官方来源并允许直接查看原文。

### 7.3 AI 增强验收门禁

- 每条 route 在覆盖矩阵有且只有一个 AI 分类；共享宿主的不同 route 可以复用组件，但输入、输出和回退必须符合各自任务。
- Ready 态中 AI 辅助不得挤占列表、详情、预览或主操作；普通目录/详情页优先使用紧凑的就地入口，不常驻大横幅。
- 对 `AI-DIRECT` 至少截图并验证 input/missing-context、processing、result、unavailable/failed；对 `AI-CONTEXT` 至少验证可用、缺输入、AI 不可用和手动回退。
- 浏览器门禁必须证明：无真实输入时不会出现个性化结果，AI 失败不阻断主任务，AI 输出不能直接改写支付/设备/登录/来源事实。
- 静态原型中的 AI 状态只表达产品合同，不代表模型、TRTC、ASR/TTS、API、记录持久化或生产能力已经接通。

## 8. 与生产的对接边界

| 设计方交付 | 对接方负责 |
|---|---|
| 语义化 HTML + 契约注释 + 状态 data-state + testid | 翻成 React 组件、接 API/路由/状态管理 |
| 令牌化样式（kiosk-tokens/components） | 提取页面级样式表、动效重接 |
| 截图自检报告（1080×1920） | 跑密度/视觉秩序/合规/类型 4 道门禁 |
