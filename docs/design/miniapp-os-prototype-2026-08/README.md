> 状态：V8.0 pilot，待用户确认后才可作为 `apps/miniapp/` 开发视觉基线  
> 日期：2026-08-06  
> 工作品牌：青序（仅用于原型，最终名称仍属于 Gate 0）

## 打开方式

直接打开 `index.html` 即可浏览，不依赖开发服务器。左侧可按阶段、Tab 和流程筛选，点击页面名称切换手机画面；手机画面中的主要按钮可跳转到下一原型页。

原型采用固定 390 × 844 微信小程序视口，同时提供窄屏模式。`captures/` 保存逐页效果图；可运行 `node capture.mjs` 使用本机 Chrome 重新生成。

## V8.0 当前 pilot：现代公共就业服务产品

V8 保留 V7.1 已确认的产品布局判断，只替换会让页面像概念稿的视觉语言：移除荧光绿、粗黑分隔线、英文控制台标签和普通文字的等宽字体，建立暖白背景、深墨绿可信状态、克制橙色行动/期限、来源蓝外部边界。41 页矩阵、四个 Tab、AI 环境层、手机 `Order` 与到机后创建 `PrintTask` 的履约边界均保持不变；本轮仍只重构 6 个母版页。

| 页面  | 首屏要回答的问题                 | V8 构图与视觉角色                            |
| ----- | -------------------------------- | -------------------------------------------- |
| `T01` | 我现在必须先做什么？             | 淡绿今日办理区 + 唯一橙色主动作 + 临期风险行 |
| `M01` | 哪些资产可以直接使用？           | 暖白材料档案桌 + 深绿主简历 + 行式成果登记   |
| `D01` | 现在什么信息值得打开？           | 来源编辑部 + 深绿官方头条 + 蓝色来源动作     |
| `U01` | 我还有哪些未完成义务？           | 服务台账 + 橙色未完成义务 + 行式账户事实     |
| `M14` | 到机码是否有效，现场会发生什么？ | 深色设备层 + 白色本人凭证 + 四步现场核验     |
| `M15` | 打印是否正常，异常如何处理？     | 深色实时状态 + 绿色运行信号 + 真实终端事件   |

设计判断：`T01`、`M01`、`D01`、`U01` 不共享同一构图；`M14` 与 `M15` 虽同属履约，但分别表达“交接凭证”和“设备状态”。页面不靠背景色制造差异，而靠操作对象、比例和阅读顺序建立场景；分隔线降为 1px 灰绿，圆角只用于真实按钮、凭证和面板。AI 以页内建议和低风险决策入口出现，不制造独立 AI 功能墙。

本轮没有新增页面、入口、数据模型、依赖或业务闭环，也没有修改 `apps/`、`services/`、`packages/`、支付、数据库和硬件链路。用户确认这 6 页 pilot 后，才扩展剩余 35 页。

## V8.0 验证结果

- 41 / 41 页面可渲染，截图全部为 780 × 1688，对应 390 × 844 双倍像素视口。
- 真实浏览器逐页检查：手机画布横向溢出、元素越界、隐藏文字裁切、可见渐变、内部目标缺失均为 0。
- 四个主页面的“今天 / 材料 / 发现 / 我的”标签、目标和激活态一致，控制台错误为 0。
- JavaScript 语法、Prettier、457 文件合规文案门禁、原型禁用投递文案扫描和目标文档 `git diff --check` 通过。
- 当前 shell 与 pnpm 使用 Node 26.6.0，仓库引擎要求 `>=22.13 <23`，所以标准 pnpm script 仍须在 Node 22 环境复验；同一合规脚本已由当前 `node` 直接执行通过。
- 本地 Claude Code `2.1.222` 完成源码级只读审查；采纳 `D01` 头条动作识别、`M15` 实时运行信号和 `U01` 账户事实语义区分三项意见。未采纳恢复黑底 `T01` 和把到机码染成橙色的建议，因为这会重新引入概念控制台感，并破坏橙色只承担行动/期限的规则。Claude 无法渲染 PNG，因此像素裁决仍以截图和真实浏览器门禁为准。

## Previous visual iterations

### V5 视觉方向：公共服务型求职行程本

V5 以墨刀案例库的[医保小程序用户端实战原型](https://modao.cc/com24/details/mtljp3e6j7rj2lbf)作为公共服务信息架构参考。采用的是“首页概览、服务目录、核心凭证、资讯详情、我的账户”按业务对象分别构图的原则，不复制其深蓝色头图、彩色宫格、政务模板配色或五 Tab 结构。

V4 已建立“求职行程本”视觉语言；V5 在此基础上把页面收敛为更接近成熟微信公共服务产品的目录、表单、报告、收据、票券和文章。它不是聊天机器人皮肤，也不是缩小的后台，而是用户随身携带的材料册、行动清单和履约凭证。

- 用编辑式编号、任务顺序、收据、票券和文档缩略图表达业务对象。
- 用细分隔线和留白组织信息，不使用重复圆角卡片墙、大面积单色 Hero 或渐变装饰。
- 珊瑚橙只承担主动作、时间风险和需要优先修正的弱项：它表达“现在应处理”，不拿来装饰普通容器。
- 墨绿只用于已验证、可信和来源状态：它比珊瑚色安静，适合承载完成、官方来源和可用性事实，不与主动作争抢。
- 钴蓝只用于外部来源、隐私和系统边界：它提示用户即将离开平台或正在阅读约束，因此不作为购买、保存或打印的默认主按钮色。
- 小青以今天页问题入口、页内批注和行前建议出现，不使用独立 AI Tab、功能墙或悬浮按钮。
- `G00` 材料册封面、`T01` 今日行程、`M01` 文档柜、`M13` 收据结算、`M14` 到机票券是五个视觉母版；账户、权益、助手和报告页已按同一语言单独构图。
- `D01` 使用公共服务目录与招聘会日程，`D03` 使用来源证据优先的岗位文章，`U01` 使用账户事实与分组服务清单，`A01` 使用行前批注而非聊天气泡，`A04` 使用证据报告而非仪表盘。
- 手机支付后仍只建立待到机订单；`M14` 明确说明到一体机核验后才创建打印任务。岗位、招聘会和政策仍只提供第三方或官方来源入口。

## Staff Designer 设计立场

非对称不是装饰手法，而是把业务判断直接写进比例、间距和字重：

- `T01` 常用动作采用 `1.42 / 1 / 0.92`，导入简历最大，因为它建立首个用户资产并开启诊断、材料包和打印链路；招聘会浏览最轻，因为它不应压过正在履约的任务。
- `D01` 不做四宫格，改为 `01–04` 左对齐目录；岗位信息行更高并带墨绿边线，因为它是最高频来源入口，招聘会、政策和机构保持次级扫描密度。
- `U01` 账户事实采用 `1.48 / 1 / 0.9`；进行中订单拥有最大数字和珊瑚边线，因为未完成履约比可用权益和未读消息更需要立即判断。
- `A04` 采用 `1.6 / 1` 的主从报告结构；最低的“证据 72”跨两行成为视觉锚点，结构和清晰度退为对照，因为报告的商业价值是指出下一次最该改什么，不是展示漂亮均分。
- 16px 页面边界保证 390px 视口下的触控和阅读密度；24px 以上数字只留给当前风险或核心凭证，普通状态回落到 17px，避免所有数据同声量。

## V5.1 账户页面族收口

V5.1 不改变 41 页矩阵，只修正账户页仍然偏“通用设置列表”的层级问题：

- `U02` 将当前待到机订单提升为履约主对象，筛选项改为自然宽度，历史订单保持次级密度。
- `U03` 把 7 天后到期的 2 页打印权益移到数字权益之前，并用大数字与珊瑚边线表达时间风险。
- `U04` 将到机码 18 小时有效期变成唯一高声量消息；报告生成和已退款消息分别回落为结果与历史状态。
- `U06` 分开身份事实、求职偏好和退出风险；偏好由通用输入框改为紧凑事实表，退出账号拥有独立危险边界。
- `U07` 改为 `01 授权边界 / 02 文件生命周期 / 03 个人信息权利` 三段账本；导出数据使用钴蓝边界，注销账号使用危险红，避免把可逆申请和不可逆动作等同处理。

本轮使用本地 Claude Code `2.1.222` 做独立页面构图审查。其“不同业务对象必须使用不同首屏构图”“避免卡片墙、渐变、大色块 Hero、重复圆角”“把截图标准量化”的意见被采用；其首轮误判 `M13/M14` 业务含义并建议天气、添加任务、字母索引、阅读数、分享和咨询等不存在内容，已被 Codex 明确驳回。Staff Designer 终审中，Claude 先误读 CSS 加载顺序，错误判断 `T01` 的非对称比例被覆盖；Codex 以 `index.html` 的真实顺序和浏览器截图驳回后，Claude 在修订轮撤销该问题，并确认四项非对称结构均在源码中成立。V5.1 聚焦审查中，Claude 对 `U03/U04/U06/U07` 的风险分层判断被采用；其把导出数据误读为金色的建议被驳回，因为源码中的钴蓝明确承担个人数据边界，注销才属于危险红。Claude CLI 仍无法解码 PNG，因此其结论只作为源码交叉审查，不冒充像素级视觉 `APPROVE`；最终视觉裁决与 41 页浏览器验收由 Codex 承担。

## V5.2 中段流程层级收口

V5.2 不增加任何页面、功能、入口、状态或数据，只修复进入简历与打印主链后仍然存在的通用模板感：

- `T02` 删除无法承载真实坐标的灰色地图占位，改为服务点名称、到机地址、楼层与服务时间组成的地址账本；用户先核对地点事实，再阅读设备能力。
- `M02` 删除正文与固定栏重复出现的“选择微信文件”，固定栏成为唯一主动作；正文只解释微信文件与三个既有备选来源。
- `M07` 将当前选中的打印友好单栏放大，紧凑双栏退为可比较备选；不再用平均双栏暗示两者同等适合当前内容。
- `M09` 把直接驱动报价与打印负荷的“10 总页数”设为主指标，文件数和总份数成为两个次级校验值。
- `A06` 保留横向 Offer 对比表与等宽优先级分段控件：并排字段比较和互斥模式选择是该页面的领域对象，不属于应被破坏的通用对称网格。

本轮再次调用本地 Claude Code `2.1.222` 做源码级只读复核。Claude 判定 `M02/M09` 必须修订，该意见被采用；它建议保留 `T02` 灰地图和 `M07` 等宽模板，Codex 未采用，因为灰块在真实截图中仍像未完成占位，当前选择与备选等宽也违反用户已经明确冻结的非对称层级标准。Claude 本轮只读输出未覆盖 `A06` 对应源文件，因此不伪造其批准；最终页面裁决继续以浏览器渲染证据为准。

### V6.0 UI Notes 行程办理系统（历史版本）

V6.0 参考 UI Notes 的[铁路 12306 确认订单时间层级](https://uinotes.com/pin/262160841776174587)，只采用“日期、地点、当前状态和下一动作属于同一个操作对象”的组织原则；不复制蓝色页面背景、圆角白卡、铁路品牌、交通图标、票据打孔或促销模块。医疗 AI 案例常见的蓝紫背景、服务宫格和大模型提问框会重新制造通用 AI 模板感，因此未作为主参考。

- `T01` 把最重要任务、18 小时内到机订单和后台生成报告放进一条办理主线；当前任务最大，有限时风险的订单次之，无需本人等待的后台任务最轻。
- `M14` 是到机办理票：手机已付款与一体机待核验构成跨端关系，到机码仍是唯一最大凭证；现场确认后才创建 `PrintTask` 的边界没有变化。
- `M15` 是履约进度单：宏观四阶段、当前印面和事件记录形成同一状态系统；“查看实时进度”接回当前订单，不再是无响应主按钮。
- `D04` 使用大日期锚点和活动事实，不使用站点圆点或线路轨道，避免把招聘会日程做成火车时刻表；官方/高校来源继续用绿色/钴蓝边界区分。
- `U02` 将当前办理订单做成唯一高声量行程，历史完成/退款记录压缩为凭证账本，不再让所有订单同等重要。

本轮调用本地 Claude Code `2.1.222` 做两次只读审查。首轮认可“已有履约链路显性化”的方向，并指出旧到机码仍残留车票打孔伪元素、`M15` 主按钮无目标以及 `D04` 不应使用站点圆点轨道；三项均已修正。第二轮终审运行约 11 分钟后仍无输出，已终止且不记录虚构的最终 `APPROVE`。Claude 无法替代浏览器进行像素裁决，最终视觉判断仍以真实截图和 41 页浏览器门禁为准。

### V6.0 验证结果（历史版本）

- 41 / 41 页面可渲染，逐页截图为 780 × 1688 像素，对应 390 × 844 双倍像素视口。
- 41 页文档级与元素级横向溢出均为 0，隐藏文字裁切为 0，可见渐变为 0。
- “今天 / 材料 / 发现 / 我的”四个 Tab 在四个主页面完全一致，没有 AI Tab。

- Node `v22.22.0` 下直接合规文案门禁（457 文件）、Prettier、JavaScript 语法与 `git diff --check` 均已通过；每次后续修改仍须重跑。

## 联合设计结论

本轮先由 Codex 盘点正式方案、当前代码事实与旧 56 页原型，再调用本地 Claude Code 进行独立页面矩阵审查。Claude 建议将首发收敛为约 27 个唯一页面，取消独立 AI Tab、AI 功能墙以及手机端 U 盘/扫描仪控制。Codex 在该结论上补齐正式方案要求但 Claude 初版遗漏的微信支付退款、权益、消息、反馈、隐私、模板生成、语音面试和低风险微应用，形成 41 个页面级原型。

41 页并不代表首发同时开发 41 个独立业务模块：其中 35 页属于 M0-M2 商用闭环，6 页是 M3-M4 的前置体验设计。筛选、协议、支付确认、退款原因、删除确认、订阅消息授权等均使用 Sheet / Modal，不再单独计页。

## 不独立成页的交互

- 用户协议、隐私政策摘要与版本化同意：登录页 Sheet；完整法律文本使用现有法律页面或 WebView。
- 短信验证码降级登录：登录页 Sheet。
- 列表筛选、排序、来源筛选：底部 Sheet。
- 文件删除、退出登录、注销确认：Modal。
- 微信支付确认与支付取消：微信原生支付面板 + 返回状态。
- 退款原因、反馈类型、订阅消息授权：Sheet。
- AI 页内建议：上下文操作条，不新增 AI 工具中心。
- 全局小青：默认半屏 Sheet，复杂任务才进入 A01 全屏态。

## 旧原型处理

- 保留并重构：首页、登录、打印下单主链、岗位/招聘会/政策、简历诊断优化、订单、消息、设置与隐私。
- 合并：旧“打印中心 + AI 中心”并入今天与材料；“我的简历 / 我的文档 / AI 记录”并入材料库及统一详情；打印完成并入订单详情。
- 删除：手机端 U 盘导入、远程扫描仪控制、扫码接力控制台、独立 AI 工具墙、假附近终端、假排队时间和假优先队列。
- 新增：规则优先今天页、统一材料包、Order-only 到机释放、真实退款状态、权益、反馈售后、服务机构、受控 AI 微应用。

## 开发使用边界

原型只确定信息架构、交互、文案和视觉优先级，不证明 API、支付、订阅消息、定位或硬件已经实现。开发必须按 Gate 0 和 M0-M4 分期，不得依据静态原型伪造数据闭环。
