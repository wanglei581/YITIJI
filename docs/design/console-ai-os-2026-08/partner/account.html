落地口径
  • 路由不变、不新建页：仍是 /account，把空态换成 3 个 Tab；原拟的 /tickets 并入第三个 Tab。
  • 服务端先行：User 需建机构内子角色；审计需建按 orgId 过滤的机构视图；通知与工单需先建模型。不得先做前端再补后端，否则又是空壳。
  • 红线：隐藏导航 ≠ 权限控制，所有可见性收窄必须有 API 与路由校验兜底。
  • 高风险操作（换绑 / 删号）建议保持平台侧执行，机构通过工单发起。
