但这一条不能照「线下机构档案」的方式修：线上平台目录是平台向求职者推荐第三方平台， 推荐权属于平台的编辑责任。该表字段本身就带治理意图—— operatorLegalName（运营方法定名称）、officialDomainsJson（官方域名白名单）、 evidenceFileId（资质证据）、neutralDescription（中立描述）。 最后这个命名说明设计上就要求平台保持中立。 若开放机构自助发布，任何机构都能把自己的平台塞进推荐位。 因此本 Tab 只能申请收录 / 提交更新；发布、排序、上下架由平台管理员掌握。

落地口径
  • 路由不变：仍是 /profile，加 4 个 Tab。原页 248 行，加 Tab 后建议按 Tab 拆子组件，主文件保持在 300 行内。
  • 线下机构档案：复用已有 OfflineAgencyProfile / OfflineAgencyBranch， 只需补 Partner 侧读写 API 与归属校验（orgId 必须等于当前登录机构），模型零改动。 开放对象限定为名下确有 offlineAgencyProfile 的机构。
  • 线上平台收录：Partner 侧只给「申请 / 提交更新」，不给发布、不给 displayOrder。 需新增申请态（或复用 reviewStatus），并新建 Admin 治理页（见 admin/online-platforms.html）—— 那是本轮唯一确实需要 Admin 新增的页面。 域名白名单与政策「官方入口」合并成一套机制，不要各写一份。
  • 资质：复用已有 QualificationRecord，补「机构提交 → 平台核验 → 到期降级」状态机。过期自动转不可见 + 通知，不静默下架。
  • 账单：必须等许可边界审查结论；前置是 AiUsageLedger + orgId。未就绪前本 Tab 显示「尚未开放」，不显示任何金额。
