双后台 AI 化改造 · 原型

管理员后台 · 合作机构后台 —— 在现有页面上改，不新建后台

前台已经是 AI 操作系统（30 个页面每一页都要回答「这里的 AI 是什么」）， 后台还是 表格管理系统（Admin 34 页 + Partner 13 页里，AI 只占 2 页且管不住全站）。

中间缺的不是「AI 中台」这个大架子，而是一层 AI 内核（ai-core）—— 把 contract-review 已经验证过的那套编排（脱敏 → 规则 → 模型 → 安全闸 → 落库 → 保留期） 从单个业务里抽出来，变成全站 AI 点共用的地基。地基铺完，Admin 才有东西可管，Partner 才有东西可卖。

运营大屏
一个引擎 + 四套视图（政务 / 运营 / 销售 / 机构），不是四块屏
产品所有者提出「要不要做数据大屏，数字孪生那种效果」。 结论：值得做，但不叫数字孪生——终端只有 locationLabel 文本没有经纬度、 全仓没有 WebSocket/SSE、心跳没有耗材余量数值、完全没有空间模型。 硬做只能买模板套假数据，而大屏是最容易被截图传播的界面。
做法：/screen?profile=gov|ops|sales|org 一个引擎 + Admin 一个配置页。 这是整个方案里唯一建议新建的页面——它塞不进任何现有页（分辨率/交互/鉴权/刷新四件事全不同）。
一期只上现有真实数据能撑起的 8 个模块；地图、实时推送、机构版按数据前置分二三期。 排期：上线后启动（产品所有者拍板）。

原型说明
  • 这不是新设计语言。色值全部取自 packages/ui/src/styles/inkpaper.css（墨绿 #10302b / 纸色 #f4f1e8 / 青玉 #1f9e86 / Noto Serif SC），侧栏 1:1 复刻现有 NAV_ITEMS。落地时改动直接落在现有组件上，本目录不进生产。

  • 数据均为示意。「未计量 / 合并计 / 按量·未估算 / 样本不足」是刻意保留的诚实标注，不是占位符。
