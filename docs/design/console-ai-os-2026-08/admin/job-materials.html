产品所有者 2026-08-11 决定：迎新板块只保留「证件与材料复印」这一个功能 （理由：其余五个候选功能全部依赖高校先录内容，没有客户就是空壳；而复印零依赖、全年可用、换到人社大厅同样成立）。 该功能的后台配置面应并进本页——本页管的就是「用户能打印什么材料」， 而材料清单与复印预设本就是一对：清单告诉用户要带什么，复印帮他现场补齐。

求职材料库

本页管终端上用户能生成或打印的材料。 内容模板 → 前台「AI简历服务」与「我的文档」； 复印预设 → 前台「打印扫描」的证件复印入口。

当前为 mock 模式（VITE_API_MODE 不等于 http），页面数据和未接后端的操作不会写入数据库。

新增 Tab · 模型是空壳，需先补后端 PrintMaterialPack 模型已存在但只有占位字段 （name / description / items JSON / priceCents / isActive / sortOrder）， 没有会员归属、文件条目、批次任务、订单或子任务关系； bundle_render 目前只返回 skeleton / queued:false，没有批量渲染执行器。

落地口径
  • 路由不变：仍是 /job-materials，加 2 个 Tab。不新建页—— 本页管的就是「用户能打印什么材料」，复印预设是同一件事。
  • 证件复印预设可先落地：PrintMaterialPack 够不着，但「单预设」不需要它—— 一个预设 = 一组扫描引导 + 一个排版规则 + 一次单文件打印，完全在现有单文件契约内。
  • 不得提供彩色 / 双面选项，直到真机验证通过（CLAUDE.md §3 明确区分「硬件能力」与「已验证的驱动控制」）。 证件照排版继续保持前台 disabled +「即将上线」。
  • 材料包要等后端：需 MaterialPackTask + MaterialPackItem 与多文件契约； 在那之前 Tab 显示「需后端先落地」，不放可点的假按钮。
  • 证件图像按敏感文件处理：签名 URL + TTL + 自动清理 + 访问审计（compliance-boundary.md）， 识别链路之外不留存。
  • 「材料清单」现有类型建议先启用：它不依赖任何校方接口，通用版即可上线， 且与复印预设天然配套——这是迎新场景零依赖能做的另一半。
