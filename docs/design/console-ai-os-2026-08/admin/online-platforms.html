本轮唯一确实需要 Admin 新增的页面 问题：OnlinePlatformDirectory 全局只有 2 处引用——Prisma client 与一处只读 service。 两个后台都没有写入口，数据只能靠 seed 或直接改库。 而终端「岗位信息 → 线上招聘平台」正在向求职者展示这份目录。

这是产品所有者 2026-08-11 指出「前端加了线上招聘平台和线下招聘公司」后核查发现的。 与「线下招聘公司」不同——那一条该开放给机构自助维护（数据是机构自己的门店档案）， 本页这一条不能：线上平台目录是平台向求职者推荐第三方平台，推荐权属于平台的编辑责任。

线上平台目录

本页决定终端向求职者推荐哪些第三方招聘平台，以及它们的展示顺序。 机构只能在合作机构后台 · 机构资料 · 线上平台收录提交申请； 是否收录、排在第几位，只在本页决定。

当前为 mock 模式（VITE_API_MODE 不等于 http），页面数据和未接后端的操作不会写入数据库。

为什么不开放给机构自助发布

OnlinePlatformDirectory 的字段本身就带治理意图：

operatorLegalName
运营方法定名称——不是品牌名，要能对上营业执照
officialDomainsJson
官方域名白名单——决定终端扫码跳到哪里
evidenceFileId
资质证据文件——私有存储，不对外
neutralDescription
中立描述——这个命名说明设计上就要求平台不做倾向性推荐
displayOrder
展示顺序——推荐位次
若开放机构自助发布：任何机构都能把自己的平台塞进推荐位， 目录立刻变成竞价位，neutralDescription 形同虚设。 且曝光位不得按曝光 / 按跳转计费（compliance-boundary.md §8.8.1 第二类，须先过许可边界审查）。

目录加载失败

无法读取（GET /admin/online-platforms 返回 500）。终端已收录的平台不受影响，仍按上次下发展示。

落地口径
  • 新建页面：/online-platforms，归入「数据内容」分组。 这是本轮审查中唯一确实需要 Admin 新增的页面——其余需求都能并进现有页的 Tab。
  • 模型零改动即可起步：OnlinePlatformDirectory 字段已齐（含 reviewStatus / publishStatus / displayOrder）。 需补的是 Admin 读写 API 与 Partner 侧的申请态。
  • 权责分离：Partner 只能申请 / 提交更新；收录、排序、上下架、中立描述定稿只在本页。 displayOrder 绝不下放。
  • 域名白名单与政策「官方入口」合并成一套机制——两处都决定用户从终端跳到哪里， 不要各写一份校验。百宝箱已有 ToolboxAllowedHost 可复用。
  • 驳回必须回传原因：修掉岗位/招聘会 rejectReason 不回传的同类问题，不要再复制一遍。
  • 计费红线：曝光位不得按曝光 / 按跳转计费；商业平台与官方平台不得按付费混排。
