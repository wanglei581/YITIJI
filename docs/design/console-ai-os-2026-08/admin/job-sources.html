这就是产品所有者点名「混乱」的那一组 原话：「岗位信息和数据内容里面的这些功能应该大概率是不匹配的，功能和接口都是混乱的，不知道哪个应该对接哪个。」
诊断属实。这一组 7 个页面（岗位信息源 / 招聘会信息源 / 政策信息源 / 招聘会管理 / 企业展示管理 / Excel导入记录 / 数据接入通道） 存在两处结构性错配： ① 「信息源」做审核、「管理」做内容，但界面上从不互相说明—— 运营点进「招聘会信息源」以为能改场次，点进「招聘会管理」又找不到审核按钮； ② Excel导入记录 与 数据接入通道 是同一件事的两半（都是「内容怎么进来」），却分成两个菜单项。
本页演示改法一：把职责和去向写在界面上。

岗位信息源

本页只做审核。通过并发布后，岗位会出现在一体机的 「岗位信息」列表与岗位详情页（前台 P13 / P14）。 要改岗位内容，请去 合作机构后台 · 岗位信息管理 或 数据接入通道。

为什么这句话必须写在界面上 产品所有者要求「要让客户知道每个功能是干什么的，对应的是前端用户界面里面的哪些页面哪些功能」。 做法不是写帮助文档，而是页头副标题做常驻文案：一句话说清 ① 本页管什么（只做审核）② 结果出现在前台哪里（P13/P14）③ 相邻职责在哪（改内容去哪）。 47 个后台页都要有这句话，文案清单见对应总表。

落地口径
  • 路由不变：仍是 /job-sources。核心改动是页头副标题的常驻文案与 AI 预审排序。
  • 风险详情进抽屉不进列：本表已 7 列，加长文本列会破坏可读性（Codex 复核）。

  • AI 不替人做审核决定：只给判断依据与排序，通过/驳回必须人工点击并落审计。
