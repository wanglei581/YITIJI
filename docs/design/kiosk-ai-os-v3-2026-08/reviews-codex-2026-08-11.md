## (c) 域首屏还是工作台

判断标准不是“所有入口都进 hub”，而是看入口有没有明确任务、有没有满足前置条件。

| 入口语义 | 应落点 |
|---|---|
| 只说域名：“打印扫描”“岗位信息”“政策服务” | 对应域首屏 |
| 来自首页主卡、全局导航、跨域泛入口 | 域首屏 |
| 已明确具体任务：“材料扫描”“文档打印”“文件转 PDF” | 对应子工作台第一个可操作步骤 |
| 已选中真实文件/产物，带稳定 `artifactId/version` | 可直达打印 s3 核价 |
| 已有打印订单，带 `orderId/jobId` | 可直达 s6 进度 |
| 缺少文件、对象 ID 或必要选择 | 不得跳过首步 |

具体定夺：

- 首页主“打印扫描”卡：P39，当前已经正确。
- 首页底部“打开打印扫描”：改为 P39。
- P25、P27 中仅写“打印扫描/打印、扫描”的入口：P39。
- P27“要打印、要出纸”：这是明确子任务，应进 P06 s1，不是 P39，也不是 s3。
- P39 七个子入口可以直接分流：
  - 文档打印 → P06 s1
  - 手机扫码上传 → P05 上传方向
  - 材料扫描 → P07 s1
  - 照片打印 → P06 s1，并预选照片来源；目标必须真实消费该参数
  - 证件照 → P29 当前可用/锁定首屏
  - 格式转换、签名盖章 → P08 对应首步
- 从扫描结果、简历结果、政策清单等点“打印这份”：只有产物已生成并带 ID 时才进 P06 s3；否则先选文件或生成产物。
- 同理，“岗位信息/招聘会/面试训练/政策服务/AI 简历服务”这种泛入口分别进 34/36/37/38/32；“看岗位详情”“看社会招聘会场次”“做面试练习”“核对补贴条件”“上传简历诊断”可直达子页。

## (f) 哪些空白语义正确

语义上正确、不应靠假内容填充的有：

- P08 t3：硬件/能力未开放。
- P27 s1：后台尚未批准任何扩展。
- P28 s4：按隐私规则不保存作答原文，不能伪造历史对比。
- P09 first、AI 降级、错误态：不能显示不存在的简历诊断结论。
- P04 错误、锁定、恢复中：没有实时结果时不能编造设备数据。

但这些只能说明“数据缺失是正确的”，不能说明当前 300–750px 的底部空洞就是正确版式。所有者的新要求下，上述状态应通过放大、居中、改单栏、展示真实原因和真实出口形成完整构图。

区分标准：

- 正确空态：明确说明为什么没有、不会出现什么、现在能做什么；主体居中且视觉面积足够。
- 版面缺陷：正常态也反复命中；内容只堆在顶部；`pane--grow` 只有外壳撑到底；切换状态后大块内容消失却没有重排。
- 状态漏配：主区可见文本叶子少于 6，属于 `data-when/data-at` 空壳问题，[audit-plus.js:599](/Users/wanglei/YITIJI-v3-round2/docs/design/kiosk-ai-os-v3-2026-08/scripts/audit-plus.js:599) 已有独立检测。
- 正确的“留白”应是围绕放大主体的均衡空间；内容结束后单侧裸露 300–750px，不属于正确留白。
