# 设计冻结版全量回归报告（2026-08-11）

> **结论：45 页 / 940 组合 / 823 条站内链接，全部检查项 0 缺陷。**
> 这是第一份**可复现**的全量回归 —— 驱动台在仓库里（`tools/regress.html`），
> 任何人按下面的环境重跑，应当得到同一份数字。

## 一、为什么这一份才算数

上一轮回归用的是「跑完就删」的临时驱动台，于是 Codex 终审给出
「候选稿在终审过程中仍在变化，当前不存在可复现的最终版」。

更糟的是，本轮开始时发现**此前的「0 缺陷」是假的**：
驱动台只统计顶层数字键，而 `v3AuditPlus()` 的「版面留白 / 内部裁切 /
联动接线 / 假入口 / 主区空壳 / 卡内溢出」是嵌套对象，
「违禁文案 / 量化红线 / 来源三字段缺」是数组 —— **全被跳过**。
修正后 04 那一屏立刻报出「右栏底部空 676px」。

同一天内**第二次**栽在同一件事上（上一次是 `stage.js` 的 `audit()` 忘了 `return`）。
所以本报告的第一条纪律是：**检测器自己必须被检测。**
本轮新加的每一项检查，都用「造一个真缺陷 → 必须报出来」验过。

## 二、怎么重跑

```
cd docs/design/kiosk-ai-os-v3-2026-08
sh tools/make-pages.sh              # 刷新页面清单，不跑会静默漏测新增页
python3 -m http.server 8899         # 必须走 http：file:// 下读不到子页 DOM
```
浏览器打开 `http://localhost:8899/tools/regress.html`，按「开始全量回归」。

**三个必须照做的环境条件**（不照做会量出不同结果，都是实打实踩过的坑）：

1. **浏览器标签必须在前台。** 后台标签会节流定时器，跑一半看起来像挂死。
2. **每页每轮清 `localStorage`。** `themes.html` 会把主题写进去，
   不清的话同一份代码会量出 0 / 44 / 68 三种不同的溢出值。驱动台已内置。
3. **关 HTTP 缓存。** 否则改完代码重跑，量的还是旧文件。

驱动台会逐页自验舞台：视口须 `1080×1920`、`capture=1` 下 `transform` 须为 `none`。
任何一页不满足就判装载失败，不拿失真的数去凑「跑过了」。
本次 45 页全部通过。

## 四、枚举口径（说清覆盖了什么、没覆盖什么）

**逐轴遍历，不是笛卡尔积。** 06 有 7 条附加轴，全交叉是 193 万组合；
抽 260 个只覆盖 0.013%，而其中绝大多数现实里不可能同时成立
（免费单 × 卡纸 × 正在选遮盖区）。一个覆盖率 0.013% 的报告写成「跑过了」，
比不跑更误导。

改成：其余轴保持页面默认值，一次只动一条轴，且**只在该轴真正起作用的阶段变化**
（判据是带这条轴的元素用 `data-at` 声明了哪些阶段）。于是能诚实地说：

- ✅ **每条轴的每个取值，都在四态 × 全阶段下跑过**
- ❌ **轴与轴的交叉只跑了默认组合** —— 这是本台子的已知边界，不是「全覆盖」

## 五、已知盲区（写在这里，不写在漂亮话里）

1. **交互驱动的文本态没有覆盖。** 像扫描格式（PDF / JPG / 可检索 PDF）、
   分辨率、彩色黑白，是页面局部脚本改**文字**而不是改可见性的。
   本台子靠枚举 `data-*` 轴驱动，够不到这一类。没跑过就是没跑过。
2. **链接只验了「目标页存在 + 阶段存在」，没验落地内容名副其实。**
   「点进去是不是这个链接承诺的东西」机器判不了，本轮靠 Codex 逐条人核
   （117 条错配，见 `reviews-codex-2026-08-11.md`）。
3. **动效与时序没有验。** 审计取的是某一帧的静态版面。
4. ~~只在 Chrome / `theme=warm` 下跑过~~ —— **已补跑：9 套主题各 940 组合，
   合计 8460 组合，全部 0 缺陷 0 console 错 0 死链**（`v3RunAll('', '<主题>')`）。
   值得跑是因为 `--fog-aNN` 那次事故就是主题相关的：26 个页面引用三个从未定义的变量，
   整条 background / border 声明作废；而 themes.css 里每套主题各自覆盖 `--surf-*` / `--brd-*`，
   **只在一套主题下跑等于只验了九分之一**。仍未覆盖：Chrome 以外的浏览器。

## 六、本轮修好的检测器盲区（三处，都验过没把检查关死）

| 盲区 | 后果 | 验法 |
| --- | --- | --- |
| 只统计顶层数字键 | 嵌套的留白 / 卡内溢出 / 假入口全漏，报「0 缺陷」 | 修正后 04 立刻报出右栏空 676px |
| 「按钮被遮挡」不分裁切类型 | 第一版 73 条全是误报；第二版矫枉过正，把首页那个真缺陷也放过 | 合成遮挡层报、复原首页旧 CSS 报「查看招聘会 被 .vbody 裁掉」、撤销后清 |
| 「卡内空洞」只看底边 | ①贴底的绝对定位页码让纸样永远读 0 ②居中构图被误判成没写完 | 造真空洞报；**给它加一个贴底页码仍然报**；居中构图撤掉豁免也不报 |

另清理了两类噪声：「联动接线·声明条数」是统计不是缺陷（曾误报 192 条）；
「疑似未登记的轴」按取值形态过滤后从几十条降到 0
（`个人简历.pdf`、`广州××科技`、`O-20260809-1023` 这类是内容不是轴）。
两处都验过没把告警关死：现造一个新属性照报不误。

## 七、声明式豁免

有些空是对的（等你落笔的手写板、短文档印在 A4 上的下半截、居中构图）。
这类用 `data-void-ok="理由"` 显式声明，**必须写理由，空值不算豁免**。
做成声明式而不是在工具里硬编码类名，是因为**例外应该被看见**：
改页面的人一眼能读到「这里为什么允许空」，不必去翻工具源码。

判豁免的每一处都留了实测自证，例如：
- 面试单：0 题→空 609、答 3 题→375、答满 8 题→分成 2 页且第 1 页只空 92
- 求职信：200 字档→547、300→500、500 字档→350
- 百宝箱「示意到此为止」：实测上留白 194px、下留白 194px 完全对称

**本轮明确拒绝过的一条捷径**：09 的纸样一直不报数，是因为纸底有 `bottom:22px`
的绝对定位页码。整改代理没有给其它页补假页码来消数，原话「**那是糊弄检查器**」——
反而由此暴露出上表第三条盲区。
