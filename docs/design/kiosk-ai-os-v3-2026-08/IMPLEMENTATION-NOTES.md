# 从这批原型建生产页时的须知

写给**照着 `docs/design/kiosk-ai-os-v3-2026-08/` 建真实页面的人**。

这里只写「照着原型做会踩、但原型本身看不出来」的东西。
页面长什么样看原型就行,不用读这份。

---

## 一、最要紧的一条:原型即规范,包括它的缺点

终审(`final-audit-2026-08-09.md`)测出:被测到的 10 页**每一页**都有
964–1389px 的主栏底部空白。内容区总高 1728px —— 也就是 **55%–80% 的一栏是空的**。

这不是个别页面没写完,是整批页面的共同写法:**内容按「最小可行」写,
不按屏幕高度写**。

> **建生产页时不要原样继承这个。**
> 原型的目的是说清交互和口径,不是给出最终的内容密度。
> 照抄一个空了 60% 的栏,用户会以为页面没加载完。

怎么办:每个栏建完后,在 1080×1920 下看一眼底部。空得多就补内容 ——
但**补的必须是真有用的东西**,不是填充物。判断标准见下一条。

### 什么算「真有用」

做这批页面时的实际经验,按价值从高到低:

1. **反向说明** —— 「哪些**不**跟着账号走」「本机**比不了**的三件」
   「这个月**不用**做的」。比正向罗列信息量更大,且用户更需要。
2. **可行动的下一步** —— 「还没答的 4 道题」放在「继续答」按钮旁边。
3. **依据与边界** —— 「这 80 家我读到什么程度」「这些数字是什么」。
4. **常见的坑** —— 「校招常见的三个坑」「政策类的三个坑」。
   公共场所面对找工作的人,防骗信息比功能介绍实用。

**不算有用的**:重复左栏已有的内容、把一句话拆成三行、装饰性图形、
「小贴士」这类泛泛而谈。

### 但也不要把数字压到 0

同样 500px,在**撑到栏底的卡片里**是呼吸感,在**没有容器的背景上**是没写完 ——
数值一样,观感天差地别。检测器分不出来,眼睛能。

反例:P19 智慧校园里保留了 568–685px 不修 —— 那两屏是「尚未接入的功能」的预览,
再往里填就是编造更多不存在的东西,正是那一页反对的事。

## 二、四个组件语义陷阱

这批原型复用了既有 CSS 层的类名。以下四个**名字和实际语义不一致**,
按字面理解会直接把布局做塌:

| 类名 | 你以为 | 实际是 |
|---|---|---|
| `.dir-lead` | 内容容器 | **`height:1px` 的虚线引导线**(目录里名称与页码之间那条点线) |
| `.dir-row` | 通用行 | **单行**目录行:`align-items:center`,子元素全 `flex:0 0 auto`,套多行卡片必塌 |
| `.tl` | 时间轴容器 | **它本身就是一步**(左圆点 + `::before` 画连接线);容器是 `.tline`,而 `.tl-s` 是副文不是步骤 |
| `.chk` | 复选框 | **带图标的清单行容器**;复选框视觉是 `.ck-box`(22px 方块 div) |

另外:`.jobrow` 和 `.ck` 家族**只在 11 页、12 页页内定义过**,公共层没有 ——
新页面要自带一份。

## 三、两个会把布局做塌的写法

### 3.1 `<a>` 不能嵌套 `<a>`

首页功能卡整卡是 `<a class="card">`,里面的 pill 如果也用 `<a>`,
**浏览器会重构 DOM** —— 实测 pill 宽度从 88px 变成 348px,
把页面底部的合规文字挤出视口。

正确写法:`span[role="button"][data-href]` + JS 绑定并 `stopPropagation()`。

同一处还踩过三次:`::before` 撑 48px 热区、`min-height:34px`、`padding-left:12px`
—— 三种都把 pill 顶大、把卡片顶高,进而把底部的
「费用以现场公示价为准」「离场自动清空会话」挤出屏幕。

**首页版面已排满,任何增高增宽都会从底部挤掉东西,而挤掉的恰恰是合规必读文字。**
可点性只能靠**不占空间的信号**表达:光标、悬停底色、按压缩放、下划线。

### 3.2 flex 列里的卡片会被压扁

flex 子项默认 `flex-shrink:1`。内容超过容器高度时,**卡片被压扁而不是撑开**,
文字直接画到下一张卡上(P05 实测溢出 9–19px)。

修法:给卡片 `flex:0 0 auto`。

**这类溢出自检抓不到** —— 卡片没有 `overflow:hidden`,不算裁切容器,
文字不是被裁掉是**画在了别人身上**。视觉上比裁切更糟(两段字叠着都读不清)。
`audit-plus` v13 为此加了「卡内溢出」这一项。

## 四、状态标签 vs 入口,必须在代码里分开

自检会把「长得像 chip/tag、但点不了」的元素报为**假入口**。

处理口径:**在类名里写明它是什么**,不要改检测器。

- 状态标签(「12 家来源」「已同步」「本周 3 场」)→ 类名带
  `info` / `status` / `state` 等词,自检自动放行。已有先例:
  `chip--info`、`.rev-tag-status`、`.pol-verdict-status`、`.mb-tag-status`。
- 真入口(标签名指向一个**去处**,如「U盘」「手机扫码传」)→ **做成真的可点**。

> **不能一刀切改名。**
> 曾想把检测改成「有可点祖先就放行」,但那会掩盖首页那三个 pill 的真缺陷 ——
> 它们在可点的整卡里、有可点祖先,可**标签名指向的是另一个功能,点了却去了整卡的目的地**。
> 失败模式不只是「点了没反应」,还有「发生的事和标签承诺的不一样」。

## 五、这台机器在公共场所 —— 三条贯穿全套的判断

原型里反复出现,建页时不要当成文案润色删掉:

1. **语音是可选项,不是默认。** 让人站在大厅里对着屏幕念
   「我专科学历是不是没戏」不现实。默认打字,并**在选语音之前**
   就写明「你说话周围的人能听见」。(P20 面试练习、P25 顾问)
2. **敏感输入尽量挪离公共屏幕。** 手机号在大屏上输,旁边人能看见 ——
   所以身份验证优先走手机扫码,号码中段打码,并直接告诉用户
   「周围有人的话,扫码比输号码稳妥」。(P03 身份门、P05 手机接力)
3. **离场清空是功能不是限制。** 要说清**什么会留下、什么会清掉**,
   而不是只说「会清空」。P23 用「会留下 / 会清掉」两栏对照直接回答。

## 六、诚实口径:哪些话不能说

全套页面共用,已在多处 verify 与合规检查里固化,建页时不要放松:

- **不预测**录用结果、通过率、薪资。P22 职业规划因此只用
  「本机在这批岗位里见到 N 条」这种**可核对的计数**说话,不说「前景好」。
- **不做资格认定**。政策页判不了的条件就**不给结论**,直接写
  「不猜比猜错强」,并说明最终以经办机构为准。
- **没出处的结论当场标为参考**。P25/P26 的每条回答尽量带出处;
  没有的明写「这条算参考,本机没有你所在行业的具体数据」。
- **不替用户编事实**。填槽型里数字、公司名、时间、离职原因一律留空:
  「编出来你面试时答不上,比空着更糟」。
- **办不了就说办不了,不做灰色按钮**。P23 的「导出数据」「注销账号」
  直接写明为什么办不了 —— 灰按钮会让人以为「点了没反应」。
- **允许否定式声明**。「本机不代收简历」「不预测录用概率」这类合规披露
  必须能写,否则页面会被逼着回避这些词、反而说不清边界。
  违禁词检查要能识别否定语境。

## 七、自检工具

`scripts/audit-plus.js`(v13,六项):
内部裁切 / 联动接线 / 假入口 / 版面留白 / 主区空壳 / 卡内溢出。

跑法:浏览器里遍历**四态 × 全部阶段**的所有组合,每次
`v3ApplyVisibility()` 后调 `v3AuditPlus()`。视口 **1080×1920 真实尺寸**。

### 两个已知局限,别当成通过

1. **没有 `.wmain` / `.wside` 骨架的页面**(P02 待机、P03 身份门、P05 手机接力),
   「版面留白 / 主区空壳」两项会**静默跳过**。
2. **视口不够大时 `stage.js` 会缩放画布**,测出来的尺寸是缩放后的 ——
   曾因此误报「60 个触控目标小于 48px」。测之前先确认缩放系数接近 1.0。

### 检测器为什么长这样

六项里有四项是被真缺陷逼出来的,不是设计出来的:

| 项 | 因什么加的 |
|---|---|
| 假入口 | 首页三个 pill 看着能点、实际点不了 |
| 版面留白 | P17 初版 16 个状态组合全绿,页面中间却空 900px |
| 主区空壳 | P22 `device-off` 态下整栏空白(状态门控漏配) |
| 卡内溢出 | P05 flex 子项被压扁,文字画到下一张卡上 |

「版面留白」中途还修过一次**假通过**:初版量所有元素的底边,
而 `.pane--grow` 会自动撑到栏底 —— 于是「把 pane 改成撑高」
就能让检测永远通过,哪怕里面是空的。改为只量叶子节点后,
立刻抓出 P18 的 488–781px(而当时已准备按「12 组合全通过」交付)。

**教训:一个只会报绿的检测器比没有检测器更危险。**
