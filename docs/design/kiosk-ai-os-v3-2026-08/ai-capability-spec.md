# AI 能力接线清单(交 Codex 开发用)

> 2026-08-10。**分工**:Claude 把 AI 设计进页面并定义契约;**Codex 按本清单开发实现前后端对接**。
> 背景:线上 78 屏原型**没有设计过 AI**,所以生产代码里没有这些能力。本清单是新增部分的实施依据。
> 全量审计(46 个业务页)结论:**40 页有 AI,36 页设计到位,假 AI 0 页**;6 页无 AI(5 页已写明理由)。
> 相关文档:`interface-handoff.md`(接口契约)、`step-reduction.md`(步骤压缩账)、`closed-loop-map.md`(AI 覆盖矩阵)。

## 0. 通用规则(每个 AI 能力都适用)

| 规则 | 要求 |
| --- | --- |
| **输入门** | 缺必需输入时**不出结论**,前端已做 first 态硬拦(如「还没有简历,无法逐条比对」「猜一个顺序会让你白跑」)。后端同样不得在缺参时返回兜底内容。 |
| **证据分级** | 每条结论标 E1(用户材料)/E2(来源方或系统事实)/E3(模型判断)。**E3 必须带「仅供参考」**。确定性逻辑(计数、排序、映射)**不得标 E3**。 |
| **AIGC 标识** | 模型生成的内容与其打印件必须带可见标识 + 文件元数据标识,每页恰好一次。 |
| **降级** | AI 不可用时:①不给兜底猜测 ②撤下结论但保留用户自己的东西(原文、已答、已上传)③给至少一条仍可用的替代路径 ④**打印件也要随之改名与改口径**(不能印着「根据你的简历生成」)。 |
| **红线** | 禁百分比、录用概率、通过率、打分排名;不预测薪资;不替用户决定投不投;法律与政策原文不得改写。 |

## 2. 明确**不接 AI** 的地方(接线时不要加)

| 页/区域 | 为什么 |
| --- | --- |
| P06 收银与核价、P41 支付履约八态 | 钱只能由支付回执与出纸计数决定 |
| P40 会话安全六态 | 超时、锁屏、接管、清空是安全判定,模型判断有害 |
| P42 打印订单栏 | 金额、页数、支付状态、取件码是订单原文,不做加工 |
| P45 现场数据、P19/P46 校园数据 | 只读事实;无数据时诚实空态,不编分布 |
| P21 法条原文、P31 合同原文 | 法律文本一字不改 |
| P35 线上平台目录 | 四家平台不排名、不比较 |
| P03 身份门 | 只做手机号验证与回跳 |
