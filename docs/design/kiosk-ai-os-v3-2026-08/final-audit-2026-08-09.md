## 二、三个结论

### 1. 结构是干净的

**内部裁切 0 · 主区空壳 0 · 卡内溢出 0，无一例外。**

这三项覆盖的是"内容被挤出去看不见""某个状态整块没配内容""文字画到别的卡上"——
全套 26 页一个都没有。这说明这批页面的骨架和状态门控是可靠的。

### 2. 假入口集中在五页，共 156 处（按组合累计）

集中在 12、13、14、15、16 —— 都是**长得像 chip/tag、但既不是链接也不是按钮、
且没有 cursor:pointer** 的元素。

绝大多数应该是**状态标签**（"已导入""待审核""官方来源"这类），不是真缺陷。
**处理方式已有先例，不要改检测器**：

- P17 的场次状态 → `chip--info`
- P20 的点评结论 → `.rev-tag-status`
- P21 的政策判定 → `.pol-verdict-status`
- P26 的作业型标识 → `.mb-tag-status` / `.ci-tag-status`

即在类名里写明它是状态而非入口。**不能为了让数字归零去放宽检测器** ——
放宽一格就会掩盖「标签名指向另一个功能、点了却去了别处」那类真缺陷
（P01 的「U盘」pill 就是这一类，当初花了四次才修对）。

### 3. 版面留白是系统性的，且比想象严重

**被测到的 10 页，每一页都有 964–1389px 的主栏底部空白。**

内容区总高 1728px。也就是说这些页面有 **55%–80% 的一栏是空的**。

这不是个别页面没写完，是**整批页面的共同写法**：内容按"最小可行"写，
不按屏幕高度写。之前用旧检测器测这批页面得到的是"零缺陷"——
那个结论是用只查一个方向（内容被挤出去）的工具得出的，不成立。

已在 P09 上做过肉眼复核：右栏在全部 20 个状态组合里都空 920–1346px，
是**没有容器的背景空洞**，不是卡片内的呼吸感。

## 三、要注意的两条口径

### 留白是烟雾报警器，不是判决

同样 500px，在撑到栏底的卡片里是呼吸感，在没有容器的背景上是没写完 ——
数值一样，观感天差地别，检测器分不出来，眼睛能。

所以上表的数字**只用来定位该看哪一页**，改不改要人看过再定。
**不要为了把数字压到 0 塞填充物，那比留白更糟。**

反过来也成立：我在 P19 智慧校园里保留了 568–685px 不修，因为那两屏是
"尚未接入的功能"的预览，再往里填就是编造更多不存在的东西 ——
正是那一页反对的事。

### 三页存在检测盲区

P02 待机屏、P03 身份门、P05 手机接力**没有 `.wmain` / `.wside` 骨架**，
「版面留白 / 主区空壳」两项会**静默跳过** —— 是假通过，不是真通过。

已在各页注释中写明，并改用整屏底部空隙、卡内溢出等替代量法人工核。

## 五、检测器本身

audit-plus 从 1 项长到 6 项，每一项都是被一个真缺陷逼出来的：

| 检测项 | 因什么加的 |
|---|---|
| 内部裁切 | 原有 |
| 联动接线 | 原有 |
| 假入口 | P01 三个 pill 看着能点、实际点不了 |
| 版面留白 | P17 初版 16 组合全绿，中间却空 900px |
| 主区空壳 | P22 `device-off` 态下整栏空白（门控漏配） |
| 卡内溢出 | P05 flex 子项被压扁，文字画到下一张卡上（主检测器完全看不见） |

其中「版面留白」中途修过一次假通过：初版量所有元素的底边，
而 `.pane--grow` 会自动撑到栏底 —— 于是"把 pane 改成撑高"就能让检测永远通过，
哪怕里面是空的。改为只量叶子节点后，立刻抓出 P18 的 488–781px
（当时我已准备按"12 组合全通过"交付）。

「假入口」则始终**没有为页面放宽**。曾想改成"有可点祖先就放行"，
但那会掩盖 P01 那类"标签指向另一个功能、点了却去别处"的真缺陷 —— 作罢。
