# V3 设计 → 生产接口对接契约

> 2026-08-10 起草。**用途**:Claude 交付设计稿,Codex 按本文件把每屏接到现有 API。
> 设计稿是静态 HTML,不含后端;本文件把「每屏收什么输入、产出什么、交给谁」写成可实现的契约。
> 生产路由与页面对照见 `closed-loop-map.md §七`;红线见 `docs/compliance/compliance-boundary.md`。

## 0. 三条全局契约

**① 四态由服务端/探测结果驱动,不由前端猜**

| 态 | 触发条件 | 前端行为 |
| --- | --- | --- |
| `default` | 会话正常 + AI 可用 + 设备能力已确认 | 全功能 |
| `first` | 未登录 / 无历史记录 | 不显示任何个性化数字,改功能说明式文案 |
| `ai-down` | AI Provider 健康检查失败或降级 | AI 结论区不出内容(不给兜底猜测),非 AI 能力保持可用 |
| `device-off` | Terminal Agent 心跳缺失 / 打印扫描能力探测失败 | 出纸类动作禁用并改「存我的文档 · 扫码带走」 |

**关键**:`ai-down` ≠ `device-off`。AI 挂了不影响出纸;打印机离线不影响 AI 生成。生产上 `ResumeServiceHubPage` 现用 `useApiReadiness` 一挂全挂——**这条与设计口径冲突,需要裁决**(见 §5)。

**② 能力探测 fail-closed**:读不到能力配置时显示「服务状态无法确认 · 暂不开放任务 · 重新检测」,**不得默认设备正常**(P39 已按此还原线上行为)。

**③ 打印是唯一出纸通道**:任何页面的打印动作都跳 `06-print-workbench.html?stage=s3`(生产 `/print/upload`),携带材料载荷(见 §2),价格一律「预估 · 以打印工作台核价为准」,金额只在打印台产生。

## 1. 每屏输入契约(Codex 接线时按此采集)

> 「必需」= 缺了就不能出结论,前端应门控;「可选」= 缺了降级但仍可出。

| 屏 | 功能 | 必需输入 | 可选输入 | 输入来源 |
| --- | --- | --- | --- | --- |
| P36 / P17 | 招聘会参会规划 | **城市**(默认本机所在城市,可改;**不使用 GPS**,一体机无定位权限)、**日期范围** | 岗位方向(从简历带入)、到场时段、可停留时长 | 本机配置 + 用户选择 + 简历解析结果 |
| P37 / P20 | 面试出题与点评 | **岗位方向**、**难度档** | 题量、作答方式(打字/语音)、具体 JD 文本 | 收藏岗位 / 浏览记录 / 手选 |
| P38 / P21 | 政策条件核对 | **适用城市**、身份、参保状态、**是否已办失业登记**、**社保连续缴费月数**、**毕业年份** | 离职原因、是否领过同类补贴 | 全部用户选择,允许「不确定」→ 结论标「待确认」 |
| P28 | 自我评估 | **必勾同意项**、25 题作答 | 可选同意项 | 用户 |
| P09 | 简历诊断/优化 | **简历文件**(上传/扫码/扫描/U盘) | **目标岗位**(缺则不给「按岗位」类改写理由) | 用户 + 岗位收藏 |
| P11 / P30 | 岗位匹配 | **简历** + **目标岗位(1–3 个)** | 手输 JD 文本 | 收藏/浏览记录/手输 |
| P12 | 求职材料生成 | **简历** + **目标岗位** | 语气、字数、是否写抬头 | 同上 |
| P06 | 打印 | **文件** + 份数 + 黑白/彩色 + 单双面 | 页码范围、缩放、方向 | 用户;非 A4 需确认缩放 |
| P07 | 扫描 | **原件放置确认** + 输出格式 | dpi、色彩、单双面、送稿器 | 用户 |
| P29 | 证件照 | **照片** + 规格 + 底色 | 目标简历(用于替换照片) | 用户 + 我的简历 |
| P31 | 签约风险 | **合同文件** + **合同类型**(含 `generic` 通用) + **五项知情同意全勾** | — | 用户;同意未全勾必须门控 |
| P13 | 岗位检索 | — | 关键词、25 项筛选 | 用户(需软键盘) |

**软键盘**:一体机无物理键盘,任何文本输入必须走屏幕键盘组件(`scripts/keypad.js`)。生产接线时同样要保证输入法可用。

## 2. 材料交接契约(跨屏带走)

任何「去打印 / 存我的文档 / 扫码带走」出口,按钮上必须显示**本次带去什么**,并传递载荷:

```
payload = {
  source: 'resume-report' | 'policy-checklist' | 'interview-sheet' | 'fair-plan' | 'jobfit-report' | 'contract-report' | 'id-photo-sheet',
  title:  '诊断报告',        // 用户可读名
  files:  [{ name, pages }], // 页数用于预估
  pages:  3,                 // 合计
  fromScreen: 'P09-s5'
}
```

- 打印台在参数阶段顶部显示**来源回执**:「本次来自:简历工作台 · 诊断报告 · 3 页」,让用户确认是不是这份。
- `device-off` 时统一降级为「存我的文档 · 扫码带走」并生成真实取回码(设计稿画的是示意码)。
- 记录去向:我的文档(短期)+ 打印订单 + AI 服务记录(若产物由 AI 生成)。

## 2A. 资产契约(Codex 闭环验收 P0 第 1/2 条,**接线时必须先做这个**)

设计稿只能传展示参数(`title/pages`),这在原型里够用,**但生产上必须换成不可伪造的资产 ID**。Codex 的原话是:"任何页面都能制造『已送达』回执而无需真实文件"。

```
artifact = {
  id:        'art_...',        // 服务端生成,唯一
  kind:      'resume-report' | 'policy-checklist' | ...,
  ownerId:   '...',            // 只有本人可读
  files:     [{ id, name, pages, bytes, sha256 }],
  createdAt, expiresAt,        // 按 §2B 保留策略
  sourcePage:'P21'
}
```

接线规则:
1. **产物先落地再开放出口**:诊断报告/办事清单/复盘单/参会作战单/证件照排版,必须先生成并保存资产,拿到 `artifactId` 才点亮"去打印 / 存我的文档"按钮。
2. **打印台按 ID 查**:`06` 收到 `artifactId` 后向服务端查询真实文件与页数渲染回执;**查不到就回到第 1 步选文件**,不得凭 URL 文案显示"已送达"。
3. **同一资产被三处引用**:打印台、我的文档、打印订单引用同一个 `artifactId`,不得各存各的副本。
4. **无资产直达**:`06` 无参数进入时默认落在选文件步骤,不显示任何来源回执。
5. **来源感知返回**:共享页(`06/07/08/09/11/12/18/22`)按 `from` 参数决定返回去处;缺失时回退到该页默认父级。
   - 2026-08-10 补 `09`:P07 扫描台发的 `?stage=s2&from=P07&src=scan` 此前无人消费,返回键写死回 AI 简历服务,扫描线索断在这里。现按同一份域登记表改指来源域,并补一个「简历首页」次要入口。
   - `?src=` 只用来渲染**来源回执**(`scan|phone|local|usb`),不得据此改写本机对文件的读数(页数、文件名一律以服务端/本机体检为准)。
6. **`?view=` 落区参数**:`23-me.html?view=resume|docs|orders|favorites|ai|benefits|notice|settings` 定位到对应功能卡。
   设计稿只做**定位**(高亮 + 顶部一行来源回执),**不得据 URL 显示「已保存成功」**——保存结果必须由文档/订单列表接口回答(见 §2A 第 2 条)。

## 2B. 文件保留策略(全站唯一口径)

| 文件类型 | 保留 | 说明 |
| --- | --- | --- |
| 敏感文件(证件照、身份证复印件、含身份证号的扫描件) | **7 天** | 到期物理删除并留删除日志 |
| 一般文档(简历、求职材料、扫描件、生成产物) | **90 天** | 到期自动清理 |
| 未登录的本次会话文件 | **离场即清** | 不进入长期存储 |
| 面试练习作答 | **从不保存** | 只记「练过一次」,不留内容 |
| 待打印订单里的文件(已下单未出纸 / 已支付可复打) | **7 天** | **订单口径**,不是文件保存期:取件码 7 天说的是「还能不能复打」。同一份文件另存进「我的文档」时,按上面的类型算 |

单个功能**可以定得更短,不许更长**。已知两处更短:自我评估结果 **24 小时**(可随时撤回,撤回即物理删除,P28)、合同分析文件 **2 小时**(打印完成或离场立即删除,P31)。

页面上写保留期限时必须按类型写,不得笼统说"所有文件 90 天"或"24 小时"。

> `01-home.html`、`01-home-v4.html` 是 `compare.html` 里的甲 / 乙历史比稿,**刻意不同步**,不作为线上文案来源。
> 用户可见的基准表在 P23「我的 · 账号设置 · 文件保存期限」,本节与它逐行对齐。

## 3. 证据分级契约(E1/E2/E3)

前端每条结论必须带级别,后端返回时应一并给出依据字段:

| 级别 | 含义 | 后端应返回 |
| --- | --- | --- |
| E1 | 用户自己的材料事实 | 原文摘录 + 位置(页码/字段) |
| E2 | 系统/来源方事实 | 来源机构 + 同步时间 + 外部ID |
| E3 | AI 判断 | 必须带「仅供参考」,禁止百分比/录用概率/通过率 |

**AIGC 标识**:所有 AI 生成内容(含打印件)必须带可见标识与文件元数据标识,每页恰好一次。

## 4. 降级契约(ai-down / device-off 时页面怎么写)

- **不得留空**:AI 结论区撤下后,必须补等量的真实内容 + 「为什么没有」一句 + **至少一个仍可用的动作**。
- **不得自相矛盾**:同屏不能一边写「本次不做条件核对」,一边显示逐条核对结论(已在 P20/P21/P22 修复)。
- **保留用户自己的东西**:AI 挂了,用户已答的原文、已上传的文件、已有的记录照常显示(E1 不依赖 AI)。
- **每个(阶段 × 态)组合可见区内至少 1 个前进动作**(返回与全局导航不算)。

## 4A. AI 输出异常与争议契约(Codex 最终审查 B 类:原契约只覆盖「模型不可用」)

`ai-down` 只是**模型调不通**。以下几种「模型通了但输出不能用」的情况必须各有屏与出路:

| 情形 | 前端行为 | 用户出路 |
| --- | --- | --- |
| 输出被安全策略拦截(敏感/歧视/违法内容) | 不展示原始输出,显示「这次的内容没有通过安全检查,不会给你看」 | 改输入重试 / 报告问题 / 找人工 |
| 事实明显错误(引用了不存在的条文、算错数) | 不做静默修正 | 报告问题(记录 traceId)/ 改输入重生成 / 以原文为准 |
| 用户质疑输出(「这不对」) | 提供争议入口,不与用户辩论 | 报告问题 / 找人工 / 打印原文自行核对 |
| 涉及自伤或紧急风险的表达 | 停止常规流程 | 显示公开求助渠道(按站点配置下发),并提示现场服务台 |
| 超时/部分生成 | 明示「只生成了一部分」 | 继续等待 / 用已生成部分 / 重新生成 |

硬线:**任何一种都不得把"没生成出来"渲染成"生成完了但内容为空"**;报告问题必须留下可追溯标识(traceId + 时间),但不得回传用户原文之外的内容。

## 4B. 边界值契约(Codex D 类:工程自己决定不了的)

| 输入 | 下限 | 上限 | 非法输入怎么办 |
| --- | --- | --- | --- |
| 打印份数 | 1 | 99 | 越界即钳制并提示;0 与负数视为 1 |
| 页码范围 | 1 | 文档总页数 | 全无效→提示并回退全选;倒序(9-3)→归一化为 3-9;重复/交叉(1-5,3-7)→合并为 1-7 |
| 单次任务页数 | 1 | 200(超出需二次确认并提示费用) | 超上限不静默截断,明确拒绝并给替代(分批) |
| 上传文件 | — | 单份 20MB / 单次 20 份 | 超限逐份标红,不整批失败 |
| 合同文本 | — | 20MB / 100 页 | 超出明确拒绝并说明原因 |
| 手输 JD | — | 2000 字 | 实时计数,超出禁止提交而非截断 |

## 4C. 站点配置模型(禁止把示例值当上线值)

设计稿里写死的这些**必须来自站点配置**,缺配置时显示替代渠道而不是示例值:
`serviceDeskLocation`(服务台位置)、`serviceHours`(服务时间)、`supportPhone`(客服电话)、`venueName`(场馆)、`terminalNo`(终端编号)、`cityCode`(本机所在城市)、`officialSiteUrl` / `hotline`(政策官方渠道)。
缺任一项时的兜底文案:「本机未配置<该项>,请到现场服务台咨询」——**不得沿用设计稿里的示例值上线**。

## 4D. 信息架构裁决(2026-08-10,产品所有者拍板)

`closed-loop-map.md` 早期写「不新增功能菜单页 · 首页直达作业台」,与当前「首页八磁贴 → 六域首屏 → 子功能页」冲突。
**裁决:保留域首屏。** 理由:线上生产本就有 `/print-scan`、`/resume-service`、`/jobs-service`、`/fairs-service`、`/interview-service`、`/policy-service` 六个 Hub;产品所有者明确要求「每个功能进去要能看到该域的全部子功能」。
早期那条口径作废,`closed-loop-map.md` 已同步。工程按域首屏实施,不再二选一。
