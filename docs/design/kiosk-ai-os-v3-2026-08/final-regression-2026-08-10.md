## 一、跑法与口径

**驱动方式**（任务书给定，未改动 `scripts/stage.js` 任何既有逻辑，只读）：

```js
screen.setAttribute(axis, value)   // 逐条轴设值
window.v3ApplyVisibility()         // stage.js 的四态/阶段合并判定
void document.body.offsetHeight    // 强制重排，避免量到上一帧
window.v3AuditPlus()               // audit-plus.js 合并 stage.js 的九项基础自检
```

**跑法**：临时驱动台（同目录 `_regress.html`，**跑完已删除**）把每页 `fetch` 成源码，
在 `<head>` 后注入 console/error 钩子再 `document.write` 进 iframe ——
这样能抓到**加载期**的报错（iframe 的 `load` 事件已经太晚，P21 那条就是这么抓到的），
再用 `history.replaceState` 把 `location.search` 补回去，以便测 `?view=` / `?from=` 这类参数页。

**组合策略**（不穷举笛卡尔积，但每条轴都覆盖到）：

| 轮次 | 内容 |
| --- | --- |
| Pass A | 四态 × 该页**全部**阶段值，全交叉 |
| Pass B | 其余每条轴的**每个取值** × 四态，落在该轴「活跃」的阶段（活跃 = 带该轴门控的元素所在的 `data-at`） |

**轴发现**（不靠人工列举，避免漏轴）：读 `.screen` 的**运行时**属性（含页面脚本自己加上去的）
＋ `[data-X]` / `[data-X-go|btn|when]` 的取值 ＋ 样式表里 `[data-X="v"]` 选择器命中的取值。
全站盘点结果：**页级轴只有四页有额外的**——

| 页 | 额外轴（`.screen` 上） |
| --- | --- |
| P06 打印工作台 | `data-src` `data-file` `data-pay` `data-job` `data-off` `data-done` |
| P09 简历工作台 | `data-src` `data-file` `data-job` |
| P39 打印扫描域首屏 | `data-probe` |
| 其余 35 页 | 仅 `data-state` + `data-stage` |

其它 `data-cap` / `data-tri` / `data-opts` / `data-spot` / `data-tpl` 等都挂在**部件内部**，
不是屏级状态轴，`screen.setAttribute` 驱动不到它们，也不该驱动 —— 已逐页确认，不是漏跑。

**跳过的两页**：`01-home.html`（甲 · 玻璃卡片版）、`01-home-v4.html`（乙 · 印务台版）。
两页是 `compare.html` 里的**历史比稿快照**，只用于视觉方向对比，不是线上页面；
基线首页是 `01-home-v5.html`（丙）与 `01-home-v6.html`（丁），两者都跑了。

## 四、仍然存在、但判定为「不修」的项（附测量证据）

### 1. P05 手机接力：9 个组合没有前进主操作 —— **按设计如此**

`interface-handoff.md §4` 要求「每个（阶段 × 态）组合可见区内至少 1 个前进动作」。
P05 的 9 个组合为 0，逐个看过：

| 组合 | 可见按钮 | 为什么不该有「前进」 |
| --- | --- | --- |
| s2 × 四态 | 「取消这次传输」 | s2 = **传输进行中**，用户该做的就是等 |
| s3 × 四态 | 「关闭这一页」 | s3 = 「这次办理结束了」，**终态**，下一步在机器那边不在手机上 |
| device-off × s1 | 「先存到「我的文档」，等机器好了再打」 | 机器离线时**故意不给上传**（hint 原文：「传过去也打不出来 · 别白跑一趟」） |

P05 是**手机页**不是一体机页，没有操作栏也没有全局导航；三处按钮都在、都 ≥48px。
把它们改成「前进」等于骗用户往下走。**不修。**

### 2. P02 待机屏（4 组合）、P25 顾问驾驶舱 first 态（1 组合）：严格口径为 0 —— **量法误报**

严格口径只认 `.btn--primary` 与 `data-*-go` 推进器。两页的前进入口不是这两种：

- **P02**：整屏热区 `a.sb-hit { position:absolute; inset:0; z-index:5 }` —— 碰哪儿都进首页，
  和真机「触摸唤醒」一致（宽口径量到，为 0 缺口）。
- **P25 first 态**：托盘还没钉住任何东西，主按钮「去打印」自然不显示，
  显示的是 `a.btn--ghost`「先去打印别的文件」（宽口径量到）。托盘空时没有可打印的东西，
  给一个 primary 反而是假承诺。

两页宽口径缺口均为 **0**。**不修**（要改的是量法，不是页面）。

### 3. P10 访谈式生成 s2 「卡内溢出 ×3」 —— **检测器误报（修完之后的）**

原始缺陷是真的，已修：`.qa-said` 写了 `overflow-y:auto`，但在 flex 列里默认
`flex:0 1 auto` + `min-height:auto`，压不到内容高度以下，滚动条永远不出现，
第 10 条「联系方式」直接画到 `.pane` 外面。补 `flex:1 1 auto; min-height:0` 后：

```
.qa-said  707→1527  h820  scrollHeight 977  clientHeight 859   ← 977 > 859，确实在滚
末条 .said-a  1600→1622                                        ← 位于滚动内容内，被 .qa-said 裁掉
.pane      658→1620  overflow: visible
```

`auditCardOverlap`（audit-plus.js:655）只在**卡片自己**有 `overflow: hidden|clip|auto|scroll`
时跳过，不检查叶子与卡片之间是否隔着一个滚动容器 —— 于是拿末条的**布局矩形**去比 `.pane` 底边，
报出 3px。但那 3px **不会被画出来**（`.qa-said` 已裁），不存在「重叠在下一块上」。

**不改检测器**：`audit-plus.js` 是跨轮次共用的同一把尺子，中途改它会让本轮数字和历史轮不可比。
留作已知误报，附上面的测量。

### 4. P15 企业导览「代收简历」 —— **合规否定式披露，豁免**

源码连写扫描会命中 `<span class="k">不做</span><span class="v">代收简历 · 候选人筛选 · 面试邀约…</span>`，
因为「不做」在**上一个元素**里。运行时按 `screen.innerText` 量：

```
命中位置前 5 个字符 = "本机不做\n"     → 含「不」→ 否定式豁免命中
v3Audit 违禁文案 = []                  （四态全部为空）
```

全站另有 20 处同类否定式披露（「本机不代收简历、不代为投递」等），全部豁免。
**肯定式违禁词全站 0 处。不修。**

### 5. P23「疑似假入口 ×4」（`.ub-chips`） —— **容器类名误报**

`auditFakeAffordance` 按类名含 `pill|chip|tag|btn` 判定。`.ub-chips` 是**一行容器**
（`display:flex` 的 wrapper），里面装的「退出登录」本身是真 `<button>`，可点、有事件。
豁免正则里没有 `chips` 这个词，于是把 wrapper 判成假入口。改动前就存在，与本轮无关。**不修。**

### 6. 「主栏留白过大」共 302 次 —— **提示项，不是判决**

`audit-plus.js` 自己写着：「**这是烟雾报警器，不是判决**……别为了把数字压到 0 塞填充物，那比留白更糟」。

**本轮不动**（属结构性留白，不属缺陷）。

## 二-三、本轮修掉的真缺陷（6 类 / 6 个文件）

### 1. 01-home-v6 版头文案被裁掉 —— 基线首页，用户第一屏

**这是本轮最严重的一条。** `.vhero` 被限高 `226px`（`ai-down` 186px）+ `overflow:hidden`，
而 `.vhero-inner` 的行高由 `.vfigure`（300px，刻意出血站在版头底边上）决定，`.vhero-copy`
又 `align-items:end` 贴在这 300px 行的底部：

```
.vhero        128 → 354      (height 226, overflow hidden)
.vhero-inner  152 → 452      ← 比版头底边多出 98px
.vhero-title  204 → 359      ← 第二行「序我来排」被从中间切开
.vhero-sub    371 → 434      ← 整条落在裁切线以下，四态 0% 可见
```

后果不只是难看：`.vhero-sub` 三条按态分支的文案 —— `ai-down`「AI 排序暂时不可用。打印、扫描、
上传与岗位招聘会浏览都正常，顺序需要你自己选。」、`device-off`「这台机器打印机离线。材料可以
先存起来，凭手机号在任一台空闲机器取回打印。」—— **一个字都看不到**。状态说明不可见等于没说
（CLAUDE.md §9「不伪造能力」）。

**为什么检测器没报**：`v3AuditPlus` 的「内部裁切」只报了两条`一般`（标题溢 19.4px、
副标题溢 80.1px），量级看着不大；真正致命的是「整条不可见」，那不在任何一项判据里。

**改法**（只动版头，未碰 `.vbody` 既有的四态试算结果）：版头文案改顶对齐、标题收成单行。
76px 单行需要 912px 宽，版头左栏只有 614px，按宽度反推最大单行字号 —— 实测 50px 单行 /
52px 起换两行，取 **48px** 留余量。

还有一层第一遍没看见的：**可视下边界不是 `.vhero` 的 354，而是 328**。
`.vcommand`（跨在版头底边上的玻璃指令胶囊，`margin-top:-26px; z-index:6`）会盖住版头最后 26px。
按 354 收完，`ai-down` 态副标题第二行仍被指令条压着（`elementFromPoint` 命中 `DIV.vcommand`，
`headroom = -8px`）—— 检测器**量不到这种「被别的层盖住」**，只有对着 328/288 这条线量才看得见。
于是 `ai-down` 再收一档（版头上内边距 24→12、标题 48→40、两处行距 12→6）。

| 态 | 指令条顶边 | 副标题末行底 | 余量 |
