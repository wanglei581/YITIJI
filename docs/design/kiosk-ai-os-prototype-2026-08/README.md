# 一体机 AI 求职操作系统 75 屏高保真原型 V2

> 状态：完整 75 屏视觉与流程重设计候选，不替代现网 Kiosk
> 范围：27 寸 1080x1920 竖屏一体机，覆盖 01-75 的全部既有功能去向

本版根据用户提供的墨刀《AI 智慧党建 APP》参考提炼“场景先行、内容节奏明确、页面构图随任务变化”的方法，但不复制其手机比例、党建装饰或红色主题。01 首页、03 打印参数、13 AI 顾问分别采用不对称服务编辑页、文档工作台、任务计划板三种独立构图；其余页面按业务任务进入七类母版。主流程、辅助工具、来源信息和可信状态使用不同权重，不采用平均六宫格或“所有元素同等重要”的卡片墙。

## 设计立场

- 炭黑顶栏来自线下服务终端的设备属性，用来稳定品牌与终端状态，不承担营销氛围。
- 赤土红只用于本人确认、创建任务等不可轻率触发的主动作；不用默认 SaaS 蓝。
- 森林绿只用于本机服务与已验证状态；钴蓝只用于第三方或官方来源；琥珀只用于设备、能力和价格尚未核实。
- 主内容左右留白固定 54px，对应 1080 宽竖屏的远距离阅读和边框安全区；8/12px 只用于控件内部关系，不作为整页平均网格。
- 01 的打印横向主入口、AI 简历纵向主区和四个紧凑入口故意不等宽；03 让文件预览占约 60%；13 让任务计划占约 64%。页面比例由任务决定，不由组件默认值决定。
- 目录、办理、文档、列表、详情、履约和系统状态分别服务于选择、操作、校对、扫描、阅读、等待与恢复，不共享同一种“白底卡片 + 标题 + 按钮”构图。

## 设计目标

这版原型把 AI 从“每页一条 AI 横幅”和独立聊天外壳，改成一套可恢复的任务编排机制。用户始终围绕同一个核心对象工作：**本次办理单**。

```text
说清目标 / 直接选服务
-> 系统确认已有材料与缺口
-> AI 给出受控建议
-> 用户确认关键动作
-> 服务端、支付或硬件真实门控
-> 结果进入本人资产、订单或第三方来源
```

AI 可以识别意图、检查材料、建议顺序、解释结果和恢复任务，但不能直接支付、出纸、删除文件或打开第三方来源。所有高风险动作都保留明确确认。

## 信息架构

- 底部三项仍为：首页 / AI 顾问 / 我的。
- 首页仍保留六个定版业务入口：打印扫描、AI 简历服务、岗位信息、招聘会、AI 面试训练、政策服务。
- 百宝箱与智慧校园只作为后台开关控制的专区，不进入六个主入口。
- 旧 01-75 编号全部保留为功能映射，但流程状态不再被误当成 75 个互不相关的产品入口。
- 62 / 63 是扫码后的一次性手机接力页，只承接当前一体机会话，不是微信小程序，也不建立第二套产品导航。

## 视觉方向

视觉语言定义为“公共服务工作台”：白色与冷灰承担信息底色，墨绿承担可信服务状态，朱红承担关键确认，钴蓝承担来源与外部信息，琥珀色承担警告。没有渐变、毛玻璃、光晕、巨型 Hero、圆角卡片墙或装饰性 AI 图标阵列。

页面使用八类母版，并对三个标志性页面单独构图：

1. 首页任务台（01 独立场景页）
2. 服务目录
3. 办理工作台（03 文档打印、13 AI 编排另有专属布局）
4. 文档与对比
5. 列表与记录
6. 来源详情
7. 实时履约
8. 系统状态

## 打开方式

从仓库根目录启动静态服务器：

```bash
python3 -m http.server 8932
```

浏览器打开：

```text
http://127.0.0.1:8932/docs/design/kiosk-ai-os-prototype-2026-08/index.html
```

左侧可筛选 01-75 屏，原型内主按钮可沿真实流程跳转。右上角可切换默认、加载、空态和异常状态。

## 验证结果

- 75 个屏幕编号完整，内部跳转目标无缺失。
- 1080x1920 下完成 75 屏默认态和加载、空态、异常共 300 组布局检查。
- 可见操作目标不小于 48px；未发现横纵截断、文本裁切或图片加载失败。
- 第三方来源先展示离站确认，原型不会伪造投递、预约或签到结果。

## 开发边界

- 原型只确定信息架构、操作流程、文案优先级和视觉方向，不证明 API、支付、设备、耗材或硬件已经可用。
- 页面中的设备状态采用“检查中 / 未知 / 需现场确认”等诚实状态，不把静态样例写成实时事实。
- 岗位、招聘会和企业只展示第三方或官方来源。投递与预约必须去来源平台，不记录第三方结果。
- 不硬编码打印机型号，不假设 A3、云端远程扫描或未确认的彩色打印 mode。
