# 运营数据大屏 · 设计方案（2026-09-06）

对应看板序 15。原型：[01-gov-screen.html](01-gov-screen.html)（政务版）、[02-ops-screen.html](02-ops-screen.html)（运营版），1920×1080，样式 [screen.css](screen.css)。

数据就绪度的逐项盘点见 [launch-audit-2026-09-05.md](../../reviews/launch-audit-2026-09-05.md) 的「运营数据大屏 · 数据就绪度盘点」一节，本文不重复，只写设计决定。

## 一、这块屏最大的风险不是好不好看

行业里大屏翻车的方式高度一致：内蒙古 48 块屏建完基本关闭、耒阳虚报数据、「数据出官」被点名。翻车点从来不是配色，是**屏上有数字但没人能说清它从哪来**。政府采购验收也是照着这条问：数据有没有来源与时间戳、能不能追溯台账、跟省平台对不对得上。

所以本方案的第一条硬约束不是视觉的：

> **每一块卡片都必须带来源脚注，写清模型/端点、统计窗口与口径。原型里 22 块卡片无一例外。**

第二条：

> **没有数据的模块显示「未接入」加一句为什么，不显示 0，不显示占位动画，不用代理值凑。**

`0` 会被读成「没发生」。招聘会资料打印量的计数器字段存在但全仓没有自增路径，显示 0 等于告诉领导「没人打印资料」——这是假话。所以它显示「未接入：计数器无自增路径」。

同理不做的：服务人次（会话表零写入）、耗材余量（心跳只有状态枚举没有数值）、终端地图（没有经纬度）、审核时效（审核决策表零写入，`reviewedAt` 会被三个不同动作覆盖，拿它算时长会得到偏小的假值）、按机构维度（AI 日志与订单没有机构字段）。

## 二、两套 profile，不是两个产品

| | 政务版 `?profile=gov` | 运营版 `?profile=ops` |
|---|---|---|
| 观众 | 上级检查、来访参观、大厅公开屏 | 运维与内容审核，管理员登录后 |
| 布局 | 4 列 × 3 行，10 块 | 6 列 × 3 行，12 块 |
| 含告警队列 | ❌ | ✅ |
| 含成本与 token | ❌ | ✅ |
| 投放 | 可公开 | **仅内网，不投放公开场所** |

告警、待审队列、AI 成本这些是内部运维信息，公开屏上出现「离线 34 分钟」只会变成扣分项，所以政务版不放。这是分版的唯一理由，不是为了做两套皮肤。

## 三、合规：屏上不能出现什么

大屏是最容易越界的地方，因为它天然想展示「撮合成果」。红线（详见 `CLAUDE.md` §2、§10 与 `docs/compliance/compliance-boundary.md`）：

- **任何形式的投递数据都不能上屏**，包括按企业名或岗位聚合后的数量。本平台不做招聘闭环，屏上出现「成功投递 N 人」既是假的也是违规的。
- 外部跳转只能表述为「打开来源平台入口 N 次」。用户是否真的投递发生在来源平台，本平台无从得知也不记录。原型里这块的脚注就是这么写的。
- 不显示任何会员字段、行为日志里的用户标识、文件名与内容、取件码、扫描件、AI 结果内容。
- 「企业入驻数」这种行业惯用词不能直接用——我们只有「接入信息来源机构数」，含义完全不同。
- 「求职登记数」同理，我们没有登记业务；能对应的是「AI 简历建档数」，必须换名字。

热门来源 Top-N 可以显示（是机构不是个人），但 N 不小于 5，避免小样本反推。

## 四、口径统一：在线阈值现在有三套五处

盘点发现「终端在线」在仓库里有三个不同阈值、五处实现：管理端 3 分钟、device-fleet 180 秒、内容与工具箱 2 分钟、一体机与小程序 5 分钟。大屏如果自己再挑一个，就变成第六处。

**大屏只认 device-fleet 的投影，并且把窗口秒数打在页眉上**（原型页眉「在线判定窗口 180 秒」）。这样即使别处口径不同，看屏的人也知道这个 37/42 是按什么算的。

「从未上报」（已注册但没有过任何心跳）单列，不并进离线，也不进在线率的分子——否则装机当天注册一批设备会让在线率凭空难看。

## 五、取数：一个端点，不是十几个

工作台现在已经是 9 个端点并发，大屏模块更多。方案是一个聚合端点：

```
GET /api/v1/admin/screen/snapshot?profile=gov|ops
```

服务端缓存分三档，对应原型页眉写的刷新节奏：

| 档 | 内容 | TTL |
|---|---|---|
| 实时 | 告警、进行中任务 | 15 秒 |
| 计数 | 各类状态计数、AI 24h、同步成功率 | 60 秒 |
| 累计 | 累计打印页数、累计调用、趋势折线 | 5 分钟 |

响应必须回带 `generatedAt` 与每块的 `window`，前端页眉与脚注直接渲染它，不在前端自己造时间戳。

聚合实现注意：AI 用量现在是 `findMany take:10000` 后在 JS 里算，超过一万条会少算，大屏必须改 `groupBy`。

## 六、只读访问令牌

大屏经常要挂在一台没人看管的机器上长期显示，不能用管理员的 24 小时 JWT。

建议照搬 `TerminalBindCode` 的形状（`codeHash` 唯一 + `expiresAt` + `usedAt` + `revokedAt`），签发逻辑可参考 `terminal-credential-security.service.ts`。要点：

- 令牌只读，只能打 `screen/snapshot`，打不了任何写端点；
- 可吊销（无状态 HMAC 令牌做不到吊销，因此不用它）；
- 有效期由签发时指定，过期后屏上显示「令牌已过期，请联系管理员」而不是空白；
- **不要沿用 `terminals/:id/config` 与 `printer-status` 那种无 Guard 公开读的做法**——那两个端点现状如此不代表大屏可以照做。

签发入口放管理员工作台的一个区块，不新建页面。

## 七、字号与观看距离

大屏是 3 米外看的，不是后台页面放到投影仪上。

- **可见文字下限 13px**，写在 `screen.css` 顶部。原型的自动探针会把小于 13px 的文字全部列出来。
- 主数字 46px 等宽字体，KPI 标签 16px，脚注 13px。
- 底色用墨青系（`--dark:#0b241f`），因为墙面屏与投影多在暗环境；主色仍是青玉，与后台同一套色板，不新造设计语言。

## 八、原型自检

`/tmp/screen-probe.mjs` 那类探针（Playwright，1920×1080）检查四件事，两个页面当前全部通过：

| 检查 | 结果 |
|---|---|
| 页面高度恰好 1080，无横向滚动 | ✅ 两页 |
| 卡片内容无裁剪、同级元素无重叠 | ✅ 两页 |
| 无小于 13px 的可见文字 | ✅ 两页 |
| 每块卡片都有来源脚注 | ✅ 22/22 |

落地时这套检查值得做成门禁；原型阶段先手工跑。

## 九、落地顺序

1. 先补聚合端点与只读令牌（后端），前端用原型的静态数据接线；
2. 再逐块接真，**接不通的块保持「未接入」不要先填假数**；
3. 「服务人次」「审核时效」「按机构维度」三块需要先补数据写入，属于独立任务，不在大屏一期。

一期只做原型里标了真实来源的那些块。
