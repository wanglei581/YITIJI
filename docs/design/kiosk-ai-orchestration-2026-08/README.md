## 一、范式定义

**旧范式**：首页摆功能目录 → 用户自行判断问题归类 → 进入 → 自行填参数 → 自行决定下一步。
**新范式**：用户带处境来 → 系统翻译成任务链 → AI 给**带理由的下一步** → 用户只做**确认**。

一条不可违反的推论：

> **AI 承担"想"，用户承担"定"，系统与硬件承担"做"。**
> AI 永远不替用户按下不可逆的按钮。

### 1.1 一体机特有约束（决定形态）

站在机器前的用户：站立、可能排队、平均停留 3–8 分钟、手不干净、旁边有人。因此：

- **自由文本输入不能是主路径**。它是兜底，不是入口。主路径必须是**场景化大按钮**。
- **每一步只给一个主推荐**。给 6 个平等选项等于没引导。
- **建议必须给理由**。没有理由的推荐 = 广告；有理由的推荐 = 顾问。
- **隐私是默认前提**。公共终端，超时清空，敏感内容不常驻屏幕。

## 二、核心对象：办理单（Errand）

全站围绕**一次办理单**工作，不是 75 个互不相干的入口。

```text
说清处境 / 直接选场景
  → 系统盘点已有材料与缺口
  → AI 给受控建议（动作 + 理由 + 代价 + 备选）
  → 用户确认关键动作
  → 服务端 / 支付 / 硬件真实门控
  → 结果进入本人资产、订单或第三方来源
```

### 2.1 办理单数据结构（前端契约草案，不含实现）

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `errandId` | 办理单标识 | 会话级，非账号级 |
| `intent` | 意图（封闭集，见 §3.1） | 必填 |
| `goalText` | 用户原话 / 场景卡文案 | 用于回显，让用户确认"系统没理解错" |
| `steps[]` | 任务链步骤 | 每步含 `key / title / status / gate` |
| `assets[]` | 本单产生的资产 | 文件 / 简历版本 / 报告 / 订单 |
| `context` | 盘点结果 | 已有材料、缺口、设备能力、现场事件 |
| `advice` | 当前建议（见 §4） | 一主二备 |
| `status` | `active / completed / timeout / abandoned` | |

### 2.2 生命周期与隐私

- 90 秒无操作 → 前台提示"是否继续办理"；120 秒无响应 → **清空办理单与全部本地缓存**，回待机。
- 未登录也可创建办理单。**登录门设在「沉淀」这一步，不设在入口** —— 用户先看到价值，再决定是否留手机号。
- 手机接力（62/63 屏）只承接**当前一体机会话**的一次性任务，不建立第二套导航。

## 三、意图层：怎么把处境变成任务

### 3.1 意图为封闭集，不做开放域 NLU

一体机场景下，开放 NLU 的失败成本远高于收益（识别错 = 用户当场放弃）。意图限定为 7 条：

| 意图 key | 用户语言（场景卡文案） | 任务链 |
| --- | --- | --- |
| `print` | 我要打印材料 | 上传/扫码/U盘 → 材料检查 → 参数核价 → 支付 → 出纸 → 取件码 |
| `resume` | 我要弄简历 | 来源（上传/扫描/生成）→ 识别 → 诊断 → 优化 → 沉淀 → 打印 |
| `fair` | 我要去招聘会 | 选场次 → 展位企业 → 匹配参考 → 参会准备单 → 打印 → 导览 |
| `job` | 我在找工作 | 岗位列表 → 详情 → 匹配参考 → 收藏 → 去来源平台投递 |
| `interview` | 我要练面试 | 设置 → 逐题会话 → 报告 → 沉淀 → 打印 |
| `policy` | 我要查政策办事 | 政策列表 → 详情 → 材料清单 → 打印 |
| `unsure` | **我不知道从哪开始** | AI 三问引导 → 收敛到上面某一条链 |

`unsure` 是新范式最核心的入口，不是兜底装饰。它必须做到：**三个问题以内收敛到一条确定的任务链**。

### 3.2 意图的四个来源（优先级从高到低）

1. **场景卡点击** —— 主路径，零歧义
2. **上下文推断** —— 已登录/已扫码带入：上次未完成的办理单、已上传的简历、已收藏的岗位、今天的招聘会
3. **自由文本** —— 兜底。识别后**必须回显解析结果让用户确认**，不得直接执行
4. **手机接力带入** —— 手机端已选定的目标

**规则**：自由文本解析出的意图，置信度不足时不猜，直接问"你是想打印材料，还是想改简历？"——两个大按钮。

## 四、建议层：AI 引导的核心规范

> 这一层做不好，整套范式就是花架子。

### 4.1 每条建议必须四要素齐全

| 要素 | 说明 | 反例 |
| --- | --- | --- |
| **动作** | 一个明确、可执行的下一步 | ✗「优化一下你的简历吧」（不明确做什么） |
| **理由** | 指向**可验证事实**，不是模型口味 | ✗「AI 认为这样更好」 |
| **代价** | 耗时 + 花钱，一体机用户最关心 | ✗ 不说要多久、要不要钱 |
| **备选** | 至少一个「跳过 / 换一个」出口 | ✗ 只有一个按钮，等于强制 |

标准句式：

> **建议先做简历诊断。**
> 因为你这份简历里 6 段经历有 5 段没写清成果数字，而周五这场招聘会有 128 家企业参展、现场普遍收纸质简历。
> 约 40 秒 · 免费
> `[开始诊断]` `[跳过，直接打印]`

理由两句都是可核对的事实（E1 + E2），没有一句结果预测。
**反例**：「直接投出去命中率会明显偏低」——这是 E3 结果判断，既无法核对也未标注，禁止作为主建议的理由。

### 4.2 理由的证据分级（**硬约束**）

| 级别 | 来源 | 措辞权限 |
| --- | --- | --- |
| **E1** | 用户数据事实（文件页数、简历缺项、历史订单、收藏记录） | 可用陈述句，可用祈使句「建议…」 |
| **E2** | 系统 / 设备 / 来源事实（打印机彩色可用、今天有招聘会、政策截止日） | 可用陈述句，可用祈使句 |
| **E3** | 模型判断（表达优劣、岗位匹配感受） | **必须显式标注「AI 判断，仅供参考」**，且不得单独构成主建议 |

**无 E1/E2 支撑时，不得使用祈使句**，只能用疑问句给选项。
这条直接对应 CLAUDE.md §9「不伪造能力」——AI 不能靠语气把猜测说成结论。

**适用范围**：本条只约束**建议层（S1/S2）**，即 AI 主动给出的「你应该做什么」。
界面自身的操作指引（「先选一项服务」「请选择支付方式」）和降级/目录模式下的引导文案不受此限——
它们不声称任何关于用户的判断，只描述界面怎么用。

### 4.3 数量与视觉权重

- 每屏**最多 1 条主建议（S1）**，最多 2 条备选（S2）。
- S1 是全屏视觉最强项；S2 为文字按钮级别。
- 建议不可用时（AI 服务故障 / 无上下文），**整个建议区不渲染**，页面退回目录模式 —— 不显示空的 AI 壳子。

### 4.4 建议区的物理位置（设计决定，非随意）

**建议卡的内容在视线区，它的主按钮下沉到常驻 ActionBar。**

理由：建议是"下一步动作"，动作必须落在手能舒适触到的区域；而理由需要被阅读，属于视线区。把两者拆开分别放到最合适的高度，比整卡上移或下移都好。

## 五、执行层：AI 预填 + 真实门控

### 5.1 权限矩阵（**红线，不可协商**）

| 动作 | AI 自动执行 | 需用户确认 | AI 永不执行 |
| --- | :---: | :---: | :---: |
| 识别文件类型 / 页数 / 是否简历 | ✅ | | |
| 预填打印参数（份数/单双面/彩黑） | ✅ 标注"已预设，可改" | | |
| 材料完整性预检（缺证件照/缺页） | ✅ | | |
| 简历诊断打分与建议 | ✅ | | |
| 生成简历新版本 | | ✅ 用户点"采纳" | |
| **覆盖 / 删除原简历** | | | ❌ 只生成新版本 |
| **发起支付** | | ✅ 用户按下 | |
| **出纸** | | ✅ 用户确认核价单后 | |
| **删除文件** | | ✅ 二次确认 | |
| **跳转第三方来源** | | ✅ 离站确认页 | |
| **平台内投递 / 代收简历** | | | ❌ 合规红线，永不实现 |

### 5.2 预填的诚实表达

AI 预填过的字段必须**可见地标注来源**，例如打印参数区显示「已根据文件内容预设 · 可修改」。
不得让用户误以为是自己设的，也不得让用户以为不能改。

## 六、失败与降级（商用生死线）

| 故障 | 降级路径 | 绝不能做 |
| --- | --- | --- |
| AI 服务不可用 | 退回目录模式，六入口全展开，业务不阻断 | 显示空建议卡 / 假建议 |
| OCR 置信度低 | 标注"需人工复核"，**不送 LLM** | 用低置信文本生成结论 |
| 打印机离线 / 缺纸 / 缺粉 | 建议改为"转存我的文档"或"手机接力"，明示故障 | 显示"设备正常" |
| 支付成功但打印失败 | 生成待打印订单 + 取件码，可在任一空闲机复打 | 静默失败 |
| 会话超时 | 恢复页可凭手机号找回未完成办理单 | 直接丢弃已付费任务 |
| 用户不满意 AI 生成结果 | 版本列表可回退到任一历史版本 | 覆盖原件 |

**规则**：任何"顺利路径"设计稿必须同时给出对应失败路径，否则不进入实现。

## 七、页面落地规则（解决"按钮/文件位置不好"）

### 7.1 1080×1920 站立操作分区（**全站强制**）

```text
  0 ─  400px   顶栏：品牌 / 时间 / 设备状态      只看不摸（高于视线，够不着）
400 ─ 1200px   内容主体 / 文件预览 / 建议理由    视线自然落点，阅读区
1200 ─ 1700px  主操作区（ActionBar 常驻）        手的舒适落点，主按钮恒定【右下】
1700 ─ 1920px  底部导航                          三项定版：首页 / AI 顾问 / 我的
```

### 7.1A 版面契约（2026-08-08 定，可自动检查）

7.1 的分区是**意图**，本节是**可验证的硬约束**。起因：生产页 `/print/preview` 在有真实文件时，
内容长到 2995px 塞进 1920 视口，文档又不滚动，主 CTA 被推到 **top 2842**（屏幕外 922px）——
用户能调完全部打印参数却找不到「下一步」，这条流程在 1080×1920 上根本走不通。
根因不是视觉，是**没给版面定预算**：`min-h-full` + `flex-1` 等于放弃版面控制权。
生产端 7 个页面用了这种写法（`print/` 全链路）。

**四条硬约束：**

1. **固定画幅**：1920 = 顶栏 76 + 内容区 1728 + 底部 Tab 116。内容区是**硬上限**，
   超出必须内部滚动并给出滚动提示，**不许溢出消失**。禁止在页面根节点用 `min-h-full` 让内容自由生长。
2. **主操作常驻**：ActionBar 固定在内容区底部，位置与内容多少无关。
   自检：四态（或全部状态）下主 CTA 的 `top` 值应基本一致。
3. **预览按比例分配**：文件预览容器按内容真实比例（A4 = 1:1.414）分配高度，
   不用 `flex-1` 抢占剩余空间。注意：`aspect-ratio` + `width:auto` 在子元素全为绝对定位时会**塌成 0**，
   须改为高度驱动（`height:X; width:auto; aspect-ratio:...`）。
4. **竖屏不做三栏并排**：1080 宽最多两栏且次栏 ≥400px；三路以上用分段切换 + 纵向铺开。
   反例：07 初版三栏 392/290/290，正文可用宽仅 280px，连「对上了」三个字都折两行。

**建议的 CI 门禁**（能挡住现有视觉测试挡不住的问题）：

```
在 1080×1920 下，任一页面若满足以下任一条，CI 失败：
  · 内容区 scrollHeight 超过 clientHeight 且无内部滚动容器
  · 存在可交互元素落在视口外（bottom > 1920 或 top < 0）
  · 存在可点击元素高度 < 48px（主按钮 < 56px）
```

> **为什么现有测试没挡住**：视觉回归测试只覆盖**空态**（如 `/print/params` 的断言是 `'未找到文件信息'`），
> 而空态永远不会超高。**有真实内容才出现的布局崩溃，测不出来。**

### 7.1B 演示视图一致性

10 张样张统一用 `<div id="stage">` 包裹 `.kiosk`，并带 `fit()` 缩放，
使左上角状态切换面板不遮挡页面。
**注意**：`fit()` 会缩放整个舞台（`(innerWidth-290)/1080`），
因此**用 `getBoundingClientRect()` 量触控尺寸时必须先确认缩放系数为 1**，
否则会把 48px 量成 35px，得出错误的「触控目标不合格」结论（本轮曾发生）。

### 7.2 ActionBar 规则

- **全站同一位置、同一高度、主按钮恒定在右下角**，不随内容长短漂移。用户三次操作后形成肌肉记忆。
- 主按钮 ≥56px 高，可点击目标 ≥48px。
- 左侧放"返回 / 跳过 / 备选"，右侧放唯一主动作。
- 页面内容再长，ActionBar 不参与滚动。

### 7.3 文件显示规则

用户是**核对完才敢付钱**的，所以：

- 打印 / 简历 / 扫描类页面，文件预览占视觉主体 **55–65%**，完整显示不截断。
- 参数收进侧栏或下方抽屉，**不得反客为主**。
- 多页文件必须可翻页且显示"第 X / 共 Y 页"。

### 7.4 视觉体系

- 基底：墨青纸感（取自 `direction-d-refined-home.html` 的 token）。
- **token 化强制**：色值、圆角、间距、字号一律走变量，禁止硬编码 —— 现有 166 个 tsx / 38295 行的"不美观"根因正是各页各写各的。
  深色「机器声」面板同样有 token（`--ink-panel-*` / `--on-ink-*` / `--mint*`），不允许因为"只有一个深色区"就写死十几个十六进制色值。
- 同名组件全站一种长相。

## 八、合规红线（与 CLAUDE.md / docs/compliance 一致）

AI 引导层不得成为绕过合规的通道：

- 按钮白名单不变：查看岗位 / 去来源平台投递 / 扫码投递 / 查看招聘会 / 去来源平台预约 / 扫码预约。
  **禁止**一键投递 / 立即投递 / 平台投递 / 收简历 / 候选人管理。
