G3-05 / domain-overlays「物理设备与边缘代理」证据
取证时间 2026-09-02   环境 windows-kiosk（Windows 一体机 + 奔图 CM2820ADN）
执行人 产品负责人（本项目的验收权威）   方式 真机实操，非模拟

## 已验证通过

1. 彩色打印 —— 本地驱动路径可控制彩色输出。
   此前状态：CLAUDE.md §3 标注「硬件支持，Phase 8.1 驱动控制待真机验证」。
   现状态：已验证。CLAUDE.md 能力表、packages/shared/src/types/print.ts、
   apps/terminal-agent/src/printer/types.ts 三处标注已同步更新。

2. 自动双面 —— 可自动双面出纸（无需人工翻面）。
   此前状态：「硬件支持，Phase 8.1 DEVMODE 控制待验证」。现状态：已验证。

## 仍未验证（不得据本条推断）

- **长边 / 短边的实际翻页方向未核对。** duplex_long_edge 与 duplex_short_edge
  在代码里只是两个名字，哪个对应「像书一样左右翻」、哪个对应「像日历一样上下翻」，
  只有实际出纸能确定。搞反了用户拿到的装订方向是错的，且要到打印完才发现。
  → 待补：4 页文件各打一次，看第 2 页正反。
- 故障恢复路径（缺纸 / 卡纸 / 断网重连 / 缺粉）未验证。
  按 domain-overlays 的要求，物理设备 GO 必须包含故障恢复记录，仅证明顺利路径不足。
- 奔图开放打印 API 的彩色能力**与本条无关且仍未知**。本条验证的是本地 Windows
  驱动路径；开放 API 的 V1.0 协议里不存在彩色取值（全文 color/彩色/cmyk 各 0 次），
  真机能彩打不代表该协议能下发彩色任务。两条路必须分开判断。

## 可解锁的后续动作

服务端对 color_print / duplex_print 是 fail-closed（未登记即拒绝，见
packages/shared/src/types/printScanCapability.ts 的 DEFAULT_DENY_CAPABILITY_KEYS）。
本条验证后，可在管理员后台 /devices 为该终端登记这两项能力，
服务端才会接受该终端的彩色 / 双面订单。

## 证据性质

本条为验收权威的口头/文字报告，非自动化产出。按 domain-overlays 口径，
物理设备不接受截图或状态徽章作为 GO 证据；本条的效力来自「由验收权威在真实设备上
实际操作并确认输出」。若需更强证据（例如提交给第三方验收），应补出纸实物照片。
