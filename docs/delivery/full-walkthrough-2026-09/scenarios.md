#### 2. 异常分支处理
* **走错页返回**：在 `/scan` 扫描完后，老人误点了顶部的【返回】或面包屑导航。
  * *期望*：弹出明确警示弹窗：“您刚才扫描的 1 页文件尚未保存或打印，返回将丢弃本次扫描，确定返回吗？”【继续打印】为显眼绿色，【放弃返回】为灰色辅助键。不许直接白屏或无提示丢弃数据。
* **中途犹豫与闲置超时**：停留在 `/print/desk` 长达 60 秒未触碰屏幕。
  * *期望*：第 60 秒时全屏弹窗半透明遮罩，伴随提示音，大倒计时：“您已长时间未操作，将在 30 秒后自动退出并清理数据，防止信息泄露”。点击任意位置倒计时重置；若 30 秒倒计时结束，静默清理所有缓存，安全回退到 `/screensaver`。
* **换人遗留**：老人在收银台 `/print/cashier` 点完出纸拿了纸就走，未点击【结束使用】。
  * *期望*：`/print/done` 页面强制设置 20 秒极短倒计时自动退回首页；下一位用户上机前必须已经完成清场。若下一个人在 5 秒内走上来触碰屏幕，屏幕顶端醒目红条警示【当前账号：139\*\*\*\*5678】，并提供唯一的【换人使用：一键清理退出】按钮，绝不能让下一个人直接点进“我的”。
* **断网（网络断开或后端 500）**：点击【获取验证码】或【确认出纸】瞬间断网。
  * *期望*：前端弹出非阻塞式轻提示（Toast）：“网络连接不稳定，请稍后重试”，同时保留当前输入的手机号与扫描件缓存，提供【重试连接】按钮，绝不出现未捕获的 Unhandled Promise Rejection 白屏，更不允许死在加载中动画（Spinner）。
* **打印机缺纸 / 卡纸 / Agent 离线**：Mock Agent 上报 `PRINTER_OFFLINE` 或 `PAPER_EMPTY`。
  * *期望*：收银台在点击支付前或出纸进度页检测到硬件告警，界面变红并清晰提示：“奔图一体机当前缺纸，无法出纸。本次订单未扣费，请联系现场就业站工作人员添纸”，并提供【返回修改】与【呼叫协助】按钮，不假装出纸成功。

#### 2. 异常分支处理
* **文件格式不支持或损坏**：手机端尝试上传一个 `.doc`（老版本加密文件）或 `.exe` 伪装文件，或者无转换引擎支持的特殊排版 WPS 文件。
  * *期望*：一体机与手机端同步明确拦截报错：“上传失败：不支持该文档格式或文档已被密码加密保护，仅支持未经加密的 .docx / .pdf 格式文件”，提供【重新上传】引导，绝不能卡死在“正在解析中”。
* **文件超大或页数超限（>50页）**：学生误传了一个 120MB 的毕业论文 PDF。
  * *期望*：前端预检与后端网关联合拦截：“文件过大（超过 20MB 限制）”或“页数超限（当前文件为 68 页，单次简历打印不能超过 50 页）”，页面保持在上传选择态，不允许阻塞内存。
* **手机上传一半断开**：手机微信扫码后刚选好文件，网络中断或学生直接将微信后台杀进程。
  * *期望*：一体机上传二维码等待界面在 60 秒未收到数据后，提示“等待手机上传超时，请重新扫码”，并提供【重新生成二维码】与【改用 U 盘读取】切换入口。

## 二、 专项深度审查与风险排查表

### A. 最容易出错、最容易被开发忽略的 20 个操作（按风险由高到低排序）

1. **上一个用户未点「结束使用」直接离开，下一个用户直接触碰屏幕操作**
   * *为什么*：高发于公共服务大厅，上一位用户的简历、姓名、联系方式、诊断痛点完全裸露给陌生人，是重特大隐私泄露合规事故。
2. **身份证正反面复印后，扫描产生的原图留在一体机 Windows 本地缓存或对象存储中未物理销毁**
   * *为什么*：开发往往直接复用统一文件上传与存储逻辑，导致高度敏感的公民身份证切片长期留存在云盘或终端磁盘，违反个人信息保护法与等保红线。
3. **在 27 寸竖屏上误用了针对 16:9 横屏设计的模态弹窗与虚拟键盘**
   * *为什么*：竖屏底部高度与人体工学差距大，虚拟键盘弹起时经常直接遮挡住输入框或【确认】按钮，且由于页面无滚动能力导致界面卡死。
4. **零元支付（¥0.00 试运营）跳过订单状态机与出纸令牌生成**
   * *为什么*：开发容易偷懒在前端“既然 0 元就直接调打印 Agent”，绕过收银台后端订单创建与防重鉴权，导致后台无订单流水、无纸张账目对齐、无取件码生成。
5. **在收银台连续猛击「确认支付 / 出纸」按钮造成重复出纸**
   * *为什么*：公共触控屏由于震动回馈差，用户习惯连续拍击屏幕，若前端无节流禁用且后端无 Idempotency-Key 幂等校验，极易生成多笔重复打印任务导致纸张严重浪费。
6. **AI 服务（简历诊断/岗位对照/面试）因网络波动超时（>15s）直接白屏崩溃**
   * *为什么*：LLM 流式调用未做 Try-Catch 包裹或未编写手动降级兜底逻辑，直接在 UI 层抛出未处理的 Runtime Error，导致一体机黑屏死机。
7. **用户将外部招聘网复制的一长串岗位要求粘贴到对照框，带入了非法特殊字符或 Emoji 导致 SQL/后端解析崩溃**
   * *为什么*：富文本剪贴板格式混杂，未做纯文本过滤与字符集转义，导致后端 API 报 500。
8. **把违规的“企业直投/职位列表”通过富文本政策公告的形式绕过合规监管发布**
   * *为什么*：平台没有人力资源服务许可证，机构可能误把企业招工简章当政策发，系统若无涉企关键词检测，会直接触犯非法经营中介业务红线。
9. **打印机因缺纸/开盖/卡纸处于 Error 状态时，系统依然让用户完成了下单与扣款**
   * *为什么*：前端收银台未在付款前一秒对本地 Agent 实施“硬件就绪状态强校验（Pre-flight Check）”，等钱扣完了才发现机器根本无法打印。
10. **双面打印时，页数为奇数（例如 3 页）造成最后一页出纸逻辑错乱或吞纸**
    * *为什么*：打印机双面翻转器处理奇数页需要额外的走纸逻辑，开发未做适配易导致最后一页反面空白未正常喷出，或者任务卡死在队列中。
11. **手机扫码上传 Word 文档后，因一体机未安装 Office 运行环境且无云端转 PDF 引擎导致解析失败**
    * *为什么*：本地 Agent 为 Windows 环境，若未配置 Headless LibreOffice / 专业转换微服务，遇到复杂格式排版的 docx 会直接报底层调用异常。
12. **扫描仪自动拼接身份证正反面时，因分辨率设置不当导致缩放失真（不再是 1:1 原大）**
    * *为什么*：办理政务与入职手续严格要求身份证复印件必须与实物 1:1，开发若使用 CSS 响应式 `object-fit: contain` 直接拉伸打印，会导致打出的身份证变成超大图或微缩图而失效。
13. **微信扫码登录二维码超时失效后，前端未停止轮询导致内存泄露与大量 400 刷屏**
    * *为什么*：长久停留在屏保或登录界面的公共一体机，若定时器（Timer）与轮询器未在销毁时 Clear，会导致内存飙升至浏览器崩溃。
14. **用户上传了带密码保护的 PDF 文件，一体机无限等待光栅化**
    * *为什么*：PDF 渲染器在解析加密文件时静默阻塞等待密码，既不报错也不出纸，彻底卡死打印队列。
15. **手写签名板只做了低清渲染，打印出来边缘全是非平滑锯齿**
    * *为什么*：Canvas 物理像素未适配 27 寸大屏的高 DPI，导出为 72 DPI 的图片打印到 300/600 DPI 的激光纸张上，签名呈现严重马赛克与模糊。
16. **合规功能边界失守：在求职材料模版中误放了“带单位公章”的企业录用类/介绍信模版**
    * *为什么*：模版库缺乏合规隔离审查，误将需要企业资质盖章的证明放入公益端，引发现场纠纷与公章伪造法律风险。
17. **在一体机上使用 U 盘打印时，直接读取 U 盘根目录大量非文档文件导致文件浏览器崩溃**
    * *为什么*：工友的 U 盘往往存有上万张杂乱生活照片、视频或潜伏病毒文件，未做后缀预筛选（仅放行 pdf/doc/jpg）直接全盘递归遍历会导致 Node/前端瞬间卡死。
18. **管理员在后台执行「紧急下架」政策后，一体机内存中仍缓存着该条政策，离线点击仍可查看甚至打印**
    * *为什么*：前端单页应用（SPA）使用了全局持久化状态且无 WebSocket / Push 唤醒机制，导致违规内容在物理终端上“阴魂不散”。
19. **打印机彩色墨粉耗尽但黑色充足时，黑白打印任务被误拦截**
    * *为什么*：打印 Agent 上报硬件状态粗暴使用了 `PRINTER_ERROR`，未区分是哪种耗材耗尽，导致黑白打印业务全部被连带阻断。
20. **用户未登录状态下扫描了文件，在最终确认时点击登录，页面刷新导致刚才扫描的图像数据被初始化清空**
    * *为什么*：登录路由跳转未妥善暂存当前的 Redux / Pinia / Session 内存状态，用户好不容易扫好的文件一登录全没了，引发极大挫败感。

### B. 容易被做成「死胡同」或「假装成功」的 10 个地方

| 序号 | 功能节点 | 典型的「死胡同」表现（卡住无法退出） | 典型的「假装成功」表现（虚假繁荣） | 合格的兜底设计要求 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **Word 简历转 PDF 失败** | 页面一直转圈提示“正在转换中...”，无任何超时机制，无【取消】按钮，用户只能走开。 | 界面直接跳到打印预览，但预览区域是一片空白或断裂图标，点击打印打出白纸。 | 转换设置 10 秒硬超时；失败时弹出提示“文档结构过于复杂”，提供【改用手机转为图片上传】或【手动录入】。 |
| **2** | **AI 岗位对照服务超时** | 请求超过网关时间，页面停留在“小青正在深度分析”，无返回、无终止、无报错提示。 | 强行套用一个毫无关联的兜底死模板得分（如“匹配度 60 分”），给出的建议与用户的 JD 完全不匹配。 | 明确告知用户“当前 AI 分析专线繁忙”，立即降级为【纯文本并排人工对照模式】，支持人工边看边改。 |
| **3** | **奔图打印机出纸过程中卡纸** | 屏幕一直停留在“正在出纸 3/5”，进度条定格，没有任何指引与退出按钮。 | 界面直接跳转到“打印完成，请取件”，但实际出纸槽空空如也，订单被后台标记为成功。 | Agent 捕获硬件卡纸码，屏幕切为红底故障排查指引动图；订单置为“异常中断”，生成补打凭证码。 |
| **4** | **手机扫码上传断开** | 一体机保持展示二维码，手机端网页闪退后，一体机无法得知手机状态，永远等待。 | 手机端显示“上传成功”，但一体机根本没收到文件，学生在一体机前傻等。 | 建立心跳探针；手机端上传成功必须等一体机回传 ACK 才算成功；一体机设 90 秒等待倒计时。 |
| **5** | **免登录复印身份证只扫了正面** | 工友扫完正面后找不到“扫反面”在哪里，误触返回导致正面数据丢失，只能从头来。 | 未扫反面就允许点击打印，直接在一张 A4 纸上打出一个孤零零的正面，背面空白。 | 严格的两步向导（向导式 Stepper），大字标明“第 1 步已完成，请翻转证件按第 2 步”，严禁单步早产。 |
| **6** | **U 盘拔出异常** | 在读取或打印中途用户把 U 盘拔掉，界面报底层 IO 异常白屏，不可交互。 | 假装文件还在列表中，点击打印后陷入无限无响应。 | 全局捕获设备断开事件，弹出温和提示“U盘已拔出”，自动安全回退至 U 盘选择根页面。 |
| **7** | **手写签名保存** | 签名后点击“完成”，因格式编码问题失败，按钮置灰无下一步，无法重新签。 | 用户明明画了签名，但合成到 PDF 时透明通道失效，变成一个纯黑方块挡住简历文字。 | 保持画布独立图层；保存失败时高亮【重试】并允许【清空重写】；本地离线合成先行校验 Alpha 通道。 |
| **8** | **短信验证码超频或被拦截** | 点击获取验证码后无反应，界面也不提示原因，倒计时置灰无法再次点击。 | 显示“发送成功”，但后台由于欠费或频控根本没发出去，用户苦等 60 秒徒劳无功。 | 接口精准透传错误码（如“今日次数超限/发送过于频繁”）；Mock 模式必须在屏幕或日志明确给出提示。 |
| **9** | **机构发布政策附件为空** | 机构在后台发布政策时选了附件但上传失败，系统直接发布，终端用户点击打印附件报错 404。 | 前台显示有附件下载/打印按钮，用户点击后无任何反应，像坏了一样。 | 发布前强制拦截“空附件关联”；前台若检测到附件未就绪，隐藏打印附件按钮并提示“请咨询经办柜台”。 |
| **10**| **平台管理员紧急下架** | 机构端正在查看该政策时被管理员下架，点击任何按钮报全局 500 异常。 | 政策下架后，前台一体机仅隐藏了标题，直接输入 URL 或从历史浏览仍能打开已下架内容。 | 下架策略全局路由强拦截，返回专用的友好 410 Gone 占位页：“该政策已被下架处置”，并引导回主列表。 |

### C. 两端（一体机↔小程序）和两后台（管理员↔机构）最容易对不上的 10 个数

| 序号 | 核心指标 / 数据项 | 出现账差的典型原因与场景 | 判定对齐的标准与正确表现 |
| :--- | :--- | :--- | :--- |
| **1** | **打印纸张消耗总数**<br>（A4 张数） | 双面打印计算错误（如 4 页文档双面打印实际消耗 2 张纸，但统计模块按页数算了 4 张）；单面/双面计费模型混淆。 | **消耗张数 = ceil(单面页数) + ceil(双面页数 / 2)**。无论在一体机、小程序订单、两后台大屏，纸张物理消耗数必须完全相等。 |
| **2** | **订单实付金额**<br>（试运营补贴金额） | 试点期全额抵扣，某端将原价（如 ¥1.00）记为流水，另一端按实收（¥0.00）记，导致财务报表出现虚假应收与对账不平。 | 所有端一律严格记录：`应付金额 = ¥0.00`、`抵扣金额 = ¥0.00`、`实付金额 = ¥0.00`。任何端均不得出现隐性挂账。 |
| **3** | **服务人次 vs 订单总数** | 一个用户登录后连续打印了 3 份不同材料（产生 3 笔订单），机构后台把人次算成了 3 次，或者把免登录工友的多次打印漏记。 | **服务人次按「独立会话 / 独立账号」去重**（1 人 = 1 人次）；**服务订单数按实际支付成单数统计**（3 笔 = 3 单）。 |
| **4** | **AI 服务调用次数** | 用户进行了一次模拟面试，中途由于网络卡顿重试了 2 次，管理员后台扣减了 3 次，而用户前端记录只展示了 1 次完成记录。 | 业务层「服务记录」展示**有效交付次数（1 次）**；管理员「技术监控」展示**实际 API 物理请求次数（3 次）**，两者必须分字段隔离。 |
| **5** | **终端在线 / 离线状态** | 心跳上报周期不同步。Agent 已被拔电源，但管理员后台依然显示“在线”，直到 5 分钟后才变；机构工作人员以为机器正常，导致群众排队。 | 心跳超时判定阈值必须固化为 **90 秒**。超时未收到 Agent 探针，两后台大屏必须同步标红为 `离线`。 |
| **6** | **机构发布的有效政策总数** | 某机构自发了 5 条政策，其中 1 条被平台管理员「紧急下架」。机构后台统计看自发数是 5 条，一体机显示 4 条，大屏显示 5 条。 | 报表统计必须区分口径：`机构累计自发政策数 = 5`，`当前线上公开生效数 = 4`，`平台紧急下架数 = 1`。各端标签必须明晰。 |
| **7** | **简历解析与优化版本数** | 学生在一体机上导入一份 Word，点击优化生成了版本 B，然后只保存了 B。一体机“我的简历”显示 2 份，小程序由于草稿未同步只显示 1 份。 | 一体机上的瞬时生成草稿，在用户点击【保存】前仅存本地内存；一旦点击保存，必须通过后端 API 产生持久化版本，两端简历库条数保持一致。 |
| **8** | **取件凭证码与待取订单状态** | 用户下发了打印任务获得取件码 `A-108`，一体机已完成物理出纸，但网络延迟导致 ACK 未回传，小程序上订单依然显示“待取件/出纸中”。 | 终端 Agent 本地打印完毕必须先向一体机前端发出本地事件（Local Event）使屏幕完成跳转，同时向云端派发原子更新事务，状态延迟不得大于 2 秒。 |
| **9** | **敏感身份证扫描记录数** | 访客复印了 1 张身份证。机构后台数据统计显示“今日文件扫描量 +1”，但在文件管理列表里根本找不到这张图（因合规即焚），导致审计员质疑数据丢失。 | 业务计数器明确拆分为：`复印处理业务量（计数 +1）` 与 `合规归档文档存储量（不增加）`。报表中标注“即印即焚”，账目合规对应。 |
| **10**| **用户注销后的资产统计** | 管理员响应隐私请求彻底抹除了用户 A。在用户总数统计中，大屏立刻 `-1`，但历史产生的累计打印订单张数却被连带删除了，导致累计纸张消耗对不上。 | 严格执行**「数据主体销毁，业务凭证匿名化归档」**原则：用户主表记录物理注销（总用户数 -1），但其历史打印订单中的关联外键更新为 `GUEST_ANONYMIZED`，纸张总消耗量绝对保持不变。 |
