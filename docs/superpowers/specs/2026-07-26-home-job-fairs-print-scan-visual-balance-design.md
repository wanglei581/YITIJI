# 首页招聘会与打印扫描专区视觉平衡设计

日期：2026-07-26
产品：青序 LightFlow
状态：方案 A 已形成并完成本地候选验证，未推送/未部署

## 1. 背景与问题

Kiosk 首页在 1080×1920 原型画布中，“打印扫描”使用五列入口，尺寸与其他业务组协调；但在小于 760px 的窄屏响应式布局中，五列会折为两列。现有纵向磁贴仍沿用 90px 的竖排结构，形成三排大面积蓝色块，其中主入口和禁用入口占据相近面积，视觉重量明显超过相邻“招聘会”专区。

本次只解决窄屏下两个相邻专区的视觉失衡，不重做首页信息架构，也不改变 1080×1920 原型真值。

## 2. 目标

- 以 390×844 和 390×700 为主要优化视口，降低“打印扫描”的纵向高度和色块强度。
- 保留“招聘会”与“打印扫描”各自的业务识别，同时统一标题、入口、间距和状态层级的节奏。
- 保持 1080×1920 一体机布局、底部动态专区和合规提示锚点稳定。
- 保留所有真实路由、入口顺序、文案语义、禁用条件、返回路径与既有功能。

## 3. 非目标与硬边界

- 不修改 API、DTO、Prisma、认证、权限、支付、打印/扫描任务状态机、Terminal Agent、AI 或 TRTC。
- 不修改岗位投递、招聘会预约或签到的合规语义。
- 不修改 `ProfilePage`、`/me/*` 或其相关生产文件。
- 不新增入口、假数据、演示状态、本地假设备状态或新的 UI 依赖。
- 不把本次窄屏增强反向定义为 86/82 视觉目标的全量 1:1 完成证明。

## 4. 已选方案

采用方案 A「分区有别，节奏统一」。

### 4.1 招聘会

- 保持现有单列轻量入口结构，不改变三项顺序：社会招聘会、校园招聘会、扫码签到。
- 保留麦金色品类识别：组卡左侧色条、组头图标和两个主入口图标继续使用麦金色 token，组卡容器维持纸色背景。
- 社会招聘会、校园招聘会只使用低饱和浅麦金背景，不使用整块实心麦金填充；实色只落在小面积图标容器上。
- 扫码签到维持纸色/中性色入口和麦金色描边图标，不增加主入口强调。
- 不改变招聘会现有单行高度和纵向间距；本次“弱化”只收敛背景与图标的色块层级，避免额外增加页面高度。

### 4.2 打印扫描

- 在首页手机竖屏（宽度不大于 760px）及手机横屏（宽度不大于 960px 且宽度大于高度）下，将现有竖排大磁贴收敛为两列紧凑横向磁贴。
- 保持既有 DOM 与视觉顺序：文档打印、证件复印、纸质扫描、格式转换、证件照打印。
- 前四项组成两列两行；最后一项“证件照打印”通栏，消除单项悬空和右侧空洞。
- 文档打印、纸质扫描仍是主能力，但强调限定为浅色容器与实色图标，不再形成整块高饱和背景。
- 格式转换保持普通可用态。
- 证件复印、证件照打印继续使用真实禁用态；采用中性低对比背景、明确的“即将上线”状态，不得伪装成可点击入口。

## 5. 视觉规格

### 5.1 窄屏排版

- 生效范围：首页手机竖屏 `width <= 760px`，以及手机横屏 `width <= 960px && width > height`；不得影响 1024×768 或 1080×1920 原型舞台。横屏判定不得依赖易受浏览器地址栏收放影响的固定高度阈值。
- 首页在该范围内必须使用真实手机视口排版，不得继续把 1080×1920 逻辑舞台整体缩小；否则 CSS 中不低于 56px 的触控目标会在物理屏幕上缩成约 20–25px。
- 打印扫描入口网格：2 列，列间距 6–8px，行间距 6–8px。
- 紧凑磁贴固定高度：80px，保证触控热区和五项等高；取消现有窄屏下 90px 竖排体量。
- 磁贴改为横向排列：图标在左、标题和说明在右；文字不得重叠或横向溢出。
- 通栏项占据两列，但视觉高度与普通紧凑磁贴一致。
- 卡片内边距和组头间距可适度收紧，但标题、说明和聚合页箭头不得隐藏。

### 5.2 状态层级

- 打印扫描的可用主入口：浅蓝背景、蓝色实心图标、正常文字对比度；这条规则不得应用到招聘会或首页其他业务组。
- 打印扫描的可用普通入口：纸色或极浅中性色背景、蓝色描边图标。
- 打印扫描的禁用入口：低对比中性色、虚线或弱描边、禁用鼠标样式，并保留“即将上线”。
- 招聘会继续使用第 4.1 节定义的麦金色 token，不得因打印扫描的蓝色层级规则改成蓝色。
- 不通过降低文字可读性来换取“弱化”；普通正文和标题与背景的对比度目标不低于 4.5:1，非文本图标/边界目标不低于 3:1。

### 5.3 动效与反馈

- 保留现有按压反馈，不新增装饰性动画。
- `prefers-reduced-motion: reduce` 下继续关闭位移反馈。
- 禁用入口不得出现可点击的 hover/active 反馈。

## 6. 响应式与一体机保护

- 1080×1920：维持现有五列打印扫描布局、卡片高度、动态专区和合规提示锚点；本次不得改变主画布布局合同。
- 390×844：两个专区完整可读，无横向溢出、文本裁切或触控目标过小。
- 390×700：首页使用 `mobile` 壳层语义并在真实视口内滚动，不得套用 1080×1920 舞台缩放；专区自身不得重叠、溢出或遮挡底部导航。
- 430×932、760×1024：继续使用同一 `.kiosk-home-mobile` 紧凑规则，不得在 421–760px 区间回退到桌面字号或列数。
- 844×390、932×430、932×800：按手机横屏处理，保持真实视口、底栏和滚动状态，不得重新套用缩放舞台。
- 800×932：宽度超过竖屏阈值且不是横屏，保持 staged kiosk 壳，锁定方向判定边界。
- 1024×768：继续使用 1080×1920 舞台等比缩放，不能被横屏例外误判为手机。
- 首页始终保留 `host/scaler/stage` DOM；响应式首页只把 `data-kiosk-stage-fit` 切换为 `off`，并使用 `100vw`、`100dvh`、`transform:none`，避免旋转时替换根节点导致状态或滚动位置丢失。
- 其他布局内路由继续沿用既有舞台策略；本次只修正首页窄屏，不把改动扩大为全站壳层迁移。
- “百宝箱”和“智慧校园”的显示门控、单卡通栏行为及入口必须保持不变。

## 7. 实现边界

预计只涉及以下文件类别，精确文件由后续实施计划确定：

- 首页结构作用域标识：`apps/kiosk/src/pages/home/HomePage.tsx`

- 壳层静态 verify：`apps/kiosk/scripts/verify-fusion-shell.mjs`
- 必要的浏览器视觉回归用例
- 必要的 `docs/progress/` 记录与 CCG 任务文件

如可通过稳定的现有组合类精确限定两个专区，则不增加新组件；如现有品类类可能误伤其他组，应给服务卡增加稳定的 group-id 作用域类。不得以标题文本 CSS 匹配或 `:nth-child()` 作为长期业务选择器。

## 8. TDD 与验收

### 8.1 RED

先新增静态合同，至少锁定：

- 窄屏打印扫描使用两列紧凑横向布局。
- 最后一项在窄屏通栏。
- 紧凑磁贴触控高度不低于 56px。
- 首页在手机视口下保留稳定 `.kiosk-stage` DOM，但 `data-kiosk-stage-fit="off"`、`transform:none`，且 KioskLayout 使用 `mobile` viewport 属性。
- 禁用状态和“即将上线”保留。
- 禁用磁贴不通过父级透明度弱化文字；标题、说明和状态标签使用明确的中性色，保持正文对比度目标。
- 招聘会与打印扫描分别使用稳定的 group-id 作用域，麦金色与蓝色规则不得串组或误伤首页其他服务组。
- 招聘会组卡保持纸色容器；两个主入口只使用浅麦金背景，扫码签到保持中性背景。
- 1080×1920 的五列布局与原型合同未被修改。

门禁必须在生产实现前失败，记录 RED 结果。
