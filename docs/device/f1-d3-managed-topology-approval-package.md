# F1 D3 managed 拓扑审批治理包（双模式）

> 状态：**空模板，不是生产批准，当前 F1 仍为 NO-GO。**
>
> B1–B9 技术输入、状态词法和关闭条件的唯一 SSOT 是
> [f1-d3-managed-topology-inputs.md](./f1-d3-managed-topology-inputs.md)。本文不重复保存主机、路径、
> 摘要或权限字段，只定义审批职责、签批索引和证据输出边界。

完整变更记录必须保存在仓库外受保护的位置：机构模式使用受限运维/审批系统；单一负责人模式可使用
负责人控制的受保护本地目录或私有云盘，并至少保留一份独立备份。仓库只允许记录非秘密的记录编号、
治理模式、动作、负责人身份引用、时间、证据引用、结论和原件摘要；不得记录密钥、token、密码、
环境变量值、连接串、日志正文或业务数据。

## 1. 使用边界

- 本模板只治理下一次 D3 只读预检的申请和签批，不授权 SSH、D4 Genesis、D5 切流或 D6 activation。
- 技术值只能填写到仓库外受保护记录，并按 B1–B9 字段 ID 引用；不得在本文复制第二套字段或状态。
- 所有 B1–B9 必填项均为 `VERIFIED_READ_ONLY` 前，D3 总体结论必须是 **NO-GO**。
- D3 PASS 不自动授权 D4、D5 或 D6；每层仍须独立、限时、具名授权。
- 普通聊天中的“可以”“继续”“按推荐”等回复不构成 SSH、D3、删锁、D4 Genesis、D5 切流或
  D6 activation 授权；生产授权必须使用本文定义的单一用途变更记录。

## 2. 治理模式与责任

每条变更记录必须显式选择且只能选择一种治理模式。两种模式共用同一 B1–B9 技术 SSOT，均不得
复制技术值、状态或关闭条件。

| 治理模式 | 适用场景 | 责任规则 |
| --- | --- | --- |
| `single-owner` | 当前只有一名真实负责人的公司 | 申请、业务、运维和安全决策可由同一名业主负责人承担；禁止虚构独立签批人 |
| `institutional` | 学校、政府、合作机构或多人团队 | 机构、运维、安全和 D3 核验职责分离；沿用联合复核 |

`single-owner` 只合并角色归属，不合并技术账户、证据门槛或授权闸门。一个自然人仍须使用相互分离的
部署账户与 API 运行账户，并满足 B9 权限矩阵。由 `single-owner` 切换到 `institutional` 时必须重新
取得机构签批；历史单人记录不得追溯视为机构三方批准。

### 2.1 单一负责人补偿控制

单一负责人模式缺少第二名人类复核人，因此以下控制缺一即 **NO-GO**：

1. 变更记录先于操作生成，包含单一动作和 RFC3339 起止窗口；过期必须重新记录。
2. release provenance、Genesis/activation、路径类型、摘要和参数契约等确定性门禁保持 fail-closed。
3. 完整原件在仓库外受保护保存并备份；执行账户不能删除唯一原件和全部备份。
4. 部署账户与 API 运行账户继续分离，不因两者由同一自然人管理而放宽 ACL。
5. 每个动作结束后先形成脱敏证据和 PASS / NO-GO，再申请下一动作。
6. 自动测试和 AI 只能提供技术意见或触发 NO-GO，不能自动产生生产 GO。

### 2.2 AI 技术复核（非审批）

AI 只形成“只读技术核对意见”，用途等同于静态分析、测试和规则比对。AI 不得进入签批人、批准人、
负责人或执行人字段；AI 的 APPROVE 不会改变 GO / NO-GO，也不能替代真实自然人的具名决定。AI 发现
状态缺口、证据污染、秘密泄露或越权风险时可以触发 NO-GO。

**固定声明：AI 技术复核不构成生产审批，不是组织或法律责任主体。**

### 2.3 机构职责分离

| 角色 | 必须完成 | 禁止事项 |
| --- | --- | --- |
| 申请人 | 提交审批索引和 B1–B9 受限记录引用 | 自行批准；填写秘密值；猜测技术输入 |
| 机构负责人 | 批准业务窗口、资产归属和责任人 | 替代运维或安全负责人做技术签批 |
| 运维负责人 | 批准 managed 拓扑、PM2、路径和零流量核验方法 | 以 legacy `online` 或 HTTP 200 代替 managed 证据 |
| 安全负责人 | 批准账户/ACL、control root 留存、锁恢复和审计方式 | 让执行账户同时拥有记录删除与审批权 |
| D3 只读核验人 | 按已批准 B1–B9 引用核验并登记状态 | 触发生成、激活、重启、删锁或切流 |
| D4–D6 执行人 | 仅在后续独立授权中执行 | 把 D3 PASS 当作后续操作授权 |

## 3. 单一用途变更记录索引

以下五种动作必须分别建立记录，不得用一条宽泛授权覆盖多个阶段：

| 动作类型 | 允许范围 | 前序动作是否自动授权 |
| --- | --- | --- |
| `D3_READONLY_PRECHECK` | 限时生产只读核验；连接方式和只读命令使用白名单 | 否 |
| `RESIDUAL_LOCK_DISPOSITION` | 两把锁只读判定后的独立处置 | 否 |
| `D4_GENESIS` | 平行 Genesis bootstrap | 否 |
| `D5_CUTOVER` | 负载层切流 | 否 |
| `D6_ACTIVATION` | 稳态 activation | 否 |

| 字段 | 申请人填写 | 判定规则 |
| --- | --- | --- |
| 变更记录编号 | `<CHANGE_RECORD_ID>` | 在仓库外记录系统内唯一、可追溯 |
| 治理模式 | `<GOVERNANCE_MODE>` | 只能为 `single-owner` 或 `institutional` |
| 动作类型 | `<ACTION_TYPE>` | 只能选择上表中的一个动作 |
| 负责人身份引用 | `<RESPONSIBLE_OWNER_REF>` | 真实自然人；不得填写 AI 或虚构角色 |
| 原件 SHA-256 | `<CHANGE_RECORD_SHA256>` | 仓库外完整原件的 64 位小写 hex |
| 候选 Git commit | `<FULL_40_HEX_COMMIT>` | 与候选 CI 和 source archive 一致 |
| 候选 CI 证据 | `<CI_RUN_ID_OR_APPROVED_EVIDENCE_REF>` | 只记引用和结果，不复制日志正文 |
| B1–B9 记录引用 | `<RESTRICTED_B1_B9_RECORD_REF>` | 指向受限系统内的完整非秘密输入记录 |
| 技术复核引用 | `<TECHNICAL_REVIEW_REF>` | 只读自动门禁 / AI 意见引用；必须标明“非审批” |
| 操作前/后证据引用 | `<PRE_POST_EVIDENCE_REF>` | 只记脱敏引用和结论，不复制日志正文 |
| 授权窗口 | `<RFC3339_START>` / `<RFC3339_END>` | 仅对本记录动作有效；窗口外不得执行 |
| 负责人结论 | `<GO_OR_NO_GO>` / `<RFC3339>` | 真实自然人具名；不能由 AI 自动产生 |

完整记录保存在仓库外受保护位置并备份；Git 只保存本节白名单字段。禁止保存密码、token、私钥、
OTP、环境变量值、连接串、Cookie、完整 PM2 dump、日志正文、业务数据或个人隐私数据。

## 4. B1–B9 责任映射

签批人只对 [managed 输入清单](./f1-d3-managed-topology-inputs.md) 的字段 ID 作批准或拒绝：

| 范围 | `single-owner` | `institutional` 主责 / 联合复核 |
| --- | --- | --- |
| B1–B4：主机、PM2、current、control root | 业主负责人 | 运维负责人 / 机构、安全负责人 |
| B5、B9：长期留存、权限、残留锁 SOP | 业主负责人 | 安全负责人 / 运维负责人 |
| B6–B7：launcher 与 runtime contract | 业主负责人 | 运维负责人 / 安全负责人 |
| B8：零流量证明 | 业主负责人 | 运维负责人 / D3 只读核验人 |

任一字段缺失、拒绝、为占位符，或状态仍为 `UNSET`、`NOT_VERIFIED`、`BLOCKED`，均不得签出 D3 PASS。

## 5. 两类残留锁的独立处置

| 锁 | 固定位置 | 默认结论 |
| --- | --- | --- |
| Genesis lock | `<DEPLOYMENT_CONTROL_ROOT>/GENESIS.lock` | 存在即 D3/D4 NO-GO，不得擅自删除 |
| Activation lock | `<MANAGED_CURRENT_LINK>.activation.lock` | 存在即 D3/D6 NO-GO，不得擅自删除 |

每把锁都必须执行“只读判定 → 单独具名授权 → 处置后证据复核”。D3 审批包本身不授权删除，
本文也不提供删除命令。任何 intent/success/failure 记录缺失或疑似被篡改时，必须升级为 control root
事故并保持 **NO-GO**，不得重新 Genesis 覆盖事实。

## 6. 签批与结论

每条记录只能使用与其治理模式匹配的签批区。两种模式下，技术复核引用均单独登记为“非审批”，
不得填入任何签批角色行。

### 6.1 `single-owner`

| 记录角色 | 姓名/身份引用 | 结论 | 时间 | 仓库外记录引用 |
| --- | --- | --- | --- | --- |
| 业主负责人 | `<RESPONSIBLE_OWNER>` | GO / NO-GO | `<RFC3339>` | `<REFERENCE>` |
| D3 只读核验执行记录 | `<RESPONSIBLE_OWNER>` | PASS / NO-GO | `<RFC3339>` | `<EVIDENCE_REFERENCE>` |

单一负责人可以同时承担申请、业务、运维、安全决定和 D3 只读核验，但必须使用真实身份；不得虚构
独立角色。只有补偿控制全部满足、原件摘要可比对且 B1–B9 全部为 `VERIFIED_READ_ONLY` 时，业主负责人
才可对当前 D3 动作给出 PASS。该 PASS 仅关闭当前 D3 记录，不授权任何后续动作。

### 6.2 `institutional`

| 签批角色 | 姓名/工号 | 结论 | 时间 | 审批系统记录引用 |
| --- | --- | --- | --- | --- |
| 申请人 | `<APPLICANT>` | 已提交 | `<RFC3339>` | `<REFERENCE>` |
| 机构负责人 | `<INSTITUTION_OWNER>` | 批准 / 拒绝 | `<RFC3339>` | `<REFERENCE>` |
| 运维负责人 | `<OPS_OWNER>` | 批准 / 拒绝 | `<RFC3339>` | `<REFERENCE>` |
| 安全负责人 | `<SECURITY_OWNER>` | 批准 / 拒绝 | `<RFC3339>` | `<REFERENCE>` |
| D3 只读核验人 | `<AUDITOR>` | PASS / NO-GO | `<RFC3339>` | `<EVIDENCE_REFERENCE>` |

仅当三位负责人全部具名批准、原件摘要可比对、B1–B9 全部为 `VERIFIED_READ_ONLY` 时，D3 核验人
才可形成新的只读审查报告。无论采用哪种模式，空模板和治理包本身都不会改变 production F1 的
**NO-GO** 状态。

## 7. D3 输出白名单

只允许留存以下脱敏结论：候选 commit/CI 引用、B1–B9 字段状态、节点类型与权限结论、文件
SHA-256 比对结论、PM2 的 name/status/cwd/script/args 白名单字段、`100% legacy / managed 0%`
结论，以及两把锁和 control 记录的组合状态。

禁止输出 `pm2 env`、全量 `pm2 describe/jlist`、环境值、`.env`、连接串、日志正文、用户文件或业务数据。

## 8. 硬停止条件

出现任一情况必须停止并记录 **NO-GO**：

1. 空模板、占位符、未签批文件或猜测值被当作生产批准。
2. 本审批包与 B1–B9 输入清单、runbook 或当前源码不一致。
3. 治理模式未明确、同时选择两种模式，或使用普通聊天回复代替单一用途生产授权。
4. 单一负责人模式虚构独立签批人、把 AI 当作批准人，或任一补偿控制未满足。
5. 机构模式任一必需签批不完整，或任一 B1–B9 字段未达到 `VERIFIED_READ_ONLY`。
6. 变更记录缺失、过期、动作范围不明确、原件摘要无法比对，或一条记录覆盖多个生产动作。
7. 无法证明 managed 与 legacy 隔离、managed 零流量、权限分离或 control root 长期留存。
8. 审批记录或证据中出现秘密、环境值、日志正文或业务数据。
9. 任一残留锁/control 状态未知，或处置缺少独立具名授权。
10. 只读预检需要扩大为 Genesis、activation、reload/restart、删锁、切流或其他写操作。

满足本文只能产生“可以另行申请 D3”的输入，不会自动授权 D4–D6。
