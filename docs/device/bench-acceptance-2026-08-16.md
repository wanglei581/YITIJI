# 一次台架验收，解开四个卡点（2026-08-16）

> **为什么合成一场**：截至 2026-08-16，有四件事各自卡住一条产品链路，而它们**全部只能在真机上确定**。
> 分开做要跑四趟，合并成一场台架、一台机器、一个下午。
>
> **执行者不需要懂代码。** 每项都写明「怎么做 / 看什么 / 记什么」。
> 判定不了就写「判定不了」——**空着比猜着有用**。

---

## 0. 这一场解开什么

| 测项 | 现在卡住的是 |
|---|---|
| A 扫码器 | 取件码核销、付款码支付两条链路能不能用 |
| B 麦克风 | 模拟面试语音功能（生产构建里**强制开启**，却从没对真设备跑过） |
| C 彩色打印 | 证件照整条路（服务端目前 `@IsIn(['black_white'])` 硬拒彩色） |
| D 尺寸精度 | 证件照对 mm 零容忍，`scale:'actual'` 从没量过 |

**每项都可能推翻现有结论。** 例如 A 若发现扫码器出厂是虚拟串口而非 HID 键盘，那么「扫码零集成」这条决策（章程 D-4）当场作废，需要在 Terminal Agent 里新写串口读取。

## 2. A · 扫码器（最先做，它最可能推翻结论）

### A1 · 出厂是 HID 键盘还是虚拟串口？

**做**：把扫码模组插到这台 Windows 上 → 打开记事本 → 光标放进去 → 扫任意一个二维码。

**看**：

| 现象 | 结论 |
|---|---|
| 记事本里直接出现一串字符 | **HID 键盘模式** ✅ 现有代码零改动可用 |
| 什么都没有 | 大概率是**虚拟串口 / COM 模式** ⚠️ 需按说明书切到 HID 键盘模式；切不了就要在 Agent 里新写串口读取 |

**记**：出现的字符串原样抄下来（含首尾有没有多余字符）。

### A2 · 后缀是什么？

**做**：接着 A1，观察扫完之后光标的位置。

**看**：换到下一行 = 回车后缀；跳到下一个输入框/缩进 = **Tab 后缀**；停在原地 = 无后缀。

**判**：**回车或无后缀都行。Tab 不行**——一体机上会导致焦点跳走。是 Tab 就按说明书改掉。

### A3 · 能不能读手机屏幕？

**做**：手机上打开**小程序的取件二维码**（若还没有，用任意二维码代替），亮度调到最高，对着扫码模组。

**看**：记事本里出没出字符。

**判**：读得到 = 影像式 ✅。读不到 = 可能是激光式，**取件码与付款码两条链路都判死**，只能退回手输，需要换硬件。

**记**：读到的字符串、以及大概多远距离、多久读上。

### A4 · 付款码能不能读？

**做**：手机打开微信「收付款」→ 付款码页面 → 对着扫码模组。**支付宝同样测一次。**

**看**：记事本里应出现 **18 位纯数字**。

**判**：读不到就是付款码支付走不通。

**记**：位数（应为 18）。**不要把码本身抄进记录或截图**——它是一次性支付凭证。记「18 位，读到了」即可。

### A5 · 误扫会不会串进别的输入框？

**做**：记事本里先手打几个字，然后**不动光标**直接扫一个码。

**看**：扫到的内容是不是接在你打的字后面。

**说明**：这是**预期行为**（HID 就是键盘）。项目已经加了全局防护（PR #648），这一项是**记录硬件行为**，不是找 bug。嵌入式模组常亮自动触发，所以误扫是默认状态而非意外。

**记**：模组是不是一直亮着、有没有触发距离、大概多远会自动读。

## 3. B · 麦克风（第二做，因为它可能压根不存在）

### B1 · 这台机器有没有音频输入设备？

**做**：Windows 右下角喇叭图标 → 右键 →「声音设置」→ 看「输入」一栏。

**看**：有没有列出任何输入设备。

**判**：一条都没有 = **这台机器没有麦克风**。

**背景**：设备验收文档的外设清单只有 4 行、**没有麦克风**；「Windows 麦克风/触控录音验收」至今未勾选；所有通过的语音测试用的都是 `--use-fake-device-for-media-stream` 假设备。而语音功能在生产构建里是**强制开启**的。

### B2 · 插上摄像头之后呢？

**做**：把海康 USB 摄像头插上 → 回到「声音设置」→ 刷新。

**看**：输入列表里有没有多出一个（通常叫 "USB Camera" 或型号名）。

**判**：多出来了 = 这颗摄像头的麦克风能用，**语音功能有救**（而且是零开发，直接可用）。

**记**：设备名原样抄下来。

### B3 · 真的能录到声音吗？

**做**：Windows「声音设置」→ 输入 → 对着说话，看音量条动不动。

**记**：动 / 不动。不动就查一下是不是被静音或权限挡了。

## 4. C · 彩色打印（决定证件照整条路）

> ⚠️ 服务端目前**硬拒彩色**（`@IsIn(['black_white'])`）。这一项测的是**打印机本身能不能打彩色**，
> 不需要动代码——直接从 Windows 打印，绕开我们的服务端。

### C1 · Windows 直接打彩色

**做**：找一张彩色图片（或彩色 PDF）→ 右键打印 → 选奔图那台 → 打印设置里选**彩色** → 打。

**看**：出来的纸是不是彩色。

**判**：能出彩色 = 硬件没问题，服务端那道闸可以按流程解开。出不来或报错 = 记下报错原文。

**记**：颜色还原大概怎么样（偏色？发灰？）——证件照对底色（白/蓝/红）敏感。

### C2 · 自动双面

**做**：打一份 2 页以上的文档，打印设置里选**双面**。

**记**：能不能自动双面、有没有卡纸。

### C3 · 纸张类型

**做**：打印设置里找「纸张类型/介质类型」，看有没有「厚纸 / 铜版纸 / 照片纸」这类选项。

**记**：有哪些可选项。

**背景**：我们的 `paperType` 字段目前**端到端不通**（DTO 直接 400），没有任何方式告诉打印机「这是厚纸」。这一项是看驱动侧到底提供了什么，决定后续要不要打通。

### C4 · 证件照实际效果（只有真机能答）

**做**：拿一张排好版的证件照图（比如一张 A4 上排 8 张一寸），用 C1 的方式**彩色打印**。若带了激光专用厚纸，两种纸各打一张。

**看**：出来的照片能不能用于报名 / 贴简历。

**记**：普通纸效果、厚纸效果、你的主观判断（能用 / 勉强 / 不能用）。**拍张照留证。**

**这一项没有代码能替你回答。**

## 5. D · 尺寸精度（证件照零容忍）

### D1 · 打一张已知尺寸的图，量它

**做**：准备一个 A4 PDF，上面画一个**边长正好 50mm 的正方形**（或任意已知尺寸的矩形）。
打印时**关掉「适应页面 / 缩放」**，选「实际大小 / 100%」。

**看/量**：用直尺量打出来那个正方形的边长。

**记**：量到多少 mm。

**判**：50mm ± 1mm 以内 = 精度够。差得多 = `scale:'actual'` 这条链路在真机上不成立，证件照要另想办法。

**背景**：代码路径通到 SumatraPDF 的 `noscale`，但**没人真机量过**。证件照差 2mm 就会被报名系统拒。

## 8. 结果回来之后会推翻/确认什么

| 结果 | 影响 |
|---|---|
| A1 是虚拟串口 | **章程 D-4「扫码零集成」作废** —— 要在 Agent 里新写串口读取 |
| A3 读不了屏幕 | 取件码与付款码两条链路判死，需换影像式硬件 |
| B1+B2 都没有麦克风 | 语音功能在生产上是**空承诺**，必须按能力门禁置灰（PR #FIX-HW-TRUTH 正在做探测三态） |
| C1 打不出彩色 | 证件照整条路封死，与代码无关 |
| C4 效果不能用 | 即使解开彩色闸门，证件照也不该做——要么换打印方案，要么放弃该品类 |
| D1 偏差大 | `scale:'actual'` 不可信，证件照排版方案要重做 |
