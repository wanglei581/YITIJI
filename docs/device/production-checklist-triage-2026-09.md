## 这份分类不保证什么

- **A 类只说明仓库里有门禁在断言这件事的软件不变量，并且本轮退出码为 0。** 不代表断言面覆盖了清单项的全部含义。例如 `verify:activity-logs` 证明跳转记录模型没有投递结果字段，不证明生产域名上点「去来源平台投递」已经用真实岗位走通（那条仍在 E）。`verify:compliance-copy` 扫的是源码字符串，不扫生产 CDN 上正在服务的旧 bundle。
- **A 类绿不等于源清单可以打勾。** 源清单的 `- [x]` 口径是「有可复核的生产/现场证据」。本文件不改勾选。
- **名字像、或 CI 里有过 PASS，都不自动进 A。** 本轮另外实跑过、但**没有**用来把清单项标成 A 的门禁包括：`verify:production-runtime-gates`（exit 0，仍把「生产 NODE_ENV 下闸门已执行」留在 B）、`verify:demo-seed-guard`（exit 0，生产是否跑过 seed 仍要 SQL）、`verify:word-conversion-ui` / `verify:renshi-policy-ui` / `verify:scan-input-safety` / `verify:usb-import-agent` / `verify:print-scan-first-release` / `verify:print-parameter-capability` / `verify:job-info-ui` / `verify:p39-print-hub-fidelity`（源码契约或假服务，覆盖不了生产 capabilities、真 U 盘、真扫码枪、真岗位数据）。
- **B 不保证有人已经持有 SSH。** 只说明这条离开服务器/生产 env/云控制台就证不了。
- **C 不保证现场还有那台机器。** 进度文档里有过「用户没有一体机整机、只有主机+打印机」的口径；本分类不裁决 BL-03，只把需要硬件的项标出来。
- **D 不保证授权函已经在谈。** 只说明工程做不了，要法务或来源机构。
- **E 不保证账号已经发下来。** 本地探针/会员闭环证据明确写了「本地 PASS 不等于可勾」；本分类把那些项留在 E，避免把夹具绿当成生产验收。
- **复合项按最保守的缺口归类。** 一条里同时要门禁、服务器、真机、账号时，只要门禁盖不住全部含义，就不进 A。
