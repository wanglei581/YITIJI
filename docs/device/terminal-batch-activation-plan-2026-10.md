## 一句话结论

现在一台一台装：现场要人选打印机、粘贴 20 位绑定码，码最多 60 分钟就过期。后台一次只能建一台。没有防克隆，令牌 365 天到期后也不会自动续。

- **一期**的定位要说清楚：它是**单台免敲命令装机**，打下防克隆和长期运行的基础，**还不是批量**。11/13 第九次发布前做完，11/23 试点装机用（试点只装 1 台）。内容：
  - U 盘签名激活文件；
  - 插 U 盘、双击安装，自动激活；
  - 打印机没接好不卡安装；
  - 装完自检回报后台，网络慢会等，失败时把日志导出到 U 盘；
  - 令牌心跳续期；
  - 兑换失败可以重试；
  - 防克隆：多因子硬件指纹，疑似克隆就告警，由后台一键放行或吊销。
- **二期**（试点后，第二批设备进场前）才是真正的批量：后台批量建台、按批次导出激活包和二维码、成批看状态、打印机名由后台下发、换机一键切换。

一期约 14–18 人日，三个窗口并行，日历上约三周半，时间偏紧，退路见第四节。二期约 8–12 人日。

## 一、现状清单

### 1. 安装
- EXE 和 MSI 都能静默装：EXE 用 `/install /quiet`（`installer/test-exe-lifecycle.ps1:15`），MSI 用 `msiexec /i … /qn /norestart`（`test-msi-lifecycle.ps1:27`）。
- 除了内部用的 `AGENTBOUND`，**没有任何公开参数**（`Bundle.wxs:9-22`、`Agent.wxs:13-15`）。设计文档把静默参数定为「仅 CI 用」（`docs/device/windows-agent-msi-design.md:139-141`）。
- 新装后服务是「手动 + 停止」，绑定后才改「自动」（`Agent.wxs:36-44`，CI 断言见 `test-msi-lifecycle.ps1:287-288`）。已绑定的机器升级或修复后，安装包会恢复自动启动和失败重启（`Agent.wxs:17-26`）。
- 升级：CI 断言升级前后 ProgramData 逐字节不变、服务恢复（`test-exe-upgrade-lifecycle.ps1:143,214`）。**旧 Agent 正在打印、文件被占用时的现场热升级，代码确认，待真机验证**（可能返回 3010，要求重启）。
- 激活向导和控制中心里写死了生产地址和版本串（`provision-installed-agent.ps1:61,65`、`terminal-control-center.ps1:17-19`），每出一版都要改脚本。

### 2. 激活
- 只有一条路：管理员在后台给**一台**终端生成绑定码，现场运行向导，从列表里选打印机序号，再粘贴码（`provision-installed-agent.ps1:45-67`）。
- 绑定码：
  - 20 位、一次性，库里只存哈希；默认 10 分钟，最长 60 分钟（`services/api/src/terminals/terminal-utils.ts:15,144-150`、`dto/create-terminal-bind-code.dto.ts:3-9`）。
  - 只有管理员能生成，终端须处于「计划中」或「维护中」且没有在途任务（`terminal-credential-security.service.ts:74-176`）。
  - 重发即作废旧码（`:130-138`）。
- 兑换接口不需要登录，只限速（`terminals.controller.ts:67-71`）。
  - **兑换时**会检查网卡 MAC：已绑到别的终端就拒绝（`credential-security:231-236`）。
  - 兑换成功后，这台终端的旧令牌全部作废（`:352-355`），旧机器收到 401 就自锁（`apps/terminal-agent/src/agent/heartbeat.ts:192-203`）。
  - **兑换不是幂等的**：码一用即废。网络在响应回来之前断了，码就白白作废，只能重发。
- 后台一次只能建一台（`apps/admin/src/routes/terminals/CreatePlannedTerminalDialog.tsx:16-34`），不能导出。
  - 建台开关 `TERMINAL_PLANNED_PROVISIONING_ENABLED` 在生产上是 `true`：10/6 本窗口和总指挥各自只读核过。
  - 绑定码弹窗给出的命令指向仓库源码路径，不是安装后的路径（`TerminalBindCodeDialog.tsx:54-62`）。

### 3. 打印机
- 只能现场手选或手填（`install-production-agent.ps1:69-71,788-794`、`config-manager.ts:152`），后端不下发（`terminals-agent.service.ts:419`；`schema.prisma:21-62` 终端表没有这个字段）。
- 重跑安装脚本**不保留** printerName（`install-production-agent.ps1:347-403`）。

### 4. 身份与令牌
- 都放在 `%ProgramData%\AIJobPrintAgent`：`agent-config.json`、DPAPI 加密的 `agent.token`（`install-production-agent.ps1:555-576`），以及只给本机用的 `instance-id`（`instance-lock.ts:24-50,110`）。
- 升级、修复、卸载都保留：ProgramData 组件是永久组件（`Agent.wxs:92`），CI 已断言（`test-exe-lifecycle.ps1:68`）。
- 注册表 Bound 值由安装脚本写入（`install-production-agent.ps1:921-924`），不归 MSI 管；它所在的键由永久组件持有（`Agent.wxs:92-94`）。所以卸载不删：**代码确认，待真机验证**。这意味着卸载后重装会直接用回旧身份，而想清干净没有现成的脚本。
- 令牌有效期 365 天，不续期（`terminal-utils.ts:16`），**同一批装的机器会在同一天一起失效**。
- 防克隆：
  - 兑换时写入的指纹是 `sha256(主机名:网卡MAC)`（`install-production-agent.ps1:656-675`、`credential-security:247`），**之后从不比对**。
  - 心跳不带指纹，每次心跳都会**直接覆盖**终端的 MAC，不检查、不报警（`terminals-agent.service.ts:370-394`）。所以两台机器拿同一个当前令牌都能用。
  - 先激活再做母盘镜像的话，克隆出来的每台机器都是同一个身份。

### 5. 换机
- 能走通的流程：「维护中」→ 生成码 → 新机兑换 → 旧机令牌自动失效 → 手动恢复「运行中」。7/27 在 KSK-001 上实操过。
- 设计文档里的候选机预检加原子切换没有实现（`docs/device/terminal-fleet-management-design.md:3,89-115`）。
- 维修换件（换网卡、换硬盘）之后身份怎么处理，现在没有任何规定。

### 6. 测试
- 后端有绑定码、凭证、建台、身份四组门禁。
- Windows 上有 MSI/EXE 安装、修复、卸载、升级的测试。
- **没有**「安装 → 兑换 → 心跳」的端到端测试，也没有克隆测试。

## 二、方案

### 一期（单台免敲命令装机加防克隆基础，随 11/13 第九次发布）

**A. 签名激活文件**（后端接口按 `backend-reply.md` A 节定）
- 后台在终端行点「生成激活文件」，调 `POST /api/v1/admin/terminals/:terminalId/activation-file`（会生成新码、作废旧码），下载 `AIJobPrint-activation-<终端号>.json`。
- 文件内容：`{schemaVersion, terminalCode, bindCode, expiresAt, apiBaseUrl, printerNamePattern, kid, signature}`。
- 签名：Ed25519。签名对象是去掉 `signature` 后、按键名排序的规范 JSON 的 UTF-8 字节。私钥只放服务端环境变量 `ACTIVATION_FILE_SIGNING_KEY`（PKCS8，base64），生产写入要逐次请示产品负责人。安装包内置公钥表 `{kid: 公钥}`，装「当前」和「下一把」两把。轮换顺序：先发带两把公钥的安装包，服务端再切到新 kid，旧 kid 留到下一版安装包再删。没配私钥时接口回 503 `ACTIVATION_SIGNING_UNAVAILABLE`，不签发未签名的文件。终端先验签，签名不对就不用。
- 有效期：可选 24–72 小时，**默认 24 小时**（10/6 已定）。后端用环境变量 `TERMINAL_BIND_CODE_MAX_TTL_MINUTES` 控制上限：缺省 60，硬上限 4320。**拍板前生产上限是 60，激活文件实际只有 60 分钟**；拍板后要改生产这个变量，逐次请示。现有 bind-code 接口默认 10 分钟不变。
- **首次兑换绑定硬件指纹**：这张码第一次被某台机器兑换后，就只认这台机器。复制走 U 盘的人抢先兑换，真机器到场会报「已被另一台机器使用」，后台同时告警。这样抢先冒领至少当场可见，而且能马上作废重发。
- 文件里的 `apiBaseUrl` 必须在安装包内置白名单里，终端不信文件。
- `printerNamePattern` 来自部署配置 `TERMINAL_PRINTER_NAME_PATTERN`，不在代码里写死型号（CLAUDE.md §3）。不配就是 null。
- 激活成功后，U 盘上的文件改名为 `.used` 并清空内容。清空失败要在屏幕上提示，并写进审计。

**B. 一键安装激活**
- 现场流程：插 U 盘 → 双击 U 盘里的 `AIJobPrintTerminalSetup.exe` → 装完自动打开控制中心 → 找到激活文件 → 显示「将激活为 终端 XXX」→ 点「激活」→ 自检 → 显示结果。
- **同一个 U 盘放多个激活文件时**：控制中心列出全部终端号，**由装机人按机身上贴的终端号标签点选**。只有一个文件时自动选中。理由：终端号对应安装地点，按顺序领容易装错地方。备 U 盘时每台机器先贴好标签。
- **兑换可以重试**（后端约 1 人日，和「首次兑换绑定指纹」是同一件事）：本次安装生成一个 `installNonce`，和硬件指纹四项一起发给后端，码被兑换时后端记下 nonce 和这组指纹。码在有效期内，同一 nonce、同一组指纹（≥2 项一致）重发兑换，后端作废上一次签发的令牌、重新签发；换了指纹再来就拒绝（`BIND_CODE_USED`）并告警。4G 掉包不会把码作废。
- **打印机没接好不卡安装**：
  - 匹配到 1 台就直接用；
  - 匹配到 0 台时激活照常完成，终端进入「待接打印机」状态（后台可见，不领打印单）。看门狗每分钟查一次，打印机插好、驱动装上、只匹配到 1 台时自动接管；
  - 匹配到多台，或 pattern 为 null 时，控制中心让人点选，也可以以后再选。
- 重跑时保留上次的 printerName。
- 去掉写死：版本从安装包身份读，地址从激活文件读，再按白名单校验。

**C. 装完自检与回报**（接口按 `backend-reply.md` C 节）
- 自检项：`api_reachable`、`bind_exchanged`、`service_running`、`local_port_loopback_only`、`printer_ready`、`agent_version_match`、`first_heartbeat_ack`、`boot_print_guard`、`edge_kiosk_policy`，以及后端 10/6 同意加的第 10 项 `hardware_identity`（取到几项硬件身份）。
- 网络项**先等 4G 拨号**：退避重试，总共至少等 90 秒才判失败。
- 回报接口 `POST /terminals/:id/provision-report`，只带结论和原因码。后台终端行显示「上次装机自检：通过 / 失败（哪几项）」。
- **自检失败或回报发不出去时**，把诊断包导出到 U 盘根目录 `AIJobPrint-diag-<终端号>-<时间>.zip`。内容：自检结果、启动诊断、最近日志，不含令牌、用户文件名、账号。装机人拔盘交给本公司。

**D. 防克隆（总指挥 1、7 条；后端 10/6 晚确认的落地方式）**
- 母盘规矩：**先克隆，后激活**。母盘清单加一条：做镜像前 `%ProgramData%\AIJobPrintAgent` 里不能有 `agent.token`，Bound 值不能存在。
- 硬件指纹：**不含主机名，不含 MAC**。MAC 遇到 USB 网卡、开关无线都会变，后端另有记录。分项采集四项：SMBIOS UUID、主板序列号、MachineGuid、系统盘序列号，每项各自做 sha256（64 位小写十六进制），放进心跳字段 `hardwareIdentity: { smbiosUuid?, boardSerial?, machineGuid?, systemDiskSerial? }`。取不到的项不传（例如 UUID 全 0），在自检里标黄；至少 2 项才参与判定。
- 后端存档：凭证上存「当前认定的四项哈希」和 `identityLastSeenAt`，只在判为同一台的心跳上刷新。
- 判定：
  - 四项里有 ≥2 项与存档一致，判为**同一台**，刷新存档；
  - 有 <2 项一致，且 `identityLastSeenAt` 在 10 分钟内，判为**疑似克隆**（两台同时在用同一身份）：标 `suspectedCloneAt`，领任务、回执拒绝（409 `TERMINAL_IDENTITY_CONFLICT`），心跳和自检回报照常收，并发告警 `terminal_identity_conflict`；
  - 有 <2 项一致，且超过 10 分钟，判为**疑似换机或大修**：只告警，不停领任务；
  - 后两种都不改存档，同一回合只告警一次。疑似换机期间新机器的心跳一直对不上，要等管理员「确认换件」后才把存档换成新的一组。
- 现场**不自锁**（总指挥第 1 条）。后台三个按钮对应三个接口，都写审计：
  - 「放行」：`POST /api/v1/admin/terminals/:terminalId/identity/accept`，用最近一次上报的那组覆盖存档、清掉可疑标记；
  - 「确认换件」：`POST /api/v1/admin/terminals/:terminalId/identity/confirm-replacement`，效果同上，审计动作名不同；
  - 「吊销」：沿用现有紧急吊销接口，然后重发激活文件。
- 已记过指纹的凭证，之后心跳不带指纹的（回滚到旧版 Agent），只记日志、不拒绝。二期再收紧。

**E. 令牌心跳续期**（10/6 晚总指挥定：**放二期，2027-06-30 前必须上线**；一期先做「到期日可见 + 到期前 60 天告警」）
- 令牌剩余有效期不到 30 天时，心跳响应带回新令牌。Agent 原子写入 DPAPI，下一次心跳就用新令牌。新令牌第一次被用之前，旧令牌仍然有效，作为宽限。
- 续期只发给指纹判为同一台的凭证。疑似克隆的凭证不续期。
- 估计后端约 1 人日（要单独验「两台抢续期」和克隆判定的边界），终端 0.5–1 人日。
- 后端的意见：一期装的机器令牌最早 2027 年才到期（KSK-001 是 9/6 重新绑定的，约 2027 年 9 月到期；试点设备 11/23 激活，约 2027 年 11 月到期）。续期放一期就要挤掉第八次的「远程清空打印队列」。

**E1. 一期先做：令牌到期日可见与提前告警**（总指挥 10/6 晚定）
- 后端（10/6 晚确认）：终端列表每行加 `credentialExpiresAt: string | null`（ISO），取当前有效凭证（未吊销、generation 最大）的 `expiresAt`，没有凭证为 null。派生告警只用一个类型 `terminal_credential_expiring`，靠严重程度分两段：到期前 60 天起为 warning，标题「终端 {网点名或终端号} 的终端凭证将于 {北京日期} 到期」；过了到期日升为 error，标题「终端 {…} 的终端凭证已过期，需要重新激活」。只看 enabled 且 active 的终端；按「终端 + 凭证 id」计回合，重新激活换了新凭证告警自然消失。告警说明写「重新激活这台终端（生成激活文件）」，不写找工作人员。
- 管理员后台：终端列表加「令牌到期日」一列；新告警类型进告警页 TYPE_META、TYPE_FILTERS 和工作台 ALERT_ROW_ICON，否则 `verify:service-desk-dashboard-ui` 会红。

**F. 重装、升级、换机、换件、丢码**
- 升级：沿用现有机制。在途任务和文件占用下的现场热升级，放到 KSK-001 上真跑时验。
- 重装：卸载重装默认保留身份。另给一个「清除本机身份」脚本，删令牌、配置和 Bound 值，用于报废、转作他用、重新激活前。
- 换机：「维护中 → 生成激活文件 → 新机激活 → 旧机令牌自动失效 → 恢复运行」，写成一页现场步骤。新凭证的指纹从零开始记。
- 换件：上面 D 节的「确认换件」按钮。
- 丢码：重新生成即作废旧码，生成按钮旁写明这一点。

### 二期（试点后、第二批设备进场前）
1. 后台批量建台：输入前缀加起止号，一次建 N 台。
2. 按批次导出激活包：一个 zip，每台一个签名文件，加一张不含码的汇总表；另出可打印的二维码页，配合手机扫码激活。
3. 成批视图：按批次看激活、自检、指纹状态。
4. 打印机名由后台按台下发。
5. 换机一键：候选机预检加原子切换（F2）。
6. 心跳必须带指纹（收紧 D 节最后一条）。

## 三、改哪些地方、工作量

## 五、怎么验收
1. **Windows CI**（每个 PR 自动跑）：
   - 安装：新装、静默装成功，服务「手动 + 停止」；激活后改为「自动 + 运行」。
   - 升级：从 0.4.14 升到新版，身份、printerName、服务状态都不变。
   - 重装：卸载再装，身份保留；先清除身份再装，必须重新激活。
   - 续期：假后端在第 N 次心跳下发新令牌，之后只用新令牌，旧令牌宽限期内仍可用。
2. **本地验证脚本**（Windows 真机或虚拟机，本窗口跑）：
   - 克隆：把一台的 ProgramData 和 Bound 拷到另一台，两台同时在线。后端判为疑似克隆，暂停领任务并告警；后台点「吊销」后重发激活文件能恢复。
   - 换件：换掉一项指纹，静默更新；换掉三项，告警，但不停领任务。
   - 4G 掉包：兑换响应丢失后重试成功，码没有白废。
   - 多文件：一个 U 盘放三个激活文件，按标签选对。
3. **后端门禁**：首兑绑指纹、幂等重试、得分判定、暂停领任务的范围、续期、签名校验、白名单。
4. **KSK-001 真跑**：维护中 → 生成激活文件 → U 盘一键安装激活 → 自检全过 → 恢复运行。只算预演。
5. **试点设备**：11/23 装机记录每一步用时和自检结果。

## 六、拍板结果（产品负责人 10/6 晚「激活按推荐」，前 4 条全部按推荐；第 5 条总指挥定）
1. 激活文件有效期：推荐**默认 24 小时**，后台可选到 72 小时。一次性，首次兑换绑定那台机器，重发即作废。
2. 一期定位：**单台免敲命令装机加防克隆和续期基础**，批量导出和二维码放二期。试点只装 1 台，一期足够；第二批设备进场前做完二期。
3. 疑似克隆怎么处置：推荐**告警，加暂停这条身份领打印任务，由后台放行或吊销，现场不自锁**；换件只告警、不停。
4. 一期赶不上 11/13 时，试点按现有流程逐台装：推荐**是**。令牌续期必须在到期前补上。
5. **（10/6 晚总指挥已定：二期，截止 2027-06-30）令牌续期放一期还是二期**：后端建议二期，理由是最早 2027 年 9 月才有令牌到期，而且放一期会挤掉第八次的远程清空打印队列（P1，试点前必须有）。本窗口倾向**二期，但写死截止日：2027 年 6 月 30 日前上线**，并在后台终端列表显示「令牌到期日」，到期前 60 天告警。这样既不挤掉清空队列，也不会忘。

## 七、风险
- 激活文件在有效期内被复制走、抢先兑换：首次兑换绑定指纹，加上告警，加上一键作废重发，冒领当场可见、可恢复；默认 24 小时也缩短了窗口。
- 硬件项取不到，或者主板厂商把 UUID 写成全 0：分项采集、按得分判定，单项缺失不影响判定，自检标黄。
- 判定规则误伤：现场不自锁，只在两台同时在线时暂停领任务，后台一键放行。
- 工期偏紧：后端 10/12 才能开始，11/6 交 PR。终端侧先做不依赖接口的部分；退路见第四节。

## 附：终端侧装机自检原因码（草案 v1）

> 用在 `POST /terminals/:terminalId/provision-report` 的 `checks[].code`。格式 `^[A-Z0-9_]{1,64}$`。`ok=true` 时不带 code。
> 「后台显示」一列给管理员和运维看（可以写「联系技术人员」）。一体机屏幕上的文字另定，不在这张表里，也不能写找人。
> 终端侧实现以本表为准；要加码先改本表，再通知管理员后台窗口和后端。

| 检查项（key） | 原因码（code） | 后台显示 | 怎么处理 |
|---|---|---|---|
| `api_reachable` 能连上服务器 | `NET_TIMEOUT_AFTER_WAIT` | 等了 90 秒以上仍连不上服务器 | 查 4G 路由器有没有电、信号、流量，网线插好没有 |
| | `DNS_FAILED` | 服务器域名解析失败 | 同上；4G 卡欠费也会这样 |
| | `TLS_FAILED` | 和服务器的加密连接没建起来 | 查本机时间是否准确；联系技术人员 |
| `bind_exchanged` 激活码兑换 | `ACTIVATION_FILE_NOT_FOUND` | U 盘和安装包目录里都没找到激活文件 | 后台生成激活文件，拷进 U 盘根目录 |
| | `ACTIVATION_SIGNATURE_INVALID` | 激活文件签名不对，可能被改过或不是本系统生成的 | 重新生成激活文件，不要手改文件 |
| | `ACTIVATION_HOST_NOT_ALLOWED` | 激活文件里的服务器地址不在允许范围内 | 重新生成；文件来源可疑时作废并上报 |
| | `ACTIVATION_EXPIRED` | 激活文件已过期 | 后台重新生成（旧的自动作废） |
| | `BIND_CODE_USED` | 激活码已被别的机器用过 | 后台重新生成；若不是自己用的，按冒领处理并看审计 |
| | `BIND_CODE_INVALID` | 激活码无效或已被作废 | 后台重新生成 |
| | `TERMINAL_STATE_NOT_ALLOWED` | 终端不在「计划中」或「维护中」，或还有进行中的任务 | 后台把终端设为「维护中」并等任务排空，再重新生成 |
| `service_running` 终端程序服务 | `SERVICE_NOT_RUNNING` | 终端程序服务没有运行 | 远程看启动诊断；按验收手册 4.1 判断 |
| | `SERVICE_NOT_AUTOMATIC` | 服务不是「自动启动」 | 重跑一键激活；仍不行联系技术人员 |
| `local_port_loopback_only` 本机接口只听本机 | `LOCAL_PORT_NOT_LISTENING` | 本机接口 9527 没在监听 | 服务没起来时会连带出现，先看上一项 |
| | `LOCAL_PORT_EXPOSED` | 本机接口对外网卡开放了（安全问题） | 立即设维护，联系技术人员 |
| `printer_ready` 打印机 | `PRINTER_PENDING_CONNECT` | 还没接打印机（待接打印机） | 插好打印机 USB、装好驱动，程序会自动接管 |
| | `PRINTER_MULTIPLE_MATCH` | 匹配到多台打印机，需要人选 | 在控制中心点选正确的那台 |
| | `PRINTER_PATTERN_NOT_SET` | 服务器没配打印机型号规则，需要人选 | 在控制中心点选；或请技术人员配置 |
| | `PRINTER_NOT_READY` | 打印机在，但不是就绪状态（缺纸、卡纸、离线等） | 看打印机面板 |
| `agent_version_match` 版本一致 | `AGENT_VERSION_MISMATCH` | 运行中的终端程序版本与安装包不一致 | 重启服务后再测；仍不一致重装 |
| `first_heartbeat_ack` 首次心跳 | `HEARTBEAT_NOT_ACKED` | 服务器没收到这台机器的首次心跳 | 先看 `api_reachable`；再看服务 |
| | `HEARTBEAT_UNAUTHORIZED` | 服务器拒绝了这台机器的身份（令牌无效） | 重新生成激活文件再激活 |
| | `TERMINAL_IDENTITY_CONFLICT` | 这个终端身份同时出现在另一台机器上（疑似克隆） | 后台在告警里选「放行」「确认换件」或「吊销」 |
| `boot_print_guard` 开机打印防护 | `GUARD_TASK_MISSING` | 开机打印防护的计划任务不存在 | 重跑一键激活（专用一体机模式） |
| | `SPOOLER_NOT_MANUAL` | 打印服务不是「手动」启动，防护不生效 | 同上 |
| | `GUARD_LAST_RUN_FAILED` | 上次开机时防护没跑成功（可能有删不掉的残留作业） | 远程看 `boot-spool-guard.log`；联系技术人员 |
| `edge_kiosk_policy` 一体机浏览器策略 | `EDGE_POLICY_MISSING` | 一体机浏览器策略没写入 | 重跑一键激活 |
| | `EDGE_POLICY_MISMATCH` | 浏览器策略里的网址与本机配置不一致 | 重跑一键激活 |
| 通用 | `CHECK_ERROR` | 这一项检查本身出错，没有得到结论 | 看诊断包；联系技术人员 |
| `hardware_identity` 硬件身份（第 10 个键，后端 10/6 已同意；取到 4 项为 ok） | `HARDWARE_ID_PARTIAL` | 硬件身份只取到 2–3 项（不影响使用，标黄） | 记录即可 |
| | `HARDWARE_ID_INSUFFICIENT` | 硬件身份只取到 0–1 项，防克隆判定对这台不生效（标红） | 联系技术人员看主板信息；不影响打印 |

说明：
- `BIND_CODE_USED`、`TERMINAL_IDENTITY_CONFLICT` 与后端错误码同名，终端侧直接透传。后端返回别的错误码时，终端侧原样透传，后台按后端码表显示，查不到的显示「未归类（原码）」。
- `hardware_identity` 是第 10 个键，后端 10/6 已同意，白名单变成 10 项。后台按 `failedChecks: [{key, code}]` 区分黄（PARTIAL，防克隆照常生效）与红（INSUFFICIENT，写明「这台终端的防克隆判定不生效」），`failedKeys` 并存。
