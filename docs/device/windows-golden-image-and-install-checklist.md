# Windows 一体机 · 母盘镜像清单与现场装机 Checklist（一页纸）

> **正式终端以本清单为准（2026-09-29 补注）**：现有真机 KSK-001 是测试笔记本（横屏非触摸显示器、远程工具虚拟屏、管理员账号登录、装着个人微信与远程工具），A3、A8、A11、A11b、A12 基本都不满足。在它上面得出的结论，都要在按本清单装好的正式终端（27 寸竖屏触摸屏）上复验。
>
> 2026-09-05 首版。适用对象：现场安装人员（不需要懂代码）。上位文档：[production-agent-onboarding.md](production-agent-onboarding.md)（安装脚本参数）、[windows-host-acceptance-runbook.md](windows-host-acceptance-runbook.md)（真机验收）、[terminal-fleet-management-design.md](terminal-fleet-management-design.md)（批量与换机）。
> 硬规则：绑定码、桥接令牌、任何 token **只在提示框里输入**，不写进命令、工单、聊天、截图。安装包必须来自受控发布的签名 EXE/MSI，不从 Git 检出目录运行。

## B. 现场装机 Checklist（每台机器一遍，目标 15 分钟）

**装机前（后台，1 分钟）**
- [ ] B1 在管理员后台「设备 · 终端」**只预创建终端**：终端编码（如 `KSK-012`）、站点名称、所属机构。
      **此时不要生成绑定码** —— 生成挪到现场的 B5b。
- [ ] B2 记下终端编码与站点，确认打印机 Windows 识别名（B6 要按序号选，必须与 A6 一致）。

> **为什么绑定码不在这里生成（2026-09-10 修正）**：弹窗默认有效时长 **10 分钟**
> （`TerminalBindCodeDialog.tsx:66`，最长可设 60），而 B1 到真正使用它的 B6 之间隔着
> 路途 + 刷镜像 + 接线 + 装包 —— **按原顺序走，码到 B6 时基本已经过期**。
> C 段那行「绑定码提示无效 → 是否过期」正是这个流程自己造成的症状。
> 码是一次性、一码一机，过期只能回后台重开，现场白等。

**现场（12 分钟）**
- [ ] B3 刷母盘镜像（A13 登记的版本），开机自动进入桌面。
- [ ] B4 连好电源、网线、打印机 USB/网线、扫码器；打印机开机并有纸。
- [ ] B5 运行签名安装包（EXE），保持默认目录；安装结束服务 `AIJobPrintAgent` 应处于「正在运行」。
- [ ] B5b **在现场生成绑定码**（紧挨着 B6 做，不要提前）：管理员后台该终端行 →「生成绑定码」，
      **有效时长按现场情况设，建议 30–60 分钟**而不是默认 10；生成后弹窗只显示这一次，
      关掉就看不到了。按后台给出的命令安装（它用 `-PromptForBindCode` 交互输入，
      **不要把码写进命令行**，那样它会留在 PowerShell 历史里）。
- [ ] B6 双击桌面「设备绑定」（`provision-terminal.cmd`）：按序号选择打印机（必须与 A6 名称一致）→ 在提示框输入绑定码 → 等待「心跳在线」提示。如需 U 盘/扫码桥接，在同一向导里输入桥接令牌 —— **值见下方说明，不能现编**。

> **桥接令牌的值从哪来（2026-09-10 补）**：它必须与**已部署的 Kiosk 构建里内联的那个值完全相同**。
> Kiosk 侧是构建期内联（`apps/kiosk/src/services/auth/memberQrLoginApi.ts:8` 读
> `import.meta.env['VITE_TERMINAL_AGENT_BRIDGE_TOKEN']`），发布时由 GitHub Actions secret
> `KIOSK_TERMINAL_AGENT_BRIDGE_TOKEN` 注入（`deploy.yml:169` 未配置即拒绝发布）。
> **GitHub secret 写进去就读不回来**，所以现场要用的值只能取自团队自己保管的那份
> （设置该 secret 时用的同一个来源），完整流程见
> [gate-0k-usb-bridge-token-field-acceptance.md](gate-0k-usb-bridge-token-field-acceptance.md)。
>
> **输错或跳过不会报错，会静默降级**：扫码登录显示「本机扫码登录服务未正确配置，请使用手机号登录」
> （`ScanQrLoginPanel.tsx:237`），U 盘导入显示「当前终端未配置 U 盘导入，请联系现场工作人员」
> （`userErrorMessage.ts:79`）。手机号登录与其它上传方式仍可用 —— 这是设计上的诚实降级，
> **但如果你没预期到，会以为设备坏了**。
>
> 值丢了只能轮换：换新 secret → 重新发布 Kiosk → **每一台机器都要重配**。
- [ ] B7 重启一次。验证：自动登录 → Edge 全屏进入 Kiosk 首页 → 顶栏显示本机终端编码与「打印机在线」。
- [ ] B7a 在 Edge 地址栏（维护时临时退出 Kiosk）打开 `edge://policy`，确认 `LocalNetworkAccessAllowedForUrls`、`AudioCaptureAllowedUrls` 与 `AllowFileSelectionDialogs=0` 已生效；重启浏览器后不再出现“访问此设备上的其他应用和服务”或麦克风权限框，页头出现终端号。策略撤销使用安装脚本的 `-RemoveEdgeKioskPolicies`，或卸载后由受控脚本删除三项策略。
- [ ] B7b **逃逸实测**（对应 A11b）：在 Kiosk 全屏下依次按 `Alt+Tab`、Win 键、`Ctrl+Shift+Esc`，三个都不得露出桌面或任务管理器；再从任意上传入口打开文件选择框，确认点不进系统盘。**任一项能逃出去即视为未交付** —— 一期是普通 Windows 主机（口径「打开这个网站，在本地电脑能完成打印操作就行」），不是锁死的整机，这一条比二期更要紧。
- [ ] B8 现场三步实测：用手机扫码上传一页 PDF → 走完确认与支付（免费/测试价）→ 真实出纸；再做一次扫描原件 → 结果页显示真实文件。
- [ ] B9 在后台「设备机队」确认该终端：在线、版本号与发布计划一致、无告警。
- [ ] B9a 同版本重装后卸载列表只剩一条「AI Job Print Agent」注册（MSI 已开同版本升级）。
- [ ] B9b 断电重启后 Agent 自动恢复并在线（单实例改为进程退出即释放，真机-8）；已绑定终端升级或修复后，服务为 `Running` + `Automatic`，失败重启策略仍在（`sc.exe qfailure aijobprintagent.exe` 显示 60 秒、300 秒两次重启，真机-7）。**从 0.4.11 首次升级时安装包还认不出这台已绑定**：绑定标记（`HKLM\SOFTWARE\AIJobPrint\Agent` 下的 `Bound`）由 0.4.12 的生产安装脚本写入，所以这一次装完必须重跑一次生产安装脚本，此后的升级由安装包自行恢复。终端退役时删除 `Bound`，否则重装会尝试启动服务（没有配置时启动即失败并留一条诊断，无害）。两项以 Windows CI 的进程级与安装生命周期测试为准；装上新版后在真机按本条复验。

**交付（2 分钟）**
- [ ] B10 填写装机记录：终端编码、站点、镜像版本、安装包版本、打印机序列号、出纸照片、验收人。
- [ ] B11 把桌面「设备绑定」快捷方式保留（换机/重绑时用），管理员账号密码交给站点负责人保管，不留在机器上。

## C. 出问题先看这里

| 现象 | 先查 | 不要做 |
|---|---|---|
| 首页顶栏显示「未配置终端」 | Agent 服务是否运行；本地端口 9527 是否被占；重新运行「设备绑定」 | 不要在 URL 里手填终端编码 |
| 后台显示离线但机器在用 | 网线/DNS；`Test-NetConnection` API 域名 443 | 不要重装系统 |
| 「打印机离线」 | 打印机电源与 USB；`Get-Printer` 名称是否与 A6 一致 | 不要改驱动名 |
| 绑定码提示无效 | 是否过期（默认只有 10 分钟，B5b 已要求现场再生成并调长）、是否已被另一台用过；到后台重新生成 | 不要提前在办公室生成；不要把旧码发到群里 |
| Edge 白屏或退出全屏 | 看门狗是否在跑；手动重启 Edge | 不要退出 Kiosk 模式给用户用 |
| 用户能 Alt+Tab 切到桌面 | A11b 的 AssignedAccess / Shell Launcher 是否生效（`Get-AssignedAccess`）；是否用管理员账号登录了（A3 要求标准账号） | 不要只靠看门狗——它只管「被关掉」，不管「被切走」 |

> 换机（同一终端身份迁到新主机）与批量升级/回滚不在本页：按 `terminal-fleet-management-design.md` 的 F2/F3 流程，未落地前换机须先在后台把该终端设为「维护」并排空在途打印任务，再在现场生成换机绑定码；新主机兑换后旧主机凭证随即失效。**不要「停用」终端**：已停用的终端生成不了绑定码（2026-09-29 按 `terminal-credential-security.service.ts` 核对更正）。冷备主机与耗材见 [现场故障处置单](onsite-failure-recovery-runsheet-2026-09.md)「耗材更换与冷备」。

## D. 现场测试日一（P0-9 / next-tasks 1.7，一天做完）

> 在最终硬件（竖屏触摸屏 + 按 A 段装好的镜像）上做才算数；在 KSK-001 这类测试机上只算演练。每项留照片或回执，回执里不能出现个人信息。
> 取证脚本（管理员 PowerShell，只读）：`collect-field-day-evidence.ps1` 在每个动作前后各跑一次，例如 `powershell -ExecutionPolicy Bypass -File .\collect-field-day-evidence.ps1 -OutFile D:\field-day-before.md`。它在仓库 `apps/terminal-agent/scripts/` 下、不在安装包里，用 U 盘带到现场；原有的全量取证 `collect-field-evidence.ps1` 在安装目录的 `provision\` 下。
> `stale_lock_requires_operator` 这类「人工清锁」状态已不存在：单实例锁随 Agent 进程退出由系统释放，`agent.pid` 只是诊断记录，任何情况下都不要删。

| T6 | 断电重启 | 直接拔电源（不是关机），30 秒后上电：来电自动开机、自动登录、一体机自动全屏，Agent 服务 Running/Auto。再跑取证脚本，D2-0～D2-6 不得有 FAIL：扫描目录与 `_unclaimed` 没有超时残留，打印临时目录没有早于本次启动的 `task_*`，单实例锁在，最近一次启动诊断是本次开机后的 `AGENT_READY`；浏览器配置目录（D2-4）各项与断电前的回执对比，记下有没有上一位用户留下的数据 | 前后两份回执 |
| T7 | 逃逸键 | Win、Alt+Tab、Alt+F4、Ctrl+Shift+Esc、Ctrl+Alt+Del、屏幕四边滑动、触摸键盘，都离不开一体机界面。专业版拦不住 Ctrl+Alt+Del，要记下安全选项屏出现后能否回到一体机 | 视频 |
| T8 | 新键盘 | 插一把没登记过的 USB 键盘，按键无效；原扫码枪照常（A11c） | 视频 |
| T9 | 机箱与打印机位 | 都已上锁，线缆不外露；钥匙由谁保管写进回执 | 照片 |
| T10 | 系统与锁机 | 取证脚本 D1-1（系统版本与支持期）PASS；D1-4、D1-5 没有 FAIL；D1-6 列出的远程工具与 E 段批准的一致 | 回执 |

## E. 远程运维（P1-12）

- **远程桌面**：一台机器只保留一款经产品负责人批准的远程工具。工具账号归公司，不用个人账号；每次远程由现场或产品负责人当次同意；只在维护窗口用，时间、人员、目的、做了什么记进运维记录；远程期间不打开用户文件，不在一体机上登录个人或后台账号；维护结束退出工具。Windows 远程桌面（RDP）保持关闭（A11）。分配访问要求本机控制台登录，远程工具在分配访问会话下能不能用，要在最终硬件上实测后再定。
- **远程断电重启**：BIOS 开「来电自动开机」（A4），主机电源接一只能远程断电、上电并回报状态的智能插座，打印机单独一路电源，不跟着主机反复断电。只在 Agent 连不上、且后台没有进行中的打印任务时用：远程断电 30 秒再上电，然后看后台心跳恢复，再远程跑一遍取证脚本（D 段 T6 的判定）。
- **Agent 升级**：在线更新（D-02）还没有进候选，目前只能在现场或远程桌面里手工升级，步骤按 [windows-agent-upgrade-and-phase-f-recheck-2026-09.md](windows-agent-upgrade-and-phase-f-recheck-2026-09.md)：进维护、排空在途任务、装新版 MSI、恢复运行。已绑定终端升级后，安装包会自行恢复自动启动与失败重启（真机-7，B9b）；**从 0.4.11 首次升级时仍要重跑一次生产安装脚本**。装包不能降级（MajorUpgrade 拒绝旧版本），回退要先卸载新版、再装旧版，ProgramData 里的配置与令牌保留。
