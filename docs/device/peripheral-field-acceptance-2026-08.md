# 外设真机验收准备包（扫码枪付款码 + 面板扫描 SMB）

> 状态：**准备文档，未执行真机操作 / 未授权生产操作**。面向“无一体机整机、但有 Windows 主机 + 打印机（含扫描面板）+ 扫码枪”的现场验收；与 `windows-field-acceptance-runsheet-2026-08.md` 衔接，不复制既有标准。
> 基线：`main@c8389b5e`（2026-08-07）。

## 1. 现状与缺口（只读盘点）

| 外设                 | 代码现状                                                                                                          | 验收状态                  | 缺口                                                                                                                                   |
| -------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 扫码枪（HID 付款码） | `POST /orders/:id/code-pay` 付款码支付链路 + `code-payment-convergence` 自动收敛 cron；付款码不落库/不审计/不日志 | 未真机验收                | 微信需商户开通“付款码支付”；支付宝需现场探测扫码枪输出码制（当前记录 18 位 vs 支付宝 25–30 位）；HID 键盘输入与并发/查单边界需现场复核 |

> 二维码类扫码（登录 `/member/qr-login`、手机扫码上传 `/upload/phone`、招聘会签到等）均为“Kiosk 显示二维码、用户手机扫”，**不需要扫码枪或摄像头**。

## 2. 环境要求（Windows 主机，不需要一体机整机）

- Windows 10/11 x64；Edge/Chrome Kiosk 模式打开 `https://zyidai.cn`。
- Terminal Agent 服务 `AIJobPrintAgent` Running / Automatic；`127.0.0.1:9527` 仅监听本机。
- 打印机驱动识别名（现场 `Pantum CM2800ADN Series`）经 `printerName` 配置，不硬编码。
- 扫码枪 HID 即插即用（模拟键盘输入付款码）。
- 面板支持“扫描到网络 / SMB”并可在面板配置目标目录。
- 商户侧：微信商户“付款码支付”产品开通（如需被扫）；支付宝当面付/被扫配置（如适用）。
- 测试只用可丢弃账号与小额/免费单，不触碰其他会员数据。

## 3. 扫码枪 → 付款码支付验收

### 3.1 前置检查

- [ ] 商户“付款码支付”产品与参数（如线下门店商户编码）已配置；未配置时付款码支付应明确拒绝。
- [ ] 付款码自动收敛 cron（C5-8）已开启；Kiosk 退出后 pending/expired 仍能按渠道账本幂等收敛。
- [ ] 同一订单已有未完成支付尝试时，二维码与付款码互斥（先完成/过期再切换），防止双扣。

### 3.2 现场步骤

1. 收银页发起支付 → 选择“扫用户付款码”。
2. 扫码枪读取用户微信/支付宝付款码（HID 输入），提交 `code-pay`。
3. 渠道受理/查单 → 支付完成 → 进入打印履约（免费/已支付门禁不变）。
4. 失败场景：付款码无效/过期/格式不符 → 提示重扫，不把无效码发给渠道；渠道未决 → 只查单收敛，不立即改发二维码。

### 3.3 重点核对

- [ ] 付款码不进入 Storage/Cookie/URL/错误信息/审计日志。
- [ ] 支付宝：现场探测扫码枪输出码制；若为 18 位数字而支付宝码实际 25–30 位，链路应拒绝并提示，不得发送渠道。
- [ ] 自动收敛日志 `code-payment auto-converge: scanned=… paid=… released=…` 出现且计数合理。
- [ ] 完成/失败/退款后订单、支付尝试、打印任务状态一致。

### 3.4 证据

订单 ID、attemptId、渠道返回/查单结果、收敛日志、打印任务 ID、脱敏截图。

## 4. 面板扫描 → SMB 验收

### 4.1 前置检查

- [ ] Agent 配置 `scanWatchFolder` 为本地路径或已映射 UNC；路径存在且非 reparse point；Agent 进程可读。
- [ ] 打印机面板“扫描到网络 / SMB”目标与 `scanWatchFolder` 为同一目录（或面板落盘后同一目录）。
- [ ] 未配置 `scanWatchFolder` 时：Agent 跳过扫描监听，Kiosk 不显示“扫描仪就绪”等假硬件态。

### 4.2 现场步骤

1. Kiosk 创建扫描会话（`/scan/start` → 按服务端指令操作面板）。
2. 面板扫描到目标目录（PDF/图片）。
3. Agent `scan-watcher` 检测稳定文件 → deliver → COS/「我的文档」（按流程进入 OCR/预览）。
4. 失败/重试：文件不稳定、消失、重试超时、状态变更按既有规则隔离/重试，不伪造文件。

### 4.3 重点核对

- [ ] 日志出现 `scan-watcher: watching …`；deliver 完成有旁证。
- [ ] 扫描文件真实进入「我的文档」并可预览/用于后续流程。
- [ ] 失败场景有明确提示且不产生脏数据。

### 4.4 证据

扫描会话/文件 ID、Agent 日志行、面板操作记录、我的文档可见性、脱敏截图。

## 5. 摄像头决策

- **不接入**：当前无真实业务闭环（拍照识别、证件照、拍摄付款码均需新链路与门禁）；上线前收口阶段不新增非必要功能。
- 未来如需（如证件照拍摄、摄像头读付款码），须单独立项：先定义用途/隐私边界/文件与 TTL/能力门禁，再开发。
- 二维码类扫码不依赖摄像头或扫码枪。
