## 怎么用

每一条都是四段。缺「应该看到什么」的步骤不允许出现在本文件里。

1. **做什么** — 点哪个按钮、跑哪条命令、把什么东西放到哪。
2. **应该看到什么** — 屏幕/命令行上的字符串必须能在仓库 grep 到，并标 `（来源：路径:行号）`。仓库没有的文案（例如微信 App 里的「立即支付」）只写「此处应有状态提示」，不编。
3. **看不到时属于哪一类** — 用文末「问题分类」里的编号，不要现场发明新类。
4. **现场立刻能做的补救** — 只写站在机器旁 2 分钟内能做的事；不要「回去改代码」。

**依赖顺序不可跳。** 终端未绑定 → 一体机没有本机身份 → 打印任务 fail-closed。彩色 / 双面未登记 → 选了也会被拒。应付金额为 0 → 收银台走零元单，**测不到真实收款**。扫码枪只在收银台页消费付款码。小程序未发布 → G 段整段停在前置条件。

**不确定的写成「未验证」，不要写成肯定句。** 本脚本里标「未验证」的项，现场做完请把结果写进文末记录表，不要口头说「应该可以」。

## 0. 开始前（约 3 分钟）

### 0.1 核对现场物件

1. **做什么**  
   看一眼：Windows 主机已开机、有线网已插、奔图已开机且有 A4 纸、扫码模组（机身侧面接近感应区）已接上 USB。准备：一份 1～2 页 PDF（可丢弃）、一部能开微信的手机、管理员后台账号、小额可报销的真实付款（D 段会真实扣款）。
2. **应该看到什么**  
   打印机面板能亮、纸盒有纸。Windows 能打开浏览器。  
   驱动识别名现场曾确认为 `Pantum CM2800ADN Series`，但代码禁止硬编码型号，现场以 `Get-Printer` 列出的准确名称为准。
3. **看不到时属于哪一类**  
   ① 本机装机 / 打印机硬件。
4. **现场立刻能做的补救**  
   电源、USB/网线、换纸。驱动名对不上就先不要绑定——绑进去的 `printerName` 错了，后面全部出不了纸。

### 0.2 打开三个入口

1. **做什么**  
   - 管理员后台：浏览器打开 `https://admin.zyidai.cn/`（正式入口是子域；同主机路径 `/admin` 会落到一体机 SPA，那不是后台）。  
   - 一体机前台：`https://zyidai.cn/`（全屏 Kiosk 或本机 Edge）。  
   - 本机 Agent 状态页：`http://127.0.0.1:9527/local/panel`（只读，每 15 秒刷新）。
2. **应该看到什么**  
   - 后台登录页标题「管理员登录」，副文案「支持账号或手机号登录，登录行为将记录审计日志」（来源：`apps/admin/src/routes/login/index.tsx:344-345`）。  
   - 一体机首页有磁贴「打印 · 扫描」（来源：`apps/kiosk/src/pages/home/components/QxHomeView.tsx:178`）。  
   - 本机状态页标题区写「只读本机状态」「AI Job Print Terminal」「后台服务运行中 · 页面每 15 秒自动刷新」（来源：`apps/terminal-agent/src/local-api/status-panel.ts:84-86`）。若 Agent 还没装，这一页打不开——先做 A 段。
3. **看不到时属于哪一类**  
   ⑪ 网络 / 域名；或 ① 本机装机（9527 打不开）。
4. **现场立刻能做的补救**  
   后台务必走 `admin.zyidai.cn`。一体机走 `zyidai.cn`。9527 打不开就先装/启动 Agent，不要改 hosts 猜端口。

### 0.3 登录管理员后台

1. **做什么**  
   选「密码登录」，填「账号 / 手机号」和「密码」，勾选协议后点「登 录」（按钮原文带空格）。
2. **应该看到什么**  
   模式按钮「密码登录 / 验证码登录」（来源：`apps/admin/scripts/verify-admin-terminal-bind-code-ui.mjs:168``、`:373`）。提交按钮「登 录」（来源：同文件 `:441`）。登录成功后左侧有「设备管理」「打印扫描运维」「计费与对账」（来源：`apps/admin/src/layouts/AdminLayoutWrapper.tsx:91`、`:98-99`）。  
  > ⚠️ **稿上有、当前实现里未见**：「密码登录 / 验证码登录」 —— 屏幕上可能没有这句话，找不到**不代表设备故障**（核验方式：全仓代码 grep，2026-09-10）。
3. **看不到时属于哪一类**  
   ③ 后台账号 / 权限。
4. **现场立刻能做的补救**  
   协议没勾会拦登录。不要用验证码登录，除非该账号已经完成本人验证（页上写「验证码登录仅支持已完成本人验证手机号的管理员账号」，来源：同文件 `:491`）。

### 0.4 先看价目和支付通道（D 段的前置，放在最前以免白打一单）

1. **做什么**  
   后台点「计费与对账」→「价目配置」。再在本机 PowerShell（或手机浏览器）打开：  
   `https://zyidai.cn/api/v1/print/price-config`  
   `https://zyidai.cn/api/v1/payment/channels`
2. **应该看到什么**  
   - 价目表列名「价目项」，键对应「黑白打印（每页）」「彩色打印（每页）」（来源：`apps/admin/src/routes/billing/index.tsx:19-21`、`:349`）。记下两行的单价（元）和是否启用。  
   - `payment/channels` 应能看到已启用通道名。生产曾开通 `alipay,wechat`（文档记载，**现场以这次 GET 为准**）。通道展示名：`微信支付` / `支付宝`（来源：`apps/kiosk/src/pages/print/cashierStatus.ts:41-44`）。

3. **看不到时属于哪一类**  
   ⑤ 价目 / 零元跳过收银；或 ⑥ 支付通道未开通。
4. **现场立刻能做的补救**  
   两行单价都是 0：C 段仍可测出纸，D 段整段记「未验证（零元，收银被跳过）」。**不要现场擅自改价**——改价会立刻全端生效并记审计（来源：`apps/admin/src/routes/billing/index.tsx:73`）。需要改价时由你本人在「价目配置」确认框里改，并先看彩色行的 `description` 是否还写着免费试运营（开通彩色前必须先改描述，否则后台报价和实收会对不上）。  
  > ⚠️ **稿上有、当前实现里未见**：「未验证（零元，收银被跳过）」 —— 屏幕上可能没有这句话，找不到**不代表设备故障**（核验方式：全仓代码 grep，2026-09-10）。

把这次读到的数字抄到文末记录表，后面所有金额都以屏幕上服务端报价为准，不要心算。

## A. 装机与终端绑定

> 目标：管理员预创建 → 一次性绑定码 → Agent 兑换 → 心跳把生命周期从「安装中」推到「运行中」→ 一体机认到本机身份。  
> **已经绑过、后台已是「运行中」且「在线」的机器：从 A.7 开始核对，不要重新生成绑定码。** 重新生成会使旧 token 立即失效。

### A.1 看打印机在 Windows 里叫什么

1. **做什么**  
   本机管理员 PowerShell：

   ```powershell
   Get-Printer | Select-Object Name, PrinterStatus | Format-Table -AutoSize
   ```

2. **应该看到什么**  
   列表里有一台将用于本终端的打印机。现场真机曾用名 `Pantum CM2800ADN Series`，**以本次输出为准**，后面绑定下拉框必须选这一条，一个字都不能改。
3. **看不到时属于哪一类**  
   ① 本机装机 / 打印机驱动。
4. **现场立刻能做的补救**  
   装奔图驱动、设为默认、USB/网线重插。不要手打一个「差不多」的名字。

3. **看不到时属于哪一类**  
   ③ 后台生命周期；编号冲突会在弹窗里出现错误提示（来源：同对话框 `:36`「预创建设备失败，请稍后重试」或服务端返回原文）。

   页标题「报价确认」（来源：`apps/kiosk/src/pages/print/PrintConfirmPage.tsx:623``）。零元主按钮「确认并建单」，付费主按钮「确认并去付款」（来源：同文件 `:441-443`）。底部说明付费时「确认后创建订单并进入付款。金额以服务端返回为准。」（来源：同文件 `:543`）；零元时「零元单确认后仍会先建单，再进入打印。不存在不建单直接出纸。」（来源：同文件 `:541-542`）。流程条「创建订单 / 完成付款 / 开始打印」（来源：`PrintConfirmView.tsx:265-269`）。能力被拒时「参数回到黑白单面再报价，才能确认这一单。」（来源：`PrintConfirmPage.tsx:481`）。  
  > ⚠️ **稿上有、当前实现里未见**：「创建订单 / 完成付款 / 开始打印」 —— 屏幕上可能没有这句话，找不到**不代表设备故障**（核验方式：全仓代码 grep，2026-09-10）。
3. **看不到时属于哪一类**  
   ⑤ 报价失败（主按钮「重新报价」，来源：`PrintConfirmPage.tsx:512`）；④ 彩色/双面参数。
4. **现场立刻能做的补救**  
   「返回修改」改回黑白单面再报价。价格暂不可用不要猜一个金额。把屏幕上的订单金额抄下来。

### C.6 零元单：看领取和出纸（付费单跳到 D.5）

1. **做什么**  
   零元确认后若停在收银台，标题会是「本次无需付款」，点「开始打印」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:102`` + `PrintCashierPage.tsx:493`）。然后站在出纸口，不要离开。
2. **应该看到什么**

   - `claimed`：「终端已领取任务」/「终端准备中」

3. **看不到时属于哪一类**  
   ⑦ 打印机；② Agent 没在领任务（进度长时间停在「等待终端领取」）；③ 终端不是「运行中」。
4. **现场立刻能做的补救**  
   控制中心看服务是否 Running。后台「打印扫描运维」→「任务中心」→「打印」，看该任务是「待领取 / 已领取 / 打印中 / 已完成 / 失败」（来源：`apps/admin/scripts/verify-admin-print-scan-ui.mjs:1`-55`）。缺纸看奔图面板。不要刷新乱点「再印一份」。  
  > ⚠️ **稿上有、当前实现里未见**：「待领取 / 已领取 / 打印中 / 已完成 / 失败」 —— 屏幕上可能没有这句话，找不到**不代表设备故障**（核验方式：全仓代码 grep，2026-09-10）。

**C 段通过标准：** 出纸内容与上传文件一致；进度走过领取 → 打印中 → 打印完成。付费单的收款不在本段验收，到 D。

## D. 支付全链路（本脚本最重要的一段）

> 路径：屏上出码 → 手机扫 → 付款 → 渠道回调 → 服务端 `paid` → 放行 PrintTask → Agent 领取 → 出纸。  
> 主路径是 **微信 Native 动态码**（来源：`apps/kiosk/src/pages/print/cashierStatus.ts:50`-2`、`:215-232`）。支付宝当面付是并列通道，步骤对称，文案换成「请打开支付宝「扫一扫」…」。  
> 回调地址由服务端拼：`{PAYMENT_NOTIFY_BASE_URL}/api/v1/payment/callback/wechat`（来源：`services/api/src/payment/payment-provider.types.ts:219`-220` + wechat provider `:216`）。现场看不到回调报文，只看一体机是否变成已付。  
> **会真实扣款。** 用可丢弃的小额单。不要用沙箱按钮——生产包会裁掉沙箱入口（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:7`-8`）。

### D.0 这单必须应付大于 0

1. **做什么**  
   重复 C.1～C.5，仍选黑白单面（除非 0.4 显示只有彩色才收费，并且你已经做完 B.3）。在「报价确认」上看金额。金额为 0 就不要进本段。
2. **应该看到什么**  
   主按钮是「确认并去付款」，不是「确认并建单」（来源：`apps/kiosk/src/pages/print/PrintConfirmPage.tsx:441`-443`）。点下去之后到达「订单支付」页，副标题「选择服务端已启用通道；支付确认到账后才会释放打印任务」（来源：`PrintCashierPage.tsx:509-510`）。顶栏状态此时应是「支付尚未确认」（来源：同文件 `:453`）。金额区标签「本次应付」，数字为 `¥x.xx`（来源：`CashierQxView.tsx:175`、`cashierStatus.ts:57`）。金额下来源说明「本单实付金额 · 来自服务端已建订单，前端不重新计算」（来源：`CashierQxView.tsx:250`）。抄下「订单号」。
3. **看不到时属于哪一类**  
   ⑤ 进了「本次无需付款」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:102``）= 这单是零元，测不了支付。⑥ 「当前设备暂不支持在线付款」（来源：同文件 `:104`）= 通道列表空。
4. **现场立刻能做的补救**  
   零元：回 0.4 看价目，不要在收银台干等。通道空：点「重新读取支付通道」（来源：`apps/kiosk/src/pages/print/PrintCashierPage.tsx:494``），仍空就停，记「未验证（线上支付未开通，请联系现场工作人员）」——这句也是页上的错误底文（来源：`PrintCashierPage.tsx:177`）。  
  > ⚠️ **稿上有、当前实现里未见**：「未验证（线上支付未开通，请联系现场工作人员）」 —— 屏幕上可能没有这句话，找不到**不代表设备故障**（核验方式：全仓代码 grep，2026-09-10）。

### D.1 选支付通道

1. **做什么**  
   若只有一个通道，页面可能已经选中。若有「微信支付」和「支付宝」两个按钮，**点其中一个**（不要两个都点）。本段按微信写；测支付宝时把「微信」换成「支付宝」。
2. **应该看到什么**  
   分组标题「支付通道」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:185``）。按钮文字「微信支付」或「支付宝」（来源：`cashierStatus.ts:43-44`）。选中后标题变为「通道已选，请选择扫码方式」，说明「选屏上收款码会立即创建支付尝试；付款码读满并提交后才创建尝试。」（来源：`CashierQxView.tsx:107`）。主按钮此时是禁用的「选择上方扫码方式」（来源：`PrintCashierPage.tsx:499`）。
3. **看不到时属于哪一类**  
   ⑥ 「正在加载支付方式」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:103``）一直转 = 通道接口失败；「支付方式加载失败」（来源：同文件 `:105`）。
4. **现场立刻能做的补救**  
   「重新读取支付通道」。不要刷新整页重复建单。可用「退出支付」（来源：`apps/kiosk/src/pages/print/PrintCashierPage.tsx:530``）离开，未支付超时关闭「未产生扣款」（来源：`CashierPaymentPanel.tsx:162`）。

### D.2 选「屏上收款码」（立刻出码）

1. **做什么**  
   点「屏上收款码」。小字是「手机扫屏幕上的码」（来源：`apps/kiosk/src/pages/print/PrintCashierPage.tsx:72``）。**一选就会向微信下单出码，不要反复点。** 不要点「扫付款码」——那是 F 段。
2. **应该看到什么**  
   标题「请扫码支付」（两处会同时出现：青序状态机 `CashierQxView.tsx:108`，以及收银状态 `cashierStatus.ts:151`）。微信通道的提示「请打开微信「扫一扫」，扫描下方二维码完成支付。」（来源：`apps/kiosk/src/pages/print/cashierStatus.ts:49``）。码下方「请使用微信支付扫码支付」（来源：`CashierPaymentPanel.tsx:311`，`PAY_CHANNEL_LABEL.wechat`）。再下一行「支付主体与金额以手机端展示为准」（来源：同文件 `:313`）。徽章「微信支付 · 支付结果以服务端确认为准」（来源：同文件 `:318`）。倒计时「收款码 mm:ss 后失效，过期请重新出码」（来源：同文件 `:322`）。**测试通道才会出现「测试支付通道 · 非真实收款」**（来源：同文件 `:317`）；生产不应出现这句。若出现，停，不要付款。  
  > ⚠️ **稿上有、当前实现里未见**：「请使用微信支付扫码支付」、「微信支付 · 支付结果以服务端确认为准」、「收款码 mm:ss 后失效，过期请重新出码」 —— 屏幕上可能没有这句话，找不到**不代表设备故障**（核验方式：全仓代码 grep，2026-09-10）。
3. **看不到时属于哪一类**  
   ⑥ 出码失败：页上「出码失败，请稍后重试或联系现场工作人员」（来源：`apps/kiosk/src/pages/print/PrintCashierPage.tsx:155``）。码出不来但有「正在生成支付码…」（来源：`CashierPaymentPanel.tsx:289`）——等几秒。
4. **现场立刻能做的补救**  
   不要用扫码枪扫这块屏上码（扫码枪是扫用户付款码的）。手机打开微信「扫一扫」。倒计时走完见 D.7。出码失败查网线，不要连点出第二笔。

### D.3 手机扫屏幕上的码并付款

1. **做什么**  
   用微信扫一体机屏幕上的二维码。在手机上确认金额后完成支付。支付过程中**人不要离开机器**，也不要在一体机上改通道、点「重新出码」、或再下一单。
2. **应该看到什么**  
   - 一体机在回调到达前应仍停在「请扫码支付」（来源：`apps/kiosk/src/pages/print/cashierStatus.ts:151``）。这是正常的：Kiosk 每 2.5 秒轮询 `GET /orders/:id/pay-status`（来源：`PrintCashierPage.tsx:64-65`），不以手机界面为准。  
   - 手机端此处应有微信支付确认页。**具体按钮文案以微信客户端为准，仓库没有那份文案。** 只核对：商户名/金额是否与一体机「本次应付」一致。不一致就取消，不要付。  
   - 手机显示已付之后，一体机应在数秒内变为：标题「支付成功」，提示「正在进入打印，请稍候…」（来源：`apps/kiosk/src/pages/print/cashierStatus.ts:110``），青序态「付款已由服务端确认」「系统正在创建或恢复同一打印任务，不会再次发起收款。」（来源：`CashierQxView.tsx:112`），顶栏「服务端确认已付」（来源：`PrintCashierPage.tsx:445`）。出纸条件变为「服务端已确认 paid」（来源：`CashierQxView.tsx:269`）。
3. **看不到时属于哪一类**  
   ⑥ 手机付了、一体机仍「请扫码支付」= 回调未入账或轮询失败。手机付不了 = 商户号/回调 URL/金额问题，现场改不了密钥。
4. **现场立刻能做的补救**  
   先看手机账单有没有扣款。  
   - **没扣款：** 可等码过期后「重新出码」，不要同时再扫旧码。  
   - **已扣款但一体机没变：** 点「已支付但未跳转？点此核实支付结果」（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:337``）。核实中按钮变为「正在向支付渠道核实…」（来源：同文件 `:337`）。这会走 `POST /orders/:id/pay/reconcile`（来源：`payment.controller.ts:88-91`），用来补丢失的回调。  
   - 不要再扫一次、不要换支付宝再付一次（未完成尝试会锁住选择，避免双扣，来源：`cashierStatus.ts:88-90`）。

### D.4 放行打印任务

1. **做什么**  
   服务端确认 `paid` 后页面应自动进入 `/print/progress`（来源：`apps/kiosk/src/pages/print/PrintCashierPage.tsx:113`-125`、`:316`）。若停在收银台，点「开始打印」。不要再付款。
2. **应该看到什么**  
   自动跳转后就是 C.6 的进度文案。若释放失败：标题「打印任务尚未建立」，说明「支付或零元订单状态已经由服务端确认；当前只重试打印任务释放，不会重新收款。」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:113``），主按钮「重试创建打印任务」（来源：`PrintCashierPage.tsx:493`）。失败底文「订单已付款，但创建打印任务失败，请重试或联系现场工作人员」（来源：同文件 `:129`）。
3. **看不到时属于哪一类**  
   ③ 终端不是 active（「目标终端当前不接收新打印任务」）；⑦ 打印机不可用；④ 能力门禁（若这单偷偷带了彩色）。
4. **现场立刻能做的补救**  
   「重试创建打印任务」。不要再扫码。后台看该订单是否已支付、是否已有 PrintTask。

### D.5 出纸

1. **做什么**  
   站在出纸口等到纸出来。核对页数。点「我拿走了，结束并清空」。把订单号、出纸张数写进记录表。
2. **应该看到什么**  
   与 C.6 相同的「等待终端领取 → 终端已领取任务 → 正在打印 → 打印完成」。完成页若带了金额，状态会是「已付 ¥x.xx · 打印完成」（来源：`apps/kiosk/src/pages/print/PrintDonePage.tsx:330``、`:609`）。  
  > ⚠️ **稿上有、当前实现里未见**：「等待终端领取 → 终端已领取任务 → 正在打印 → 打印完成」、「已付 ¥x.xx · 打印完成」 —— 屏幕上可能没有这句话，找不到**不代表设备故障**（核验方式：全仓代码 grep，2026-09-10）。
3. **看不到时属于哪一类**  
   ⑦ 硬件；② Agent claim。**已付款但不出纸**是履约事故：留在机器旁，用订单号找工作人员，不要再扣一次。
4. **现场立刻能做的补救**  
   完成页若进了费用异常说明，按页上三步把订单号告诉现场（来源：`apps/kiosk/src/pages/print/PrintDonePage.tsx:406`-408`）。本机「不会自动处理费用」（来源：同文件 `:411`）。后台任务中心看失败原因。缺纸/卡纸看奔图面板。

### D.6 回调丢失的补救（若 D.3 一次就过，本步可记「未触发」）

1. **做什么**  
   仅当手机已扣、一体机未变时：点「已支付但未跳转？点此核实支付结果」，必要时再点「刷新付款结果」（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:337``）。
2. **应该看到什么**  
   核实中「正在向支付渠道核实…」。成功后仍须出现「支付成功」/「付款已由服务端确认」。失败时「暂未查到支付结果，请稍候或继续等待自动确认」（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:337``）。
3. **看不到时属于哪一类**  
   ⑥ 回调与查单都失败。可能是 `PAYMENT_NOTIFY_BASE_URL` 公网不可达——现场改不了，记「未验证（需运维查微信商户回调）」。
4. **现场立刻能做的补救**  
   不要重复付款。保留手机账单截图（可脱敏）和一体机订单号。

### D.7 屏上码过期（可选）

1. **做什么**  
   若倒计时走完还没付：看屏幕，再点「重新出码」。不要用旧码付款。
2. **应该看到什么**  
   显示期到点：「收款码到期核验中」+「该二维码已达到显示有效期。重新出码或切换付款码时会先向支付渠道确认关闭；未确认前请勿重复支付。」（来源：`apps/kiosk/src/pages/print/cashierStatus.ts:184`-185`，青序态 `CashierQxView.tsx:114`）。渠道确认关单后：「屏上收款码已过期」+「该二维码已失效，可重新出码，或改用扫码枪扫描用户付款码。」（来源：`cashierStatus.ts:172-174`）。按钮「重新出码」（来源：`CashierPaymentPanel.tsx:345`）。
3. **看不到时属于哪一类**  
   ⑥ 卡在「到期核验中」太久 = 查单/关单未完成，此时**不要付款**。
4. **现场立刻能做的补救**  
   等「屏上收款码已过期」再重新出码。若期间手机已扣，走 D.6，不要出第二张码。

**D 段通过标准（必须同时成立）：**

| # | 事实 | 记录 |
|---|---|---|
| 1 | 一体机出现微信/支付宝动态码，且不是「测试支付通道」 | 通道名、订单号 |
| 2 | 手机实际扣款金额 = 屏幕「本次应付」 | 金额 |
| 3 | 未点沙箱、未手工改库的情况下，屏幕变为「支付成功」/「付款已由服务端确认」 | 时间 |
| 4 | 随后出现领取 → 打印中 → 打印完成，纸从奔图出来 | 张数 |
| 5 | 全过程没有第二笔扣款 | 手机账单 |

缺任一项不得把「支付全链路」勾成通过。

### E.1 确认扫描能力未关闭

1. **做什么**  
   Hub 点「材料扫描」。看是否被挡。
2. **应该看到什么**  
   页标题「材料扫描」。可创建时状态「可创建扫描任务 · 需面板操作」（来源：`apps/kiosk/src/pages/scan/ScanStartPage.tsx:91``），副标题「请先选择扫描类型；本页尚未创建任务。下一步会创建真实扫描会话」（来源：同文件 `:97`）。说明卡标题「为什么屏幕上没有「开始扫描」」，正文含「这台一体机的扫描只能在奔图自己的操作面板上启动」（来源：同文件 `:272-275`）。  
  > ⚠️ **稿上有、当前实现里未见**：「这台一体机的扫描只能在奔图自己的操作面板上启动」 —— 屏幕上可能没有这句话，找不到**不代表设备故障**（核验方式：全仓代码 grep，2026-09-10）。
   若管理员把 `scan` 配成非 available：状态「扫描能力暂未开放」（来源：同文件 `:88`）。
3. **看不到时属于哪一类**  
   ④ 扫描能力被关；⑦ Hub 因一体机离线把扫描一起停（「打印和扫描是同一台机器，它出不了纸，扫描一起停。」来源：`PrintScanHomePage.tsx:183`）。
4. **现场立刻能做的补救**  
   后台设备能力里不要把「材料扫描」留在维护/未验收。打印机离线先修打印机。

### E.2 建扫描会话

1. **做什么**  
   类型选「普通文档」（来源：`apps/kiosk/src/pages/scan/scanWorkbench.ts:16``）。点「下一步 · 创建扫描会话」。等到出现任务编号后，**再**去奔图面板。不要提前按面板。
2. **应该看到什么**  
   下一屏标题「扫描指引」，副标题含加粗「扫描任务已创建」（来源：`apps/kiosk/src/pages/scan/ScanSettingsPage.tsx:382`-383`）。状态「第 2 步 · 去面板操作」（来源：同文件 `:384`）。任务编号、剩余时间在「任务信息」里（来源：同文件 `:410-413`）。指引原文由服务端下发，普通文档为（来源：`services/api/src/scan-tasks/scan-tasks.service.ts:118-121`）：  
   - 「多页材料放入自动进纸器，单页证书放在玻璃板上」  
   - 「在打印机操作面板打开「扫描」，并选择扫描到网络 / SMB（本机已配置的接收目录）」  
   - 「按「开始」扫描；整叠扫完后回到本屏幕等待自动生成 PDF，请勿关闭页面」  
   主按钮「我已操作，开始等待」（来源：`apps/kiosk/src/pages/scan/ScanSettingsPage.tsx:391``）。
3. **看不到时属于哪一类**  
   ⑧ 会话创建失败；⑪ 网络。
4. **现场立刻能做的补救**  
   创建失败不要在面板上扫——扫出来的文件没人认领（页上也是这么说的，来源：`ScanSettingsPage.tsx:365`）。

### E.3 在奔图面板上扫

1. **做什么**  
   按屏幕指引把纸放好。在奔图面板打开扫描，目标选能写到 A.8 那个目录的「扫描到网络 / SMB」（或现场等价项）。按面板的开始。扫完回到一体机点「我已操作，开始等待」。
2. **应该看到什么**  
   一体机进入「等待打印机端扫描完成」，副标题「请在打印机面板完成扫描到本机接收目录；本页每 3 秒自动检测结果」（来源：`apps/kiosk/src/pages/scan/ScanProgressPage.tsx:268`-269`）。状态「等待文件回传」（来源：同文件 `:262`）。面板标题「正在等文件回传」（来源：同文件 `:314`）。  
   奔图面板上的菜单名**以现场机器为准**（仓库没有奔图固件截图）。U 盘那条独立路径明确写着「具体菜单名称、可选格式和 USB 接口位置以现场奔图面板为准。」（来源：`apps/kiosk/src/pages/scan/ScanStartPage.tsx:180``），SMB 路径同样不要臆造菜单字。
3. **看不到时属于哪一类**  
   ⑧ 目录未配置 / 奔图没扫到该目录 / Agent 扫描监视未工作。本机状态页若是「扫描目录未配置」，本步必失败。
4. **现场立刻能做的补救**  
   回到控制中心核对扫描目录。看该目录是否出现新文件。点「立即检查」（来源：`apps/kiosk/src/pages/scan/ScanProgressPage.tsx:300``）。不要反复按面板开始造成多份无人认领的文件。

### E.4 看结果

1. **做什么**  
   等自动跳到结果页。可点「直接打印」走回打印链路，或「重新扫描」。
2. **应该看到什么**  
   成功：标题「扫描完成」，状态「服务端已回完成并带回文件」（来源：`apps/kiosk/src/pages/scan/ScanResultPage.tsx:214`-216`）。主按钮「直接打印」（来源：同文件 `:224`）。  
   失败：「扫描未完成」或「会话已过期」（来源：同文件 `:146`）。无文件的完成：「已完成 · 回执里没有文件」（来源：同文件 `:146`）。
3. **看不到时属于哪一类**  
   ⑧ 回传匹配失败。
4. **现场立刻能做的补救**  
   「重试扫描」是另一次任务（页上写明，来源：`ScanResultPage.tsx:190`）。连续失败找人看 SMB/目录权限，不要把同一份纸扫进别人的会话。

**E 段通过标准：** 结果页「扫描完成」且能看到回传文件。U 盘扫描路径标注「Windows / 奔图真机尚未验收」（来源：`packages/shared/src/types/complianceCopy.ts:82``），本脚本不把它勾成通过。

## F. 扫码枪读付款码

> 机身侧面是影像扫码模组，在系统里是 **HID 键盘**，靠接近感应触发（代码注释，来源：`KioskHidScanGuard.tsx:70-74`）。  
> **只在收银台页消费付款码。** 授权路由只有 `/print/cashier` 和 `/print/pickup-claim`（来源：同文件 `:19`）。  
> 微信/支付宝付款码都是 **18 位数字**（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:13`-18`）。  
> 本路径依赖服务端 `PAYMENT_CODEPAY_AUTO_CONVERGE_ENABLED=true` 以及微信门店编号；未启用时会明确失败。现场是否已开通 **标未验证，以这一单结果为准**。

### F.1 先回到收银台，不要在别的页扫

1. **做什么**  
   再下一笔应付 > 0 的单，走到「订单支付」。若在首页/表单页把手机付款码凑近扫码区，只是为了看防护是否生效——不要用真的待付码做这个试验。
2. **应该看到什么**  
   非授权页误扫：顶部提示标题「已忽略一次扫码」，正文「扫码设备在本页读到了一串内容。本页不需要扫码，内容已丢弃，你正在填写的内容没有被改动。」（来源：`apps/kiosk/src/components/hid-guard/KioskHidScanGuard.tsx:167`-170`）。
3. **看不到时属于哪一类**  
   ⑨ 扫码模组没接好 / 不是键盘模式 / 没有以 Enter 结尾（母盘要求 HID 键盘模式并以 Enter 结尾，来源：`windows-golden-image-and-install-checklist.md:18`）。
4. **现场立刻能做的补救**  
   用记事本测：扫一枚码应出现字符并回车。不进记事本就先修 USB 模式，不要继续用付款码试。

### F.2 选「扫付款码」，不要扫屏幕上的收款码

1. **做什么**  
   先选通道（微信或支付宝，须与手机付款码品牌一致）。点「扫付款码」（小字「出示你的付款码」，来源：`PrintCashierPage.tsx:73`）。打开手机微信/支付宝的**付款码**（用户被扫的码），把屏幕凑近机身扫码区。屏幕上的动态收款码不要用枪扫。
2. **应该看到什么**  
   标题「请出示手机付款码」，说明「现在还没有向支付平台发起收款，读满十八位并提交后才会创建支付尝试。」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:109``）。表单标题「请扫描或输入手机付款码」，提示「扫码器会自动读取并提交；也可手动输入 18 位数字。」「为保护你的支付安全，付款码不会显示在这块公共屏幕上。」（来源：`CashierPaymentPanel.tsx:222-226`）。进度「等待扫码」（来源：同文件 `:264`）。读入过程「已读取 n / 18 位」（来源：同文件 `:266`）。读满「已读取完整付款码，正在提交…」（来源：同文件 `:262`）。提交后「正在确认付款结果」（来源：`CashierQxView.tsx:110`）或「支付处理中」「请按手机提示完成验证，支付结果会自动确认。」（来源：`cashierStatus.ts:161-163`）。成功后仍须变成「支付成功」/「付款已由服务端确认」，然后出纸。  
  > ⚠️ **稿上有、当前实现里未见**：「已读取 n / 18 位」 —— 屏幕上可能没有这句话，找不到**不代表设备故障**（核验方式：全仓代码 grep，2026-09-10）。
3. **看不到时属于哪一类**  
   ⑨ 位数读不满；⑥ 失败文案若是「付款码支付自动核验未启用，请联系工作人员」或「付款码支付未配置，请联系工作人员」（来源：`services/api/src/payment/providers/wechat-pay.provider.ts:245``、`:250`，经 `PrintCashierPage.tsx:284` 上屏）= 生产没开付款码核验，**不是枪坏了**。读满却提示「请输入 18 位数字付款码」（来源：`PrintCashierPage.tsx:235`）= 缓冲被清或混入非数字。
4. **现场立刻能做的补救**  
   「清空重扫」（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:278``）。调高手机亮度、关掉屏幕花纹。品牌必须和所选通道一致。失败后看清屏幕上的失败句再决定：配置类失败整段记「未验证」，不要反复扣款。成功后的出纸标准同 D.5。

**F 段通过标准：** 付款码从未显示在公共屏幕上；读满 18 位后服务端确认 paid 并出纸。若失败句是「未启用 / 未配置」，勾「未验证（服务端未开通付款码）」而不是「扫码枪损坏」。

## G. 小程序扫码上传

> 与 C.2 不是同一条路。C.2 是 H5：「不用登录，也不用装软件。」  
> 本段才是微信小程序。**发布管道不发小程序**（`deploy.yml` 不拷 `apps/miniapp`）。未发布时，微信生成小程序码返回 `errcode 41030`（来源：`docs/progress/next-tasks.md:87-88`）。

### G.0 前置条件（不满足就停，不要扫）

1. **做什么**  
   确认下面全部为真，否则本段整段记「未验证（小程序未发布）」：  
   - 微信公众平台已有**已发布**的正式版，或至少把体验版成员加了你的微信号，且服务端 `WECHAT_MINIAPP_ENV_VERSION=trial`。  
   - 生产 `POST /api/v1/miniapp/code/capabilities` 曾返回 `available:true`（记载于 `docs/progress/next-tasks.md:168`），**现场再打一次为准**。  
   - 不要用未发布的 AppID 去扫一体机上的 H5 码指望进小程序——H5 码本来就不是小程序码。
2. **应该看到什么**  
   前置不满足时：微信侧此处应有无法打开小程序的提示（**具体文案以微信为准，仓库没有**）。不要把它理解成一体机坏了。
3. **看不到时属于哪一类**  
   ⑩ 小程序未发布。
4. **现场立刻能做的补救**  
   上传文件继续用 C.2 的 H5。把本段标未验证。不要改一体机二维码「好让小程序能扫」——那会破坏已验证的 H5 通道。

### G.1 小程序内扫一体机上传码（仅当前置满足）

1. **做什么**  
   打开已发布/体验版小程序，进入扫码（`pages/kiosk-login` 的 `scanCode`）。扫一体机「手机扫码上传」那张码。选一份 ≤10MB 的文件传上去，再回一体机确认。
2. **应该看到什么**  
   小程序页标题「传文件到一体机」（来源：`apps/miniapp/pages/kiosk-send/kiosk-send.wxml:9`）。空闲：「已连上终端」「选一份文件传过去，终端屏幕上会自己出现。单个文件不超过 10MB。」按钮「选择文件」（来源：同文件 `:18-20`）。传输中：「正在传给终端…」「请不要关闭小程序」（来源：同文件 `:35-36`）。完成：「已传给终端」「请回到一体机屏幕继续操作」（来源：同文件 `:44-45`）。失败：「没能传过去」（来源：同文件 `:57`）。  
   扫到既不是登录码也不是上传码：「这不是一体机上的二维码，请确认扫的是终端屏幕上的登录码或上传码」（来源：`apps/miniapp/pages/kiosk-login/kiosk-login.js:88`）。  
   一体机侧确认文案与 C.2 相同（「手机传上来一份，等你确认」）。
3. **看不到时属于哪一类**  
   ⑩ 小程序版本/权限；或扫的是支付码/别的码。
4. **现场立刻能做的补救**  
   回到一体机刷新二维码。scene 码一次性，兑换失败不要点重试死循环（页上会改说「请回到一体机屏幕重新生成二维码」，来源：`kiosk-send.wxml:60`）。

**G 段通过标准：** 仅当文件经小程序到达一体机并完成确认。H5 成功不得记成「小程序扫码上传已通过」。
