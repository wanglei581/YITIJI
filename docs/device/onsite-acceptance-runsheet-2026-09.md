## 怎么用

每一条都是四段。缺「应该看到什么」的步骤不允许出现在本文件里。

1. **做什么** — 点哪个按钮、跑哪条命令、把什么东西放到哪。
2. **应该看到什么** — 屏幕/命令行上的字符串必须能在仓库 grep 到，并标 `（来源：路径:行号）`。仓库没有的文案（例如微信 App 里的「立即支付」）只写「此处应有状态提示」，不编。
3. **看不到时属于哪一类** — 用文末「问题分类」里的编号，不要现场发明新类。
4. **现场立刻能做的补救** — 只写站在机器旁 2 分钟内能做的事；不要「回去改代码」。

**依赖顺序不可跳。** 终端未绑定 → 一体机没有本机身份 → 打印任务 fail-closed。彩色 / 双面未登记 → 选了也会被拒。应付金额为 0 → 收银台走零元单，**测不到真实收款**。扫码枪只在收银台页消费付款码。小程序未发布 → G 段整段停在前置条件。

**不确定的写成「未验证」，不要写成肯定句。** 本脚本里标「未验证」的项，现场做完请把结果写进文末记录表，不要口头说「应该可以」。

**禁止：** 把绑定码、付款码、token 发到聊天、工单或截图；不要在 URL 里手填终端编号；不要假设奔图面板菜单名与仓库指引逐字相同。

**奔图面板速查：** 面板提示原文「进纸失败」「纸张设置不匹配」「打印机卡纸」，以及粉盒、废粉瓶类提示，含义与耗材更换步骤见 [现场故障处置单](onsite-failure-recovery-runsheet-2026-09.md)「耗材更换与冷备」（奔图 CM2800 系列用户指南 V1.4 第 82 页，PDF 页码）。电源键短按只进节能、按住超过 2 秒才关机，电源灯闪烁是休眠（奔图 CM2800 系列用户指南 V1.4 第 23、25 页，PDF 页码）。缺纸、卡纸时以面板提示 + 出纸口实况为准，不要只看一体机屏幕。

## R. 发布验收：先过渡检查，再升级 Agent，再走闭环（第一次发布当天）

> 2026-09-29 总指挥定：真机四条闭环（C 打印出纸回写、E 扫描回传、H 到机码、I 缺纸/卡纸恢复）放到**第一次发布部署完成之后**作为发布验收来走。发布顺序是**后端先部署、Agent 后升级**，中间会有一段「旧 Agent + 新后端」，所以先验这段过渡，再升级。
> 装的 Agent 必须是**本次发布实际部署的那个提交**对应的 `windows-agent-installer` 产物（运行号由 Windows 真机路发给产品负责人），保证 Agent 与后端同版。装包由产品负责人本人做。KSK-001 系统保持 Windows 11 22H2，不升级。

> **前置与分工（与发布当天清单互相引用，不重复）：** 发布当天清单（`docs/progress/next-tasks.md`「2026-09-29：合规与运维 → 两次发布清单 → 第一次发布」）第 6 步已见 `✅ 部署完成`；R.1 是该清单「发布后核对」第 10 条，R.1 不通过不解除冻结；R.2–R.5 在第 8 步解除冻结之后做（同日或次日）。

### R.1 过渡检查：新后端 + 旧 Agent

1. **做什么**  
   后端部署完成、**Agent 还没升级**时：后台「终端管理」找到这台机器看一行；然后按 C.1–C.6 走一张零元单（黑白单面 1 份）。
2. **应该看到什么**  
   - 表头有「生命周期」「运行状态」「最近心跳」「Agent 版本」（来源：`apps/admin/src/routes/terminals/index.tsx:472`）。这台机器：生命周期「运行中」，运行状态「在线」（来源：同文件 `:91`），最近心跳在一分钟内（Agent 每 30 秒一次），Agent 版本仍是旧版（来源：同文件 `:768`）。  
   - 零元单照 C.6 走到「打印完成」并出纸。
3. **看不到时属于哪一类**  
   心跳停了或变「离线」（来源：同文件 `:92`）、零元单卡在「等待终端领取」= 新后端与旧 Agent 不兼容，**发布阻塞**，记下时间和屏幕原文。
4. **现场立刻能做的补救**  
   不要为了让它通过而跳过这步直接升级 Agent——真实网点在升级前也会经历这段。先把现象报给 Windows 真机路和总指挥，再决定回滚后端还是立即升级 Agent。

### R.2 升级 Agent

1. **做什么**  
   产品负责人本人双击安装本次发布的 MSI（U 盘拷入或本机下载后安装，见母盘清单 A14）。发布当天装的 Agent 必须是 **0.4.13 或更高**，并且必须包含「图片临时 PDF 开机清理」与「打印队列空闲暂停 + 开机清理残留作业」两处修复。**从 0.4.11 首次升级时，装完须按 [生产接入说明](production-agent-onboarding.md) 重跑一次生产安装脚本**（这台兼作工作电脑，带 `-KeepFileSelectionDialogs`），否则升级后的自动启动恢复标记还不存在。**发布当天 KSK-001 不加 `-KeepPrinterQueueUnpaused`**（2026-09-29 总指挥定：测到的是生产行为）。后果要先告诉产品负责人：空闲时这台奔图的队列是暂停的，他从别的软件打到这台奔图的文档会一直停在队列里，等 Agent 下次为一体机用户放行时才出，而且会和那位用户的打印件一起出、甚至夹在中间——这本身就是隐私问题。所以不加开关期间，**他不能从别的软件往这台奔图打印**；要打就先临时加开关重跑生产安装脚本，或者用别的打印机。R.5 做完后，按这台电脑是否还兼作工作电脑，再定是否改成带开关。专用一体机一律不加。**版本搭配：Agent 0.4.13 需要服务端为第一次发布或更新的版本**（老服务端不认 `queue_cleanup_failed` / `queue_pause_failed` 两个状态值，也不按新时限判未确认），不要单独先升 Agent。
2. **应该看到什么**  
   Agent 日志里有一行 `print-queue-cleanup: matched by SID (count=N)`（来源：`apps/terminal-agent/src/agent/print-queue-hold.ts:309`，N 可以是 0），说明按账号 SID 比对成功；后台这台终端的打印机状态**不是**「开机清理失败，暂停接打印单」或「暂停队列失败，暂停接打印单」——若是，说明打印闸门合上了，这台机器整机不能打印，属发布阻塞，立即报 Windows 真机路和总指挥。后台同一行「Agent 版本」变成 0.4.13 或更高（来源：`apps/admin/src/routes/terminals/index.tsx:768`），运行状态回到「在线」（来源：同文件 `:91`）；一体机首页「打印 · 扫描」徽章回到「打印机在线」（见 A.7，来源：`apps/kiosk/src/pages/home/hooks/useHomeDeviceStatus.ts:36`）。版本号来源：`apps/terminal-agent/package.json` 的 `version` 与 `apps/terminal-agent/scripts/install-production-agent.ps1:81`。兼作工作电脑的开关来源：同文件 `:23`、`:108`；生产默认写入暂停的来源：同文件 `:900`。
3. **看不到时属于哪一类**  
   ① 本机装机 / Agent。
4. **现场立刻能做的补救**  
   服务没起来先跑 `diagnose-production-agent.ps1`（只读）并保留 `last-startup-diagnostic.json`；**不要删 `agent.pid`**（它只作诊断）。

### R.5 用户走后本机留下什么、打印中强制关机、强杀 Agent（2026-09-29 总指挥定，用 0.4.13 做）

> 背景：走查总表漏链 1、8，问题 W-85 / W-86 / W-87。0.4.11 的只读对照底子（9/29 22:52、23:3x）见 `docs/progress/current-progress.md` 同日条目：临时目录只有两件旧遗留，打印队列、扫描、下载、用户临时目录均为 0。以下只统计数量与时间，不列文件名、不看内容。
> **剩余风险（本版不覆盖，如实写）：** 0.4.13 空闲时暂停队列，只保护「空闲时」。正在出纸的那一段队列必须是恢复的，这时主机断电，开机后 Windows 打印服务可能在 Agent 起来之前把剩下的作业送出去。第 ③ 步就是测这个窗口；若实测会续打，第二次发布前按 next-tasks 立项处理，本版靠故障处置单「给巡检与运维人员」的出纸盘规则兜住（断电恢复后尽快安排巡检取走遗留件）。
> KSK-001 是笔记本，拔电源有电池顶着，测不出断电，所以第 ③ 步用长按电源键强制关机代替。

1. **做什么**  
   ① 各做一次 U 盘打印、面板扫描投递、手机上传打印，每做完一次、回到首页后，由 Windows 真机路远程读一次：`%ProgramData%\AIJobPrintAgent\temp`（`task_*`、`print_*.pdf`）、扫描目录与 `_unclaimed`、`C:\Windows\System32\spool\PRINTERS`、用户 `%TEMP%` 与「下载」里的 PDF、一体机 Edge 配置目录下 `Default\Cache`、`Local Storage`、`IndexedDB` 的最后写入时间（W-87）。  
   ② 图片打印出纸开始后，Windows 真机路远程**强杀 Agent 进程**（只杀 Agent，先按命令行确认是它）；服务自动拉起后看本单状态、队列与临时目录。  
   ③ **打印中强制关机（产品负责人现场做）**：打一份 **≥5 页**的文档，出到第 2 页时**长按主机电源键强制关机**，再开机，**全程不碰打印机**。记三项：剩下的页或整份有没有自己打出来、打了几页；从开机到出纸隔了多久；Agent 起来后开机清理找到、删除了几个残留作业（日志只记数量）。  
   ④ 缺纸或卡纸后点「重新提交打印」，看能不能出纸（W-86）。

2. **应该看到什么**

   点「下一步：材料检查」，等检查结束。若弹出隐私片段，逐条选保留或遮挡。然后点「下一步：预览与参数」。
2. **应该看到什么**  
   页标题「材料检查」，副标题含「第 2 步 / 共 4 步」（来源：`apps/kiosk/src/pages/print/PrintMaterialCheckPage.tsx:519`-520`）。进行中状态「正在检查材料」（来源：同文件 `:506`）。完成后「材料检查完成」（来源：同文件 `:513`）。主按钮「下一步：预览与参数」（来源：同文件 `:543`）。未裁决完时「每一处隐私片段都必须由你选择保留或遮挡。」（来源：同文件 `:533`）。
3. **看不到时属于哪一类**  
   ⑪ 检查失败（「材料检查失败 · 结果未知」，来源：同文件 `:504`）；或文件被判定不能打（「文件需要重新上传」，来源：同文件 `:508`）。
4. **现场立刻能做的补救**  
   「返回选文件」换一份简单 PDF。隐私项不要空着点下一步——按钮会按住。

### C.4 参数：黑白、单面、1 份

1. **做什么**  
   页标题「预览与打印参数」。色彩模式选「黑白」，单双面选「单面」，份数 1。看一眼预览确实是那份文件。点「下一步：让服务端报价」。若出现「我已逐页看过预览，确认可以打印」，先点它。
2. **应该看到什么**  
   副标题「第 3 步 / 共 4 步 · 逐页核对文件，再确认份数、颜色、单双面和页范围」（来源：`apps/kiosk/src/pages/print/PrintPreviewPage.tsx:447`-448`）。选项「黑白 / 彩色」「单面 / 双面（长边）/ 双面（短边）」（来源：同文件 `:70-77`）。彩色禁用理由见 B.2。底部说明「本页不显示金额；下一步由服务端按真实页数和参数报价。」（来源：同文件 `:468`）。主按钮「下一步：让服务端报价」（来源：同文件 `:471`）。打印机不可用时该按钮变成「打印机不可用」（来源：同文件 `:471`）。  
3. **看不到时属于哪一类**  
   ⑦ 打印机离线/异常（状态「打印机离线」「打印机异常」，来源：同文件 `:438-440`）；④ 误选彩色被拒。
4. **现场立刻能做的补救**  
   回到黑白单面。打印机徽章不是「打印机在线」就先别点报价。

### C.5 看报价并确认建单

1. **做什么**  
   等报价回来。看金额。  
   - 金额 > 0：点「确认并去付款」，进入 D 段（不要在 C 里再另开一条付款故事，D 才是付款正文）。  
   - 金额 = 0：点「确认并建单」，本段继续看到出纸；D 段事后用一笔应付 > 0 的单补做。
2. **应该看到什么**  
   页标题「报价确认」（来源：`apps/kiosk/src/pages/print/PrintConfirmPage.tsx:623``）。零元主按钮「确认并建单」，付费主按钮「确认并去付款」（来源：同文件 `:441-443`）。底部说明付费时「确认后创建订单并进入付款。金额以服务端返回为准。」（来源：同文件 `:543`）；零元时「零元单确认后仍会先建单，再进入打印。不存在不建单直接出纸。」（来源：同文件 `:541-542`）。流程条「创建订单 / 完成付款 / 开始打印」（来源：`PrintConfirmView.tsx:265-269`）。能力被拒时「参数回到黑白单面再报价，才能确认这一单。」（来源：`PrintConfirmPage.tsx:481`）。  
3. **看不到时属于哪一类**  
   ⑤ 报价失败（主按钮「重新报价」，来源：`PrintConfirmPage.tsx:512`）；④ 彩色/双面参数。
4. **现场立刻能做的补救**  
   「返回修改」改回黑白单面再报价。价格暂不可用不要猜一个金额。把屏幕上的订单金额抄下来。

### C.6 零元单：看领取和出纸（付费单跳到 D.5）

1. **做什么**  
   零元确认后若停在收银台，标题会是「本次无需付款」，点「开始打印」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:102`` + `PrintCashierPage.tsx:493`）。然后站在出纸口，不要离开。
2. **应该看到什么**  
   进度页随任务状态切换（来源：`apps/kiosk/src/pages/print/PrintProgressPage.tsx:138`-172`）：  
   - `pending`：「等待终端领取」/ 徽章「排队等待中」  
   - `claimed`：「终端已领取任务」/「终端准备中」  
   - `printing`：「正在打印」/「打印进行中」，副文案「打印机正在出纸，请在出纸口等候」  
   完成后页标题「打印完成」，副标题「文件已从出纸口送出，请核对页数后取走」（来源：`apps/kiosk/src/pages/print/PrintDonePage.tsx:607`-608`）。主按钮「我拿走了，结束并清空」（来源：同文件 `:636`）。
3. **看不到时属于哪一类**  
   ⑦ 打印机；② Agent 没在领任务（进度长时间停在「等待终端领取」）；③ 终端不是「运行中」。
4. **现场立刻能做的补救**  
   控制中心看服务是否 Running。后台「打印扫描运维」→「任务中心」→「打印」，看该任务是「待领取 / 已领取 / 打印中 / 已完成 / 失败」（来源：`apps/admin/scripts/verify-admin-print-scan-ui.mjs:1`-55`）。缺纸看奔图面板。不要刷新乱点「再印一份」。  

**C 段通过标准：** 出纸内容与上传文件一致；进度走过领取 → 打印中 → 打印完成。付费单的收款不在本段验收，到 D。

## D. 支付全链路（本脚本最重要的一段）

> 路径：屏上出码 → 手机扫 → 付款 → 渠道回调 → 服务端 `paid` → 放行 PrintTask → Agent 领取 → 出纸。  
> 主路径是 **微信 Native 动态码**（来源：`apps/kiosk/src/pages/print/cashierStatus.ts:50`-2`、`:215-232`）。支付宝当面付是并列通道，步骤对称，文案换成「请打开支付宝「扫一扫」…」。  
> 回调地址由服务端拼：`{PAYMENT_NOTIFY_BASE_URL}/api/v1/payment/callback/wechat`（来源：`services/api/src/payment/payment-provider.types.ts:219`-220` + wechat provider `:216`）。现场看不到回调报文，只看一体机是否变成已付。  
> **会真实扣款。** 用可丢弃的小额单。不要用沙箱按钮——生产包会裁掉沙箱入口（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:7`-8`）。

### D.0 这单必须应付大于 0

1. **做什么**  
   重复 C.1～C.5，仍选黑白单面（除非 0.4 显示只有彩色才收费，并且你已经做完 B.3）。在「报价确认」上看金额。金额为 0 就不要进本段。
2. **应该看到什么**  
   主按钮是「确认并去付款」，不是「确认并建单」（来源：`apps/kiosk/src/pages/print/PrintConfirmPage.tsx:441`-443`）。点下去之后到达「订单支付」页，副标题「选择服务端已启用通道；支付确认到账后才会释放打印任务」（来源：`PrintCashierPage.tsx:509-510`）。顶栏状态此时应是「支付尚未确认」（来源：同文件 `:453`）。金额区标签「本次应付」，数字为 `¥x.xx`（来源：`CashierQxView.tsx:175`、`cashierStatus.ts:57`）。金额下来源说明「本单实付金额 · 来自服务端已建订单，前端不重新计算」（来源：`CashierQxView.tsx:250`）。抄下「订单号」。
3. **看不到时属于哪一类**  
   ⑤ 进了「本次无需付款」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:102``）= 这单是零元，测不了支付。⑥ 「当前设备暂不支持在线付款」（来源：同文件 `:104`）= 通道列表空。
4. **现场立刻能做的补救**  
   零元：回 0.4 看价目，不要在收银台干等。通道空：点「重新读取支付通道」（来源：`apps/kiosk/src/pages/print/PrintCashierPage.tsx:494``），仍空就停，记「未验证（线上支付未开通，请联系现场工作人员）」——这句也是页上的错误底文（来源：`PrintCashierPage.tsx:177`）。  

### D.1 选支付通道

1. **做什么**  
   若只有一个通道，页面可能已经选中。若有「微信支付」和「支付宝」两个按钮，**点其中一个**（不要两个都点）。本段按微信写；测支付宝时把「微信」换成「支付宝」。
2. **应该看到什么**  
   分组标题「支付通道」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:185``）。按钮文字「微信支付」或「支付宝」（来源：`cashierStatus.ts:43-44`）。选中后标题变为「通道已选，请选择扫码方式」，说明「选屏上收款码会立即创建支付尝试；付款码读满并提交后才创建尝试。」（来源：`CashierQxView.tsx:107`）。主按钮此时是禁用的「选择上方扫码方式」（来源：`PrintCashierPage.tsx:499`）。
3. **看不到时属于哪一类**  
   ⑥ 「正在加载支付方式」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:103``）一直转 = 通道接口失败；「支付方式加载失败」（来源：同文件 `:105`）。
4. **现场立刻能做的补救**  
   「重新读取支付通道」。不要刷新整页重复建单。可用「退出支付」（来源：`apps/kiosk/src/pages/print/PrintCashierPage.tsx:530``）离开，未支付超时关闭「未产生扣款」（来源：`CashierPaymentPanel.tsx:162`）。

### D.2 选「屏上收款码」（立刻出码）

1. **做什么**  
   点「屏上收款码」。小字是「手机扫屏幕上的码」（来源：`apps/kiosk/src/pages/print/PrintCashierPage.tsx:72``）。**一选就会向微信下单出码，不要反复点。** 不要点「扫付款码」——那是 F 段。
2. **应该看到什么**  
   标题「请扫码支付」（两处会同时出现：青序状态机 `CashierQxView.tsx:108`，以及收银状态 `cashierStatus.ts:151`）。微信通道的提示「请打开微信「扫一扫」，扫描下方二维码完成支付。」（来源：`apps/kiosk/src/pages/print/cashierStatus.ts:49``）。码下方「请使用微信支付扫码支付」（来源：`CashierPaymentPanel.tsx:311`，`PAY_CHANNEL_LABEL.wechat`）。再下一行「支付主体与金额以手机端展示为准」（来源：同文件 `:313`）。徽章「微信支付 · 支付结果以服务端确认为准」（来源：同文件 `:318`）。倒计时「收款码 mm:ss 后失效，过期请重新出码」（来源：同文件 `:322`）。**测试通道才会出现「测试支付通道 · 非真实收款」**（来源：同文件 `:317`）；生产不应出现这句。若出现，停，不要付款。  
3. **看不到时属于哪一类**  
   ⑥ 出码失败：页上「出码失败，请稍后重试或联系现场工作人员」（来源：`apps/kiosk/src/pages/print/PrintCashierPage.tsx:155``）。码出不来但有「正在生成支付码…」（来源：`CashierPaymentPanel.tsx:289`）——等几秒。
4. **现场立刻能做的补救**  
   不要用扫码枪扫这块屏上码（扫码枪是扫用户付款码的）。手机打开微信「扫一扫」。倒计时走完见 D.7。出码失败查 4G CPE 与网线，不要连点出第二笔。

### D.3 手机扫屏幕上的码并付款

1. **做什么**  
   用微信扫一体机屏幕上的二维码。在手机上确认金额后完成支付。支付过程中**人不要离开机器**，也不要在一体机上改通道、点「重新出码」、或再下一单。
2. **应该看到什么**  
   - 一体机在回调到达前应仍停在「请扫码支付」（来源：`apps/kiosk/src/pages/print/cashierStatus.ts:151``）。这是正常的：Kiosk 每 2.5 秒轮询 `GET /orders/:id/pay-status`（来源：`PrintCashierPage.tsx:64-65`），不以手机界面为准。  
   - 手机端此处应有微信支付确认页。**具体按钮文案以微信客户端为准，仓库没有那份文案。** 只核对：商户名/金额是否与一体机「本次应付」一致。不一致就取消，不要付。  
   - 手机显示已付之后，一体机应在数秒内变为：标题「支付成功」，提示「正在进入打印，请稍候…」（来源：`apps/kiosk/src/pages/print/cashierStatus.ts:110``），青序态「付款已由服务端确认」「系统正在创建或恢复同一打印任务，不会再次发起收款。」（来源：`CashierQxView.tsx:112`），顶栏「服务端确认已付」（来源：`PrintCashierPage.tsx:445`）。出纸条件变为「服务端已确认 paid」（来源：`CashierQxView.tsx:269`）。
3. **看不到时属于哪一类**  
   ⑥ 手机付了、一体机仍「请扫码支付」= 回调未入账或轮询失败。手机付不了 = 商户号/回调 URL/金额问题，现场改不了密钥。
4. **现场立刻能做的补救**  
   先看手机账单有没有扣款。  
   - **没扣款：** 可等码过期后「重新出码」，不要同时再扫旧码。  
   - **已扣款但一体机没变：** 点「已支付但未跳转？点此核实支付结果」（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:337``）。核实中按钮变为「正在向支付渠道核实…」（来源：同文件 `:337`）。这会走 `POST /orders/:id/pay/reconcile`（来源：`payment.controller.ts:88-91`），用来补丢失的回调。  
   - 不要再扫一次、不要换支付宝再付一次（未完成尝试会锁住选择，避免双扣，来源：`cashierStatus.ts:88-90`）。

### D.4 放行打印任务

1. **做什么**  
   服务端确认 `paid` 后页面应自动进入 `/print/progress`（来源：`apps/kiosk/src/pages/print/PrintCashierPage.tsx:113`-125`、`:316`）。若停在收银台，点「开始打印」。不要再付款。
2. **应该看到什么**  
   自动跳转后就是 C.6 的进度文案。若释放失败：标题「打印任务尚未建立」，说明「支付或零元订单状态已经由服务端确认；当前只重试打印任务释放，不会重新收款。」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:113``），主按钮「重试创建打印任务」（来源：`PrintCashierPage.tsx:493`）。失败底文「订单已付款，但创建打印任务失败，请重试或联系现场工作人员」（来源：同文件 `:129`）。
3. **看不到时属于哪一类**  
   ③ 终端不是 active（「目标终端当前不接收新打印任务」）；⑦ 打印机不可用；④ 能力门禁（若这单偷偷带了彩色）。
4. **现场立刻能做的补救**  
   「重试创建打印任务」。不要再扫码。后台看该订单是否已支付、是否已有 PrintTask。

### D.5 出纸

1. **做什么**  
   站在出纸口等到纸出来。核对页数。点「我拿走了，结束并清空」。把订单号、出纸张数写进记录表。
2. **应该看到什么**  
   与 C.6 相同的「等待终端领取 → 终端已领取任务 → 正在打印 → 打印完成」。完成页若带了金额，状态会是「已付 ¥x.xx · 打印完成」（来源：`apps/kiosk/src/pages/print/PrintDonePage.tsx:330``、`:609`）。  
3. **看不到时属于哪一类**  
   ⑦ 硬件；② Agent claim。**已付款但不出纸**是履约事故：记下订单号，报 Windows 真机路远程核查，不要再扣一次。
4. **现场立刻能做的补救**  
   完成页若进了费用异常说明，按页上三步把订单号告诉现场（来源：`apps/kiosk/src/pages/print/PrintDonePage.tsx:406`-408`）。本机「不会自动处理费用」（来源：同文件 `:411`）。后台任务中心看失败原因。缺纸/卡纸看奔图面板。

### D.6 回调丢失的补救（若 D.3 一次就过，本步可记「未触发」）

1. **做什么**  
   仅当手机已扣、一体机未变时：点「已支付但未跳转？点此核实支付结果」，必要时再点「刷新付款结果」（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:337``）。
2. **应该看到什么**  
   核实中「正在向支付渠道核实…」。成功后仍须出现「支付成功」/「付款已由服务端确认」。失败时「暂未查到支付结果，请稍候或继续等待自动确认」（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:337``）。
3. **看不到时属于哪一类**  
   ⑥ 回调与查单都失败。可能是 `PAYMENT_NOTIFY_BASE_URL` 公网不可达——现场改不了，记「未验证（需运维查微信商户回调）」。
4. **现场立刻能做的补救**  
   不要重复付款。保留手机账单截图（可脱敏）和一体机订单号。

### D.7 屏上码过期（可选）

1. **做什么**  
   若倒计时走完还没付：看屏幕，再点「重新出码」。不要用旧码付款。
2. **应该看到什么**  
   显示期到点：「收款码到期核验中」+「该二维码已达到显示有效期。重新出码或切换付款码时会先向支付渠道确认关闭；未确认前请勿重复支付。」（来源：`apps/kiosk/src/pages/print/cashierStatus.ts:184`-185`，青序态 `CashierQxView.tsx:114`）。渠道确认关单后：「屏上收款码已过期」+「该二维码已失效，可重新出码，或改用扫码枪扫描用户付款码。」（来源：`cashierStatus.ts:172-174`）。按钮「重新出码」（来源：`CashierPaymentPanel.tsx:345`）。
3. **看不到时属于哪一类**  
   ⑥ 卡在「到期核验中」太久 = 查单/关单未完成，此时**不要付款**。
4. **现场立刻能做的补救**  
   等「屏上收款码已过期」再重新出码。若期间手机已扣，走 D.6，不要出第二张码。

| 1 | 一体机出现微信/支付宝动态码，且不是「测试支付通道」 | 通道名、订单号 |
| 2 | 手机实际扣款金额 = 屏幕「本次应付」 | 金额 |
| 3 | 未点沙箱、未手工改库的情况下，屏幕变为「支付成功」/「付款已由服务端确认」 | 时间 |
| 4 | 随后出现领取 → 打印中 → 打印完成，纸从奔图出来 | 张数 |
| 5 | 全过程没有第二笔扣款 | 手机账单 |

缺任一项不得把「支付全链路」勾成通过。

## E. 扫描（面板扫描）

> 网页**不能**远程按扫描仪。屏幕上没有「开始扫描」按钮，这是设计如此（来源：`apps/kiosk/src/pages/scan/ScanStartPage.tsx:272`-275`）。  
> 文件回传依赖 A.8 的扫描目录 + 奔图把扫描件写进该目录。奔图面板菜单名以现场机器为准；一体机只原样展示服务端指引。

### E.1 确认扫描能力未关闭

1. **做什么**  
   Hub 点「材料扫描」。看是否被挡。
2. **应该看到什么**  
   页标题「材料扫描」。可创建时状态「可创建扫描任务 · 需面板操作」（来源：`apps/kiosk/src/pages/scan/ScanStartPage.tsx:91``），副标题「请先选择扫描类型；本页尚未创建任务。下一步会创建真实扫描会话」（来源：同文件 `:97`）。说明卡标题「为什么屏幕上没有「开始扫描」」，正文含「这台一体机的扫描只能在奔图自己的操作面板上启动」（来源：同文件 `:272-275`）。  
   若管理员把 `scan` 配成非 available：状态「扫描能力暂未开放」（来源：同文件 `:88`）。
3. **看不到时属于哪一类**  
   ④ 扫描能力被关；⑦ Hub 因一体机离线把扫描一起停（「打印和扫描是同一台机器，它出不了纸，扫描一起停。」来源：`PrintScanHomePage.tsx:183`）。
4. **现场立刻能做的补救**  
   后台设备能力里不要把「材料扫描」留在维护/未验收。打印机离线先修打印机。

### E.2 建扫描会话

1. **做什么**  
   类型选「普通文档」（来源：`apps/kiosk/src/pages/scan/scanWorkbench.ts:16``）。点「下一步 · 创建扫描会话」。等到出现任务编号后，**再**去奔图面板。不要提前按面板。
2. **应该看到什么**  
   创建成功后先等**投递授权 ACK**。ACK 成功才进入「扫描指引」并显示「扫描任务已创建」与「第 2 步 · 去面板操作」。
   若 ACK 仍在确认或失败，应看到「正在确认投递授权」/「投递授权未确认」以及按钮「再确认一次」；
   这时任务尚不可交付，**不要去奔图面板按开始**。任务编号、剩余时间在「任务信息」里。
   指引原文由服务端下发，普通文档为：
   - 「多页材料放入自动进纸器，单页证书放在玻璃板上」  
   - 「在打印机操作面板点击「扫描」，并选择「扫描到 SMB」（本机已配置的接收目录）」  
   - 「按「开始」扫描；整叠扫完后回到本屏幕等待自动生成 PDF，请勿关闭页面」  
   主按钮「我已操作，开始等待」（来源：`apps/kiosk/src/pages/scan/ScanSettingsPage.tsx:391``）。
3. **看不到时属于哪一类**  
   ⑧ 会话创建失败；⑪ 网络；⑫ 投递授权未确认。会话已创建但 ACK 未成功时，不得归类成扫描目录故障。
4. **现场立刻能做的补救**  
   创建失败不要在面板上扫。若是「投递授权未确认」，先点「再确认一次」；只有进入「扫描指引」后才去面板。
   授权窗口内断网时记录屏幕文字和恢复时间，不要反复创建会话或提前扫描。

### E.3 在奔图面板上扫

1. **做什么**  
   按屏幕指引把纸放好。在奔图面板打开扫描，目标选能写到 A.8 那个目录的「扫描到网络 / SMB」（或现场等价项）。按面板的开始。扫完回到一体机点「我已操作，开始等待」。
2. **应该看到什么**  
   一体机进入「等待打印机端扫描完成」，副标题「请在打印机面板完成扫描到本机接收目录；本页每 3 秒自动检测结果」（来源：`apps/kiosk/src/pages/scan/ScanProgressPage.tsx:268`-269`）。状态「等待文件回传」（来源：同文件 `:262`）。面板标题「正在等文件回传」（来源：同文件 `:314`）。  
   奔图面板上的菜单名**以现场机器为准**（仓库没有奔图固件截图）。U 盘那条独立路径明确写着「具体菜单名称、可选格式和 USB 接口位置以现场奔图面板为准。」（来源：`apps/kiosk/src/pages/scan/ScanStartPage.tsx:180``），SMB 路径同样不要臆造菜单字。
3. **看不到时属于哪一类**  
   ⑧ 目录未配置 / 奔图没扫到该目录 / Agent 扫描监视未工作。本机状态页若是「扫描目录未配置」，本步必失败。
4. **现场立刻能做的补救**  
   回到控制中心核对扫描目录。看该目录是否出现新文件。点「立即检查」（来源：`apps/kiosk/src/pages/scan/ScanProgressPage.tsx:300``）。不要反复按面板开始造成多份无人认领的文件。

### E.4 看结果

1. **做什么**  
   等自动跳到结果页。可点「直接打印」走回打印链路，或「重新扫描」。
2. **应该看到什么**  
   成功：标题「扫描完成」，状态「服务端已回完成并带回文件」（来源：`apps/kiosk/src/pages/scan/ScanResultPage.tsx:214`-216`）。主按钮「直接打印」（来源：同文件 `:224`）。  
   失败：「扫描未完成」或「会话已过期」（来源：同文件 `:146`）。无文件的完成：「已完成 · 回执里没有文件」（来源：同文件 `:146`）。
3. **看不到时属于哪一类**  
   ⑧ 回传匹配失败。
4. **现场立刻能做的补救**  
   「重试扫描」是另一次任务（页上写明，来源：`ScanResultPage.tsx:190`）。连续失败找人看 SMB/目录权限，不要把同一份纸扫进别人的会话。

**E 段通过标准：** 结果页「扫描完成」且能看到回传文件。U 盘扫描路径标注「Windows / 奔图真机尚未验收」（来源：`packages/shared/src/types/complianceCopy.ts:82``），本脚本不把它勾成通过。

## F. 扫码枪读付款码

> 机身侧面是影像扫码模组，在系统里是 **HID 键盘**，靠接近感应触发（代码注释，来源：`KioskHidScanGuard.tsx:70-74`）。  
> **只在收银台页消费付款码。** 授权路由只有 `/print/cashier` 和 `/print/pickup-claim`（来源：同文件 `:19`）。  
> 微信/支付宝付款码都是 **18 位数字**（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:13`-18`）。  
> 本路径依赖服务端 `PAYMENT_CODEPAY_AUTO_CONVERGE_ENABLED=true` 以及微信门店编号；未启用时会明确失败。现场是否已开通 **标未验证，以这一单结果为准**。

### F.1 先回到收银台，不要在别的页扫

1. **做什么**  
   再下一笔应付 > 0 的单，走到「订单支付」。若在首页/表单页把手机付款码凑近扫码区，只是为了看防护是否生效——不要用真的待付码做这个试验。
2. **应该看到什么**  
   非授权页误扫：顶部提示标题「已忽略一次扫码」，正文「扫码设备在本页读到了一串内容。本页不需要扫码，内容已丢弃，你正在填写的内容没有被改动。」（来源：`apps/kiosk/src/components/hid-guard/KioskHidScanGuard.tsx:167`-170`）。
3. **看不到时属于哪一类**  
   ⑨ 扫码模组没接好 / 不是键盘模式 / 没有以 Enter 结尾（母盘要求 HID 键盘模式并以 Enter 结尾，来源：`windows-golden-image-and-install-checklist.md:18`）。
4. **现场立刻能做的补救**  
   用记事本测：扫一枚码应出现字符并回车。不进记事本就先修 USB 模式，不要继续用付款码试。

### F.2 选「扫付款码」，不要扫屏幕上的收款码

1. **做什么**  
   先选通道（微信或支付宝，须与手机付款码品牌一致）。点「扫付款码」（小字「出示你的付款码」，来源：`PrintCashierPage.tsx:73`）。打开手机微信/支付宝的**付款码**（用户被扫的码），把屏幕凑近机身扫码区。屏幕上的动态收款码不要用枪扫。
2. **应该看到什么**  
   标题「请出示手机付款码」，说明「现在还没有向支付平台发起收款，读满十八位并提交后才会创建支付尝试。」（来源：`apps/kiosk/src/pages/print/components/CashierQxView.tsx:109``）。表单标题「请扫描或输入手机付款码」，提示「扫码器会自动读取并提交；也可手动输入 18 位数字。」「为保护你的支付安全，付款码不会显示在这块公共屏幕上。」（来源：`CashierPaymentPanel.tsx:222-226`）。进度「等待扫码」（来源：同文件 `:264`）。读入过程「已读取 n / 18 位」（来源：同文件 `:266`）。读满「已读取完整付款码，正在提交…」（来源：同文件 `:262`）。提交后「正在确认付款结果」（来源：`CashierQxView.tsx:110`）或「支付处理中」「请按手机提示完成验证，支付结果会自动确认。」（来源：`cashierStatus.ts:161-163`）。成功后仍须变成「支付成功」/「付款已由服务端确认」，然后出纸。  
3. **看不到时属于哪一类**  
   ⑨ 位数读不满；⑥ 失败文案若是「付款码支付自动核验未启用，请联系工作人员」或「付款码支付未配置，请联系工作人员」（来源：`services/api/src/payment/providers/wechat-pay.provider.ts:245``、`:250`，经 `PrintCashierPage.tsx:284` 上屏）= 生产没开付款码核验，**不是枪坏了**。读满却提示「请输入 18 位数字付款码」（来源：`PrintCashierPage.tsx:235`）= 缓冲被清或混入非数字。
4. **现场立刻能做的补救**  
   「清空重扫」（来源：`apps/kiosk/src/pages/print/CashierPaymentPanel.tsx:278``）。调高手机亮度、关掉屏幕花纹。品牌必须和所选通道一致。失败后看清屏幕上的失败句再决定：配置类失败整段记「未验证」，不要反复扣款。成功后的出纸标准同 D.5。

**F 段通过标准：** 付款码从未显示在公共屏幕上；读满 18 位后服务端确认 paid 并出纸。若失败句是「未启用 / 未配置」，勾「未验证（服务端未开通付款码）」而不是「扫码枪损坏」。

3. **看不到时属于哪一类**  
   ⑩ 小程序版本/权限；或扫的是支付码/别的码。
4. **现场立刻能做的补救**

2. **应该看到什么**  
   - 卡片标题「到机码核销」，描述「输入 8 位数字到机码（历史 10 位码也支持），核对订单后领取打印件。」（来源：`apps/kiosk/src/pages/print-scan/PrintScanHomePage.tsx:262-264`）；未登录时副文案「凭码办理 · 不登录也能核销」（来源：`apps/kiosk/src/pages/print-scan/printHubContent.ts:261`）。  
   - 页标题「输入你的到机码」（来源：`apps/kiosk/src/pages/print/PrintPickupClaimPage.tsx:276`），提示「这一步不收钱」（来源：同文件 `:463`），主按钮「确认校验」（来源：同文件 `:510`），校验中「正在校验，请稍候」（来源：同文件 `:472`）。  
   - 已付或免费单成功：标题「打印任务已释放」，按钮「查看打印进度」（来源：`apps/kiosk/src/pages/print/pickupClaimModel.ts:104`、`:107`），**不经过预览和参数页**，参数取自订单。  
   - 未付款单成功：标题「订单核验成功」，按钮「进入现场支付」（来源：同文件 `:110`、`:113`）→ 转 D 段付款后再回来看出纸。
3. **看不到时属于哪一类**  
   码错、过期或不属于这台机器，都只显示一句「到机码无效或已过期，请核对后重新输入」（来源：`apps/kiosk/src/services/api/userErrorMessage.ts:42-43`），这是防试探的有意设计（来源：`apps/kiosk/src/pages/print/components/PickupHidGuide.tsx:350`）。10 分钟内输错超过 10 次锁定 15 分钟，显示「本机输码暂时停用」（来源：`services/api/src/print-jobs/pickup-claim-lockout.ts:48-54`、`PickupHidGuide.tsx:311`）。
4. **现场立刻能做的补救**  
   核对小程序上的码和选的终端是否是这台。**核销接口本身不检查打印机能不能出纸**——卡片副文案若是「这台出不了纸 · 核销前先换一台空闲机器」（来源：`printHubContent.ts:260`），先处理打印机再核销，否则码会被用掉而纸出不来。

### H.3 出纸

1. **做什么**  
   点「查看打印进度」，站在出纸口。
2. **应该看到什么**  
   进度与 C.6 相同：「等待终端领取」→「终端已领取任务」→「正在打印」（来源：`apps/kiosk/src/pages/print/PrintProgressPage.tsx:71`、`:83`、`:95`），完成页「打印完成」「文件已从出纸口送出，请核对页数后取走」（来源：`apps/kiosk/src/pages/print/PrintDonePage.tsx:632-633`）。
3. **看不到时属于哪一类**  
   同 C.6（⑦ / ② / ③）。
4. **现场立刻能做的补救**  
   同 C.6。中途缺纸或卡纸转 I 段，不要让用户再输一次码。

### H.4 三处看「已完成」（闭环判据）

1. **做什么**  
   出纸后依次看：① 后台「订单管理」里这一单；② 小程序「订单」列表与详情、到机码页；③ 一体机用**同一手机号**登录后进「我的打印订单」（`/me/print-orders`）。
2. **应该看到什么**  
   - 后台：菜单「订单管理」（来源：`apps/admin/src/layouts/AdminLayoutWrapper.tsx:100`），任务状态「已完成」（来源：`apps/admin/src/routes/orders/index.tsx:34`），取件列「已取件」（来源：同文件 `:118`）。  
   - 小程序：列表「已完成」（来源：`apps/miniapp/pages/orders/orders.js:29`），详情「已完成」（来源：`apps/miniapp/pages/order-detail/order-detail.js:29`），到机码页「打印已完成」（来源：`apps/miniapp/pages/print-pickup/pickup-state.js:43`）。  
   - 一体机：「已完成」（来源：`apps/kiosk/src/pages/profile/me/MyPrintOrdersPage.tsx:50`）。
3. **看不到时属于哪一类**  
   三处不一致就是闭环断了：记下每处的原文和时间，属 ⑬ 状态回写。
4. **现场立刻能做的补救**  
   先等一分钟再刷新（一体机进度 3 秒轮询、设备状态 60 秒刷新）；仍不一致就截三处的图，不要在后台手改状态。

### H.5 同一码再输一次（一次性，选做）

1. **做什么**  
   H.2 成功后 10 分钟内在同一台机器再输一次同一码；有时间的话，10 分钟后再输一次。
2. **应该看到什么**  
   10 分钟内：直接回到上次的放行结果，不再建任务、不再出纸（来源：`services/api/src/print-jobs/pickup-order.service.ts:37`、`:110-113`）。10 分钟后：服务端拒绝「这份到机码已经使用过，不能再次取件」（来源：同文件 `:315`），但**一体机当前显示的是兜底句「到机码校验没有完成，请重试或联系现场工作人员」**（来源：`PrintPickupClaimPage.tsx:215`；错误码 `PICKUP_CODE_ALREADY_USED` 不在一体机文案映射表 `userErrorMessage.ts` 里）。
3. **看不到时属于哪一类**  
   出了第二份纸 = 严重缺陷，立刻停下记录。看到兜底句属已知缺陷（2026-09-29 记入进度文档），不是现场故障。
4. **现场立刻能做的补救**  
   不要按兜底句的「请重试」反复输——每次都会计入失败次数，10 次后本机锁 15 分钟。

**H 段通过标准：** 小程序拿到码 → 一体机核销 → 出纸 → 后台、小程序、一体机三处都是「已完成」；同一码不会出第二份纸。

## I. 缺纸 / 卡纸：告警 → 处理 → 恢复（闭环）

> 人为制造故障的做法、这台奔图的驱动限制与各终态对应的钱和纸，**以 [现场故障处置单](onsite-failure-recovery-runsheet-2026-09.md) 的 §1、F1、F2 为准**，本段只补「告警 → 处理 → 恢复」这条闭环该在哪里看到什么。  
> 用**免费单**、≥2 页的 PDF。C 段通过后再做。

### I.1 缺纸

1. **做什么**  
   按故障处置单 F1 ① 制造缺纸（纸盒留 5–10 张，出纸开始后抽走剩余纸）。等一体机进入结果页，最多约 5 分钟。然后打开后台「告警中心」。  
   **抽走纸之后、补纸之前**，在管理员 PowerShell 里做一次只读探测（Windows 真机路经远程做，产品负责人不用动手；打印机名用 `Get-Printer` 里看到的那个）：
   ```powershell
   Get-CimInstance Win32_Printer -Filter "Name='<打印机名>'" | Select-Object PrinterStatus,DetectedErrorState,ExtendedDetectedErrorState,PrinterState,ExtendedPrinterStatus,WorkOffline,PortName | Format-List
   Get-PrintJob -PrinterName '<打印机名>' | Select-Object Id,JobStatus,PagesPrinted,TotalPages | Format-List
   ```
   两条都只读，不输出文件名。补纸后再跑一次做对照。**可选**（不在必做步骤里）：打印机当天若另插了网线、有固定 IP，Windows 真机路再探一次 SNMP 的打印机错误状态。这些读数用来决定要不要让 Agent 走网口读缺纸（2026-09-29 总指挥定：先拿读数再决定，不先写代码）。
2. **应该看到什么**  
   - 一体机结果页按终态分叉：`PAPER_EMPTY` 时标题「打印机缺纸」，副标题「已经登记缺纸，这次打印不会在加纸后自动续打」（来源：`apps/kiosk/src/pages/print/PrintDonePage.tsx:497-498`）；本机型更常见的是「打印结果未确认」（来源：同文件 `:543`）。  
   - 后台「告警中心」（来源：`apps/admin/src/routes/alerts/index.tsx:153`）出现类型「打印失败」（来源：同文件 `:19`），标题形如「打印任务失败(PAPER_EMPTY)」或「打印任务失败(PRINT_JOB_UNCONFIRMED)」（来源：`services/api/src/admin-ops/derived-alerts.ts:244`）。  
   - 「打印机异常」类告警（来源：`alerts/index.tsx:18`）**多半不会出现**：这台奔图的驱动不报缺纸位，心跳仍是 `ready`（见故障处置单 §1）。出现了就记下标题原文。  
   - 配了 `ALERT_WEBHOOK_URL` 时，企业微信群一分钟内收到「【职易达告警】…：正在发生」（来源：`services/api/src/admin-ops/admin-alert-push.service.ts:82`）。
3. **看不到时属于哪一类**  
   ⑦ 打印机；告警中心没有任何一条 = ⑬ 状态回写，记下任务号。
4. **现场立刻能做的补救**  
   先不补纸，把一体机结果页、告警中心、`Get-PrintJob` 三处拍下来，再进入 I.2。

### I.2 缺纸后的处理与恢复

1. **做什么**  
   补纸，按奔图面板清掉残留作业。然后按一体机结果页分两种：  
   - 有「重新提交打印」按钮（`PAPER_EMPTY` 等明确失败）：点它，站在出纸口。  
   - 「打印结果未确认」：不点任何重打。数出口实际出了几张，到后台「订单管理」这一单点「已核查·已出纸」或「已核查·未出纸」如实登记。  
   最后回告警中心处理这条告警。
2. **应该看到什么**  
   - 重提：按钮「重新提交打印」（来源：`PrintDonePage.tsx:463`），**不再收费**；随后出纸并到「打印完成」。  
   - 未确认：服务端拒绝重提「打印结果未确认，不能重新提交，请联系工作人员核查」（来源：`services/api/src/print-jobs/print-jobs.service.ts:722`）；后台核查按钮「已核查·已出纸」「已核查·未出纸」（来源：`apps/admin/src/routes/orders/index.tsx:602`、`:609`）。  
   - 告警操作「确认」「静默 1 小时」「关闭」「重新打开」（来源：`alerts/index.tsx:270-281`）。企业微信在恢复后收到「…：已恢复」（来源：`admin-alert-push.service.ts:82`）。  
   - 失败的任务**不会**因补纸自动续打（见故障处置单 F1 ④）。
3. **看不到时属于哪一类**  
   重提后又不出纸 → ⑦；告警一直不消失 → ⑬，手动「确认」并记录时间。
4. **现场立刻能做的补救**  
   绝不因为「屏幕说失败」就让用户再下一单——先数出口的纸。

### I.3 卡纸

1. **做什么**  
   按故障处置单 F2 ① 制造卡纸（出纸中打开前盖或按奔图说明制造卡纸）。等结果页，看告警中心，然后按 I.2 同样的顺序清卡纸、处理、恢复。
2. **应该看到什么**  
   结果页「打印机卡纸」，或本机型更常见的「打印结果未确认」（来源：`PrintDonePage.tsx:543`；注意任何 `PRINTER_ERROR` 都会显示成卡纸）。服务端给用户的原因「打印机可能卡纸或发生设备故障，请联系工作人员处理」（来源：`services/api/src/print-jobs/print-jobs.service.ts:122`）。告警与 I.1 相同。
3. **看不到时属于哪一类**  
   ⑦ 打印机；⑬ 状态回写。
4. **现场立刻能做的补救**  
   卡住的纸按奔图说明取出，不要硬拽。清完先打一张 C 段的零元单确认恢复，再放行下一位用户。

**I 段通过标准：** 缺纸和卡纸各一次：一体机给出失败或未确认结果（不是假「打印完成」）→ 告警中心有对应告警 → 按提示处理后出纸恢复、告警处理完、订单状态如实（已完成 / 已核查）。实际 `errorCode` 以日志为准，没有 `PAPER_EMPTY` 就不写「缺纸检测已通过」。

## 收尾

1. **做什么**  
   后台「打印扫描运维」→「任务中心」核对应付那一单为「已完成」。控制中心不要停掉看门狗。桌面绑定入口留着。把记录表填完。敏感纸张带走或销毁。
2. **应该看到什么**  
   任务状态「已完成」（来源：`apps/kiosk/tests/visual/human-journey.spec.ts:107``）。一体机回到首页，「打印 · 扫描」仍是「打印机在线」。
3. **看不到时属于哪一类**  
   按未通过项的原分类，不要改口说「整体通过」。
4. **现场立刻能做的补救**  
   未通过项单独列阻塞等级。部分通过 ≠ 整机商用通过。
