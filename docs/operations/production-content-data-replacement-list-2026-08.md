## 1. 目标与边界

- 目标：把线上样例/预生产/过期/演示内容替换为合法真实来源，并建立可重复的审核-发布-下架链路。

## 2. 数据负责人必须决策的规则（先决策，再执行）

- [ ] 每类数据（岗位/招聘会/政策/线下机构/线上平台目录）的**合法真实来源**与来源授权文件（合同/授权书/公开声明）。
- [ ] **有效期与刷新**规则（岗位下架、招聘会结束、政策版本、机构状态）。
- [ ] **审核人**与发布前必检项（谁来审、审什么）。
- [ ] 第三方来源的**标注口径**（页面「来源平台」+ 去来源平台投递/扫码投递文案，禁止平台内一键投递）。
- [ ] 无法确认授权的存量数据是**下架**还是**标注为样例**（推荐下架，避免误导）。

## 4. 执行流程（授权后）

1. 数据负责人确认第 2 节决策项并给出每类来源清单。
2. 在明确授权窗口内，先做只读现状快照（表行数、公开计数、过期计数、来源域名），留存证据。
3. 按第 3 节路径逐类处理：先下架无授权存量，再导入已授权真实数据，经审核发布。
4. 每类完成后跑对应验证门禁（质量快照、公开筛选、详情来源、合规文案、Kiosk 公网抽检）。
5. 汇总前后计数差异与审计记录，写入 `docs/progress/current-progress.md`。

## 5. 禁止项

- 未获具名授权不连接/不写入生产数据库；不使用 `db:seed*` 或演示数据填充。
- 不把预生产隔离样本直接当生产数据；第三方来源未授权前必须标注或下架。
- 不绕过 Admin/Partner 审核发布闭环直接改库；不静默删除无备份。
- 不新增重复入口或同义卡片来“显得有内容”。
