# 内容信息库录入操作手册（岗位 / 招聘会 / 政策）

> **这份文件写给运营人员，不是写给工程师的。**
> 目标：让一条真实岗位 / 招聘会 / 政策，从零出现在人才市场大厅那台一体机的屏幕上。
>
> 每一步都写清：在哪个后台的哪个页面、前置条件是什么、失败会看到什么提示。
>
> 本文所有结论都来自 2026-08-18 在隔离库上跑通的端到端实测
> （门禁：`services/api` → `pnpm verify:content-pipeline-e2e`，117 项断言全绿）。
> 没实测过的组合，本文一律标注「本机不可判别」或「未实现」，不含糊带过。

## 零、先看这一条：不做这一步，后面全白做

**来源机构必须先被管理员标记为「内容可信」，否则任何内容都发布不出去。**

- 谁能做：**管理员**（admin 角色）。合作机构自己不能给自己发这个章。
- 在哪做：管理员后台 → 合作机构 → 选中机构 → 内容可信状态。
- 接口：`PATCH /api/v1/admin/orgs/:id/content-trust`，body `{ "status": "active", "reason": "<授权依据>" }`
- 前置：先完成**来源授权核验** —— 确认这家机构确实有权把这些岗位/招聘会信息给我们展示。
  `reason` 要写清依据（合作协议编号、授权函、公开数据许可等），它会进审计日志。

**没标记时会看到什么：** 审核可以通过，但点「发布」会失败，提示：

```
来源机构「XX人才服务中心」(org-xxx) 未通过内容信任核验：
当前 contentTrustStatus=未标记(null)，发布要求 active 且未归档。
请先完成来源授权核验，再由管理员在「管理员后台 → 合作机构」把该机构标记为内容可信…
```

**为什么这么严：** 2026-08-17 发生过一起真实事故 —— 5 条未授权的第三方岗位进了生产并公网可见。
这道闸门就是为此加的，它是 fail-closed：**未标记、pending、suspended、revoked、机构不存在，一律拒绝发布。**

三件相关的事，实测确认：

- 机构未标可信时，内容**照样能录入**，只是发不出去。所以可以先录数据、后补授权，顺序不卡人。
- 已归档（archivedAt 非空）的机构，即使 `contentTrustStatus=active` 也一样拒绝。
- **下架（unpublish）永远不受这道闸门限制** —— 否则出了问题的内容反而撤不下来。

## 一、通用链路：六种方式都一样的后半段

不管数据用哪种方式进来，后半段完全一致：

```
录入 → 落「待审核 + 草稿」 → 管理员审核通过 → 管理员发布 → 一体机前台可见
```

| 步骤 | 谁做 | 在哪 | 说明 |
|---|---|---|---|
| 1. 录入 | 合作机构 / 系统 | 合作机构后台，或自动同步 | 无论哪种方式，一律落 `待审核 + 草稿`。**没有任何入口能让内容跳过审核直达前台。** |
| 2. 审核 | 管理员 | 管理员后台 → 岗位信息源 / 招聘会信息源 / 政策信息源 | 可先点「转入审核中」，再「通过」或「驳回」。驳回**必须填理由**。 |
| 3. 发布 | 管理员 | 同上，审核通过后出现「发布」 | 这里会过两道闸门，见下方「发布被拒的三种提示」。 |
| 4. 前台可见 | —— | 一体机 岗位信息 / 招聘会 / 政策服务 | 发布成功即刻可见，实测确认。 |

**审核状态是单向的：** `通过` 和 `驳回` 都是终态，点完不能反悔。
再点会提示 `审核终态 approved 不可回退,需走 reopen 流程`。
要改，只能让机构那边重新录入/编辑该条 —— 内容一变，系统自动把它打回「待审核 + 草稿」
（**注意：这会把已经上线的那条内容同时撤下来**，改完要记得重新审核发布）。

### 发布被拒的三种提示，对照表

| 看到的提示 | 真正的原因 | 怎么办 |
|---|---|---|
| `未通过审核的岗位不得发布` | 还没点「审核通过」 | 先审核 |
| `来源机构「X」未通过内容信任核验…` | 机构没标内容可信 / 已归档 | 回到第零节 |
| `岗位来源信息不完整,不得发布(缺少必填字段:来源链接)` | 这条数据本身缺来源可追溯字段 | 见下一节 |

**系统绝不会替你把空字段填上默认值。** 提示里那句
「系统不会为任何字段填充默认值」是刻意的：
伪造一个来源链接比留空危险得多 —— 留空看得出数据有问题，伪造会让一条无法追溯的岗位看起来完全正常。

### 发布必填字段（缺一条就发不出去）

| 内容类型 | 必填 |
|---|---|
| 岗位 | 来源机构、外部ID、来源名称、**来源链接（必须 http/https 开头）**、同步时间、职位名称、公司名称、工作城市 |
| 招聘会 | 来源机构、外部ID、来源名称、**来源链接**、同步时间、招聘会名称、举办地点、城市、开始时间、结束时间 |
| 政策 | 来源机构、来源名称、同步时间（这三项系统自动填）。**政策没有「来源链接」必填要求** —— 详见第四节 |

> 只有空格的字段按空处理。`来源链接` 填 `www.xxx.com`（不带 http/https）会被判为
> 「不是 http/https 开头的可追溯链接」。

## 二、六种接入方式，逐一操作说明

### 方式一：手动录入（manual）—— 线下公司最常用，**重点看这条**

适用：没有 IT 系统的线下公司、临时岗位、单条补录。

**岗位**
1. 合作机构后台 → 岗位信息管理 → 右上角「新增岗位」
2. 抽屉标题是「新增岗位(手动录入)」。填：职位名称、公司名称、城市、工作类型、薪资、**来源链接**、标签、职位描述、任职要求
3. 保存 → 自动落「待审核 + 草稿」
4. 交给管理员审核 + 发布

**招聘会**：合作机构后台 → 招聘会信息管理 → 「新增招聘会」。
填：名称、主题、开始/结束时间、举办地点、城市、详细地址、**来源链接**、签到链接、简介。

**政策**：合作机构后台 → 政策公告 → 「新增政策内容」。
填：类型（政策扶持条目 / 政策公告）、标题、适用人群或分类、摘要、正文、官方入口链接、发布日期。
⚠️ **只有「公共就业服务机构」和「高校就业中心」两类机构能录政策**，其他机构会被拒：
`仅公共就业服务机构与高校就业中心可发布政策内容`。

#### 手动录入时，「外部ID」和「来源链接」到底该填什么？

这两个字段决定了一条数据事后**还能不能追回源头**。填错就是我们自己在制造无法追溯的数据，
和 8/17 那起事故同性质。请严格按下面执行。

**外部ID —— 页面会自动生成，不用管，也不要手改成别的样子。**

系统自动生成形如 `MANUAL-1755498231-a3f9c2` 的编号。
它的含义是「**本机构手工台账的第 N 条**」，不声称来自任何第三方系统 —— 这是诚实的。

- ✅ 就用系统自动生成的
- ❌ **绝对不要**手工填一个看起来像其他平台编号的值（比如从某招聘 App 上抄一个岗位 ID 过来）。
  那等于宣称「这条数据来自那个平台」，是伪造来源。

**来源链接 —— 这是最容易出事的一格。**

它的定义是：**求职者在一体机上点「去来源平台投递」时，会打开的那个地址。**
所以判据只有一条 —— **求职者打开它之后，真的能看到这个岗位并完成投递吗？**

合法填法（三选一，按优先级）：

1. 该企业**官方招聘页**上这个岗位的地址
2. 这个岗位在官方 / 第三方招聘平台上的**公开链接**
3. 本机构自己的**公开岗位公示页**（人才市场官网、公众号推文等，且页面上真的有这条岗位）

绝对不可以：

- ❌ 随便填机构首页或企业首页凑数（求职者打开后找不到这个岗位）
- ❌ 填一个不含该岗位的页面
- ❌ 填 `example.com` 之类的占位地址
- ❌ 填内网地址

**如果上面三种都没有，怎么办？**

说明这是一条**纯线下岗位** —— 它本来就不该进「岗位信息」库。
系统里有专门的一条线：**线下机构 / 线下岗位**（管理员后台 → 线下机构 → 机构详情 → 岗位）。
那条线上的岗位允许没有外部链接，求职者看到的是「到线下机构现场咨询」，而不是「去来源平台投递」。

> 硬塞进岗位库并编一个链接，是本项目最不能接受的做法。
> 宁可这条岗位走线下机构那条线，也不要造一条打不开的来源链接。

### 方式二：Excel 导入（excel）

适用：中小机构、学校、人社批量报表。

1. 合作机构后台 → 数据源管理 → 新建数据源，接入方式选「Excel / CSV 导入」
2. 在数据源列表里点该行的「**字段映射**」
3. 下载模板（可选）：数据源页提供 `岗位模板 / 招聘会模板` 下载
4. 上传 `.xlsx` → 系统读出所有列名 → 把 Excel 列名对应到标准字段
5. 预览：系统逐行标 `可导入 / 有问题 / 重复`，并给出每一行的具体错误
6. 确认导入 → 全部落「待审核 + 草稿」
7. 交管理员审核 + 发布

**映射规则会被记住** —— 下次导入同一个数据源时自动回填，不用重配。

Excel 必填列（缺任意一列，该行会被标成「有问题」，且不计入可导入行数）：

- 岗位：外部ID、职位名称、公司名称、工作城市、来源链接
- 招聘会：外部ID、招聘会名称、开始时间、结束时间、举办地点、城市、来源链接

**⚠️ 一个必须知道的坑（已实测确认）：**
Excel 里**漏填来源链接**的行，在预览阶段就会被标成「有问题」并排除，不会导进来 —— 这是好的。
但如果某行的来源链接是**空单元格但列存在且被映射了**，它可能一路导入成功，
直到点「发布」那一刻才被拒 (`缺少必填字段:来源链接`)。
所以：**导入后先抽查几条，别等到发布环节才发现整批数据缺链接。**

### 方式三：CSV 导入（csv）

和 Excel 完全同一条流程、同一个页面、同一套字段映射 —— **区别只在上传的文件是 `.csv`**。

- 建数据源时接入方式同样选「Excel / CSV 导入」
- 上传时选 `.csv` 文件即可，系统按文件扩展名自动识别
- 同步日志里会如实记为 `csv`（本次修复前会错记成 `excel`）

> CSV 请用 UTF-8 保存，带不带 BOM 都可以。字段里有逗号或引号时用标准 CSV 双引号转义。

### 方式四：Webhook 推送（webhook）—— **只支持岗位**

适用：对方系统有数据更新时主动推给我们。

1. 合作机构后台 → 数据源管理 → 新建数据源，接入方式选「Webhook 推送」
2. 创建成功后，页面会**一次性**显示推送地址和密钥：
   - 地址：`POST /api/v1/sync/webhook?source=<数据源ID>`
   - 密钥：`webhookSecret`
   **这个密钥只显示这一次，之后再也查不到，请立刻交给对方技术并妥善保存。**
3. 数据源建好后处于**停用**状态，需要**管理员**在管理员后台启用（api / webhook 两种方式由管理员管控）
4. 对方按签名规则推送，数据落「待审核 + 草稿」
5. 管理员审核 + 发布

对方技术需要知道的（三个请求头 + 签名算法）：

```
X-Webhook-Timestamp : unix 秒，与服务器时间相差不得超过 5 分钟
X-Webhook-Nonce     : 8–128 位随机串，5 分钟内不得重复
X-Webhook-Signature : HMAC-SHA256(webhookSecret, "<timestamp>.<原始请求体>") 的十六进制
```

失败一律返回 `401 WEBHOOK_UNAUTHORIZED`，**不区分具体原因**（防探测）。
对方排查时按这个顺序自查：密钥对不对 → 时间戳是否超窗 → nonce 是否重复 → 数据源是否已被管理员启用。

实测确认：正确签名导入成功；同一个 nonce 重放 → 401；签名错误 → 401。

### 方式五：API 定时拉取（api）—— 由管理员配置

适用：招聘平台、ATS、政府/学校开放接口。

1. 合作机构后台 → 数据源管理 → 新建数据源，接入方式选「API 直连」，填接口地址与凭证
2. 数据源建好后是**停用**状态，须**管理员**在管理员后台启用
3. 管理员配置返回格式（`dataType` 选 岗位 或 招聘会）
4. 之后按同步频率自动拉取；管理员也可手动点「立即同步」
5. 拉回的数据落「待审核 + 草稿」

**接口必须是公网可访问的 http/https 地址。** 内网地址、`127.0.0.1`、`192.168.*` 等
会被安全守卫拒绝，同步日志里会记 `SSRF_PRIVATE_IP_BLOCKED`（实测确认）。

**只接受 JSON 返回。** 返回 CSV / XML 会解析失败并记入同步日志。

同步结果在：合作机构后台 → 同步日志。失败原因会写在那里。

### 方式六：JSON 文件导入（json）—— **当前不可用**

数据源接入方式里虽然有 `json` 这个取值，但**系统没有 JSON 文件解析器**。
上传 `.json` 文件会被拒绝：

```
文件格式不受支持：当前仅支持 .xlsx 与 .csv 两种格式，请另存为后重新上传。
```

**运营请勿使用这种方式。** 需要从 JSON 导数据，两条现成的路：
把 JSON 转成 CSV 走「方式三」，或让对方走「方式四 Webhook」（Webhook 收的就是 JSON）。

## 三、6 种接入方式 × 3 类内容 覆盖矩阵

实测日期 2026-08-18，方法：隔离 SQLite + 真实 HTTP + 真实后台接口，逐格跑。

图例：**真通** = 从入口进数据一路到一体机前台可见，有实测输出；
**半通** = 断在某一步；**只有壳** = 类型里有名字、没有实现；**不适用** = 该组合本就不该有。

| 接入方式 | 岗位 | 招聘会 | 政策 |
|---|---|---|---|
| **manual** 手动录入 | ✅ **真通** | ✅ **真通** | ✅ **真通** |
| **excel** Excel 导入 | ✅ **真通** | ✅ **真通** | ⛔ **不适用**（见下 A） |
| **csv** CSV 导入 | ✅ **真通** | ✅ **真通** | ⛔ **不适用**（见下 A） |
| **webhook** 推送 | ✅ **真通** | ⛔ **不适用**（见下 B） | ⛔ **不适用**（见下 B） |
| **api** 定时拉取 | ⚠️ **半通**（见下 C） | ⚠️ **半通**（见下 C） | ⛔ **不适用**（见下 A） |
| **json** JSON 文件 | ❌ **只有壳** | ❌ **只有壳** | ❌ **只有壳** |

### 不适用 / 半通 的理由

**A. 政策不走文件导入和 API 拉取 —— 而且不该走。**
政策条目数量少（一个地区几十条）、正文长、要配「申领条件」结构化规则、
还要人工核对官方原文。批量导入省不下多少事，却会把「有没有人真的读过这条政策」这个把关点弄没。
政策条目本身也不在数据源体系里（政策表没有数据源外键）。
**结论：维持手动录入，不建议新增。**

**B. Webhook 只收岗位，招聘会/政策推过来会被明确拒绝（不是静默吞掉）。**
实测：推招聘会字段 → `400 property startAt should not exist`。
系统的能力矩阵里对此有明确注释：「当前 Webhook 端点只接受岗位，尚无招聘会 Webhook，先 fail-closed」。
招聘会一年就那么几场，Webhook 的实时性没有价值。**结论：不建议新增。**

**C. API 拉取标「半通」，是因为本机判别不了它的网络那一半。**
- 已实测通过：拉回来的数据能正确映射、落库、落「待审核 + 草稿」；内容变了会强制重新审核。
- 已实测通过：内网/回环地址被安全守卫拒绝，并写进同步日志。
- **未实测**：本机离线，「真的能从第三方公网 API 拉到数据」这件事无法在本机验证。
  这一格需要**接一个真实的第三方接口**才能定论。

**D. CSV 与 Excel 共用同一套流程，但两者都是逐格实测的，不是推断的。**
CSV 与 Excel 走同一个预览/确认端点、同一份字段白名单，仅按文件扩展名分流解析器。
即便如此，「岗位 × CSV」和「招聘会 × CSV」都各自跑了一遍完整链路 ——
「代码路径相同所以应该也能通」正是本项目反复出问题的那类推断，不作为结论依据。

### 已知缺口一览（不影响现在录数据，但值得排期）

| # | 现象 | 影响 | 建议 |
|---|---|---|---|
| 1 | `json` 接入方式无解析器 | 建了也用不了 | 要么实现解析器，要么从可选项里摘掉 |
| 2 | 合作机构后台建数据源时只能选 api / webhook / excel 三种 | `csv` / `manual` 源建不出来（CSV 可以在 excel 源里传 .csv 文件绕过） | 补齐选项 |
| 3 | 管理员后台没有「新建岗位 / 新建招聘会」入口 | 管理员要补一条数据，只能让机构那边录 | 视需要补 |
| 4 | 管理员直接编辑招聘会信息时不会触发重新审核 | 已发布的招聘会被管理员改了时间地点，不经复核就生效 | 建议与机构侧编辑口径对齐 |
| 5 | 政策发布不校验来源可追溯字段 | 政策的外部ID / 官方链接可为空 | **这是设计如此**，见第四节 |

## 四、为什么政策的「外部ID / 官方链接」可以为空

岗位和招聘会的来源链接是**必填**，政策不是。这不是漏了，是刻意的：

- 岗位和招聘会的来源链接有明确用途 —— 求职者要点进去投递 / 预约。没有链接，这条信息对求职者是死的。
- 政策条目的官方入口链接**经常真的不存在**：很多地方政策只有红头文件，没有可跳转的网页。
- 政策的「外部ID」是发文字号。**没有发文字号的政策，宁可留空，也不要编一个。**
  数据表里对此有明确注释：留空时前台显示「来源未提供编号」，**不得伪造**。

所以政策录入时：**有就填，没有就留空**。留空不影响发布，前台会如实显示「来源未提供编号」。

## 五、常见失败提示速查

| 提示 | 出现在 | 含义 / 处理 |
|---|---|---|
| `文件格式不受支持：当前仅支持 .xlsx 与 .csv` | 文件导入 | 换成 .xlsx 或 .csv |
| `Excel/CSV 文件为空或格式不正确` | 文件导入 | 文件真的是空的，或内容损坏 |
| `Excel/CSV 文件不能超过 10MB` | 文件导入 | 拆成多批 |
| `Excel/CSV 文件最多包含 10000 行数据` | 文件导入 | 拆成多批 |
| `Excel 包含敏感列，禁止导入求职者个人信息: 联系人手机号` | 文件导入 | **删掉那一列再传**。手机/邮箱/简历/候选人/姓名/报名/投递/面试等列一律拒收，这是合规红线 |
| `property candidateEmail should not exist` | 接口导入 / Webhook | 推送方塞了候选人相关字段，删掉 |
| `未通过审核的岗位不得发布` | 发布 | 先审核 |
| `来源机构「X」未通过内容信任核验…` | 发布 | 见第零节 |
| `…来源信息不完整,不得发布(缺少必填字段:X)` | 发布 | 补齐那个字段，**系统不会替你填** |
| `审核终态 approved 不可回退` | 审核 | 已是终态，要改让机构侧重新编辑该条 |
| `reject 必须提供 reason` | 审核驳回 | 驳回必须写理由 |
| `机构类型 X 不允许使用 Y 接入方式` | 建数据源 | 该类型机构没有这种接入权限 |
| `仅公共就业服务机构与高校就业中心可发布政策内容` | 政策录入 | 机构类型不符 |
| `401 WEBHOOK_UNAUTHORIZED` | Webhook | 密钥/时间戳/nonce/数据源启用状态，四项自查 |
| `SSRF_PRIVATE_IP_BLOCKED`（同步日志里） | API 拉取 | 接口地址是内网地址，必须换成公网可访问地址 |

## 六、重复导入会怎样

**同一条数据（同一个外部ID）重复导入不会产生重复记录** —— 系统按「机构 + 外部ID」更新原有那条。实测确认。

但要注意：**内容有变化时，系统会把这条打回「待审核 + 草稿」。**
如果它当时正在前台展示，**会被自动撤下来**，需要重新审核发布。

这是刻意设计的：改过的内容必须重新过一遍人工把关。
所以定时同步的数据源，如果对方频繁改动，前台内容会反复下线 —— 这种情况要和对方约定好更新节奏。

（API 定时拉取有一个例外：内容**完全没变**时只更新同步时间，不会打回重审。）
