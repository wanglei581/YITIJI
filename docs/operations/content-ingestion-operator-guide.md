# 托管 a 下的内容录入：机构官方渠道二维码 + 政策

> **状态（2026-09-26）：** 机构端录入官方渠道（next-tasks 3.14）与机构自己审核发布政策（3.13）还在开发，计划 10 月底完成。完成前不新增任何录入，按下文「现在不录入什么」执行；旧版录入指南（岗位、招聘会发布到一体机）已停用，只在 git 历史里保留。

写给机构操作员和管理员。公司没有人力资源服务许可证，定位是设备与软件供应方：卖终端、随机交付软件、按年收维保。

托管 a：我们的云上不存岗位、招聘会、企业资料。一体机只在机构自己的机器上放该机构官方渠道的二维码。客户要完整招聘功能时，按托管 b 私有化部署到客户那边。

## 1. 现在录入什么

只录入两类。

**机构官方渠道。** 机构在机构端录入本机构官网或官方平台的名称和链接。链接只在该机构自己的一体机上显示为二维码。

**政策。** 由机构自己审核、发布（next-tasks 3.13；切换前仍是管理员审核发布）。展示范围沿用现有政策规则，是否只在本机构终端展示，3.13 落地时再定。

## 2. 现在不录入什么

岗位、招聘会、企业资料不录入我们的云。客户要这些功能，按托管 b 部署到客户自己的服务器或政务云，由客户运营。

## 3. 官方渠道怎么录

1. 用本机构账号进入机构端。
2. 填写本机构官网或官方平台的名称和链接。
3. 域名只能是入驻时核验过的该机构官方域名。域名对不上，先核对入驻资料，不要改填别的网站。
4. 启用之后，二维码只出现在绑定了该机构的终端上。没有绑定机构的终端不显示这些渠道。
5. 二维码旁边写明：本渠道由该机构提供，信息以其官网为准。

## 4. 政策怎么发

1. 机构在机构端编写政策，并由机构自己发布。
2. 管理员不代写、不代发。管理员对这类内容只保留紧急下架。
3. 紧急下架必须选事由并留痕，系统自动通知机构；管理员不能恢复，机构改完之后由机构自己重新发布。

## 5. 遇到这些情况就停下来

- 有人要求把岗位、招聘会或企业资料录入我们的云。
- 链接的域名不在入驻时核验过的该机构官方域名里。
- 自营点位被要求打开招聘类内容。自营点位作演示与材料出口。
