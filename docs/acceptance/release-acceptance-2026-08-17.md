# 发布验收清单（积压 20+ PR 首次上线）

> 生产运行版本停在 **8/14 的 SHA `49772209`**。本清单用于这批积压发布后的验收。
> 由 antigravity 设计、Claude 复核合并。**回滚判据是硬指标，不是「看着不对就回」。**

---

## 一、必须验（任一不过即视为发布失败）

### 1. 服务存活

```bash
curl -fsS https://zyidai.cn/api/v1/health          # 期望 status:ok, db:postgres
curl -s -o /dev/null -w '%{http_code}\n' \
     https://zyidai.cn/api/v1/health/ready         # 期望 200（发布前是 404）
```

> **`/health/ready` 从 404 变 200，是发布成功最干脆的指纹。**

### 2. 「不撒谎」类修复——用影子探针验，不要靠肉眼看空态

这类修复的共同难点：**要验证的是「某个东西不出现」**，而「没出现」既可能是修好了，也可能是根本没数据、或者页面整个坏了。

#### 2a. 首页招聘会恒为空（P0）

修复前：前端比对接口**根本不下发**的字段（`reviewStatus`/`publishStatus`），运行时恒为 `undefined`，每一场都被判不合格。

**验法（影子数据探针）**：

```
① curl /api/v1/job-fairs?status=ongoing
   ├─ 返回非空 → 直接看首页
   │   ├─ 首页展示出来   → PASS（修复彻底）
   │   └─ 首页仍「暂无」 → FAIL（前端比对逻辑仍有缺陷）
   └─ 返回空数组 []  → 走探针
       ② 在 Admin 插入一条 5 分钟后过期的测试招聘会
       ③ 刷新首页
       ├─ 展示出测试场次 → PASS（修复生效，此前只是无数据）
       └─ 仍显示「暂无」 → FAIL（存在脏逻辑阻断渲染）
```

**关键**：不做探针，「暂无」这个结果**无法证伪**。

#### 2b. OCR 提示不再对所有来源谎称「经文字识别提取」

修复前：**任何** `extractionNotice` 都写「本简历经文字识别（OCR）提取」，包括根本没走 OCR 的普通 PDF。

**验法（两个方向都要验）**：

| 用例 | 期望 |
|---|---|
| 上传**有文字层的普通 PDF**（不走 OCR），且触发一条超长截断提示 | 页面显示截断提示，**且不出现「经文字识别（OCR）提取」** |
| 上传**图片简历 / 扫描版 PDF**（真走 OCR） | **出现**「经文字识别（OCR）提取，识别置信度X」 |

**只验第一条会退化成「把提示整个关掉」也能过。必须两个方向都验。**

#### 2c. 付款码不再明文显示在公共大屏

**大屏上应该显示什么**：付款码输入区**不回显数字**（它是一次性支付凭证，27 寸竖屏是公共可见的）。

| 检查 | 期望 |
|---|---|
| 用扫码枪扫一张付款码 | 屏幕上**看不到 18 位数字**；只显示已录入的位数或掩码 |
| 提交后 | 输入缓冲区清空，不留残值 |

### 3. 打印链路（涉及资金，必须真跑一单）

| 检查 | 期望 | 失败判定 |
|---|---|---|
| 上传多页 PDF，看计费页数 | 与实际页数一致 | **算错即资损，立即回滚** |
| 扫码支付 → 出纸 | 订单状态推进到完成，纸真的出来 | 支付成功但订单卡死 = 熔断 |
| 打印失败时的反馈入口 | 能提交，且**不需要登录** | 弹登录墙 = 修复没生效 |

### 4. 合同审查（今天修了两层）

| 检查 | 期望 |
|---|---|
| 上传一份含**座机号 / 「证件2份」/ 邮箱地址：** 的合同 | 不再报 `ANALYSIS_FAILED`；能走到模型 |
| 分析失败时 | 页面显示**具体原因**，不再是「服务端未说明原因」 |

## 三、回滚判据

### 立即回滚（熔断级，15 分钟内决策）

1. **资金与交易阻断**
   - 支付成功但一体机未收到推送 → 订单卡死且未吐纸
   - PDF 页数严重算错导致多扣/少扣款
2. **大面积崩溃**
   - PM2 中 NestJS 进程 **1 分钟内重启 > 3 次**
   - nginx 持续 502 **超过 2 分钟**不自愈
3. **数据泄露**
   - 打印完成后会话未清空，**下一个人能翻到上一位的简历**
   - 日志中出现明文身份证 / 手机号
4. **一体机瘫痪**
   - 触摸失灵、白屏、全屏报错无法退出

### 可带病观察（次日修）

- 后台某些不常用表格在宽屏下轻微横向滚动
- 超长合同超时后提示文案不通顺，但能明确告知失败并可重试
- 政策检索复合词排序权重不理想，但**不吞数据**

## 四、两端专项

### 27 寸竖屏一体机

- **热区**：主按钮 ≥ **56px**，可点击区 ≥ **48px**。1080×1920 下严禁沿用 PC 的 32px 小按钮
- **防重**：连点「支付」「打印」必须立刻 `disabled` 或 Loading 遮罩 —— 触屏双击会造成重复计费
- **人体工学**：核心操作（扫码、确认、数字键盘）落在屏幕**中下部**；顶部只放只读信息
- **超时重置**：停留在含个人信息的页面（简历 / 合同），无操作 60 秒必须提醒并返回主页、清理缓存

### 微信小程序

- **胶囊避让**：自研 NavigationBar 的页面用 `wx.getMenuButtonBoundingClientRect()` 动态撑开 `paddingTop`；返回箭头与标题距胶囊 **≥ 10px**，严禁遮挡任何可点击像素
- **底部安全区**：底部固定按钮加 `env(safe-area-inset-bottom)`，不紧贴屏幕底边（防误触系统手势）
- **层级**：预览 PDF / 付款码弹窗时，Modal 与 Toast 必须在原生组件之上
